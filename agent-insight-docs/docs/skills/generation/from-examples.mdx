# From Examples

## 是什么

给平台几对 `input → output` 样本，让 LLM 反推出能产出这种输出的 Skill。底层调用：[`skills/outcome-benchmark-generator/`](https://github.com/your-org/agent-insight/blob/main/skills/outcome-benchmark-generator) 与生成器流水线组合。

适合：你**有标准答案的输出模板**，但不知道该写什么 prompt 才能让 LLM 稳定产出这种模板。

## 它解决什么问题

样本驱动的 Skill 生成是"逆向工程" —— 从"我要什么" 反推"该怎么写"。这种思路在评测驱动开发（eval-driven development）里很常见：

| 场景 | 直接写 Prompt | 从样本反推 |
|---|---|---|
| 我要这种格式的报告 | 试错改 Prompt 几小时 | 给 3 个示例 → LLM 反推 |
| 涉及多种输出 | 写超长 Prompt | 给 5-10 个混合样本 → LLM 抽出公共结构 |
| 想保证一致性 | 凭手感 | 样本本身就是 evaluation oracle |

## 怎么用

### 通过 UI

进入 **Skills 生成 → 从样本生成**，按"案例对"形式录入：

<!-- TODO 截图：新拍。Skills 生成 → From Examples 模式，左侧是样本对录入表格，右侧是反推出的 SKILL.md 预览。 -->

每条样本至少包含：

```yaml
input:
  query: "帮我看下这台机器的内存使用情况"
output:
  format: markdown
  content: |
    ## 内存概览
    - 总内存: 16GB
    - 已用: 8.2GB (51%)
    ...
```

建议 **3-5 对样本起步**，覆盖典型场景 + 边界情况。

### 通过 REST API

```bash
curl -X POST http://localhost:3000/api/skills/generate \
  -H "x-witty-api-key: $API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "mode": "from-examples",
    "examples": [
      {
        "input": "帮我看下这台机器的内存使用情况",
        "output": "## 内存概览\n- 总内存: 16GB\n- 已用: 8.2GB (51%)\n..."
      },
      {
        "input": "网络状态怎么样？",
        "output": "## 网络概览\n- 主网卡: eth0\n- IP: 192.168.1.100\n..."
      }
    ],
    "suggestedName": "system-info-report",
    "user": "demo@163.com"
  }'
```

## 样本对怎么选

| 好样本 | 坏样本 |
|---|---|
| 输入有共同点（都是查询系统） | 输入随机不相关 |
| 输出格式高度一致 | 输出格式各异 |
| 覆盖 3-5 个典型场景 | 全是同一个场景 |
| 边界 case 也有 1 个 | 全是 happy path |

## 关键参数

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `examples[]` | object[] | ✅ | 样本对数组，至少 2 对 |
| `examples[].input` | string \| object | ✅ | 输入（query 或结构化对象） |
| `examples[].output` | string | ✅ | 期望输出 |
| `examples[].note` | string | ❌ | 这对样本的特殊说明 |
| `outputFormat` | `markdown` / `json` / `table` | ❌ | 期望输出格式，影响生成器选模板 |

## 最佳实践

- **样本输出要"打磨过"** —— 直接拿生产 Trace 当样本 = 把瑕疵学进 Skill
- **同一种格式 5-10 对**，不要 50 对 —— LLM 不需要那么多就能归纳
- **样本足够异构** —— 全 happy path 训出来的 Skill 一遇到异常就崩
- **生成后跑评测** —— 用同一批样本反过来当评测数据集（自验证）

## 常见问题

<details>
<summary>给 100 对样本会不会更好？</summary>

不会。LLM 拿太多样本反而容易过拟合（产出贴样本而非抽象）。**5-10 对** 是 sweet spot。需要更多样本时用 [From Traces](./from-traces) 而非 From Examples。
</details>

<details>
<summary>样本里有敏感信息怎么办？</summary>

先在客户端做 PII 脱敏（替换成 `<NAME>` / `<ORG>`），再喂给生成器。详见 [PII Masking](../../observability/features/pii-masking)。
</details>

<details>
<summary>生成的 Skill 在新输入上表现不好？</summary>

用 [Auto Optimize](../optimization/auto-optimize) 跑迭代优化，把表现不好的 case 加到样本集里继续训。
</details>
