# From Prompt

## 是什么

把你已经在用的一段 Prompt（system prompt、few-shot 模板、长 prompt 块）"升级"为符合 Agent Skills 标准的 Skill。生成器会：

1. 抽取 Prompt 中的**任务定义** → 写到 `description`
2. 把 **示例 / few-shot** 移到 SKILL.md 主体
3. 检测 **工具调用** → 列入 `allowed-tools`
4. 把 **参考资料** 抽到 `references/`
5. 补齐 frontmatter

## 它解决什么问题

让"散落在 system prompt 里的好实践"沉淀为可版本化、可评测、可优化的资产：

| 散 Prompt | Skill |
|---|---|
| 改一次要找散落在代码里的多处 | 中心化版本管理 |
| 没法 A/B | 一键开 GrayscaleTask |
| 没人知道这段 prompt 哪天加的 | git + changeLog |
| 复制到下一个项目 = 又写一遍 | sync 到任意 Agent 主机 |

## 怎么用

### 通过 UI

进入 **Skills 生成 → 从 Prompt 改写**，把整段 Prompt 粘贴进去：

<!-- TODO 截图：新拍。Skills 生成 → From Prompt 模式输入框 + 右侧解析后的结构预览。 -->

平台会先做"结构识别"：

```
你的输入                              生成器识别出
─────────────────────────────────    ────────────────────────────────
You are a customer support agent.    → description: 客服 Agent，处理...
Always respond politely.             → 风格指令 → SKILL.md 主体
When user asks for refund:           → 子任务 1：退款流程
  1. Check order status              → 步骤
  2. Call refund API                 → 步骤 + 需要 tool: bash
For complex cases:                   → 子任务 2：升级
  Escalate to manager                → 边界条件
```

### 通过 REST API

```bash
curl -X POST http://localhost:3000/api/skills/generate \
  -H "x-witty-api-key: $API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "mode": "from-prompt",
    "prompt": "You are a customer support agent. Always respond politely. ...",
    "suggestedName": "customer-support",
    "user": "demo@163.com"
  }'
# 响应 → { name, content, extractedTools, suggestedReferences }
```

## 适合改写为 Skill 的 Prompt

| 适合 | 不适合 |
|---|---|
| 有明确触发场景的（"当用户问退款..."） | 通用对话指令（"你是一个 AI"） |
| 有具体步骤的（"先 A 再 B"） | 抽象人设（"你应该有同理心"） |
| 有工具调用的 | 纯文本生成 |
| ≥ 200 token | < 50 token（小到不值得 Skill 化）|

如果你的 prompt 是通用人设，应该放在 Agent 主提示里，不是 Skill。

## 关键参数

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `prompt` | string | ✅ | 完整 Prompt 文本 |
| `suggestedName` | string | ❌ | 建议的 Skill name，留空 LLM 自动起 |
| `extractFewShots` | bool | ❌ | 是否把 few-shot examples 抽到 references/（默认 true） |
| `targetCategory` | string | ❌ | 场景 tag |

## 最佳实践

- **先精简 Prompt** —— 把无关上下文（如"你是 X 公司的"）删掉再喂
- **把多轮 Prompt 拆开** —— 三个独立场景应该是三个 Skill，不是一个大 Skill
- **抽取后立刻 A/B** —— 与原 system prompt 对比，看升级是否真的有用
- **保留原 Prompt 7 天** —— 万一 Skill 化后效果回退，能快速对照

## 常见问题

<details>
<summary>原 Prompt 太长怎么办？</summary>

LLM 上下文有限。建议先手动把 Prompt 按场景分段 → 每段单独生成一个 Skill。这也符合"小而精"的最佳实践。
</details>

<details>
<summary>生成器把我的 few-shot 改坏了？</summary>

加参数 `extractFewShots: false`，平台会把 examples 原样保留在 SKILL.md 里，不抽到 references/。
</details>

<details>
<summary>这与"From Description" 有什么区别？</summary>

From Description 是"无中生有"，LLM 完全自主决策。From Prompt 是"结构重组"，LLM 必须忠实于你给的内容，只做归类和补齐 frontmatter。如果你已经有可工作的 Prompt，用 From Prompt 不会改坏；如果只有想法，用 From Description。
</details>
