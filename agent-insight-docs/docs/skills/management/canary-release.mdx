# 灰度发布（Canary Release）

## 是什么

把新版本 Skill 先暴露给一小部分流量，看真实生产数据再决定是否全量。Agent Insight 提供两层灰度：

1. **平台层灰度** —— A/B 测试（`GrayscaleTask`），离线对照实验，不影响生产
2. **生产层灰度** —— 多版本同时在线 + 路由规则，按 user / tag / 流量百分比分配

> A/B 测试与 Canary Release 不是同一件事：A/B 是"离线先打过擂台再决定上线"，Canary 是"已经上线但只给 5% 真实流量"。两者通常组合使用。

## 它解决什么问题

让"上线"从一次性的开关动作变成可控、可灰度、可观测、可回滚的过程：

| 风险 | 一刀切上线 | Canary |
|---|---|---|
| 新版本有 bug | 100% 用户受影响 | 5% 用户受影响 |
| 性能回退 | 监控告警时已经晚了 | A/B 对比指标第一时间发现 |
| 回滚耗时 | 改 activeVersion + sync 几分钟 | 改流量规则秒级生效 |

## 怎么用

### 通过 UI（v2 规划）

进入 **发布管理 → 灰度配置**：

- 选要灰度的 Skill + 新旧版本
- 配灰度策略（流量百分比 / 用户 tag / 时间窗）
- 启动灰度，平台实时显示新版本流量占比 + 关键指标对比

### 通过 REST API（v2 规划）

```bash
# 启动 5% 流量灰度
curl -X POST http://localhost:3000/api/skills/{id}/canary \
  -H "x-witty-api-key: $API_KEY" \
  -d '{
    "newVersion": 2,
    "oldVersion": 1,
    "strategy": "percentage",
    "trafficPercentage": 5,
    "monitorMetrics": ["answerScore", "tokens", "latency"],
    "rollbackThreshold": { "answerScore": -0.1 }
  }'
```

### 当前可用的替代方案

平台当前版本没有内置生产 Canary 路由器，但可以组合现有能力实现：

**方案 A：用 Skill name 区分版本**

```
~/.opencode/skills/pdf-extractor/      # 旧版本（90% 流量）
~/.opencode/skills/pdf-extractor-v2/   # 新版本（10% 流量）
```

在调用层按比例选用不同 name 的 Skill。`pdf-extractor-v2` 跑稳后改名顶替。

**方案 B：业务层路由**

```python
def select_skill(user_id):
    if hash(user_id) % 100 < 5:
        return "pdf-extractor-v2"
    return "pdf-extractor"
```

5% 的用户固定走新版本，**确定性灰度**（同一用户始终同一版本）。

## 灰度策略对比

| 策略 | 适合 | 局限 |
|---|---|---|
| **流量百分比** | 中性升级，无用户偏向 | 高方差用户随机分配，结果不稳定 |
| **用户 tag** | 想先给内部 / Beta 用户尝试 | 需要预先打 tag |
| **时间窗** | 大促前先冰封新版本 | 不能精细化控制人群 |
| **业务层 hash 灰度** | 确定性灰度（同用户始终同版本） | 自己实现 |

## 监控与回滚

灰度期间要看的指标（建议在 [Metrics](../../metrics/overview) 配看板）：

- `answerScore` 平均值的新旧版本差值
- `tokens` / `latency` 的 P95 差异
- `isAnswerCorrect = false` 比例

回滚触发：任一指标恶化超阈值 → 立即把流量调回 0%（不需要等 sync，路由规则秒级生效）。

## 最佳实践

- **灰度梯度** 5% → 25% → 50% → 100%，每个 stage 至少 24 小时观测
- **同时只灰度一个变量** 别同时改 Skill + 模型 + 数据集
- **保留 A 组对照** 即使灰度 100%，留 1% 流量跑老版本做长期监控
- **回滚预案要预先验证** 灰度前先演练一次"5% → 0%"，确保流量切换确实秒级

## 常见问题

<details>
<summary>Canary 和 A/B 测试可以同时跑吗？</summary>

可以也应该。**先 A/B 离线验证 → 再 Canary 生产验证 → 再全量**。两者数据互补：A/B 看离线指标，Canary 看真实业务指标。
</details>

<details>
<summary>用户切换版本后会有"幽灵态" 吗？</summary>

业务层 hash 灰度是确定性的，同一用户始终同一版本，不会切来切去。流量百分比策略会有，所以前端通常会把用户首次分配的版本 cache 一段时间。
</details>

<details>
<summary>当前版本能用吗？</summary>

平台当前版本（v1）没有内置生产 Canary 路由器，本页描述 v2 目标设计。当前可用替代方案见上文「方案 A/B」。
</details>
