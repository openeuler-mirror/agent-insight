# Skills Management

## 是什么

Management 是 Skills 模块里的"DBA 层" —— 把零散的 Skill 文档当工程资产规范化管理：每个 Skill 有归属、有版本、有 Schema、有状态、有灰度策略、有权限。看板上的 **Skills 资产** 页面就是 Management 的入口。

底层落到两张表：`Skill`（资产主体）+ `SkillVersion`（每次发布的快照），所有 Management 能力都是围绕这两张表展开。

## 它解决什么问题

让 Skill 摆脱"散文件 + git push" 的原始管理方式：

| 问题 | 散管理 | Management |
|---|---|---|
| 一个 Skill 有几个版本？ | 看 git log | `GET /api/skills/[id]/versions` |
| v1 和 v2 改了啥？ | git diff | `SkillVersion.changeLog` |
| 哪些 Agent 主机上跑的是哪个版本？ | 各处 `scp` 后忘了 | `Skill.isUploaded` + 同步 API |
| 不同用户能不能看同一个 Skill？ | 没办法隔离 | `Skill.user` + `visibility` |
| 紧急回滚到 v1？ | 翻 git 慢 | 改 `Skill.activeVersion` 一行 SQL |
| 灰度 5% 流量到新版本？ | 自己写发布脚本 | [canary-release](./canary-release) |

## 怎么用

### 通过 UI

进入 **Skills 资产**：

- 顶部搜索 / 分类筛选
- 每个 Skill 卡片显示 name / activeVersion / 上传状态 / 创建时间
- 点击卡片进入详情，能切版本、查看 changeLog、下载 ZIP、删除

### 通过 REST API

```bash
# 列出所有 Skill
curl http://localhost:3000/api/skills?user=demo@163.com \
  -H "x-witty-api-key: $API_KEY"

# 单个 Skill 详情（按 name）
curl http://localhost:3000/api/skills/by-name?name=pdf-extractor&user=demo@163.com \
  -H "x-witty-api-key: $API_KEY"

# 列版本
curl http://localhost:3000/api/skills/{id}/versions \
  -H "x-witty-api-key: $API_KEY"

# 新增版本
curl -X POST http://localhost:3000/api/skills/{id}/versions \
  -H "x-witty-api-key: $API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"content": "...", "changeLog": "fix description", "user": "demo@163.com"}'

# 下载某版本 ZIP
curl http://localhost:3000/api/skills/{id}/versions/{version}/download \
  -H "x-witty-api-key: $API_KEY" -o skill.zip
```

完整接口：[API Reference · Skills](../../api-and-data-platform/endpoints/README)。

## 最佳实践

- **永远走 `name` 不走 `id`** —— 对外 URL、跨 Agent 引用、import 都用 name
- **改名是大动作** —— rename 会断历史 URL 与 Trace 关联，提前公告
- **每次发布都填 changeLog** —— 三个月后回过头能看懂
- **静态合规跑过才上线** —— Schema 错的 Skill 上了线，OpenCode 加载都加载不动
- **Active 版本最多 1 个** —— 通过 `Skill.activeVersion` 字段单一指向

## 常见问题

<details>
<summary>Skill 删了，已经跑出来的 Trace 还在吗？</summary>

在。`Execution.skill / skillVersion` 是字符串字段，不是外键，删 Skill 不会级联删 Trace。但 UI 上跳转「这条 Trace 用的 Skill」会显示"已删除"。
</details>

<details>
<summary>能不能限制 description 修改？</summary>

不能限制，但**强烈建议把 description 改动当作"破坏性变更"**。原因：description 是 OpenCode 选 Skill 的依据，description 变了，召回率分析的结果就变了。最佳实践：description 变动一定 bump major 版本。
</details>

<details>
<summary>怎么把别人的 Skill 拿过来用？</summary>

平台层面：`visibility = 'shared'` 的 Skill 在全平台可见，可以 fork（创建一份归属当前用户的副本）。OpenCode 层面：通过 `/api/ingest/sync/opencode` 推到本机即可。
</details>
