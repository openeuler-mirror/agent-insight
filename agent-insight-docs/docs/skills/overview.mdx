# Skills Overview

Skills 是 Agent Insight 区别于 Langfuse / LangSmith 的**一等公民**模块。它把 Prompt + 触发条件 + 行为脚本封装成一个可版本化、可评测、可优化、可分发的工程资产，覆盖完整生命周期：**生成 → 管理 → 分析 → 优化 → 发布 → 监控**。

简单说：**Prompt Engineering 进化到 Skill Engineering**。Skill 不再是一段散落的文本，而是有 schema、有版本、有评测结果、有 A/B 报告的"代码级"工程对象。

## 核心能力一览

| 子模块 | 一句话 | 文档 |
|---|---|---|
| **生成 (Generation)** | 从需求描述 / 已有 Prompt / Trace 反推，AI 辅助产出 Skill 初稿 | [generation/overview](./generation/overview) |
| **管理 (Management)** | 注册、版本、Schema、状态流转、灰度发布、权限控制 | [management/overview](./management/overview) |
| **分析 (Analysis) ★** | 三步法 A/B 测试 + 多变体对战 + 失败下钻 + 召回率分析 | [analysis/overview](./analysis/overview) |
| **优化 (Optimization)** | 基于评测结果自动迭代 SKILL.md，参数搜索 / 多目标优化 | [optimization/overview](./optimization/overview) |

```
                     ┌─────────────────┐
                     │     Skills      │ ← 你在这里
                     │ （一等公民资产）  │
                     └─────────────────┘
                            ▲   ▲
                            │   │
            提供运行结果      │   │  提供评分明细
       ┌────────────────────┘   └─────────────────┐
       │                                          │
┌─────────────────┐                      ┌─────────────────┐
│  Observability  │                      │   Evaluation    │
│  (Trace 数据)    │                      │  (评估器)        │
```

Skills 是 Observability + Evaluation 的"消费方"：从 Trace 反推 Skill 实际触发，从评估器拿到扣分项与改进建议，最后产出新版本回到 Trace 闭环。

## 为什么 Agent Insight 把 Skills 拎到一等公民？

| 维度 | 普通做法（散 Prompt） | Agent Insight |
|---|---|---|
| 版本管理 | git 提交 + 部署 | `Skill / SkillVersion` 两张表 |
| 评测 | 自己写脚本拉 trace 跑 | 评测集 + 评估器自动跑 |
| 改进 | 凭经验改 | `SkillIssue` 列表驱动 |
| 上线决策 | 拍脑袋 | 三步法 A/B + 短板原则评分 |
| 跨主机分发 | scp / git pull | `/api/ingest/sync/opencode` 一键推 |

## FAQ

<details>
<summary>Skill 和 Prompt 有什么区别？</summary>

Prompt 是给 LLM 看的文本；Skill 是"Prompt + 触发条件 + 行为脚本 + 工具列表 + 版本"的工程封装。Skill 的 `SKILL.md` 里也有 Prompt，但加了 frontmatter（name / description / allowed-tools）让 Agent 框架（OpenCode / Claude Code）能自动发现并按需加载。
</details>

<details>
<summary>必须用 OpenCode / Claude Code 才能用 Skills 吗？</summary>

不必。Skill 的 `SKILL.md` 是纯 Markdown，可以喂给任何 LLM 框架。Skill 的 "触发条件" 在 OpenCode / Claude Code 里有原生支持（按 description 自动选 Skill），在其他框架里需要你自己实现路由逻辑。
</details>

<details>
<summary>Skill 用 `name` 还是 `id` 做 URL key？</summary>

对外用 `name`（前端路由 `/skill-opt/[name]/[version]`、新 API `/api/skills/by-name/...`）。`id` 仍在 DB 里，但只内部用。代价：rename 会断 URL —— 接受这个代价，rename 本来就该是大动作。
</details>
