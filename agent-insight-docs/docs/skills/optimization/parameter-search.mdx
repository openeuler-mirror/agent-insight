# Parameter Search

## 是什么

固定 SKILL.md 内容不变，只调 LLM 的运行参数（`temperature` / `top_p` / `max_tokens` / `presence_penalty` / `frequency_penalty`），看哪组参数让 Skill 表现最好。

借鉴自机器学习的"超参数搜索"思路（grid search / random search / Bayesian optimization），但搜索目标是 Skill 的评测分。

> 注：本能力在 v2 规划中。当前版本可以通过 [A/B Testing](../analysis/ab-testing) 手动配置不同参数组比较，本页描述完整设计。

## 它解决什么问题

很多 Skill 改一遍 prompt 没明显提升，但**只是调下 temperature 就能涨 5-10 分**。原因：

- temperature 太高 → 输出抖动大，稳定性差
- temperature 太低 → 创意 / 多样性场景表现差
- max_tokens 太短 → 长 trace 被截断
- top_p 与 temperature 互相影响

手动调这些参数很难，需要系统化搜索。

## 怎么用

### 通过 UI（v2 规划）

进入 **Skills 优化 → 选 Skill → 参数搜索**：

| 配置项 | 默认 | 说明 |
|---|---|---|
| `search.temperature` | `[0.0, 0.3, 0.5, 0.7, 1.0]` | 搜索范围 |
| `search.top_p` | `[0.7, 0.9, 1.0]` | 搜索范围 |
| `search.max_tokens` | `[1000, 2000, 4000]` | 搜索范围 |
| `strategy` | `grid` / `random` / `bayesian` | 搜索策略 |
| `budget` | int | 最多评估多少组（每组 = N 个 case × M 轮） |

平台跑所有组合（grid）或采样部分组合（random / bayesian），每组都跑一遍评测集，最后给出热力图：

### 通过 REST API（v2 规划）

```bash
curl -X POST http://localhost:3000/api/skills/by-name/{name}/param-search \
  -H "x-witty-api-key: $API_KEY" \
  -d '{
    "user": "demo@163.com",
    "skillVersion": 2,
    "search": {
      "temperature": [0.0, 0.3, 0.5, 0.7, 1.0],
      "top_p": [0.9, 1.0]
    },
    "strategy": "grid",
    "datasetId": "ds_xxx",
    "evaluatorId": "evaluator_llm_judge",
    "budget": 50
  }'
# 响应 → { searchId, jobs: [...] }

# 轮询结果
curl http://localhost:3000/api/skills/by-name/{name}/param-search/{searchId}
# → { results: [{ params: {...}, score: 0.85, std: 0.04 }, ...], best: {...} }
```

## 当前版本怎么做

v2 真正上线前，可以手动用 A/B Testing 模拟：

1. 复制 Skill 三份（v2-temp00 / v2-temp05 / v2-temp10），每份在 frontmatter 加 `model-params: { temperature: 0.0/0.5/1.0 }`
2. 用 [Multi-Variant Testing](../analysis/multi-variant) 跑三方对战
3. 看哪个 variant 的能力分 + 稳定性分综合最优

## 关键参数（v2）

| 参数 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `search` | object | — | 搜索空间，每个 key 是要搜的参数名 |
| `strategy` | enum | `random` | `grid` 全网格 / `random` 随机采样 / `bayesian` 贝叶斯优化 |
| `budget` | int | 30 | 最多评估多少组 |
| `datasetId` | string | — | 评测集 |
| `evaluatorId` | string | — | 评估器 |
| `concurrency` | int | 3 | 并发上限 |

## 搜索策略对比

| 策略 | 适合 | 局限 |
|---|---|---|
| **Grid** | 参数维度少（≤ 3）+ 想看全景 | 维度多了组合爆炸 |
| **Random** | 中等维度（3-5）+ 预算有限 | 可能漏掉最优 |
| **Bayesian** | 高维 / 预算非常少 | 实现复杂，对 surrogate model 要求高 |

## 最佳实践

- **先搜温度** —— 90% 的提升空间在 temperature 上
- **每组至少跑 5 轮取平均** —— LLM 调用本身有方差，单次不可信
- **保护短路** —— 设 `budget`，避免无脑跑掉所有 token
- **可视化热力图** —— 二维参数搜索后用热力图直观看趋势
- **搜完锁定参数写到 SkillVersion** —— 不要每次都搜，搜完写到 frontmatter

## 常见问题

<details>
<summary>这与 A/B Testing 有什么区别？</summary>

A/B 是"两个完全不同的版本对打"；Parameter Search 是"同一个版本下搜不同参数"。前者是粗粒度（换 SKILL.md），后者是细粒度（不换内容只换参数）。
</details>

<details>
<summary>不同模型最优参数不一样吗？</summary>

是。Claude 3.7 vs DeepSeek 的最优 temperature 完全不同。搜索结果与模型强绑定，换模型需要重搜。
</details>

<details>
<summary>能搜 system prompt 的字数吗？</summary>

理论上不能（"字数"不是 LLM 参数）。但可以搜 SKILL.md 主体的"详细程度" —— 平台预设几个详细度版本（minimal / medium / verbose），按版本搜。这是 [Auto Prompt Optimization](./auto-prompt-optimization) 的范畴。
</details>
