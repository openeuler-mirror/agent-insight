# Auto Prompt Optimization

## 是什么

[Auto Optimize](./auto-optimize) 是端到端"执行 → 评估 → 改 → 再跑"的循环；本页讲的是更聚焦的能力：**只针对 SKILL.md 的 prompt 部分做算法层改写**。借鉴学术界的 APE / OPRO / TextGrad 等思路，平台对常见 prompt 反模式（罗嗦 / 模糊 / 漏边界）做专项优化。

> 注：本能力在 v2 规划中，当前版本通过 [Auto Optimize](./auto-optimize) + `static` / `feedback` 模式间接覆盖。本页描述完整设计。

## 它解决什么问题

`Auto Optimize` 是端到端的，会把 SKILL.md 的所有部分（指令、scripts、references）都拉进 LLM 一起改。但很多时候问题只在 Prompt 部分（description 写得太泛、指令罗嗦、缺少边界条件）。专门的 Prompt 优化能：

| 端到端优化 | Prompt 算法优化 |
|---|---|
| 一次改 200 行 | 只改 frontmatter + 主指令段 |
| 改了 references 风险高 | 不动 scripts / references |
| 多目标交叉 | 单目标聚焦（清晰度 / 召回率 / 简洁度） |
| 黑盒 | 可对照学术算法（APE / OPRO）解释 |

## 支持的优化目标

| 目标 | 算法 | 评估指标 |
|---|---|---|
| **清晰度** | APE（Automatic Prompt Engineer） | LLM 5D 评估的 Role + Structure 维度 |
| **召回率** | 多轮变异 + 召回评测 | `SkillTriggerEvalRun.truePositiveRate` |
| **简洁度** | TextGrad-style 梯度反传 | token 数 + 评分保持 |
| **可读性** | LLM-as-Judge 二维评分 | 人类可读性专项打分 |

### 通过 REST API（v2 规划）

```bash
curl -X POST http://localhost:3000/api/skills/by-name/{name}/optimize-prompt \
  -H "x-witty-api-key: $API_KEY" \
  -d '{
    "user": "demo@163.com",
    "objective": "clarity",
    "candidateCount": 5,
    "evaluatorId": "evaluator_llm_judge"
  }'
```

平台后台跑算法迭代，每轮生成 N 个候选 prompt → 评估 → 选最好的进入下一轮，直到收敛。

## 当前版本如何实现

在 v2 真正上线前，可以组合现有能力达到类似效果：

1. 用 [Auto Optimize](./auto-optimize) 跑迭代
2. 在 `iter-config.yaml` 的 `optimization.goal` 字段写明专项目标（如"description 改更清晰"）
3. LLM 会主要聚焦在 prompt 部分

或者：

1. 用 [Skill 静态合规扫描](../analysis/overview) 找出 prompt 类 SkillIssue
2. 在 [Skill 优化页](./overview) 只选 prompt 相关 issue 跑 `static` 模式优化

## 关键参数（v2）

| 参数 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `objective` | string | — | `clarity` / `recall` / `brevity` / `readability` |
| `candidateCount` | int | 5 | 每轮生成多少候选 |
| `maxRounds` | int | 5 | 最大迭代轮数 |
| `evaluatorId` | string | — | 评估器 |
| `preserveSections` | string[] | `["scripts", "references"]` | 不被修改的段落 |

## 算法思路速览

### APE（Automatic Prompt Engineer）

1. 用 LLM 反推候选 prompt（"以下示例是用什么 prompt 跑出来的？"）
2. 在评测集上 score 每个候选
3. 选最高分的几个，继续变异 → 评测 → 迭代

### TextGrad

1. 计算每个 prompt 段落对最终评分的"梯度"
2. 反向传播改写信号
3. 多轮收敛

> 这些算法在内部 `src/lib/skill-analysis/prompt-optimization/` 实现（v2）。

## 最佳实践

- **objective 选一个，不要全开** —— 多目标拉扯反而收敛慢
- **候选数 5 是 sweet spot** —— 太多浪费 token，太少不够多样
- **preserveSections 保护已经稳定的部分** —— 别让算法把 scripts 改坏
- **跑完用 A/B 验证** —— 算法收敛 ≠ 真实业务提升

## 常见问题

<details>
<summary>这与 Auto Optimize 有什么本质区别？</summary>

Auto Optimize 是端到端 black-box：跑评测 → 改 SKILL → 再跑。算法优化是 white-box：知道 prompt 结构，按特定算法变异 prompt 段落。前者通用、后者专项。
</details>

<details>
<summary>支持哪些 LLM？</summary>

需要 LLM 支持长上下文（候选 prompt × N × 评估输出会很长）。Claude Sonnet 4 / GPT-4 Turbo 推荐。DeepSeek 也行，但可能需要降低 `candidateCount`。
</details>

<details>
<summary>能用我自己的算法吗？</summary>

v2 规划支持自定义 optimizer 插件（类似 Custom Evaluators）。当前版本不行。
</details>
