# Experiment History

## 是什么

把每次跑过的 A/B 任务（`GrayscaleTask`）按时间线沉淀成历史记录，可以横向对比、查 diff、回放。让 Skill 的迭代有"考古证据"。

平台 UI 入口：**Skills 分析 → A/B 测试 → 历史任务**。源数据 = `GrayscaleTask` 全表查询，按 `user + skillName` 过滤。

## 它解决什么问题

让"上次跑的实验"不再丢失：

| 没历史 | 有历史 |
|---|---|
| 跑完就忘，下次又跑 | 历史结果直接 reuse |
| 不知道几个月前的 v1 怎么样 | 时间线一目了然 |
| 老板问"上次 A/B 结论是什么" | 一键 share link |
| 没法看 Skill 演进趋势 | 跨任务画分数曲线 |

## 怎么用

### 通过 UI

进入 **Skills 分析 → A/B 测试 → 历史任务**：

<!-- TODO 截图：新拍。历史任务列表：每行展示 taskName / Skill 名 / 版本对比 / 综合判定 / 时间。 -->

每行展示：

| 列 | 含义 |
|---|---|
| `taskName` | 用户起的名字 |
| Skill + 版本对比 | A: v1, B: v2 |
| 综合判定 | direct-release / monitor / reject / insufficient |
| 三维得分 | 能力 / 成本 / 稳定性 |
| 评测集 | 用的哪份数据集 |
| 创建时间 | 跑实验的时间 |
| Actions | 查看详情 / 回放 / 删除 / share link |

点击任意行可以：

- **查看详情** — 重新打开 Step 3 报告
- **回放** — 重新跑同样配置（新建一个 GrayscaleTask + clone configJson）
- **share link** — 复制专属 URL，团队内共享

### 通过 REST API

```bash
# 列出当前用户的全部 A/B 任务
curl "http://localhost:3000/api/debug/grayscale-tasks?user=demo@163.com&skillName=pdf-extractor" \
  -H "x-witty-api-key: $API_KEY"
# 响应 → [
#   { id, taskName, skillName, skillVersion, createdAt, configJson, scoring: {...} },
#   ...
# ]

# 单个任务详情
curl http://localhost:3000/api/debug/grayscale-tasks/{id}

# 删除任务
curl -X DELETE http://localhost:3000/api/debug/grayscale-tasks/{id} \
  -H "x-witty-api-key: $API_KEY"

# 克隆 + 重跑（"回放"）
curl -X POST http://localhost:3000/api/debug/grayscale-tasks/{id}/clone \
  -H "x-witty-api-key: $API_KEY"
```

## 跨任务的趋势分析

历史不只是"列表"，还能画**趋势**：

```
能力分
 100 ┤                              ╭ v5 (today)
     │                          ╭───╯
  80 ┤                      ╭───╯ v4
     │                  ╭───╯
  60 ┤              ╭───╯ v3
     │          ╭───╯
  40 ┤      ╭───╯ v2
     │  ╭───╯ v1
  20 ┤
     └────────────────────────────────────→ time
        Jan    Feb    Mar    Apr    May
```

每个点对应一次 A/B 任务的能力分。**Skill 不是越改越好**也可能"中间有回退"，趋势图能让你看到。

> 当前版本：UI 展示列表 + 单任务详情。跨任务趋势图在 v2 规划中。可以走 API 拉数据自己画。

## 关键过滤

| 字段 | 用途 |
|---|---|
| `user` | 用户隔离 |
| `skillName` | 只看某个 Skill 的历史 |
| `decision` | 只看 release / reject / monitor |
| `createdAt` 范围 | 时间区间 |
| `evaluatorId` | 只看用了同一评估器的实验 |

## 最佳实践

- **taskName 起好名字** —— "实验1"、"测试" 这种名字 3 个月后毫无信息
- **关键节点打 tag** —— 大版本发布前的最后一次 A/B 加 tag `release-v2`，便于回顾
- **跨任务对比要看相同评测集** —— 评测集换了，分数没可比性
- **不删历史** —— 即使是 reject 的任务，保留作为"为什么不上"的证据
- **定期生成趋势报告** —— 季度回顾时，给团队看 Skill 演进曲线，价值很大

## 常见问题

<details>
<summary>历史任务可以加 tag / 备注吗？</summary>

`GrayscaleTask.taskName` + `configJson.taskDescription` 已经支持文本备注。tag 系统在 v2 规划。
</details>

<details>
<summary>不同评测集跑出来的能力分能直接对比吗？</summary>

**不能**。能力分是"B 比 A 高多少分 × 2.5"，分母是评测集的内部均值。换评测集 = 分母变了。跨数据集比较只看"在各自数据集上的相对位置"。
</details>

<details>
<summary>能给历史任务加 share link 供团队外查看吗？</summary>

当前版本：跨 user 的 share link 在 v2 规划。当前可以走 `/api/debug/grayscale-tasks/{id}` 拉 JSON 然后自己渲染分享页。
</details>
