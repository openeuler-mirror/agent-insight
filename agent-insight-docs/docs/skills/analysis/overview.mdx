# Skills Analysis Overview

Skills Analysis 是 Agent Insight 最有差异化的子模块。它回答一个问题：**这个 Skill 到底好不好？该不该上线？**

分析能力分四类，逐层递进：

| 维度 | 看什么 | 数据来源 | 典型问题 |
|---|---|---|---|
| **① 静态合规** | SKILL.md 本身写得对不对 | LLM 5D 评估 + 规则引擎 | frontmatter 缺字段、description 太短、工具列表混乱 |
| **② 召回率分析** | Skill 在 OpenCode 里能不能被正确触发 | `SkillTriggerEvalSet/Run` | 该触发没触发 / 不该触发却触发 |
| **③ A/B 测试 ★** | 开/关 Skill 或 v1/v2，到底哪个好 | `GrayscaleTask` | 能力提升了吗？成本翻了吗？稳定吗？|
| **④ 失败下钻** | 失败的 case 到底卡在哪一步 | `SkillIssue` 按 case / Skill / 评分项聚合 | 是 Skill 没触发？还是触发了走错步骤？|

Analysis 是 Skill 的"质检台" —— 上游接 Generation/Management 的产物，下游驱动 Optimization。

## 三步法工作流（核心）

`/skill-eval?view=gray` 页面的 A/B 测试严格按三步法组织。每一步对应 UI 上的一张 Card，强制串行：

```
┌────────────────────┐    ┌────────────────────┐    ┌────────────────────┐
│  ① CONFIG          │ →  │  ② EXECUTION       │ →  │  ③ DECISION        │
│                    │    │                    │    │                    │
│ 选 A/B 版本         │    │ 调度 Agent 执行     │    │ 算三个分数          │
│ 选数据集 + 用例     │    │ 并发执行 + 评估      │    │ 短板原则汇总        │
│ 选评估器            │    │ 实时矩阵刷新         │    │ 出判定 + 建议       │
│ 设重复轮次 / 并发    │    │                    │    │                    │
└────────────────────┘    └────────────────────┘    └────────────────────┘
   保存 GrayscaleTask        填 caseStatesJson         算 capabilityScore /
   configJson               + 评估器结果              costScore / stabilityScore
                                                     → min() → decision
```

详细分页：[Step 1](./step1-config) · [Step 2](./step2-execution) · [Step 3](./step3-decision)。

## FAQ

<details>
<summary>必须把三步法跑完才能上线吗？</summary>

强烈建议。Step 3 给出的"短板原则"判定（能力 / 成本 / 稳定性取最低分）是平台的发布决策标准。跳过任何一步都可能漏掉短板。

但如果你只是想做 quick check（例如改了 description 想看会不会触发），可以跳过 A/B 直接跑「召回率分析」—— 这是更轻量的入口。
</details>

<details>
<summary>静态合规、召回分析、A/B 三个评测顺序怎么选？</summary>

推荐顺序：
1. **先静态合规**（不耗 LLM token，秒级）—— 把低级错误清掉
2. **再召回分析**（中等耗时，30-90 秒）—— 确认 description 写得够好
3. **最后 A/B**（最耗时，5-30 分钟）—— 端到端跑用例

跳过 1 直接跑 3 也行，但 A/B 失败时不知道是哪个环节坏，调试成本高。
</details>

<details>
<summary>A/B 任务可以中途修改配置吗？</summary>

不能。`GrayscaleTask` 创建时 `configJson` + `skillId + versionBId` 强绑定，保存后不可改绑（避免历史结果被污染）。要改请删旧任务建新任务。
</details>
