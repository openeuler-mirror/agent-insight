# Multi-variant Testing

## 是什么

把 A/B 测试扩展到 3 个以上变体（A vs B vs C vs D ...），让你同时对比多个版本 / 多个模型 / 多组参数。

底层实现：内部把每对变体（A-B, A-C, A-D, B-C, ...）拆成多个 `GrayscaleTask`，并发跑，最后汇总成多变体报告。

> 注：原生多变体能力在 v2 规划中。当前版本可通过"两两 A/B + 手动汇总"实现，本页同时描述目标设计与当前替代方案。

## 它解决什么问题

只能 A/B 时，要选出 4 个候选里最好的得跑 6 次（每两两对打），费时且不直接给出排名：

| 候选数 | A/B 对数 | Multi-variant |
|---|---|---|
| 2 (A vs B) | 1 | 1 |
| 3 (A/B/C) | 3 | 1 |
| 4 (A/B/C/D) | 6 | 1 |
| 5 | 10 | 1 |

Multi-variant 一次跑完 + 直接出"全局排名"，省 60-90% 时间。

```bash
# 响应 → { variantScores: [...], ranking: ["B", "A", "D", "C"], bestVariant: "B" }
```

### 当前版本如何实现

v2 真正上线前，手动跑两两 A/B 然后汇总：

1. 对所有 N 个变体两两组合，跑 `C(N, 2)` 个 A/B 任务
2. 每个任务的 `versionAId` / `versionBId` 不同
3. 跑完 export 结果（`/api/debug/grayscale-tasks/{id}/export`），手动算每个变体在所有对照下的胜率
4. 胜率高的变体 = 最优

可以用 [Score Comparison](../../evaluation/features/score-comparison) 辅助可视化。

## 排名算法（v2 规划）

```
对每条 case：
  跑所有变体 × repeatRounds 轮
  评估器给每个变体的每次运行打分

每个变体的"全局分"：
  avg_eval_score = mean(score for all runs of this variant)
  invokeRate = (# runs with skillTriggered) / (# total runs)
  variance = mean(per-case variance)

  capability_score (vs 整体平均) = clamp(50 + (Δ vs mean) × 2.5, 0, 100)
  cost_score      ↓ 类似
  stability_score ↓ 类似

排名 = sort by min(三个分) desc（短板原则）
```

参考 [Step 3 · DECISION](./step3-decision) 的短板原则，扩展到 N 个变体。

## 关键参数

| 参数 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `variants[]` | object[] | — | 2-6 个变体，每个含 skillVersionId / modelConfigId / params |
| `repeatRounds` | int | 1 (推荐 3) | 每条 case × 每个变体的重复 |
| `concurrency` | int | 5 | 并发上限 |

总执行 = N_cases × N_variants × repeatRounds。4 变体 × 10 case × 3 轮 = 120 次执行。

## 最佳实践

- **变体数控制在 ≤ 6** —— 多了一次评测成本爆炸
- **保留一个 "无 Skill" baseline** —— 即使是 multi-variant，也要知道"完全不上 Skill" 是什么样
- **变体之间只改一个维度** —— A=v1+claude, B=v2+claude, C=v1+deepseek 是好设计；A/B/C/D 全是不同 Skill + 不同模型组合 = 完全无法归因
- **跑完再做 Pareto** —— 单分排序可能错，结合 [Multi-Objective](../optimization/multi-objective) 看 Pareto 前沿

## 常见问题

<details>
<summary>3 个变体的"短板原则"怎么算？</summary>

每个变体独立算 `min(自己的能力分, 自己的成本分, 自己的稳定性分)`，再 sort。短板原则不在变体之间比较，只在每个变体内部决策。
</details>

<details>
<summary>能用"评估器投票"决定最优吗？</summary>

可以。除了"评估器打分排名"，平台还提供"评估器两两 prefer 投票"模式（v2 规划）：把任意两变体的输出给评估器看，问"你更喜欢哪个"，统计胜率。适合 LLM-as-Judge 难给具体分数但能比较两者好坏的场景。
</details>

<details>
<summary>Multi-variant 和 Pareto 前沿什么关系？</summary>

Multi-variant 给你"每个变体在三维上的得分"，Pareto 前沿（[Multi-Objective](../optimization/multi-objective)）把这些得分可视化让你权衡。两者配合：Multi-variant 产生原始数据，Pareto 帮你做决策。
</details>
