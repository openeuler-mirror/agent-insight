## 5 张核心表

### `Skill` — Skill 主体

| 字段 | 含义 |
|---|---|
| `id` | 内部主键，**只内部用** |
| `name` | **对外 key**，前端路由 `/skill-opt/[name]/[version]` |
| `user` | 归属用户（多租户隔离） |
| `category` | 分类 tag |
| `visibility` | `private` / `shared` |
| `activeVersion` | 当前激活版本号 |
| `isUploaded` | 是否已推送到 Agent 主机 |

> 不变式：`(user, name)` 联合唯一；rename 会断 URL，accept it。

### `SkillVersion` — 版本快照

| 字段 | 含义 |
|---|---|
| `skillId` | FK → Skill |
| `version` | 整数版本（自增） |
| `content` | 完整 `SKILL.md`（含 frontmatter） |
| `changeLog` | 本次变更说明 |
| `semanticVersion` | 可选语义化版本 `v1.2.3` |
| `enterpriseSkillId` | 与企业 Skill 库的映射 ID |

> 不变式：`(skillId, version)` 联合唯一；版本不可删（除非整 Skill 都删）。

### `Evaluation` — 评测事件（静态 + 动态合一）

| 字段 | 含义 |
|---|---|
| `type` | `'static'` / `'dynamic'` |
| `skillId` / `version` | 评的哪个版本 |
| `executionId` | dynamic 时指向被评 Trace |
| `contentHash` | static 时是 `SKILL.md` 内容 hash |
| `generator` | 评估器自标识（`judge.ts@1.2`） |
| `l2ScoresJson` | LLM 5D 评分 |
| `ranAt` / `status` | 时间戳 / 状态 |

**不变式**：
- 静态评估和动态评估**统一到一张表**，URL `/evaluation/<id>` 不分类型
- 1 SkillVersion : N static evaluations（重评懒删除）
- 1 Execution : N dynamic evaluations（重评懒删除）

### `SkillIssue` — 单条优化点

| 字段 | 含义 |
|---|---|
| `evaluationId` | FK → Evaluation，**Cascade delete** |
| `source` | denormalize 自 `Evaluation.type` |
| `severity` | `'high'` / `'medium'` / `'low'`（与 UI 用词一致） |
| `summary` / `evidence` / `reasoning` / `suggestedFix` | 人话描述 + LLM 给出的改进建议 |
| `dedupKey` | 跨 evaluation 聚合键 |
| `ruleId` | static 专用元数据 |

**dedupKey 规则**：
- static: `ruleId`（如 `frontmatter_missing_name`）
- dynamic: `hash6(content + explanation)`

聚合时按 `dedupKey` 计算 `prevalenceCount`，≥3/5/10 三档抬升一级 severity。详见 [`src/lib/engine/skill-issues/prevalence.ts`](https://github.com/your-org/agent-insight/blob/main/src/lib/engine/skill-issues/prevalence.ts)。

### `GrayscaleTask` — A/B 测试任务

| 字段 | 含义 |
|---|---|
| `skillId` / `skillName` / `skillVersion` / `skillVersionId` | **强绑定** Skill + B 实验版本 |
| `taskName` | 用户命名 |
| `configJson` | 完整运行配置（versionAId / versionBId / 数据集 / 评估器 / 重复轮次 / 并发） |
| `caseStatesJson` | 每个 case × A/B × round 的执行 + 评估状态 |

**不变式**：同 user 下 `skillName + skillVersion` 唯一；任务保存后**不可改绑** Skill。

### 衍生表

- **`SkillTriggerEvalSet` + `SkillTriggerEvalRun`** — 触发评价集（"召回分析"卡数据源），见 [Skills 管理 · Access Control](./management/access-control)
- **`ParsedFlow`** — Skill 流程图解析缓存
- **`ExecutionMatch`** — 单次执行 vs Skill 静态流程的匹配结果

## 两条核心 invariant

来自源码注释，开发者改 schema 前请遵守：

1. **静态评估和动态评估统一到 `/evaluation/<id>`** —— 一张 `Evaluation` 表承载两种类型，前端跳转 URL 不分类型。
2. **SkillIssue 通过 FK 链接到 evaluation_id** —— 一张 `SkillIssue` 表，每行 = 一个独立优化点；`OptIssue.id = SkillIssue.id`（真主键）。
