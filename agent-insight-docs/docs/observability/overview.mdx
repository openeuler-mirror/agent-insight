# Observability Overview

Observability 是 Agent Insight 的「看得见」层，回答一个问题：**这个 Agent 到底跑得怎么样？** 它把 Agent 的每一次 LLM 调用、tool call、子 Agent handoff 都串成一条可追溯的 Trace，并在此基础上做主动监控与归因。

底层基于 OpenTelemetry GenAI 语义约定，所以你既可以走 Agent Insight 原生 SDK，也可以把现成的 OTel 数据点直接打过来。

## 核心能力一览

| 功能 | 一句话 | 文档 |
|---|---|---|
| **链路追踪** | 把多 Agent / 多轮调用串成一棵可下钻的调用树 | [tracing](./features/tracing) |
| **Session 归组** | 多轮对话按 `taskId` 聚合，看完整上下文 | [sessions](./features/sessions) |
| **User 归组** | 按终端用户聚合 trace，看个体行为 | [users](./features/users) |
| **Tags / 环境** | 给 Trace 打标签 / 分环境查询 | [tags](./features/tags) · [environments](./features/environments) |
| **多模态** | 支持图片 / 音频 / 文件附件的 Trace | [multi-modal](./features/multi-modal) |
| **Token 与成本追踪** | 每条 Trace 的 token / cost / latency 自动归集 | [token-cost-tracking](./features/token-cost-tracking) |
| **延迟分析** | P50/P95/P99 + 慢调用下钻 | [latency-analysis](./features/latency-analysis) |
| **★ 智能诊断** | 主动发现失败模式、扣分项、路径偏离 | [intelligent-diagnosis](./features/intelligent-diagnosis) |
| **★ 质量监控** | 关键指标告警与回归发现 | [quality-monitoring](./features/quality-monitoring) |
| **采样 / 排队** | 高流量下的采样策略与异步上报队列 | [sampling](./features/sampling) · [queuing-batching](./features/queuing-batching) |
| **PII 脱敏** | 上报前自动屏蔽敏感字段 | [pii-masking](./features/pii-masking) |
| **Trace IDs** | OTel `trace_id` / `span_id` 与平台 `taskId` 的映射 | [trace-ids](./features/trace-ids) |

```

            │ Observability   │ ← 你在这里
            │ （原始 Trace）   │

        ▼            ▼            ▼
   ┌──────────┐ ┌──────────┐ ┌──────────┐
   │Evaluation│ │  Skills  │ │ Metrics  │
   │ (对 Trace│ │ (从 Trace│ │ (汇总指标│
```

Trace 是底座，Evaluation 在 Trace 上跑评估器、Skills 模块从 Trace 里挖出 Skill 的实际触发与扣分项、Metrics 汇总 Trace 出告警。

## FAQ

<details>
<summary>必须用 Agent Insight 的 SDK 才能上报吗？</summary>

不必。Agent Insight 同时支持三种入口：

1. **原生 SDK**（Python / TypeScript）— 最方便，自动注入 trace 上下文
2. **OpenTelemetry**（`/api/ingest/otel/v1/traces`）— 已经在用 OTel 的项目直接打过来即可
3. **采集插件**（OpenCode native plugin / Claude Code 日志旁路 watcher）— 不改 Agent 代码

详见 [Integrations](../integrations/overview)。
</details>

<details>
<summary>多 Agent 系统的调用树是怎么还原的？</summary>

平台从 `interaction.tool_calls` 里识别 `task` / `subagent_*` 字段，结合 OTel span 的 `parent_id` 还原层级。算法在 `src/lib/engine/observability/agent-trace.ts`。
</details>

<details>
<summary>Trace 数据可以删吗？</summary>

可以。`DELETE /api/observe/data` 支持按 `upload_id` / `task_id` / `timestamp+framework+query` 三种粒度删除，详见 [API Reference](../api-and-data-platform/endpoints/README)。
</details>
