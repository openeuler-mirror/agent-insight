# REST API

## 是什么

Agent Insight 所有功能都暴露为 REST API，可以不通过 SDK 直接 `curl` 上报 / 查询。适用：

- 没有官方 SDK 的语言（Go / Rust / Java / .NET）
- 服务端到服务端的数据传递
- shell 脚本 / CI / 自动化工具
- 自定义 SDK 二次封装

最重要的两个端点：

- **`POST /api/ingest/upload`** —— 主上报入口（SDK 内部也是调它）
- **`GET /api/observe/data`** —— 查询 Trace

## 它解决什么问题

| 没 REST API | 有 |
|---|---|
| 只能用 Python / TS | 任何语言 |
| 没法在 shell 里直接调 | curl + jq 起步 |
| 二次封装难 | 接口稳定，文档完整 |

## 上报 Trace

### `POST /api/ingest/upload`

```bash
curl -X POST http://localhost:3000/api/ingest/upload \
  -H "x-witty-api-key: ai_xxx" \
  -H "Content-Type: application/json" \
  -d '{
    "task_id": "task_uuid_xxx",
    "user": "demo@163.com",
    "framework": "custom",
    "query": "查看系统信息",
    "final_result": "## CPU\n- ...",
    "interactions": [
      {
        "role": "user",
        "content": "查看系统信息",
        "timeInfo": { "start": "2026-05-28T10:00:00Z", "end": "2026-05-28T10:00:00Z" }
      },
      {
        "role": "assistant",
        "agent": "main-agent",
        "content": "好的，我来跑几个命令",
        "tool_calls": [
          { "name": "bash", "input": "lscpu", "output": "...", "duration_ms": 120 }
        ],
        "usage": { "prompt_tokens": 150, "completion_tokens": 50 },
        "timeInfo": { "start": "2026-05-28T10:00:01Z", "end": "2026-05-28T10:00:03Z" }
      }
    ],
    "tokens": 200,
    "latency": 3000,
    "cost": 0.001,
    "timestamp": "2026-05-28T10:00:03Z",
    "label": "customer-support",
    "metadata": { "environment": "prod", "region": "cn" }
  }'

# 响应：
# { "success": true, "record": { "id": "...", "task_id": "...", ... } }
```

## 上报结构

完整 schema（按 `src/lib/storage/data-service.ts → saveExecutionRecord()` 抽取）：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `task_id` | string | ✅ | 唯一主键 |
| `user` | string | ✅ | 终端用户 ID |
| `framework` | string | ✅ | `opencode` / `claude-code` / `custom` / ... |
| `query` | string | ✅ | 初始用户输入 |
| `final_result` | string | ❌ | Agent 最终输出 |
| `interactions[]` | array | ✅ | 详细 interaction 数组 |
| `tokens` | int | ❌ | 总 token |
| `latency` | int | ❌ | 端到端耗时 ms |
| `cost` | float | ❌ | 估算成本 USD |
| `timestamp` | ISO 8601 | ✅ | 完成时间 |
| `label` | string | ❌ | 主标签 |
| `skills[]` | string[] | ❌ | 调用过的 Skill 列表 |
| `skill` / `skill_version` | string / int | ❌ | 主 Skill |
| `metadata` | object | ❌ | 任意业务元数据 |

`interactions[]` 每项：

| 字段 | 含义 |
|---|---|
| `role` | `user` / `assistant` / `tool` / `system` |
| `agent` | Agent 名（多 Agent 时） |
| `subagent_name` | 子 Agent 名 |
| `subagent_session_id` | 子 Agent 自己的 sessionId |
| `content` | LLM 文本 |
| `tool_calls[]` | tool call 列表 |
| `usage` | `{prompt_tokens, completion_tokens}` |
| `timeInfo` | `{start, end, duration_ms}` |

## 查询 Trace

### `GET /api/observe/data`

```bash
# 列表 + 过滤
curl "http://localhost:3000/api/observe/data?user=demo&framework=opencode&skill=pdf-extractor" \
  -H "x-witty-api-key: ai_xxx"

# 单 trace task-stats
curl "http://localhost:3000/api/observe/task-stats?taskId=task_xxx" \
  -H "x-witty-api-key: ai_xxx"

# 单 trace 全部 interactions
curl "http://localhost:3000/api/observe/session?taskId=task_xxx" \
  -H "x-witty-api-key: ai_xxx"
```

### 修改 Trace

```bash
curl -X PATCH http://localhost:3000/api/observe/data \
  -H "x-witty-api-key: ai_xxx" \
  -H "Content-Type: application/json" \
  -d '{
    "task_id": "task_xxx",
    "label": "high-priority",
    "user_feedback": "answer was wrong"
  }'
```

### 删除 Trace

```bash
curl -X DELETE http://localhost:3000/api/observe/data \
  -H "x-witty-api-key: ai_xxx" \
  -d '{"task_id": "task_xxx"}'
```

## 认证

所有 API 走 `x-witty-api-key` Header：

```bash
curl -H "x-witty-api-key: ai_xxx" ...
```

API Key 在 **平台配置 → 安装指导** 页可复制，或通过 `POST /api/auth/apikey` 生成。

## 错误码

| 状态码 | 含义 |
|---|---|
| 200 | 成功 |
| 400 | 请求格式错（缺字段 / JSON 无效） |
| 401 | API Key 错 / 缺失 |
| 404 | 资源不存在 |
| 409 | 唯一约束冲突（如 task_id 撞了） |
| 429 | 频率限制（节流） |
| 500 | 服务端错 |

详见 [API · Rate Limits](../../api-and-data-platform/rate-limits)。

## 最佳实践

- **task_id 在客户端生成** —— UUID v4 即可，不要让服务端生成
- **批量发** —— `interactions[]` 一次性发完比拆几次发更高效
- **timestamp 用 ISO 8601** —— 不要用 epoch（前后端时区一致性好）
- **失败重试** —— 5xx 与 429 应该指数退避重试，4xx 不重试
- **看 OpenAPI spec** —— 平台启动后访问 `/api/openapi.json` 拿完整 schema

## 常见问题

<details>
<summary>有 OpenAPI / Swagger 文档吗？</summary>

平台暴露 `/api/openapi.json`（OpenAPI 3.1 格式），可以直接喂给 Swagger UI / Redoc 渲染，或者用 `openapi-generator` 生成各语言 client。
</details>

<details>
<summary>上传大附件用 multipart 怎么传？</summary>

走 `/api/ingest/parse-document`（multipart/form-data）。详见 [Multi-Modal](../features/multi-modal)。
</details>

<details>
<summary>能批量上报多个 task 吗？</summary>

当前只能一次一个 `task_id`（避免单条失败拖死整批）。批量是客户端循环 + 并发。
</details>
