# Users

## 是什么

`Execution.user` / `Session.user` 字段把 Trace 与"终端用户"挂钩。用 user 维度聚合后，能看到某个具体用户在一段时间内的所有调用行为，做用户行为分析、问题 reproduce、个人化优化。

平台的 `user` 字段双重含义：
1. **平台账号**（API Key 归属）—— 你
2. **终端用户**（业务上的 customer）—— 调你的 Agent 的人

这两个可以是同一个，也可以不同。本页讨论"终端用户"维度。

## 它解决什么问题

| 没 User 维度 | 有 User 维度 |
|---|---|
| 用户报 bug "我的 Agent 卡了" → 找不到他的 Trace | 按 user 一键拉出所有 Trace |
| 个性化推荐不知道用户偏好 | 聚合用户历史看模式 |
| A/B 灰度按用户 | 按 user hash 灰度 |
| 客服支持没有上下文 | 一键拉用户最近 N 条 Trace |

把 user 输入栏填上业务的真实用户标识（如 `customer_12345`），列表立刻收敛。

### 通过 SDK

```python
from agent_insight import AgentInsight, observe

AgentInsight.init(api_key="ai_xxx")

@observe()
def my_agent(query: str, user_id: str) -> str:
    AgentInsight.set_user(user_id)  # 把当前调用归到这个 user
    return answer
```

```typescript
import { AgentInsight, observe } from "@agent-insight/sdk";

const myAgent = observe(async (query: string, userId: string) => {
  AgentInsight.setUser(userId);
  return answer;
});
```

### 通过 REST API

```bash
# 上报时带上 end-user ID
curl -X POST http://localhost:3000/api/ingest/upload \
  -H "x-witty-api-key: $API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "task_id": "task_xxx",
    "user": "customer_12345",
    "query": "...",
    "interactions": [...]
  }'

# 查询某用户的所有 Trace
curl "http://localhost:3000/api/observe/data?user=customer_12345" \
  -H "x-witty-api-key: $API_KEY"
```

## 关键参数

| 参数 | 类型 | 说明 |
|---|---|---|
| `user` | string | 终端用户 ID（业务标识，不是 API Key user） |
| `metadata.user_segment` | string | 可选用户分群（vip / free / trial） |
| `metadata.user_metadata` | object | 任意附加用户信息 |

## 平台账号 vs 终端用户

容易混淆，分清楚：

| 维度 | 平台账号 (API Key user) | 终端用户 (Trace user) |
|---|---|---|
| 谁？ | 用 Agent Insight 的人 | 用你的 Agent 的人 |
| 例子 | `demo@163.com` | `customer_12345` |
| 在哪存？ | `User.username` | `Execution.user` / `Session.user` |
| 用途 | 平台权限隔离 | 业务用户行为分析 |

两者可以是同一个（你自己测试自己 Agent 时），但生产用通常不同。

## 最佳实践

- **客户端就把 `user` 设好** —— 别等出 bug 才补，Trace 已经上去了改不动
- **用稳定 ID** —— 不要用邮箱（可能换），用业务系统的 user_id
- **匿名场景用 hash** —— 隐私敏感时用 `hash(real_user_id)`，平台还能聚合，但反查不出
- **加 user_segment** —— 高级账号 vs 免费账号分群，便于 A/B 与运营分析

## 常见问题

<details>
<summary>能不能不传 user？</summary>

可以。`Execution.user` 是可选字段，留空时该 Trace 不属于任何终端用户（通常是平台账号自己测试的）。
</details>

<details>
<summary>同一终端用户多次调用平台会自动关联吗？</summary>

会。`Execution.user` 是字符串字段，相同值就会被平台聚合。`GET /api/observe/data?user=xxx` 拉出所有归属该 user 的 Trace。
</details>

<details>
<summary>有"用户 dashboard"页面吗？</summary>

当前版本：UI 只有"按 user 过滤"。完整的 user 详情页（含 Trace 数量、token 总量、failure 率）在 v2 规划，对应 PROJECT.md §5.1 的 `/agents` 占位路由。
</details>
