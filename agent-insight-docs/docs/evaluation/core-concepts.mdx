# Core Concepts

本页解释 Evaluation 模块里四个核心概念是什么、怎么连接、对应平台哪张表。看完应该能回答："我评一条 Trace，从用户视角到 DB 落地中间到底发生了什么？"

## 四个核心概念

### Dataset（数据集）

「我们认为对的答案是什么样的」的载体。落到 DB 表 `AgentEvalDataset`。

| 字段 | 取值 | 说明 |
|---|---|---|
| `name` | string | 业务命名 |
| `datasetKind` | `ideal_output` / `trajectory` | 看结果还是看过程 |
| `targetSkill` | string? | 挂在哪个 Skill 上（空 = 通用 agent 评测） |
| `casesJson` | JSON | 用例数组（见下） |
| `tagsJson` | JSON | 标签 |

### Case（用例）

数据集里的「一行」，存在 `casesJson` 里。最小结构：

```json
{
  "id": "case_xxx",
  "query": "我想退款",
  "standardAnswer": "...",
  "keyActions": ["查询订单状态", "调用退款 API"],
  "rootCauses": [
    {"label": "未识别退款意图", "weight": 0.6}
  ],
  "source": "user"  // 或 "skill-gen-draft"
}
```

`rootCauses` 是平台用 LLM 抽取出来的，第一次保存时缓存到 `rootCauseMeta`。

### Evaluator（评估器）

打分的代码逻辑。Agent Insight 内置三类、也支持自定义。

| 评估器 | 适用 | 输出 |
|---|---|---|
| **LLM-as-Judge** | 开放问题 | `{score, judgment_reason, is_skill_attributable, improvement_suggestion}` |
| **Trajectory Evaluator** | 多步骤 Agent | `{deviation_steps[], key_point_findings[], tool_choice_findings[], result_issues[]}` |
| **Routing Evaluator** | Skill 选择 | `{is_correct_route, expectedSkills vs invokedSkills}` |
| **Custom** | 任意业务规则 | 用户自定义 |

实现源码：[`src/lib/engine/evaluation/judge.ts`](https://github.com/your-org/agent-insight/blob/main/src/lib/engine/evaluation/judge.ts)。

### Evaluation（评测事件）

每次"评估器对一条 Trace 跑一次"都生成一行 `Evaluation`。**1 trace : N evaluations** —— 重评不删旧记录。

| 字段 | 说明 |
|---|---|
| `type` | `'static'`（评 Skill 内容） / `'dynamic'`（评 Trace） |
| `executionId` | dynamic 时指向 Trace，static 时为 null |
| `generator` | 评估器自标识，如 `judge.ts@1.2` / `trajectory-evaluator@1.0` |
| `l2ScoresJson` | LLM 5D 评分 `{Role, Structure, ...}` |
| `ranAt` / `status` | 运行时间 / 运行状态 |

### SkillIssue（扣分项 / 优化点）

每次 Evaluation 可能产出多条 SkillIssue，作为 Skills 模块「优化点列表」的数据源。

| 字段 | 说明 |
|---|---|
| `evaluationId` | FK → Evaluation |
| `source` | `'static'` / `'dynamic'` / `'feedback'` |
| `severity` | `high` / `medium` / `low` |
| `summary` / `evidence` / `suggestedFix` | 人话描述 |
| `dedupKey` | 跨 evaluation 的聚合键（static 用 ruleId，dynamic 用 hash） |

详见 [Skills 模块 · Failure Drilldown](../skills/analysis/failure-drilldown)。

## 数据流转

```
1. 用户在 UI 建数据集 → AgentEvalDataset 落库
2. 平台用 LLM 预解析每条 case 的 rootCauses → 缓存到 casesJson
3. 用户点 Run → 后端拉出对应 Trace + 评估器
4. 评估器对每条 Trace 跑 → 生成 Evaluation + N 条 SkillIssue
5. 结果回写 Execution.failures / answerScore / isAnswerCorrect
6. UI 从 Evaluation + SkillIssue 聚合渲染（按 dedupKey 算 prevalence 抬升严重度）
```

聚合逻辑在 [`src/lib/engine/skill-issues/index.ts`](https://github.com/your-org/agent-insight/blob/main/src/lib/engine/skill-issues/index.ts)。
