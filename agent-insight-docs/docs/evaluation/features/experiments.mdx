# Experiments

## 是什么

Experiment 是 Agent Insight 对一次评测作业的封装。一个 Experiment = 「**评测集 + 评估器 + Trace 范围 + 参数**」一次性运行，输出可对比的分数。

平台对应实体：

- **UI**：`/eval` 页面的 `AgentEvalCenter`
- **DB**：`BatchEvalTask` 表（PROJECT.md §4 注释里提到）
- **底层调度**：复用 [Offline Evaluation](./offline-evaluation) 的 evaluation engine

A/B 测试（`GrayscaleTask`）是 Experiment 的特化形态（绑定两个 Skill 版本 + 三步法评分）。

## 它解决什么问题

裸跑评估器没有"作业"概念：

| 没 Experiment | 有 |
|---|---|
| 每次评测都是临时操作 | Experiment 是一等公民 |
| 没法跨次对比 | Experiment 1 vs Experiment 2 直接对比 |
| 不知道参数怎么调的 | Experiment 配置全保留 |
| 团队共享难 | 共享 Experiment URL |

## 怎么用

### 通过 UI

进入 **评测任务**（`/eval`）→ 新建 Experiment：

<!-- TODO 截图：新拍。AgentEvalCenter Experiment 配置面板：选数据集 / 评估器 / Trace 范围 / 参数。 -->

| 字段 | 必填 | 说明 |
|---|---|---|
| `name` | ✅ | 用户起的名字 |
| `description` | ❌ | 文字说明 |
| `datasetId` | ✅ | 评测集 |
| `evaluatorId` | ✅ | 评估器 |
| `traceRange` | ✅ | 哪批 Trace（时间 / Skill / user / framework） |
| `concurrency` | ❌ | 并发上限，默认 3 |
| `repeatRounds` | ❌ | 是否重复跑 |

### 通过 REST API（v2 规划）

```bash
# 创建 Experiment
curl -X POST http://localhost:3000/api/eval/experiments \
  -H "x-witty-api-key: $API_KEY" \
  -d '{
    "user": "demo@163.com",
    "name": "pdf-extractor regression 2026-05",
    "datasetId": "ds_xxx",
    "evaluatorId": "evaluator_llm_judge",
    "traceRange": {
      "skill": "pdf-extractor",
      "timeRange": "7d"
    },
    "concurrency": 3
  }'
# 响应 → { id, status: "pending" }

# 查 Experiment 进度
curl http://localhost:3000/api/eval/experiments/{id}

# 列出历史 Experiment
curl http://localhost:3000/api/eval/experiments?user=demo@163.com
```

### 当前版本

当前版本的"作业"概念较弱，主要是 UI 上的 `AgentEvalCenter` 临时 run + 历史记录。完整的 Experiment 实体（含 share link / 版本号 / 参数审计）在 v2 规划。当前可用替代：用 [A/B Testing](../../skills/analysis/ab-testing) 的 `GrayscaleTask` 走完整流程，它包含 Experiment 的所有要素。

## Experiment 生命周期

```
   ┌──────────┐  start   ┌──────────┐  case 跑完  ┌─────────────┐
   │  pending │ ───────▶ │  running │ ──────────▶ │  evaluating │
   └──────────┘          └──────────┘             └──────┬──────┘
                                                         │
                              ┌──────────────────────────┴───────┐
                              ▼                                  ▼
                         ┌──────────┐                      ┌──────────┐
                         │   done   │                      │  failed  │
                         └──────────┘                      └──────────┘
```

每次状态变化都记录到 `BatchEvalTask.status`。

## Experiment vs Evaluation 关系

```
┌───────────────┐         ┌────────────────┐
│ Experiment    │  1:N    │   Evaluation   │
│ (评测作业)     │ ─────▶  │ (单 Trace 评估) │
└───────────────┘         └────────────────┘
```

一次 Experiment 通常包含几十到几百个 `Evaluation`（每个 Trace 一个）。Experiment 是"批"，Evaluation 是"行"。

## 关键参数

| 字段 | 类型 | 说明 |
|---|---|---|
| `name` | string | 业务命名 |
| `datasetId` | string | 评测集 |
| `evaluatorId` | string | 评估器 |
| `traceRange` | object | Trace 过滤条件 |
| `concurrency` | int | 并发 |
| `repeatRounds` | int | 重复轮次（默认 1） |
| `status` | enum | `pending` / `running` / `evaluating` / `done` / `failed` |
| `results` | object | 汇总分数（done 后填） |

## 最佳实践

- **Experiment 命名带日期** —— `pdf-extractor-2026-05-28` 比 `test1` 强 10 倍
- **保留所有 Experiment 历史** —— 删了就没法跨周期对比
- **不要并发跑多个大 Experiment** —— LLM quota 会撞
- **每次 Experiment 后留 description** —— "为啥跑这次"，三个月后能看懂
- **结果对比走 [Score Comparison](./score-comparison)** —— 不要靠肉眼

## 常见问题

<details>
<summary>Experiment 跑了一半中断了怎么办？</summary>

当前 `pending → running` 后中断的 Experiment 不会自动恢复，要手动重跑。v2 规划支持 resume from checkpoint。
</details>

<details>
<summary>能定时跑 Experiment 吗？</summary>

平台没内置 cron，但可以走外部调度（cron / k8s CronJob）调 API 创建 Experiment。详见 [Webhooks](../../api-and-data-platform/webhooks)。
</details>

<details>
<summary>Experiment 数量上限是多少？</summary>

DB 层面无限。但 UI 列表只显示最近 200 个（v2 规划支持分页 + 搜索）。
</details>
