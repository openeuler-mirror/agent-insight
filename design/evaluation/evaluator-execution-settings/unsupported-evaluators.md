统计日期：2026-10-27。代码基线：`codex/evaluator-timeout-config` 的 `fa3e91fc`。

这里的“不支持”专指：未接入新建实验中的评估超时、重试次数、统一配置及评估器单独配置；不代表评估器无法运行，也不代表没有原有的规则配置。SWE-bench、Zsoft L1 及 4 个代码评估器保持原运行策略，仅在页面提示不支持配置。

## 任务完成度与轨迹质量：仅配置评分阶段的超时和重试

用户已确认：实验配置的超时和重试次数均只作用于评分阶段；前置分析、Skill 分析和附加建议沿用原有系统超时与重试策略。以下为已确认方案，已实现。

| 阶段 | 超时来源 | 重试规则 |
| --- | --- | --- |
| 前置关键观点提取、Skill 分析、关键动作准备（存在模型调用的部分） | 原有系统阶段超时，不使用本次评分超时。 | 沿用原有系统重试策略，不使用或消耗本次评分重试次数。 |
| 模型评分、结构化输出校验与分数计算 | 本次配置的评分阶段超时；每次评分重试重新计时。 | 使用本次配置的重试次数；只重试评分，复用本轮已成功的前置分析输出。 |
| 附加 Skill 改进建议（适用时） | 原有系统阶段超时，不使用本次评分超时。 | 沿用原有系统重试策略，不使用或消耗本次评分重试次数；不因建议失败重新评分。 |

### 评分阶段的时间边界

- 任务完成度：前置数据读取、关键观点提取与 Skill 上下文准备不计入；从进入模型评分到输出解析和分数计算完成，使用本次超时。
- 轨迹质量：前置轨迹整理、Skill／关键动作分析不计入；模型轨迹判定、输出校验及维度分数汇总使用本次超时；后续附加建议不计入。
- 计时逻辑放在评分阶段内部，而不是用评分超时包住整个评估器。原有固定请求、评分阶段及外层结果行保护不能提前截断显式配置的更长评分预算；其他阶段保留自己的保护，不表示无限等待。
- 例如设置 600 秒，仅代表一次评分最多 600 秒；评估器总耗时还包括其他阶段及重试等待，可以超过 600 秒。

### 评分重试的计数与失败处理

- 只提供现有的重试次数字段，计数单位为评分阶段的一次尝试，不把该数值应用到前置分析或附加建议。
- 设置重试 2 次表示评分最多尝试 3 次，成功即停止；设置重试 0 次时评分只尝试一次，不改变其他阶段原有的系统重试策略。
- 收拢评分内部的 SDK 重试、解析修复和完整评分回退，统一消耗评分重试预算，避免次数相乘；外层不能再按同一配置重跑整个评估器。
- 评分重试复用已成功的前置分析结果，不重新执行 Skill 分析；附加建议只在评分成功后按原有系统策略执行，不由评分重试重复触发。
- 可恢复技术失败才重试；评分低、正常未达标、正常无分析目标或无需生成建议等不触发重试。鉴权、无效配置和用户取消不重试。
- 评分重试耗尽则结束评分并记录失败；前置分析的失败、缺失或降级继续沿用原有系统规则。
- 附加建议按系统策略重试耗尽后保留成功评分，记录“评分已完成，附加建议生成失败”；不将有效评分改成失败或零分。
- 评分超时后确认本次请求停止、资源清理完成再重试；无法确认停止时不重叠启动下一次评分尝试。

例如设置 600 秒、重试 2 次，评分最多尝试 3 次，每次最多 600 秒；Skill 分析和附加建议的耗时、重试次数均不由这两个数值控制，整条评估流程仍可能超过 30 分钟。

### 前端最小说明

两项仍使用现有配置区域，不新增阶段参数。对应评估器显示：**仅配置评分阶段，Skill 分析和附加建议沿用系统策略。**

系统默认展示各自评分阶段真实的默认超时和重试次数：任务完成度为 180 秒/2 次，轨迹质量为 300 秒/2 次。现有历史实验不隐式迁移执行语义。

## Agent RAS 可靠性故障检测恢复评估器：已确认支持方案

适用 ID 为 `preset-ras-reliability-detection-recovery`。当前读取 Trace 与 RAS 故障事件后，通过一次通用 Judge 调用完成故障发生门控及三个维度判定，再校验输出并汇总分数；没有独立的 Skill 分析或附加建议阶段。已登记配置能力并接入评分阶段的预算和重试。

- 超时只覆盖评分阶段：模型故障发生判定、维度判定、结构化输出校验及分数计算，共用一次尝试预算。前置证据读取沿用系统策略，重试复用本轮已读取的 Trace 和故障事件。
- 重试只重新执行评分，不重新运行 Agent、不重新注入故障。设置 600 秒、重试 2 次，表示评分最多尝试 3 次，每次最多 600 秒；设置重试 0 次时只尝试一次。
- 超时、临时网络错误、可恢复服务错误及结构化解析失败按配置重试。关闭评分中的隐藏 SDK 重试或未计数的完整回退，取消与清理确认后才允许下一次尝试。
- 未确认故障真实发生属于正常不评分结果，保留理由与空分数，不重试、不计入综合分；有效低分或评判不通过同样不重试。
- 未配置模型、鉴权失败、无效配置和用户取消不重试。未配置模型保留明确的无分提示，不误报为“故障未发生”。
- 技术失败不能在重试前被转换为普通 `warn` 结果；应交给调度层识别和重试，重试耗尽后记录评估失败、实际尝试数及原因，不伪装成正常不评分或零分。不能仅按错误消息包含 `judge` 或“评测模型”判断失败类别。
- 前端复用系统默认、统一配置、评估器单独配置及逐行恢复，不新增弹窗或参数。系统默认沿用通用 Judge 新策略；未配置新策略的历史实验保留原行为，旧兼容 RAS ID 不因此重新出现在可选目录中。

RAS 专项设计与验收边界同步见[可靠性评估器设计第 6 节](../../reliability/agent-ras/ras-reliability-evaluator-split.md#6-评分超时与重试配置扩展已实现)。

## 执行过程质量、步骤效率及文本幻觉检测：接入方案

三项均已有通用 Judge 调用入口，可沿用系统默认、统一配置、单独配置及逐行恢复，不新增前端配置字段。建议先沿用通用 Judge 的系统默认策略，不另造默认超时和重试常量；未配置新策略的历史实验保留原行为。

### Agent 执行过程质量与 Agent 步骤效率

两项共用 `agent-trajectory-judge.ts`，可一起适配；各自的事实提取、rubric、维度、评分上限与汇总方式保持原状。

建议执行语义：

- 一次尝试包括事实整理、一次评分或修复请求，以及 JSON／语义契约验证，共享该次超时；成功后不再调用模型。
- 当前内部会在解析失败后额外调用一次修复。新策略将这次修复纳入统一重试预算，不再在一个尝试里赠送修复后又启动外层重试。
- 设置重试 0 次时最多执行首次评分；设置重试 1 次时最多执行首次评分及一次修复或重跑。网络故障与契约修复共用同一个次数上限，不能各自获得一份重试预算。
- 解析或语义契约失败后的下一次尝试使用原有白名单生成的安全修复反馈，保持原始任务、轨迹事实和 rubric；不直接回填原始错误文本或模型输出。修复占用一次额外尝试，并重新获得本次配置的超时。
- SDK 隐藏重试和完整评分回退继续关闭；临时网络故障、服务错误及超时按统一策略重试。低分或正常未达标不重试；缺少轨迹、输入超限、鉴权和无效配置等永久错误不重试。
- 超时或取消后传递同一取消信号，确认旧请求停止后才允许下一次尝试。结果保留实际尝试数与失败原因。

例如：600 秒、重试 1 次，最多两个尝试，每次最多 600 秒；首次输出不符合契约时，第二次可以用安全反馈修复，但不会再额外赠送第三次调用。

建议验证：两项合法评分不变、重试 0／1／2 的调用上限、解析与语义修复计数、网络故障与修复混合时仍不超上限、安全反馈约束、超时取消、成功即停及 legacy 行为兼容。

### 文本幻觉检测

当前流程为：上下文整理 → 可选联网检索 → 模型幻觉判定 → 确定性扣分。评分入口已走 `invokeSpecializedJudge`／`callJudgeLlm`，主要缺口在联网检索。

建议执行语义：

- 一次完整尝试覆盖上下文整理、检索、模型评分、解析和汇总，共用一个截止时间。后续模型请求只使用剩余预算，不重新获得完整超时。
- 搜索请求继续保留当前单请求最多 8 秒的局部保护，并受整轮剩余预算限制；搜索信号组合局部超时、整轮超时与用户取消，相关请求纳入清理跟踪。
- 搜索服务失败或局部 8 秒超时、但整轮仍有效时，沿用现有降级规则：有可用结果则使用已有证据，否则基于原上下文／知识路径评分，并在结果证据中注明检索未启用、成功、部分失败或降级。该可选阶段失败不单独消耗整轮重试次数。
- 整轮截止或用户取消必须向外抛出，不能被现有搜索降级的 catch 吞掉，也不能继续发起搜索或模型评分。
- 模型评分发生可重试技术失败或解析失败时，由统一调度按配置重新执行一轮；正常检测出幻觉、低分及无幻觉结论不重试。
- 不新增搜索超时、搜索重试或阶段预算的前端字段；既有搜索是否启用、幻觉判据和扣分规则保留。

例如：整轮配置 600 秒，检索耗时 12 秒，则模型评分最多使用剩余约 588 秒；若只是某次搜索请求在 8 秒后失败且整轮仍有效，可以降级评分；若整轮已超时则停止本次尝试。

建议验证：启用／禁用搜索、检索成功／部分失败／全部失败、单请求超时降级、整轮超时不被吞掉、用户取消后无后续调用、模型只获剩余预算、模型失败按配置重试，以及原有分数与证据规则兼容。

以上已按本轮用户授权实施，专项验证见开发计划第 10 节。

## 文本相似度与客观答案匹配：接入方案

两项均调用现有 `callJudgeLlm`，可以复用已实现的截止时间、取消信号、SDK 重试关闭及实验配置快照；不需要新增前端交互。

| 项目 | 文本相似度 | 客观答案匹配 |
| --- | --- | --- |
| 评估流程 | 一次模型调用，判断相似度档位，再按已有阈值输出结果。 | 模型提取信息点 → 代码匹配 → 必要时模型语义判定 → 汇总分数。 |
| 建议超时范围 | 覆盖本轮模型调用、解析及评分。 | 提取、代码匹配和后续判定共用整轮预算；后续调用使用剩余时间，不能分别获得完整预算。 |
| 建议重试单位 | 一轮完整相似度评估。 | 一轮完整答案匹配评估，包含信息点提取及必要的后续判定。 |
| 评分与规则 | 保留已有档位、阈值配置及评分方式。 | 保留已有信息点匹配、扣分及汇总规则。 |

- 建议两项均接入系统默认、统一配置、单独配置及逐行恢复，系统默认沿用通用 Judge 策略。
- 超时、临时网络错误及可恢复服务错误按配置重试。低分、不匹配、正常不评分结果不重试。
- `SimilarityJudgeParseError` 继承 `JudgeOutputParseError`，但改写了错误名称；新运行策略目前按名称精确匹配，不能识别该子类。应按类型或稳定错误码统一识别解析错误，再按配置消耗重试次数。
- 客观答案匹配中的提取与判定是必要阶段，不应当作重试计数；“重试 0 次”允许首轮执行这些必要阶段，但失败后不额外开启新一轮。
- 验证重点：两项配置回显与生效、解析错误子类重试、0 次重试、必要多调用共享预算、取消后不继续判定，以及原有评分和阈值配置兼容。

以上已按本轮用户授权实施；两项已加入能力清单，解析错误子类通过类型识别进入统一重试。

## 代码评估器展示方案

- 4 项代码评估器的评分阶段均不调用模型；同样输入和规则得到确定性结果，不开放本次实验的超时和重试配置。
- 选中时在评估运行设置区域显示：**代码评估器，不调用模型，不支持超时和重试配置。** 不提供相关输入框或恢复按钮，也不应用实验统一配置。

- `skill-trigger-analyzer` 前面的 Agent 执行或路由阶段可能调用模型，其超时仍归 Agent 执行设置；这里的“代码评估器”仅指对既有触发结果评分的阶段。
- 代码计算的内部耗时和输入规模保护属于平台执行策略，本结论不意味着计算不会耗时。本轮不增加面向用户的参数或 Worker 改造。

### 带 Skills 自定义评估器：已确认的简化方案

- 将现有固定 180 秒限制替换为本次实验配置的 OpenCode 执行超时，从开始本次 OpenCode 评估执行时计时，覆盖其中的模型和工具调用；不拆分 Skill 分析、工具执行和最终评分的预算。
- 排队、环境准备、Skill 文件部署及 OpenCode 服务启动沿用系统策略，不计入这次执行超时；不能从整个运行入口开始计时而提前消耗执行预算。
- 执行发生可重试技术失败时重新调用 OpenCode，使用同一份实验输入及冻结的 Prompt、Skill 快照，不续跑失败会话。重试 2 次表示最多执行 3 次，每次独立获得配置的执行超时；0 次表示只执行一次。正常多轮模型与工具调用属于一次执行，不额外算作重试；低分、正常不通过、配置错误和用户取消不重试。
- 复用现有取消与进程清理机制，确认旧执行结束后再重试；无法确认停止时终止重试，不启动重叠执行。保留原始错误类型与原因，避免包装后无法识别可重试失败，不叠加额外的整次执行重试循环。
- 沿用系统默认、统一配置、评估器单独配置及逐行恢复；系统默认展示原有执行超时和引擎重试次数的实际数值。前端说明为：**超时和重试作用于 OpenCode 评估执行。** 不新增弹窗、阶段字段或额外参数。
- 已接入配置与执行链路；未配置新策略的历史实验保留原行为。
