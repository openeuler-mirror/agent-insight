# 文本评估器运行配置：需求分析

## 1. 背景

ROUGE、完全精确匹配和实体 F1 已作为 Code 预置评估器接入实验流程。当前页面只能选择评估器，完全精确匹配和实体 F1 始终使用严格默认配置，无法在页面覆盖题面要求中的大小写、标点、空白、全半角、模糊匹配和子串匹配场景。

## 2. 目标

- 在新建实验的评估器步骤中，为“完全精确匹配”和“实体 F1 匹配”提供可发现、可修改的配置入口。
- 配置随实验持久化，实验运行时按该实验的配置评分。
- 实验总览和 Case 详情能够说明本次运行采用的配置。
- 旧实验和未传配置的 API 调用保持原有严格默认行为。

## 3. 用户场景

### 3.1 完全精确匹配

用户可配置：

- 是否忽略大小写；
- 是否忽略 Unicode 标点；
- 是否归一化连续空白；
- 是否进行 NFKC 全半角归一化；
- 多候选答案采用“任一命中即满分”或“按命中比例计分”。

### 3.2 实体 F1

用户可配置：

- 精确匹配、模糊匹配或子串匹配；
- 模糊匹配的最大编辑距离阈值；
- 是否忽略大小写；
- 是否归一化空白；
- 是否进行 NFKC 全半角归一化。

## 4. 范围与约束

- 配置粒度为“实验 + 评估器”，同一实验的所有 Case 共享同一份评估器配置。
- ROUGE 本期没有可调参数；纯英文使用确定性词级分词，任一侧含汉字时双方统一使用字符级 ROUGE-char。
- 不新增依赖，不改变评估器的百分制映射。
- 模糊阈值只接受 `0` 到 `100` 的整数。
- 配置只影响新运行；已完成结果不回算。

## 5. 验收标准

1. 新建实验时可以打开配置弹窗，修改并保存 Exact Match/F1 配置。
2. 创建请求会持久化配置，查询实验详情能返回规范化后的配置。
3. 执行引擎把对应配置传给评分器，大小写、标点、空白、全半角、模糊和子串用例产生预期分数。
4. 实验总览和 Case 详情展示实际采用的配置摘要；评分证据仍包含完整配置。
5. 旧实验、未传配置的创建请求和 Skill 评估后端继续使用严格默认配置。
