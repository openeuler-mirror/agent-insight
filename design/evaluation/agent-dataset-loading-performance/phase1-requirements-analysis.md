# Phase 1：需求分析

## 背景

`GET /api/agent-datasets` 当前先读取并解析全部用户的 `AgentEvalDataset.casesJson`，再在应用层按用户过滤。远端实测单个用户的列表响应达到 44.23 MB，同机请求耗时约 0.66–0.68 秒；即使目标用户只有 831 B 数据，仍需约 0.41 秒。

列表、Trace 回流目标选择器和实验导入均复用该接口，导致所有数据集相关入口加载完整轨迹。实验导入实际只需要 `input` 与 `expectedOutput`。

## 目标

- 数据集列表只返回元数据和样本数，不读取或传输完整 `casesJson`。
- 实验导入只返回可匹配的 `input` 与 `expectedOutput`。
- 查询在数据库层按 `user`、可选 `targetSkill` 过滤。
- 保持现有详情接口与完整数据编辑能力。
- 已有数据自动、幂等生成轻量投影，不要求用户手工编辑数据。

## 非目标

- 本期不把 JSON cases 拆成独立关系表。
- 本期不实现数据项分页和单条轨迹独立存储。
- 不改变数据集名称重复规则和评测匹配口径。

## 验收指标

- demo 数据集列表响应从约 44.23 MB 降至 10 KB 以内。
- 实验导入候选响应不包含 `trajectory`、`values.trace`。
- 数据集列表同机 P50 目标低于 100 ms，实验导入候选 P50 目标低于 100 ms（投影已回填后）。
- 新增、更新、Trace 回流后，样本数和参考答案投影与 `casesJson` 同步。
