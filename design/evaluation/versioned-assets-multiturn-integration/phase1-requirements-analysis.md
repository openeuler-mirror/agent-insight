# 多版本资产与多轮对话评测：需求分析

日期：2026-10-29。基线：master `6d7913b6`。状态：计划及两项流程边界已获用户确认，进入开发。

## 1. 目标和范围

在主线现有 Agent、评估器、数据集、实验、Trace 页面内完成三个对象的不可变版本管理和真实多轮评测。沿用 Skill 现有版本、现有执行目标/客户端/IP/模型及实验类型，不引入演示导航、演示开关、Demo 对象、模型连接或启动配置。

用户要完成的流程为：选择/登记 Agent 版本 → 逐条编辑 Case 草稿并发布数据集版本 → 发布评估器版本 → 实验选定版本 → 真实执行/关联已有 Trace → 查看结果评测和逐轮轨迹评测 → 按原条件复测及版本追溯。

## 2. 已确认的范围决策

1. 保留原实验 Agent 聚合列表。执行目标/IP/平台明确后，才选择该平台的 Agent 版本；不将不同平台的同名 Agent 共用一条版本线。
2. 首版完整支持 SQLite。OpenGauss 继续现有流程；新版本发布能力明确返回不支持，不能写本地侧库后宣称与原数据集原子发布。
3. 多轮真实下发优先支持 OpenCode v2。Pi/xiaoO 原单轮与已有 Trace 读取不变；其多轮能力尚未实现时不下发多轮任务。新增平台支持不得偷偷改变原 Trace 分片语义。

## 3. 功能要求

| 编号 | 要求 | 验收依据 |
|---|---|---|
| V01 | Agent、评估器、数据集具有稳定本体身份和顺序发布版本 | v1/v2 同时可读，v1 内容不被覆盖 |
| V02 | 已发布内容只追加，保留发布说明、内容指纹和来源 | 相同语义内容不反复生成版本；并发发布不产生重复版本号 |
| V03 | 旧对象按需建立首版，旧写 API 保持既有立即生效语义并留历史 | 旧 PATCH/PUT/生成/回流路径仍可使用，不要求旧客户端增加发布步骤 |
| V04 | 数据集逐 Case 保存/回退草稿，统一发布；多人修改和过期草稿显式冲突 | 保存 A 不覆盖 B；过期 revision/baseVersion 返回 409 |
| V05 | 评估器保留原 LLM、Code 配置、评分点及固定 Skill 快照 | 老配置不丢字段；不宣称补齐通用 Code 执行 |
| V06 | Agent 版本与运行机器、模型分开，跨平台隔离 | 换 IP 不生成新 Agent 本体；OpenCode 版本不能用于 Pi |
| V07 | 实验冻结选定的版本及 Case 内容，复用实验继承原版本 | 对象后续修改不影响运行、详情、重试和复测 |
| T01 | 同一数据集允许单轮、多轮 Case，每条 Case 的顶层输入/预期为首轮输入/末轮预期 | 原列表一条 Case 一行，详细配置查看各轮 |
| T02 | 逐轮支持输入、预期输出的精确/包含匹配、必须/禁止工具及参数、实际 Skill 使用；历史高级规则仅兼容保留 | 修改规则后仅对新发布版本生效 |
| T03 | 多轮 Case 在一次 Attempt 的同一 session/workspace 中按序执行 | 三轮随机信息记忆任务通过；其他 Case 不能读到该信息 |
| T04 | 一次 Case/Attempt 仍对应一个控制命令和明确 Trace，不向 Agent 泄漏预期答案/规则 | 下发仅包含轮次标识和输入；末轮证据完整后才完成绑定 |
| T05 | 旧单轮兼容，按客户端能力启用多轮，取消和重试保持隔离 | 老客户端拒绝多轮但能执行单轮；重试创建新 session |
| T06 | 已有 Trace 可多选关联 Case，并按真实轮次重建证据 | 工具按调用 ID 关联；无证据与无调用分别判定 |
| T07 | 逐轮规则以轨迹评估器输出评分点、分数、证据、建议 | 不足证据为未评完整，不默认通过或计 0；人工分口径保持 |
| U01 | 原页面、设计令牌和实验布局可复用就复用 | 无第二套演示专用向导，无隐藏主线菜单 |
| U02 | 详情显示版本，保留结果/轨迹分类和 Trace 下钻 | 一条多轮 Case 不拆成多条实验 Case；A/B 在一行按组比较 |
| U03 | 实验版本记录/趋势与原 Trace 版本标签分析共存 | 不同执行配置分组显示，不把数据集变易解释成 Agent 改善 |

## 4. 兼容与边界

- `RegisteredAgent.id` 不作为唯一准入条件：在线但尚无 Trace/注册行的执行目标也可登记版本。Agent 业务身份为用户域内的平台和 canonical Agent 名称。
- 评估器仍使用稳定 `custom-*` ID；版本引用另存，不能用版本记录 ID 替换 `evaluatorIdsJson`。
- 数据集已发布主表仍供原消费者读取；草稿不进入旧实验。Trace 生成只在完成后建立业务版本；后台观点缓存或进度更新不产生版本。
- 可靠性、Benchmark 公共对象维持原保护和所有者；不能因增加版本变成普通可编辑数据集。
- Agent 登记版本与执行端确认版本分别记录。平台不能声称用户选了版本就控制了外部 Agent 的实际代码。
- 模型密钥/私有连接不写进版本内容；版本固定不代表运行连接永远不变，运行公开模型信息另记。
- 历史实验未记录版本时显示未记录，不补写当前最新版本。旧本体删除不删除已有实验的冻结内容。

## 5. 验收门槛

专项单元/API测试、SQLite 旧数据升级及空库使用、应用类型检查与构建、全仓基线差异、原页面浏览器 golden path 和边界 Case。必须分别记录无模型协议测试、真实原生进程、真实模型与浏览器证据，不能用 HTTP Demo 的结果替代真实 Agent 验收。

真实流程至少包括：单轮旧流程；混合单/多轮数据集；三类对象 v1→v2；固定旧版本运行；逐轮工具规则失败定位；取消/重试隔离；原条件复测；版本记录和 Trace 下钻。已有 Code 配置编辑、LLM/Skill 评估、Benchmark、可靠性及 Skill 工作台关键流程不回退。
