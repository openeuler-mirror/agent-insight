# Benchmark 自动接入 Skill：需求分析

本文记录需求与交付边界；实施状态统一见[需求清单](../../README.md)。技术方案见[需求设计](phase2-requirements-design.md)，实施及试验安排见[开发计划](phase3-development-plan.md)。

## 1. 背景

Agent Insight 已有 Benchmark 统一接入协议。新增 Benchmark 仍需要开发者分析官方数据和评测代码，决定执行与评测边界，编写接入包并验证结果。目标是把这些工作组织成可重复运行的自动接入流程，减少逐个 Benchmark 人工开发和反复解释协议的成本。

需求候选包括 AIME 2025、BBEH、BIG-Bench Hard、ChemBench、FrontierScience、GPQA Diamond、MuSR、TruthfulQA 八个问答/推理 Benchmark，以及 EdgeBench 和 Terminal-Bench。该列表表示研究与选样范围，具体任务形式和评分依赖仍须分析官方代码。

交付形态为一个可独立分发的 `benchmark-onboarding` Skill 包。入口指令、参考资料、公共验收脚本、模板及脚本测试统一放在包内，由宿主编码 Agent 按 Skill 完成分析、开发、验收和有界修复。阶段推进依靠 Skill 指令和持久化运行记录，不引入独立工作流引擎或常驻调度服务。

公开接入文档继续维护架构、契约、能力查询方法和验收要求。Skill 携带从固定来源 commit 提炼、带版本及文件摘要的稳定协议快照；运行时与目标版本文档和源码核对，按差异适配模板，再查询代码及运行状态，不维护一份容易过期的 Workspace、Agent、Git 来源或 Collector 支持清单。目标项目是协议唯一权威。

## 2. 用户入口与首轮输出

最小请求示例：

> Agent Insight 项目地址：<目标代码仓库 URL 或本地项目路径>。
> Benchmark 来源：<官方仓库或数据集入口>。
> 按照官方标准，将该 Benchmark 接入上述项目并完成验收。

用户入口包含 **Agent Insight 项目地址**和 **Benchmark 来源**。项目地址用于确定要读取协议、查询能力和修改代码的目标仓库；不默认使用开发 Agent 当前目录或固定的官方上游。平台部署服务地址用于后续运行与验收连接，与源码项目地址分别记录。

目标分支或 commit、Benchmark 版本与子集、执行机、被测 Agent、平台部署地址和资源预算有特殊要求时可一并提供。已有上下文能确定的信息不重复询问。仅有数据集入口时，自动追溯官方评分程序和使用条件；无法确定权威判定时记录缺口。

AI 首轮应输出简短的接入判断：

- 所给项目地址对应的本地工作副本、分支及 commit，以及从该版本定位的接入文档；
- 官方数据、评分程序及拟固定的版本、子集；
- Agent 执行、提交物、评测与环境隔离的方案；
- 平台能力匹配的证据，以及部署待验证项；
- 计划使用的样例、评分对照和端到端验收范围；
- 无法通过查询解决、且会改变业务含义或授权范围的问题。

技术选择在已授权范围内自动推进。涉及未明确授权的凭据、付费资源、发布或公共能力扩展时，输出具体需求与影响；不把这些问题当作普通技术默认值。

## 3. 交付物与运行产物

| 层次 | 交付内容 | 使用者 |
|---|---|---|
| 可重复使用的 Skill 包 | `SKILL.md` 入口、`references/` 参考资料、`scripts/` 公共验收与记录程序、`assets/` 模板、`tests/` 脚本测试，以及使用说明和实测兼容范围 | 使用支持 Skill 的编码 Agent 的开发者 |
| 每次接入的产物 | `benchmarks/<key>/` 接入实现、相关测试、来源与能力分析、验收报告及可复核证据 | Agent Insight 维护者和 Benchmark 使用者 |
| Skill 的验证资料 | 三类代表试验的完整记录、失败与修复过程、宿主兼容性和已知限制；可公开摘要随 Skill 分发，原始记录按证据索引访问 | Skill 维护者与评审者 |

包内资源为可复用程序和静态材料。生成的接入代码写入目标仓库；运行状态、报告、日志和环境快照写入包外的独立运行目录，避免修改已安装 Skill 或在升级时覆盖历史记录。

编写接入包的“开发 Agent”与运行 Benchmark 的“被测 Agent”是不同角色。更换开发 Agent 不应改变官方评分语义；被测 Agent 的可用性仍通过 Agent Insight 执行目标和环境检查确认。

## 4. 首版范围

1. 通过宿主已有的 Skill 加载机制使用完整 Skill 包，按用户提供的项目地址定位工作副本，检查文件访问、命令执行及任务所需工具；不另造跨宿主安装器。
2. 读取目标仓库的协作约束与接入协议，分析官方执行和评测代码，固定数据、代码及评测配置。
3. 查询平台能力，区分可复用、部署未就绪、公共能力缺口和证据不足。
4. 在可复用范围内生成接入包、测试和文档，执行有预算限制的修复循环。
5. 使用公共验收程序验证接入契约、官方判分一致性和真实执行评测链路。
6. 保存全部尝试、失败、恢复和最终结论；缺失真实运行条件时交付明确的未完成记录。
7. 以 OpenCode 为首个完整验证宿主，以 Codex 验证同一 Skill 的可移植性；兼容范围依据实际加载、执行和恢复记录发布，不凭支持 Skill 格式推定功能等价。

首版不承诺一次完成八个问答/推理 Benchmark 的全部接入，也不把试验子集的通过扩大为完整官方数据集认证。遇到缺少执行后端或状态采集能力的任务，先产出公共扩展设计，待范围确认后继续；不得在公共流程里增加 Benchmark 名称分支来绕过契约。

## 5. 三类代表试验

三类试验按此前讨论的对象组织，用于覆盖不同接入难点。具体 Case、版本和预算在试验前冻结，不以名称代替源码分析。

| 类型 | 试验对象 | 主要验证点 |
|---|---|---|
| T1 静态回答与独立评分 | 从上述八个问答/推理 Benchmark 选择一个具有可访问权威数据及评分入口的代表 | 数据版本、公开/私有拆分、答案提取、官方评分对照、无须重跑 Agent 的重评 |
| T2 带反馈的迭代执行 | EdgeBench 的公开代表任务 | 反馈可见性、环境依赖、时间预算、过程状态与结果保存，能否保持官方迭代语义 |
| T3 终端环境任务 | Terminal-Bench 的固定版本代表任务 | 环境初始化、终端执行、最终状态验证、超时取消及清理；重评是否需要保留环境或导出状态 |

T2 和 T3 都可能需要环境隔离，区别在于试验要验证的执行、反馈和评测生命周期。不得预设它们都可以转换成“最终文本 + 离线评分”。T1 也不能仅因答案是文本，就认定网络和隐藏数据无需隔离。

## 6. 自动化边界

“自动接入”表示 AI 在明确目标、预算和权限下完成可推导的分析、开发与测试，不要求用户手工编写 Adapter。自动化不改变官方规则或目标仓库约束。

- 可查明的版本、接口、依赖和实现选择直接记录依据后推进；存在多个等价技术方案时采用可解释的默认方案。
- 无权获取的数据、未配置的凭据、不可确定的业务标准和新的公共扩展范围，进入 `needs_action`，保存可恢复记录。
- 官方基线自身失败、参考结果缺失或基础设施不可用，不生成虚构的成功结果，也不修改官方规则来满足验收。
- 任务完成以公共验收结果为准。开发 Agent 对话结束、代码生成结束、Mock 测试通过分别记录，均不能代替真实链路验收。
- 自动修复受最大尝试次数、总耗时和资源预算约束；达到任一限制即结束本轮并报告剩余问题。
- 中断后由用户或宿主再次调用 Skill，从运行记录核对并续接；Skill 本身不提供后台保活、自动唤醒或进程重启。运行环境隔离仍按 Benchmark 要求配置。

## 7. 需求验收标准

| 编号 | 验收要求 |
|---|---|
| AC-01 | 单个 Skill 包包含入口、参考、验收脚本、模板及脚本测试；复制到兼容宿主后可以加载并执行，无独立编排依赖 |
| AC-02 | 复用宿主加载机制，安装与升级不覆盖其他 Skill 或用户修改；包外运行记录独立保留，脚本不依赖安装路径或当前工作目录 |
| AC-03 | 用户提供 Agent Insight 项目地址和 Benchmark 来源后，可以定位正确工作副本并查出接入依据；不误用当前目录或其他项目的协议，无法确定的信息明确保留待办 |
| AC-04 | 能力判断引用目标代码版本和部署检查，不根据文档示例或组件名称推断可运行 |
| AC-05 | 公共验收能识别错误评分、隐藏数据暴露、提交物不完整、评测故障及缺失运行证据 |
| AC-06 | 官方程序与适配后的程序对同一组冻结提交物给出约定一致的结果；差异有逐条记录 |
| AC-07 | 再次调用 Skill 时可核对记录恢复，不重复提交在途任务，不把旧版本的检查结果用于新代码；缺少恢复证据时明确停止 |
| AC-08 | 正常、业务未通过、非法提交、基础设施失败和超时清理均有明确结果 |
| AC-09 | 三类试验均有完整记录；有未通过或未验证项目时，不能宣称全部接入成功 |
| AC-10 | 开发 Agent 和被测 Agent 分别记录，宿主切换不依赖专属提示词或硬编码路径 |
| AC-11 | 运行预算耗尽、权限不足或公共能力缺口能停止并给出下一步，不无限重试 |
| AC-12 | 平台数据集安装、执行、提交、评分、证据查询及适用的重评完成真实链路验证 |
