# Claude Code 轮次结束信号：需求分析

状态：按 Issue #424 目标行为对齐；默认分支 `86c413f1` 复现。

Claude Code 的官方 OTel logs 没有会话级结束事件，`claudecode` 聚合结果永远不带 `trace_completed_at`，前端只能等十分钟无上报后判成 `timed_out`。用户在一轮正常回复结束后看到的仍是「执行中」，随后又变成「执行超时」，会误判 Agent 未结束或采集链路失效。

目标行为：

- `Stop` 后 trace 在数秒到数十秒内由「执行中」变为「已完成」（阈值 ≤30s）。
- 多轮会话中每轮各自收敛；开始新一轮后 trace 回到执行中，不能因为上一轮的信号提前完成。
- `SubagentStop` 只表示子 agent 结束，不能完成整轮；`StopFailure` 按失败收敛，而不是等十分钟超时。
- 重复上报幂等；正常结束的轮次不再走到十分钟超时，真正无活动的 trace 仍能超时。
- 旧版客户端没有该信号时保持现有兜底（十分钟 inactivity），升级后不能直接判成已完成。

不改变 UI 文案与配色，不动其他框架的完成判定，不回填历史 trace。
