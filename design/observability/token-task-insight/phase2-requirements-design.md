# Token 与任务分析：需求设计

## 数据来源

直接读取既有 `Execution` 表（root trace）：

| 字段 | 用途 |
| --- | --- |
| `id` / `taskId` | 会话/任务标识 |
| `query` | 任务类型分类与可延后判断 |
| `user` / `agentName` / `framework` / `model` | 按用户、Agent、模型拆分 |
| `timestamp` | 时段分布（Asia/Shanghai） |
| `latency` | 长时判定，单位毫秒 |
| `tokens` / `inputTokens` / `outputTokens` | Token 汇总 |
| `cost` | 单价缺失时的成本兜底 |
| `toolCallCount` / `llmCallCount` | 多步工具信号与长时判定 |

不读取 Session interactions，避免把大 trace 全文拉进内存。

## 任务分类

规则分类位于 `src/lib/task-insight/classify.ts`，按“内容优先、行为兜底”：

1. **内容信号**：批量、代码、文档、文本、问答五类关键词累加权重。
2. 最高分 ≥ 2 时取最高分类型；同分按 `batch > code > document > text > qa` 稳定排序。
3. 内容信号不足时，工具调用 ≥ 5、LLM 调用 ≥ 5、或搜索/浏览/外部动作关键词可判为**多步工具任务**。
4. 仍无信号则为**其他**。

这样做避免“一个代码任务因为工具调用多就被归为多步工具任务”，同时保证纯工具型任务有归属。

## 长时与可延后

长时任务满足任一条件（阈值可通过 API 参数覆盖，默认值如下）：

| 维度 | 默认阈值 |
| --- | --- |
| 墙钟耗时 | ≥ 120,000 ms（2 分钟） |
| 总 Token | ≥ 100,000 |
| 工具调用 | ≥ 10 次 |
| LLM 调用 | ≥ 8 次 |

可延后判定：

- 短任务：不可延后。
- 长任务命中“立即 / 马上 / 今天必须 / 尽快 / 实时 / ASAP”等实时词：不可延后。
- 长任务命中“晚上 / 夜间 / 稍后 / 明天 / 异步 / 后台”等词：可延后（显式）。
- 其余长任务默认视为可延后，理由记为 `long_default`。

## 聚合结果

`buildTaskInsight` 输出：

- 总览：任务数、用户数、Token 输入/输出、估算成本、平均/P95 耗时、工具/LLM 调用总量、长任务与可延后长任务数。
- 任务类型：每类的任务数、Token、成本、平均耗时、长任务数、可延后数及各自占比。
- 长短时拆分：任务数/Token/成本/耗时。
- 长时原因计数：四个维度各命中多少任务（同一任务可命中多个）。
- 用户 Token 排行（Top 10）。
- 24 小时时段分布（Asia/Shanghai）。
- 调度建议：可延后任务数/Token/成本/累计耗时、其中日间执行的数量、建议窗口 22:00–06:00、按类型优先迁移建议。
- 任务明细：Token Top 20、耗时 Top 20、可延后长任务按耗时 Top 20。

## API

`GET /api/observe/task-insight`

| 参数 | 说明 |
| --- | --- |
| `range` | `7`（默认）/ `30` / `90` / `all`，滚动时间窗 |
| `user` | 可选；与大盘一致，未解析出用户时回退全量 |
| `longLatencyMs` | 可选，默认 120000 |
| `longTokens` | 可选，默认 100000 |
| `longToolCalls` | 可选，默认 10 |
| `longLlmCalls` | 可选，默认 8 |

响应包含 `truncated`、`maxTraces`、`thresholds`、`pricingMissingModels`，前端据此显示截断和成本提示。

## 前端

新增“运行观测 → Token 与任务分析”页面：

- 顶部时间范围切换与统计周期说明。
- KPI：分析任务、Token 总量、长时任务、可延后长任务、平均/P95 耗时、估算成本。
- 任务类型分布表、长短时拆分、长时原因、时段柱状图、调度建议、用户排行、三类任务明细表。

全部使用共享设计令牌（`var(--primary)`、`var(--warning*)`、`var(--success*)`、`--radius-*` 等），不新增局部色板。

## 风险与取舍

- **规则分类会误判**：首版优先可解释和可测试；分类信号与阈值都暴露在 UI/API 中，后续可按真实数据迭代词表。
- **固定阈值有偏差**：不同 Agent 的任务尺度不同，API 已允许调用方覆盖阈值；默认值面向通用场景。
- **全量扫描成本**：单次上限 10,000 条 root trace，按时间倒序取最近数据并显式标注截断。
- **成本依赖模型单价**：未配置单价的模型计 0 并在页面提示，不伪造成本。
