# Issue 381：评审修复与页面收敛方案

## 目标与边界

用户从 Trace 中定位模型调用，查看上下文组成、压缩/裁剪/模型变化，并核对压缩摘要中的关键约束。dsh-context 负责上下文投影和差异计算；Agent Insight 负责 Trace 联动、数据治理和展示。

本次只接通已存在的原生压缩摘要/checkpoint 脱敏文本，不新增模型请求采样，不改变提示词、模型或压缩策略。不将摘要正文或节点投影声称为模型最终请求的精确成员。

## 系统数据流

```text
Harness session/event
  ├─ assistant/message → collector → connection → dsh-context facts/delta
  │                                            ↓
  │                              分类估算、节点、差异、事件
  └─ compaction/summary / user/message(compact-checkpoint)
                     ↓ 提取文本、客户端脱敏、限长、固定到期时间
                本地 outbox → 既有 OTLP 日志入口（API Key 认证）
                                      ↓
                       服务端校验、再次脱敏、正文分离
                         ├─ 正文侧存储（owner + source session）
                         └─ 普通事件/Trace 仅存正文引用和元数据
                                      ↓
                  展开条目 → 既有 session?view=context-body
                                      ↓
                      登录身份 → Trace 权限 → 引用归属 → TTL
                                      ↓
                           no-store 的脱敏正文响应
```

## 页面收敛

| 页面 | 最终职责 |
| --- | --- |
| 概览 | 原节点信息、输入输出；删除重复的上下文事件统计和卡片 |
| 上下文 | 分类趋势、分类表、上下文内容；单源不显示 UUID 选择器，来源/版本收进折叠说明 |
| 相邻对比 | 继续使用同源、相邻且校验通过的 delta，缺失时明确不可比较 |
| 事件 | 默认整个会话；可过滤本次请求前的区间，保留前后上下文定位，合并重复按钮 |

上下文内容展开后自动加载，不再使用“鉴权加载已有片段”这种技术按钮。原生摘要/checkpoint 与最多 80 字符的源预览分开标注；历史压缩记录不表示它们一定属于当前请求。工具定义仅展示可获取的名称，不展示原始元数据 JSON；系统正文缺失时不补造。

## 正文实现

1. `splitNativeContextBody` 识别 `compaction/summary.summary` 和 `user/message` 中 `source.kind=compact-checkpoint` 的文本块。
2. collector 在既有脱敏之后提取文本，限制为每项 8 KiB，使用源事件时间加七天作为固定到期时间；outbox/死信维护到期时清除附件文本。
3. 服务端使用认证用户确定 owner，核对源会话、事件序号、正文类型和附件结构；再次脱敏并按 UTF-8 字节截断。
4. 复用 `saveHarnessBody` 的原子写入、进程锁和容量限制：8 KiB/项、256 KiB/集合、1 MiB/会话、256 MiB/全局、4096 文件、最多七天。
5. 事件写入普通 spool 前，剥离摘要、rawOutput、llmStreamCall 中的整份副本，以及 checkpoint.content。Trace 只保留 bodyRef、类型、序号、compactionId、存储状态、截断和到期信息。
6. 以源会话与原生序号绑定正文，以同一源会话内的 compactionId 将摘要和 checkpoint 关联。缺少 compactionId 时不按时间猜测。
7. 扩展既有 `context-body` 分支，允许读取 Trace 内原生事件正文引用；不新增 API 路由或 Prisma schema。
8. 读取验证可信身份、Trace 权限、源会话和事件引用归属。越权拒绝，引用不属于 Trace 返回 404，到期返回 410；正常正文和到期响应禁止缓存。
9. 展开时按需读取，失败可重试，折叠取消未完成读取，切换条目/Trace 清除旧状态，到期清除已显示正文。

正文完整性仅指该源事件的脱敏文本；图片等非文本块和完整服务商线缆报文不在本次范围内。超过限制显示截断，不能据此判定隐藏约束已丢失。已有历史原始事件不会被自动改写；演示环境通过重放历史事件验证新入站治理。

## 超时与恢复

- 每次投影读取使用独立 AbortController、独立 managed peer，沿用 1.5 秒总 deadline。
- facts、delta、当前节点视图顺序调用，单个采集任务同一时间只执行一个底层读取。
- 到期立即 abort、释放前台占用并 dispose peer；旧调用不能清除新任务的状态，也不能在取消后启动后续读取。
- 独立跟踪实际尚未结束的底层读取。最多允许两个：一个旧挂起读取加一个恢复读取。第一次挂起后，下一会话仍可正常完成。
- 如果插件响应取消，重复超时会释放容量；如果插件完全忽略取消且两个底层读取都永久挂起，则返回 source-busy，不再积累任务。底层结束后恢复容量；否则需恢复插件/重启 Harness。
- 该限制是针对不合作插件的资源保护，不能声称任意挂起均可在进程内强制终止。普通 Trace 上报与模型执行保持独立。
