# Core 请求容量与采集失败隔离

## 已确认范围

单实例 Core 默认允许 64 个并发 HTTP 请求，PostgreSQL 连接池默认 16。采集批次最多自动执行 5 次，独立 Trace 可以越过等待重试的批次。保留现有事务锁、权限、版本、回执和分页语义。

重试等待依次为 2、4、8、16 秒。确定的永久错误直接失败。已接收原始包、冻结计划和失败回执保留，提供显式、有界的恢复操作。同一 Trace 按接收顺序处理，多 Trace 批次共同承担依赖。

## 验收

- 64 个在途请求可接收，满载返回 CORE_BUSY、503 和 Retry-After，异常后槽位释放。
- A 失败不阻塞独立 B，A 的后续批次等待或明确失败，重启保持尝试计数。
- 部分 ClickHouse 写入重试复用冻结版本，晚到执行者不能完成新一轮恢复。
- 恢复要求实际写权限、操作幂等键和已失败批次，保留恢复历史。
- 仅运行相关功能、HTTP 和迁移测试。浏览器验证须单独确认。
