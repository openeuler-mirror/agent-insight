# 设计

## HTTP

新增 max_concurrent_requests，默认 64，范围 1–256。socket backlog 使用相同容量。实例记录活跃、峰值、拒绝数、完成数和处理耗时。满载响应有固定安全错误正文，Web 转发保留 CORE_BUSY 和 Retry-After。GET 可有限重试，写请求由原有幂等协议处理。

## 采集队列

021 迁移增加批次投递状态、批次 Trace 关系和恢复历史。投递状态关联已有 outbox event，其 created_at_ms/event_id 提供稳定先后顺序。保留 outbox attempts 的单调执行令牌，通过 attempt_base 计算本轮尝试次数，最多 5 次。

领取在现有写事务内选择已到期且无有效租约的批次。关系索引识别同 workspace/Trace 的前序批次。前序未完成则等待；前序最终失败则以 DEPENDENCY_FAILED 终止后续批次。独立批次继续。迁移时，对未准备计划即失败且已有后来准备版本的历史批次，按 Trace 回填 blocks_successors=0，避免旧逻辑曾安全跳过的失败反过来阻塞已推进的版本；恢复仍拒绝存在已准备后继的情况。新批次的此标记固定为 1。

失败将 batch 标记 failed、event 标记 dead，并记录安全错误类别及时间。暂时失败退避 2/4/8/16 秒，5 次耗尽后 RETRY_EXHAUSTED。领取后崩溃计入尝试，租约到期才可再次处理或终止。永久失败沿用既有分类。

恢复使用本机运维 CLI，读取私有 Core 配置和凭据文件，调用与运行时相同的事务逻辑。先核验当前写权限、删除状态、前序和后继版本，再登记恢复历史、保留累计执行令牌并恢复 accepted/prepared，下次领取递增令牌。同一恢复键精确重放；不同键不能重置活动任务。DEPENDENCY_FAILED 后继在前序成功后由同一恢复入口逐批恢复。原始包、计划和错误历史均保留。

## 迁移及回退

追加 021，保留 001–020 校验和。迁移在事务内从 trace_ids_json 回填索引并关联已有 outbox；无法映射时整体拒绝。历史尝试次数不清零，超限待处理任务在租约安全边界转失败。恢复通过审计记录允许终态回到原冻结计划，成功批次仍不可修改。

升级前备份事务库和制品；在上一版本 SQLite 副本经 migrate-sqlite 验证数据保留、再次启动及幂等迁移。旧程序会拒绝未知 schema 21。回退须停写后恢复成套备份，并处理升级后新增数据，禁止直接运行旧消费者或清零次数。
