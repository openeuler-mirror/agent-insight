# Trace 加载优化：开发计划

## 1. 开发前置条件

本目录为待确认方案；收到用户明确确认后才修改功能代码。用户已同意公共连接池的生命周期解释，并要求将批量查询、数据库聚合纳入本轮方案，不代表已确认全部实现细节。

保留工作区已有的 50 个 Span 分页改动与其他未提交文件；不提交、推送或覆盖无关工作。

## 2. 实施顺序

### 阶段一：建立对照与连接复用

1. 读取本地 psycopg2 版本及现有关系库测试，记录首屏 records/stats/facets 的独立基线与实际并发请求。
2. 给关系库连接提供层增加线程安全有界池，区分关闭游标/归还租约与关闭物理连接。
3. 接入 PostgreSQL runtime、配置校验、关闭排空和日志，保留 CLI、显式 factory、SQLite、openGauss 原路径。
4. 验证只读事务、写事务、嵌套获取、异常清理和复用后的状态隔离。此时保留原查询逻辑，单独判断连接复用的收益。

拟涉及 `services/storage/relational.py`、连接池资源模块、`services/storage/trace_service.py` 及必要的配置加载代码。若启动脚本拷贝配置时丢失新增字段，应补齐转交而非修改用户私有配置。

### 阶段二：批量补充与查询计划

1. 梳理当前字段来源、覆盖顺序、null 与缺失值行为，形成代码内受测映射，旧实现作为专项对照。
2. 将权限/路由/别名/annotations/标签/head/结果选择等数据获取与纯计算分开，增加批量读取和批量复核。
3. 实现当前页摘要与根执行元数据的批量读取，保留 per-Trace 上限、制品预算及身份边界。
4. 引入 records/stats/facets 共用的内部条件解释，标记可下推条件和兼容回退原因。
5. 在结果与顺序相同的前提下切换普通列表；不依赖新统计路径即可独立回滚。

拟涉及 `compatibility_list.py`、`trace_service.py`、`trace_metadata.py`、`trace_analytics.py`、`trace_outcome.py`、`authorized.py`、`clickhouse.py` 中必要的读取方法，不改写无关业务。

### 阶段三：统计与选项下推

1. 在已统一的有效字段表达式上实现 ClickHouse 聚合，使用最新版本语义与授权候选范围。
2. 支持默认条件、等价的摘要字段条件以及可在关系库求得的 ID 条件；复杂条件显式回退。
3. 实现分批聚合的可合并中间值与读取边界复核，不平均平均数。
4. 为 tags、framework、sourceKind、Agent 选项设置专用路径，保留原权限、排序及过滤语义。
5. 检查同一筛选条件下 records、stats、facets 的等价性与回退行为。不能只看到 SQL 有 COUNT 就认定性能优化完成。

### 阶段四：专项验证与指南同步

用户要求不跑全量测试，执行下述必要专项；未验证的后端或浏览器必须如实标注。启动 dev 和浏览器验证按仓库约定另行取得用户确认，使用 `scripts/develop_start.sh`。

更新对应中英文公开指南：`docs/{zh,en}/how-to/platform/storage-core.md`、`docs/{zh,en}/reference/platform/storage-core.md`，必要时更新 `how-to/observability/view-traces.md` 的加载说明。一般功能变更不修改开发者导航索引。设计阶段不提前把拟议行为写成公开指南中的现状。

## 3. 验证矩阵

| 范围 | 用例与证据 |
|---|---|
| 连接复用 | 多个顺序事务复用连接；两用户先后复用但重新授权；同一连接无并发租用 |
| 资源上限 | 创建中连接计入上限；普通等待有界；嵌套耗尽立即释放外层；5 并发正常，超容量可控失败 |
| 异常路径 | 建连失败、空闲坏连接、查询中断、rollback/reset/游标关闭失败、数据库重启、关闭服务；无泄漏与错误事务重放 |
| 事务保持 | 读仍为 READ ONLY/REPEATABLE READ；读后写成功，失败写回滚；提交成功后清理失败不触发重复写 |
| 分页 | 页大小 20/50/100，首页/第二页/末页/空页，同时间排序，无重复漏项；只有当前页组装完整摘要 |
| 字段覆盖 | 原始摘要、legacy metrics、annotations、根属性、当前结果投影及 reset；null/缺失/空数组/非法数据保持原行为 |
| 统计 | 总数、失败数、延迟空值和零值、工具零调用及多批合并；与旧逻辑同筛选结果逐项对照 |
| 条件 | 状态/时间/框架/来源/Agent/标签/用户/主子 Agent，及搜索、Skill、结果字段等兼容回退 |
| 一致性 | 用户隔离、共享授权、私有评测 Trace、撤销权限、删除屏障、source/head/结果版本变化，不能返回混合中间结果 |
| 选项 | tags/framework/sourceKind/agents 不泄露其他账号数据，空值与排序一致，不触发无必要完整记录组装 |
| 详情 | 前五条 20,001 Span 的 Trace：首次 50、后续 50、游标不重复；5 Span Trace 无多余分页 |

建议重点复用/扩展 `test_relational.py`、`test_compatibility_list.py`、`test_list_metadata_read_transitions.py`、`test_trace_execution_metadata.py`、`test_trace_metadata.py`、`test_trace_outcome.py` 和相关分页测试，新增连接池状态测试。测试选择以实际改动为准，不运行全仓套件。

## 4. 本地 1,000 条数据验收

1. 使用既有专用测试账号，保持 1,000 条 Trace、104,980 个 Span 不变，不重新导入或修改归属。
2. 分别记录关闭优化、仅开启池、池与查询优化均开启的相同请求结果和指标；基线不稳定时单独说明，不用失败请求耗时宣称速度提升倍数。
3. 每种配置验证首页/第二页、stats、初始选项；预热后连续 10 轮，记录 p50/p95 耗时、建连数、SQL 数和回退原因。
4. 以静止数据为准，默认 total 应为 1,000，前五条仍为大 Trace；实际统计由对照计算验证，不预填失败数或延迟。
5. 默认场景须验证数据库分页、当前页批量补充、数据库聚合和选项专用路径全部实际生效。否则列明原因，不能宣告该项完成。
6. 健康连接未到期时，预热后的建连数不随事务数或 Trace 数线性增长；活跃租约完成后回到零（排除有证据的后台在途操作），无 idle-in-transaction 泄漏。
7. 对普通当前页请求，单类补充 SQL 数应由批次数决定。统计不读取全部完整展示 DTO 或完整 Span；需要根元数据时记录数量和原因。
8. 5 个并发读者完成列表与统计，健康环境无池耗尽；更高负载耗尽要在配置预算内结束并能恢复。故障注入使用隔离测试库/连接，不能断开用户正在使用的数据库来做破坏性验证。

不承诺固定毫秒 SLA，首要门槛是结果一致、连接稳定和实际工作量下降。如果聚合或批量化未达到默认场景目标，先补充设计，不通过增加超时或删除一致性检查来掩盖问题。

## 5. 回滚与交付

- 独立关闭查询优化可回到旧查询但保留池；关闭池可回到原建连方式。通过现有服务启动/停止流程操作，不执行数据库重置。
- 没有 schema 变更、数据迁移或回填，无需逆向数据转换。任何超出本设计的新持久字段或认证行为改动需重新确认。
- 交付说明列明代码变更、配置默认值、专项验证结果、实际优化覆盖范围、兼容回退和未验证内容。
