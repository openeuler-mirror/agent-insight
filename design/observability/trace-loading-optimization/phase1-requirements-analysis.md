# Trace 加载优化：需求分析

## 1. 背景与证据

链路追踪页面使用本地测试账号查看 1,000 条 Trace：前 5 条各含 20,001 个 Span，其余 995 条各含 5 个 Span，共 104,980 个 Span。页面出现“记录加载失败”。

已通过同账号接口调用复现 HTTP 503。独立诊断调用相同列表逻辑时，约 1.85 秒内尝试 112 次 PostgreSQL 建连，捕获 `server closed the connection unexpectedly`。临时复用连接的对照进程用 3 条物理连接完成约 336 次事务，约 3.49 秒返回首页 20 条记录。这是单次定位证据，不是性能承诺；连接被关闭的更底层原因尚未确定。

当前实现的三个成本来源：

1. `services/storage/relational.py` 的关系库事务逐次建连、关闭，不复用健康连接。
2. `services/storage/compatibility_list.py` 的默认列表已有数据库分页，但选定当前页后仍逐条查询路由、摘要、权限、标签、别名、执行元数据和结果覆盖；内部还有重复校验。
3. 统计及部分筛选选项通过兼容路径读取、补充可见记录，再在 Python 中筛选和计算，并非简单的数据库计数。

列表浏览器响应只含当前页摘要，不等于后端只执行一次查询。OTLP 摘要补充可能读取根 Span 属性；它与点击详情后分页读取 Span 结构是不同流程。

## 2. 用户确认的方向

- 使用服务端公共连接池，不为每个登录会话分配专属物理连接。
- 登录后请求持续复用连接；退出结束当前浏览器登录状态，不关闭其他用户或后台任务仍需使用的公共连接。
- 将当前页摘要补充改为批量查询，将可等价执行的统计改为数据库聚合。
- 先审阅并确认本设计，再开发功能。
- 使用针对性验证，不要求全量测试。

“Trace 展示只读”指列表、统计、筛选选项及详情读取不修改 Trace 业务数据。登录、凭证管理、后台采集本来存在写事务，不能因本次优化把整个 Storage Core 改成只读。

## 3. 目标与非目标

### 目标

1. 连接数受配置上限约束，事务之间复用健康连接，异常连接可淘汰和补建。
2. 默认首页仅为本页 Trace 组装完整展示摘要；补充查询随批次数增长，而非每条记录重复一整组查询。
3. 普通统计在数据库中计算，后端不为统计而组装全部展示记录。
4. 首屏同时发出的筛选选项请求不绕回无必要的完整记录组装。
5. 保留身份隔离、权限撤销、删除屏障、版本检查、字段覆盖优先级、筛选语义和统计口径。
6. Trace 详情首次及后续每批最多 50 个 Span 的既有约定保持不变。

### 非目标

- 不重构登录方式，不新增 Web 退出 API，不在退出时自动撤销可能供采集器使用的 API Key。
- 不改变列表页大小、列内容、统计含义、自动刷新频率或现有接口响应结构。
- 不引入持久缓存、摘要新表或异步物化视图，不修改 Prisma schema，不重导现有测试数据。
- 不在本轮把 ClickHouse HTTP 传输改为新的连接池实现。
- 不承诺所有复杂筛选都能直接变成一条 SQL；兼容路径必须明确且可观测。

## 4. 查询适用范围

| 场景 | 目标路径 |
|---|---|
| 普通分页列表 | 权限候选范围 → 数据库筛选排序分页 → 当前页批量补充 |
| 普通统计 | 相同权限和筛选语义 → ClickHouse 聚合 → 返回统计值 |
| 标签、用户等关系库条件 | 关系库先得到授权范围内的匹配 ID，再交给摘要查询与聚合 |
| 依赖根元数据、结果覆盖、历史兼容值的复杂条件 | 能证明等价时下推，否则有界兼容路径；不得静默忽略条件 |
| 框架、来源、Agent 选项 | 经授权的摘要字段 DISTINCT/GROUP BY；必要时兼容处理 |
| Trace 详情 | 继续使用已有结构分页与单 Span 详情读取 |

默认路径也必须检查子 Agent 标识、来源版本和覆盖语义是否能够等价处理；不能仅凭“没有高级筛选”就跳过这些检查。

## 5. 验收原则

- 以现有正确的字段组装与过滤逻辑为对照，在静止数据上比较分页记录、统计和选项；若已有列表与统计不一致，记录为独立问题，不自行选择新口径。
- 在上述 1,000 条数据上检查首页、第二页、统计、筛选选项和 50 个 Span 详情分页。
- 记录物理建连数、事务数、SQL 数、根 Span 读取数、耗时、聚合路径及回退原因。查询数目标必须区分摘要、关系库补充和不可避免的制品读取。
- 单用户预热后连续 10 轮列表与统计应无连接泄漏、无建连风暴；5 个并发读者下正常完成，过载时有界失败而非无限等待。
- 单独验证跨账号隔离、权限撤销、删除、连接失效、池耗尽和读写事务状态隔离。
- 不把连接池能减少建连开销表述为可以修复所有数据库故障，也不把兼容回退宣称为已经完成数据库聚合。
