# 平台内置 Agent 运行时选择设计

## 分层

```
业务功能（Skill 生成 / 优化 / 诊断 / 内部评测）
        │  统一提交：任务、模型、Skill、工具策略、所需能力
        ▼
统一执行服务（任务入口解析默认运行时、能力检查、诊断）
        │
        ▼
运行时适配器（OpenCode / Pi / 后续扩展）
        │  原生协议、会话、事件与结果转换
        ▼
部署环境中的 Agent 进程
```

业务模块只依赖统一入口，不 import 具体 SDK、CLI 参数或原生事件类型。任务宿主统一承担身份、工作目录、资源额度、交互策略、取消、超时与异常回收；适配器只负责原生协议和事件转换。

本阶段落地的统一入口是 `runGeneralAgent`：平台内置任务已经从这里进入执行层，运行时默认值在入口解析。后续新增适配器时，替换的是入口内部的分派实现，而不是各业务模块。

## 运行时目录

`src/lib/agent-runtime` 维护运行时目录与检测逻辑：

- `types.ts`：运行时标识、能力集合、检测状态、诊断码和偏好解析结果。
- `catalog.ts`：内置运行时定义（Pi、OpenCode）、最低版本、可执行文件查找顺序和能力声明。
- `discovery.ts`：部署环境检测、版本探测、缓存。
- `preference.ts`：个人默认值校验与解析。
- `index.ts`：对外出口。

运行时标识首批为 `pi`、`opencode`。目录顺序即平台默认偏好顺序：Pi 优先，其次 OpenCode。

## 检测

检测只覆盖平台服务进程可访问的环境：

1. 按环境变量覆盖查找：OpenCode 使用 `OPENCODE_BIN`，Pi 使用 `AGENT_INSIGHT_PI_EXECUTABLE` / `PI_EXECUTABLE`。
2. 查找平台打包路径：OpenCode 还检查 `<package-root>/node_modules/.bin/opencode`，与 `resolveOpencodeBinary()` 的既有顺序一致。
3. 回退到 `PATH`。

找到可执行文件后执行 `--version` 探测，参数固定、不经过 shell、默认 3 秒超时，输出限制 64 KiB。检测不执行模型调用，不安装或升级依赖。结果在进程内缓存 30 秒，页面可显式强制刷新。

状态按以下优先级给出，并且每个状态都携带诊断码和说明：

| 状态 | 含义 |
|-|-|
| `not-installed` | 部署环境中找不到可执行文件 |
| `probe-failed` | 找到文件但版本探测失败、超时或输出不可解析 |
| `incompatible-version` | 版本低于适配要求 |
| `adapter-missing` | 版本兼容但平台尚无执行适配器 |
| `available` | 适配器存在、版本兼容，可选择 |

能力由适配器声明，不根据 CLI 参数猜测。没有适配器时能力全部为否，避免把"安装存在"误报成"可用于平台任务"。

最低版本：Pi `0.82.1`（与常驻客户端的 CLI 参数判定一致），OpenCode `1.0.0`（1.x 与 2.x 均已接入，以下未验证）。

## 个人默认值

默认值保存在既有 `UserSettings.settingsJson.agentRuntimeId`，不修改 Prisma schema：

- 未保存：按目录顺序选择第一个 `available` 运行时，来源为 `platform-default`。
- 已保存且可用：来源为 `user`，直接使用。
- 已保存但不可用：返回 `unavailable`，**不回退**到其他引擎；页面展示原因，任务入口报错。
- 保存值不受支持：返回 `unavailable`，要求重新选择。

保存接口在写入前重新检测并校验；只有 `available` 的运行时可以保存。默认值只影响之后新建的任务与会话，不修改历史 Execution、Session 或进行中任务的绑定，也不跨引擎复用原生 Session ID。

## 接口

`GET /api/agent-runtime?user=<user>[&refresh=1]`

返回 `{ runtimes, checkedAt, preference }`。`runtimes` 包含每个运行时的可执行文件、来源、版本、最低版本、能力、状态、是否可选和诊断；`preference` 包含用户保存值、实际生效值、来源、状态和诊断。

`PUT /api/agent-runtime`

请求体 `{ user, runtimeId }`。`runtimeId` 为 `null` 时清除个人默认值，恢复平台默认顺序。运行时不存在或不可选择时返回 409 与诊断码，不写入设置。

## 页面

`/config/agent-runtime`（配置 → Agent 运行时）展示：

- 平台默认与各运行时卡片，含状态、版本、可执行文件路径、来源、最低版本和六项能力。
- 每个运行时的不可用原因；未适配的运行时不可选。
- 当前生效运行时、来源和检测时间。
- 重新检测与保存操作；保存后提示仅对新任务和新会话生效。

页面只引用共享设计令牌，不新增局部色板。

## 执行入口约束

`runGeneralAgent` 在解析用户与 query 之后读取个人默认值：

- 未保存或为 `opencode`：沿用现有 OpenCode 执行路径。
- 为其他值：抛出 `AGENT_RUNTIME_UNAVAILABLE`，提示用户改选，不静默换引擎。

该约束让默认值立即生效且可审计。Pi 适配器交付后，在这里改为按适配器分派，业务模块无需改动。

## 安全与隔离

- 探测只使用固定参数与 `shell: false`，不拼接用户输入。
- 环境变量覆盖只接受存在的可执行文件；不执行目录或不存在的路径。
- 检测不接触模型凭据，不发起网络请求。
- 能力声明决定可选性；缺失能力不会被默认放行。
- 工作目录与独立 HOME 不作为文件系统安全沙箱的替代；强杀后的后代进程回收由任务宿主负责，适配器交付时一并验证。

## 不在本阶段

- Pi 执行适配器、随平台交付 Pi 运行时和模型配置注入。
- 把其余业务模块的 OpenCode 原生事件类型迁移到统一事件模型。
- MCP、子代理、强隔离能力的跨运行时等价性验证。
- 外部客户端与 Benchmark 执行端的运行时选择（保持原有机制）。
