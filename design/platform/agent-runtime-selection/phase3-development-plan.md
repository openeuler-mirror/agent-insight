# 平台内置 Agent 运行时选择开发计划

## 阶段一：检测、选择与执行入口约束（本次交付）

1. 新增运行时目录、能力模型、检测与偏好解析模块，覆盖 Pi 与 OpenCode。
2. 检测按环境变量、平台打包路径、PATH 依次查找可执行文件，并以固定参数执行版本探测；结果缓存 30 秒，支持强制刷新。
3. 以适配器声明能力，未交付适配器的运行时标记 `adapter-missing` 且不可选。
4. 新增 `GET/PUT /api/agent-runtime`，个人默认值写入 `UserSettings.settingsJson.agentRuntimeId`，不修改 Prisma schema。
5. 配置下新增「Agent 运行时」页面，展示状态、版本、来源、兼容性、能力与不可用原因，并支持重新检测和保存。
6. `runGeneralAgent` 入口读取个人默认值；非 OpenCode 选择明确报 `AGENT_RUNTIME_UNAVAILABLE`，不静默回退。
7. 专项自动化覆盖：未安装、探测失败、版本不兼容、适配器缺失、可选状态、缓存与强制刷新、平台默认顺序、个人默认优先、不可用时无回退、非法选择拒绝。

已完成：上述代码、专项测试与类型检查（新代码无类型错误）。未执行：真实 Pi 环境、真实模型与浏览器验收；本次未启动开发服务器。

## 阶段二：Pi 执行适配器与内置运行时

1. 在封闭进程中实现 Pi 适配器：固定参数 `--mode json --session-id <新 ID> --no-approve --print [--model <provider/model>]`，Prompt 走 stdin。
2. 用平台模型注册生成隔离的 Pi 配置目录（`PI_CODING_AGENT_DIR`，包含 `settings.json`、`models.json`、`auth.json`），不要求全局登录；凭据只在进程内临时存在，任务结束清理。
3. 建立 OpenCode → 统一事件模型的转换层，把 Skill 生成、优化、诊断从原生事件类型解耦。
4. 工具禁用、只读、工具白名单、取消、超时、异常退出和后代进程回收按能力逐项回归；不支持的配置必须在提交阶段报错。
5. 能力不足、版本不兼容、模型未配置分别给出诊断，不做静默降级。
6. 在目标部署环境、真实模型和浏览器中验证主要流程，并记录 Pi 与 OpenCode 的能力边界。

阶段二完成后把 Pi 适配器加入目录，`adapter-missing` 自动转为 `available`；标签页与默认顺序无需改动。

## 阶段三：扩展与治理

1. 评估随平台打包 Pi 的许可、体积、Node 版本要求和升级策略，满足"无全局 Pi 也能使用"。
2. 其余运行时（例如 xiaoO）按同一目录与能力模型接入，不在业务模块增加分支。
3. 监控各运行时的实际使用与失败诊断，作为能力边界和默认顺序的调整依据。

## 验收口径

- 阶段一：检测结果可重复、诊断明确、默认值只影响新任务、非法选择不写入且不执行。
- 阶段二：正反向能力测试通过；Trace 保留真实业务归属与执行事实；浏览器与真实模型验证完成。
- 阶段三：部署形态与运行时扩展不改变业务层契约。
