# 平台内置 Agent 运行时选择需求分析

## 背景

用户实际使用的 Agent 可能是 Pi、OpenCode 或其他运行时。不同运行时的工具集合、Skill 加载方式、上下文管理和执行行为不同，仅使用同一模型不能保证行为一致。

平台内置的 Skill 生成、优化、诊断及部分内部评测执行，目前与 OpenCode 的会话、事件和权限接口绑定。用户无法按真实使用环境选择执行引擎，既放大了平台结果与用户日常 Agent 行为之间的差距，也不利于复用已有部署和后续扩展。

## 目标

1. 识别平台服务实际可访问的已安装运行时，展示版本、来源、兼容性、能力和不可用原因。
2. 允许用户重新检测、选择运行时并保存个人默认值。
3. 统一业务提交契约，避免在 Skill 生成、优化、诊断等模块内分别增加运行时分支。
4. 所选运行时不可用或能力不足时明确提示，不静默换引擎、放宽权限或忽略配置。
5. 用户更换默认值只影响新任务和新会话；进行中任务与历史会话保持原运行时绑定。

## 典型场景

- 用户日常使用 Pi，希望平台的 Skill 生成、优化或诊断也由 Pi 执行。
- 用户已有 OpenCode 部署，依赖其特定能力，希望继续由兼容的 OpenCode 执行平台功能。
- 运维人员需要确认当前容器内实际可用的运行时及其版本，判断为什么某次任务不能使用预期引擎。

范围仅覆盖平台内置功能。外部客户端上的被测 Agent、Benchmark 执行端及其任务选择机制保持原有职责。

## 约束与边界

- 检测范围是当前平台服务进程可访问的部署环境。容器内结果不代表宿主机或用户浏览器所在电脑。
- 检测只读取可执行文件并执行版本探测，不调用真实模型，不安装或升级依赖。
- 找到可执行文件不等于具备平台执行能力。只有存在适配器、版本兼容且满足任务所需能力的安装才可选择。
- 保留进程与用户配置隔离、工具禁用、只读、工具白名单、取消与超时、异常后代进程回收、会话续接和 Trace 归属语义。
- 普通无工具 Judge 继续使用直连模型路径，不引入 Agent 执行开销。
- MCP、子代理和强隔离按各运行时实际能力单独验证，不在能力清单中默认承诺。

## 验收映射

| 验收标准 | 本阶段覆盖方式 |
|-|-|
| 无全局 Pi 的标准部署也能使用内置 Pi | 需要 Pi 运行时随平台交付并完成适配，见开发计划第二阶段 |
| 查看已适配运行时版本、能力与状态，选择并保存个人默认值 | 本阶段交付检测、能力/兼容性评估、个人默认值与页面 |
| 统一契约使用不同合格运行时，业务层不依赖具体 SDK/CLI/事件 | 统一执行入口与适配器边界；本阶段仅 OpenCode 适配器已交付 |
| 工具策略、取消、超时、异常退出与后代回收正反向测试 | 由各适配器的执行实现承担，见开发计划 |
| 切换默认值不影响进行中任务、历史会话与既有结果 | 默认值只在任务入口解析，不修改历史绑定 |
| 能力不足、版本不兼容、模型未配置有明确诊断 | 检测状态、选择校验与执行入口均返回明确错误码 |
| 目标部署环境、真实模型和浏览器验证 | 本阶段未完成真实 Pi/模型与浏览器验收，见开发计划 |
