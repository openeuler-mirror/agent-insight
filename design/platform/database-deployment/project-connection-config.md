# 项目自带一份 App 数据库连接配置

状态：已实现。

## 需求与操作顺序

项目发布时即包含 `config/deployment/storage.ini`。它是 App 的正式默认配置，字段下面直接写中文注释。用户可以在下载项目后打开它，也可以等两个数据库都启动后再编辑。使用默认部署时，跳过编辑即可。需要自定义连接时，直接修改这一份文件并保存，下次启动 App 时生效。

| 用户操作 | 该步骤读什么 | 对 App 配置文件的操作 |
|---|---|---|
| `bash scripts/deploy-step.sh clickhouse` | ClickHouse 自己的启动参数、凭据和数据卷 | 无。即使 INI 缺失或格式错误，也可以独立启动数据库 |
| `bash scripts/deploy-step.sh transaction` | 所选事务库自己的启动参数、凭据和数据卷 | 无。数据库类型由此次数据库部署决定 |
| 可选：编辑 `config/deployment/storage.ini` | 用户从项目运行环境可访问的数据库地址和实际账号 | 直接保存原文件 |
| `bash scripts/deploy-step.sh app` | 此时磁盘上的 INI 内容 | 只读，校验连接成功后启动 Web |

两库也可以由其他人预先部署在服务器上。此时只需填写连接并执行 App 启动步骤。常规流程没有复制模板、生成配置或维护第二份可编辑配置的步骤。

## 文件示例

实际文件见 [storage.ini](../../../config/deployment/storage.ini)。其中 `[transaction].backend = @instance` 沿用托管实例选定的后端（新实例默认 PostgreSQL），以兼容现有的一键选库命令。也可明确填入后端名。`[postgresql]`、`[opengauss]` 和 `[sqlite]` 分别保存其连接字段，App 使用所选后端及必选的 `[clickhouse]`。各段的密码或令牌填 `@instance` 时，只能用于与本实例服务、账号、库名匹配的内部目标。外部库直接填写实际值。端口的含义以项目运行环境为准。

## 修改后的效果

例如，管理员已经提供 `pg.internal.example:6432` 和用户 `insight_reader_writer`。用户只需在原文件事务段改主机、端口、库名、用户名和密码，ClickHouse 继续使用原来的连接。App 启动后按这组新值连接。若输入的密码与服务端不匹配，启动失败并提示检查 `[transaction].password`。编辑这份文件只改变客户端使用的密码；给数据库账号改密是数据库管理员的独立操作。

## 实现与兼容

1. 将[部署启动器](../../../scripts/deploy-docker.py)中目前由 `settings()` 一起完成的“准备数据库实例”和“生成 App 连接配置”拆开。数据库命令只处理服务端状态，既不读取、创建、校验 INI，也不生成 App 运行时 JSON。四份独立数据库 Compose 仍可分别启动。
2. App 启动入口按项目根目录定位 INI，每次重新读取，校验字段、解析引用并对 DSN 凭据编码，密码按字面值解析。将生效值转为现有 Storage Core 所需的私有运行时配置。容器可以只读挂载这个内部结果，用户维护的仍只有仓库中的 INI。配置改变时确保项目容器拿到本次结果，包括在原容器仍运行时重新执行 `app` 的情况。真实密码不写进镜像、发布包或日志；构建时须排除工作区内可能已填入实际密码的文件，并从干净版本交付默认文件。
3. 一键流程复用相同边界：前两项服务独立启动，进入 App 阶段才读取连接配置。已有实例继续使用原数据库卷、项目卷、实例身份与凭据；兼容已有显式 `--config` 私有 JSON 调用。普通 App 启动以本次 INI 为准；旧的派生 JSON 不能遮盖用户修改。若已有持久 App 实例受目标数据库身份保护，切换数据源仍须使用独立实例或显式迁移。源码部署访问宿主机可达的端口，沿用双库校验。
4. 缺文件、字段无效、凭据不匹配或数据库不可达时，在 App 启动阶段报告配置路径、服务及字段。数据库进程继续运行，用户修正原文件后可重试。

## 专项验收

- 临时移走 INI 或填入格式错误的内容，两种数据库启动命令都能成功，数据库阶段不创建或改写该文件；App 启动时给出对应错误。
- 使用随仓库提供的原始 INI，默认 PostgreSQL 和 ClickHouse 就绪后直接启动 App，验证登录和 Trace 写入、读回。
- 两库已经运行时修改同一 INI，启动 App 验证使用修改后的连接。先填错密码再改回正确值，核对错误提示、重试结果以及两库容器身份和数据保留。
- 分别验证 openGauss、网络 SQLite、外部两库及旧版显式配置路径。检查 App 重启读取最新版文件，数据库重启不触碰 INI，日志与镜像构建结果均不含测试凭据。
