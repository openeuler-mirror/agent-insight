# 数据库与项目分离部署 · 开发计划与验收

| 顺序 | 交付 | 判定依据 |
|---|---|---|
| 1 | 先验证 SQLite 网络事务和 openGauss 镜像 | SQLite 完成写事务、快照、断连回滚、幂等重试、在线备份与制品读取。openGauss 真实实例完成认证、初始化、重启及普通账号业务读写。按目标 amd64/arm64 分别记录结果。 |
| 2 | 抽出源码和容器共用的连接预检，保留旧文件格式 | 缺配置、未知字段、选多库、缺 ClickHouse、TLS 或权限错误都返回具体字段与脱敏诊断。PG/openGauss 和旧 SQLite 格式通过现有回归。 |
| 3 | 发布含 Core/Web 的项目镜像及独立数据库文件 | 单独启动任一数据库时只有该数据库运行。单独部署项目可以连接外部地址。进程退出、SIGTERM、就绪探针及原 WSS 控制通道通过验证。 |
| 4 | 整体编排、持久化与交付指南 | 默认 PostgreSQL、显式选择三个后端、重复启动、停止、恢复均用同一批独立文件。发布已验证镜像摘要，更新中英文公开指南、教程和配置参考。 |

## 验收矩阵

每个单元格均需独立实例实测。统一业务验收为登录、写入带唯一标识的 Trace、等待索引后查询、读回一个制品，记录实际容器/进程、端口和版本。

| 事务库（各搭配 ClickHouse） | Docker 一键 | Docker 分步 | 源码外接 |
|---|---|---|---|
| PostgreSQL | 省略参数与显式选择均为三容器 | 先两库后项目，再单独替换项目容器 | 对已提供的两库连接执行安装 |
| openGauss | 显式选择，检查事务库类型与卷 | 分开启动与外部服务地址各验一次 | 使用真实 openGauss 账号和 CA |
| SQLite 服务 | 显式选择，检查数据库卷只挂在 SQLite 容器 | 分开启动，终止服务连接时验证事务回滚 | 连接远程端口，项目进程无法接触数据库文件 |

另测缺少配置文件、缺任一库、错密码、非私有配置、端口冲突、权限不足、服务中途退出、停机后恢复、初始化中断重试；并行安装同一实例只能有一个初始化者。数据库未就绪时 Web 不接流量。应用重新部署后检查两个库的记录与制品仍在。数据库有卷但凭据丢失时拒绝生成新凭据。用上一版有数据的 SQLite 副本走实际入口与备份恢复，再次启动核对记录。

## 本地部署专项验证记录

2026-11-28 在 ARM64 Docker 环境构建项目镜像。PostgreSQL 16、openGauss 7.0.0-RC3 和网络 SQLite 分别搭配 ClickHouse 26.8，均验证了整体启动三个容器、单独重建项目、再次登录及读回此前索引的 Trace 和 Span 输出。源码分别连接三组已启动的数据库，完成生产 Web 构建、启动和同样的读写检查。三种事务库同时验证了公开 Web OTLP 接口对测试 Span 的接收。另将项目置于独立 Compose 项目中，连接分别启动的 PostgreSQL 与 ClickHouse，核对缺少 ClickHouse 配置时的非零退出和提示。独立 SQLite 镜像验证了通过端口写入业务记录及在线备份读回。使用上一个迁移版本 SQLite 副本验证了旧库升级提示、备份、升级及重复安装后的记录保留。

本次使用本地镜像，镜像发布、其他 CPU 架构和浏览器交互验收独立进行。
