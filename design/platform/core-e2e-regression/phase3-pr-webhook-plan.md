# PR 自动回归实施计划

**Goal:** 先在本地完成六场景统一运行、UT 独立统计、Webhook 接收和 PR 结果回写，再连接个人仓库 origin（gyctl/agent-insight）。

**Architecture:** 测试包位于 test/e2e，六个场景分别归档，运行产物仍在 exclude/core-e2e。独立控制服务验证 Webhook，持久化按仓库、PR、head/base SHA 标识的任务；执行进程与持有写凭证的通知进程分开。外部任务必须在容器或等价隔离环境执行，不能直接在开发者宿主机执行任意 PR。服务不是产品 API，不纳入生产安装包。

**Tech Stack:** Node.js、node:test、Playwright、现有产品原生客户端与 SQLite；GitCode/AtomGit OpenAPI；不新增产品依赖。

## 实施顺序

1. 迁移 test/e2e/cases/001—006、shared、fixtures；按模块依赖更新路径，运行现有工具测试并核验发布排除。
2. 为全量运行、失败继续、UT 汇总缺失/中断、不可用 Mock 和暂停例的结果约束先写负向测试，再实现 run.mjs；结果由代码生成 JSON、HTML、Markdown。
3. 为 Webhook 验签、仓库白名单、精确 SHA、去重、过期任务、重启恢复写测试，实现受限本地接收端与持久化队列；默认仅监听回环。
4. 为隔离执行、凭证隔离、超时、报告完整性写测试；本地可信代码执行与任意 PR 隔离执行必须显式区分，未配置安全执行器不得启动 PR 代码。
5. 通过最小权限 AtomGit 客户端生成/更新 PR 报告，回写前再次确认 PR SHA；本地联调用伪服务验证真实 HTTP 协议，不算远端联调通过。
6. 本地执行工具测试、UT 和可运行的业务验证；更新指南及已验证边界。真正启用 origin Webhook 前提供可达接收地址及安全执行器，并做专用 PR 联调。

## 验收

- 一个入口选择单例/全量；每例结果、UT 完整性、测试 SHA 和复现命令可读。
- 正确签名事件进入队列；错误签名/仓库不能执行；重复事件只入队一次；旧提交不能更新最新结果。
- 原始凭证、私人日志和数据库不出现在共享报告及 PR 评论中。
- npm 包与生产镜像不包含测试驱动、Playwright 或测试运行产物。
- 本地模拟、真实业务运行和远端 Webhook/PR 联调分别记录，不互相代替。
