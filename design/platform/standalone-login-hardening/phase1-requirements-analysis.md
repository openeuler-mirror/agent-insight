# Phase 1：本地账号密码登录需求分析

> 更新（2026-11-20）：实现最终采用「新建账号初始密码与账号名一致（admin 为 admin，可由 `AGENT_INSIGHT_ADMIN_PASSWORD` 覆盖），首次登录强制改密」，管理员重置密码时直接设置新密码；存量未设置密码的账号仍可免密首次登录。本文档保留原始需求分析背景，当前行为以 [Phase 2](phase2-requirements-design.md)、[Phase 3](phase3-development-plan.md) 与公开文档为准。

## 背景

`LOGIN_MODE=standalone` 是默认部署方式。当前登录流程只要求用户名：登录页提交用户名，服务端按用户名查找用户，不存在时直接建号，并把该用户永久 API Key 返回给浏览器。

相关实现：

- `src/app/login/page.tsx`：登录表单只有用户名输入框。
- `src/app/api/auth/apikey/route.ts`：standalone 分支调用 `findOrCreateLocalUser(username)` 后直接返回 `apiKey`。
- `src/lib/auth/local-user.ts`：不存在即创建，不做任何身份验证。
- `src/lib/auth/admin.ts`：`AGENT_INSIGHT_ADMIN_USERS` 未配置时默认 `admin` 为管理员。

因此任何能访问登录页的人，只要知道用户名就能完整使用该账号；用户名 `admin` 还能直接取得平台管理员能力。公开文档也把这一行为描述为“登录即注册”。

## 问题界定

| 编号 | 问题 | 影响 |
| - | - | - |
| P-1 | 用户名即凭据，没有密码校验 | 任意用户可登录任意账号，包括管理员 |
| P-2 | 登录时自动注册账号 | 无法控制账号来源，可无限建号 |
| P-3 | 管理员身份默认落到 `admin` 且无口令 | 默认部署直接暴露管理权限 |
| P-4 | 存量账号没有任何可用于校验的凭据 | 引入密码后必须有明确的迁移路径 |

本次只解决 P-1 至 P-4。API Key 的存储方式、账号禁用/删除、角色体系、`?user=` 参数冒充等问题不在本次范围。

## 候选方案与取舍

### 登录方式

| 方案 | 交互 | 优点 | 代价与风险 | 结论 |
| - | - | - | - | - |
| 本地密码 + 管理员建档 | 输用户名和密码 | 无外部依赖，离线可部署，账号来源可控 | 需要密码策略、重置流程和首次改密 | 当前建议 |
| 强制 IDaaS OAuth | 跳统一身份登录 | 不维护密码，复用企业身份 | 必须有 IdP；纯离线或小规模部署不可用 | 已有能力，保留为替代路径 |
| 组织网关集成 | 依赖上游网关 Cookie | 已有 `ORGANIZATION_MODE`，改造成本低 | 与组织 Skill 接口绑定，部署依赖重 | 已有能力，保留为替代路径 |
| 外层网关鉴权 + 信任身份头 | 网关认证后注入用户头 | 可对接任意 SSO，应用侧改动小 | 平台若可绕过网关直连即可伪造身份；需要新增信任头解析和防直连约束 | 可选补充形态，本次不实现 |
| 共享部署口令 | 先输统一口令，再填用户名 | 实现最简单，能挡住外部访问 | 账号之间仍可互相冒充，没有解决 P-1 | 不采用 |
| 邀请码 / 一次性登录码 | 管理员发码，用户凭码登录 | 不用记密码，适合低频或临时账号 | 日常每次登录都要找管理员，体验差 | 不采用；但可作为开号方式的补充 |
| 邮箱验证码 / 魔法链接 | 邮件发码或登录链接 | 无密码 | 需要 SMTP、邮箱体系与投递可靠性，范围明显扩大 | 本次不做 |
| LDAP / AD 绑定 | 直接校验目录账号 | 企业统一身份 | 新协议依赖，与 IDaaS 场景重叠 | 本次不做 |
| Passkey / WebAuthn | 浏览器生物识别 | 无密码、抗钓鱼 | 需要 HTTPS、注册与恢复流程，实现量大于密码 | 本次不做，可作为后续增强 |
| 仅本机回环、不登录 | 只监听 127.0.0.1 | 单机自用最省事 | 多人或多机部署不成立，等于放弃修复 | 不采用 |
| 管理员直接下发 API Key 当登录凭据 | 管理员把 Key 给用户 | 零改动 | Key 永久、明文、不可吊销，泄露即失控 | 不采用 |

### 账号来源

| 方案 | 做法 | 优点 | 代价 |
| - | - | - | - |
| 管理员在页面建档 | 管理页新建账号并生成初始密码 | 可视、可审计，无需登录服务器 | 需要新增管理页面与接口 |
| 命令行建档 | 服务端命令创建账号 | 适合容器初始化和自动化 | 日常运维不方便 |
| 邀请码自助开号 | 管理员发码，用户自行设置密码 | 分散管理员工作量 | 多一套邀请码生命周期管理 |
| 自助注册 + 管理员审批 | 保持注册入口，增加审批状态 | 用户上手快 | 需要审批流与状态机 |
| 保持现状（登录即注册） | 不限制账号来源 | 无改动 | P-2 无法解决 |

### 已确认延后的相关议题

- API Key 哈希存储、轮换与吊销：成本高，需要所有 Agent 重新配置，单独排期。
- 管理员建号后直接下发一次性接入令牌（免登录跑安装命令）：属于接入流程，已确认不纳入本次。
- 账号禁用、删除、角色与权限组：本次只做可用/不可用之外的最小集合。
- `?user=` 参数身份冒用：改动面覆盖数十个接口，需单独设计灰度方案。
- 密码找回、MFA、单点登出：依赖外部通道或更大的会话改造，本次不做。

### 当前建议与待抉择

建议采用“本地密码 + 管理员页面建档”，同时保留已有的 `idaas_oauth` 与 `organization` 两种模式不动。以下几点需要确认后再冻结设计：

1. 登录方式是否只保留上述三条路径，不引入共享口令或邀请码。
2. 账号来源是否只做管理员页面建档，还是同时提供命令行建档（便于容器初始化）。
3. 是否接受“升级后存量账号必须由管理员逐个重置密码”这一硬性迁移成本。
4. 首次登录强制改密是否对所有新建账号默认开启，还是允许管理员建号时选择关闭。

## 目标

1. standalone 登录改为“用户名 + 密码”，失败时不泄露账号是否存在。
2. 关闭自助注册，账号由管理员统一创建。
3. 管理员可以新建、批量导入与删除账号、重置密码；新账号初始密码与账号名一致，重置密码由管理员直接设置。
4. 用户首次登录必须修改密码；之后可凭原密码自助改密。
5. 存量未设置密码的账号可免密首次登录并强制改密；已发出的 API Key 继续有效。

## 功能需求

1. standalone 模式下 `POST /api/auth/apikey` 必须提交 `username`；已设置密码的账号必须提交 `password`，存量未设置密码的账号可只提交 `username`；不再自动创建账号。
2. 密码错误、用户不存在统一返回 401 和同一条文案，不区分失败原因。
3. 账号已设置密码但缺少密码时，与密码错误、用户不存在统一返回 401，不泄露账号状态。
4. 管理员通过“账号管理”页面查看账号列表、新建账号、批量导入、删除账号与重置密码。
5. 新建账号的初始密码与账号名一致；管理员重置密码时直接输入新密码；服务端只保存哈希，不保存或回传明文。
6. 管理员重置密码后，该账号下次登录必须先修改密码。
7. 登录用户可凭当前密码修改自己的密码；改密不改变 API Key。
8. 管理员身份仍由 `AGENT_INSIGHT_ADMIN_USERS` 决定，页面只展示不修改。
9. 账号管理与改密入口只在 standalone 模式出现；`organization` 与 `idaas_oauth` 行为不变。
10. 同一 IP + 账号连续登录失败需要限流，避免在线爆破。
11. 服务启动时仍需自动准备 `admin` 的 API Key，供本机 Agent 上报使用，不依赖网页登录。
12. 服务启动时确保 `admin` 存在；`admin` 初始密码为 `AGENT_INSIGHT_ADMIN_PASSWORD`，未配置时为 `admin`，首次登录仍强制改密。

## 非功能需求

- 密码使用 Node 自带 `crypto` 的 scrypt 加盐哈希，不新增依赖。
- 校验使用恒定时间比较；数据库与日志中都不出现明文密码。
- 登录、改密、账号管理响应禁止缓存。
- 新增列全部可空或带默认值，兼容 SQLite 与 OpenGauss，旧数据无需回填。
- 中英文界面文案同步。
- 不改变 API Key 作为业务身份和 Agent 接入凭据的现有契约。

## 非目标

- API Key 哈希存储、轮换、吊销。
- 账号禁用、删除、角色与权限组。
- 密码找回、邮件/短信验证码。
- `?user=` 参数的身份冒用修复。
- IDaaS 或组织集成的单点登出与账号同步。
- 管理端下发一次性接入令牌或免登录安装命令。
- 共享口令、邀请码登录、Passkey、MFA、LDAP 等其它认证方式。

## 验收标准

- 已设置密码的账号只提交用户名无法登录；缺少密码、错误密码与不存在的用户返回相同 401。
- 新账号首次登录被强制改密，改密后正常进入平台。
- 管理员创建账号后初始密码为账号名；重复用户名被拒绝。
- 管理员重置密码后旧密码立即失效。
- 用户改密需要正确的当前密码，改密后 API Key 不变。
- 存量未设置密码账号可免密首次登录并强制改密，其旧 API Key 仍可上报数据。
- `idaas_oauth` 与 `organization` 模式行为与现在一致。
- 服务启动后本机 Agent 上报仍能自动取得 `admin` API Key。
- 单元测试覆盖上述路径，旧库副本升级验证通过。
