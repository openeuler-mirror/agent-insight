# Agent 运行时切换开发计划

## 阶段一：探测、诊断与个人默认值（已完成）

1. 新增 `src/lib/engine/agent-runtime/`：
   - `types.ts`：运行时描述、能力、不可用原因与选择结果；
   - `version.ts`：语义版本解析与最低版本比较，无法解析时不视为兼容；
   - `detect.ts`：运行时定义、可注入探测、版本命令执行、30 秒缓存与强制刷新；
   - `preference.ts`：选择校验与概览组装，不做隐式回退。
2. `UserSettings` 增加 `agentRuntime`，读取时校验结构；模型注册/联网搜索的整份 settings 写入
   会保留该字段；新增独立偏好保存路径复用串行化写队列。
3. 新增 `GET/PUT /api/agent-runtimes`：检测、重新检测、保存/清除偏好，错误返回结构化 code
   与原因。
4. 新增「配置 → Agent 运行时」页面与侧边栏入口，展示版本、来源、路径、能力、不可用原因，
   仅允许选择可用运行时。
5. 新增 `test/agent-runtime-detection.test.ts`，覆盖版本解析、兼容性、路径缺失、未安装、
   版本不可读、无适配器、偏好解析与缓存行为。
6. 更新用户操作指南与配置参考。

## 阶段二：统一执行服务与 OpenCode 适配器

1. 定义执行契约：任务、模型、Skill、工具策略、所需能力、取消信号与超时。
2. 抽出 OpenCode 适配器，把会话创建、事件转换、权限应答、取消与结果归并收敛到适配器内部。
3. `runGeneralAgent` 及 Skill 生成/优化/评测调用方改为提交统一任务，业务层不再直接引用
   `AgentInsight`、`ensureOpencodeServer` 或原生事件类型。
4. 执行前按选中运行时重新检查安装、版本与能力；不满足时明确失败，不回退到其他引擎。
5. 偏好只影响新任务；进行中任务沿用启动时解析的运行时。

## 阶段三：内置 Pi

1. 交付内置 Pi 运行时及其兼容执行环境；这需要维护者确认新增依赖与镜像体积。
2. 复用平台模型注册配置注入 Pi，不要求全局安装或单独登录。
3. 实现 Pi 适配器：独立进程执行、事件转换、会话续接、Trace 归属、取消与后代进程回收。
4. 明确 Pi 与 OpenCode 的能力差异，按任务所需能力做前置检查。

## 阶段四：验收

- 禁用工具、只读、白名单、取消、超时、worker 异常退出与后代回收的正反向测试。
- 切换默认值不影响进行中任务、历史会话与既有结果。
- 能力不足、版本不兼容、模型未配置均有明确诊断，无静默降级或权限放宽。
- 在目标部署环境、真实模型与浏览器中验证主要流程。

## 风险

- 检测命令在容器内执行；已限定 3 秒超时并忽略异常输出，但仍需避免在高频请求路径上强制刷新。
- 部署侧可能同时存在多个来源的同一运行时；显式环境变量优先级最高，其次随包安装，最后 PATH。
- 阶段一保存的偏好尚未参与执行；在阶段二接入前，页面文案必须避免让用户以为切换已生效。
