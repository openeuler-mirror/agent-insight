# Agent 运行时切换需求分析

关联 issue：[`openeuler/agent-insight#352`](https://atomgit.com/openeuler/agent-insight/issues/352)

## 背景

平台内置的 Skill 生成、优化、诊断和部分评测执行，统一经由 `runGeneralAgent` 进入内置
OpenCode 会话。不同 Agent 运行时在工具集合、Skill 加载、上下文管理与执行行为上存在差异，
只用相同模型无法保证行为一致；用户也难以按真实使用的 Agent 环境选择平台执行引擎。

本需求为平台内置功能引入「可检测、可选择、可扩展」的 Agent 运行时边界。切换运行时用于缩小
平台执行与用户真实 Agent 使用方式之间的差异，不承诺不同运行时的结果完全一致。

## 用户与场景

- 日常使用 Pi 的用户，希望平台辅助功能也能选择 Pi 执行。
- 已有 OpenCode 部署、依赖特定能力的用户，继续使用兼容的 OpenCode。
- 用户按任务复杂度、工具需求和资源条件选择运行时，同时保留统一操作流程、结果与 Trace 归属。

## 目标

1. **运行时可切换**：平台内置功能通过统一执行契约调用运行时，业务模块不直接依赖具体 SDK、
   CLI 或原生事件。
2. **部署环境内检测**：识别当前服务进程实际可访问的运行时，展示版本、来源、兼容性、能力与
   不可用原因；支持重新检测。
3. **个人默认值**：用户可选择并保存个人默认运行时，只影响新任务和新会话。
4. **明确拒绝**：运行时不满足安装、版本、适配器或能力要求时明确提示，不静默换引擎、不放宽
   权限、不忽略不支持的配置。
5. **保留既有约束**：进程与配置隔离、工具策略、取消与超时、异常后代进程回收、会话续接和
   Trace 语义不因切换运行时退化。普通无工具 Judge 继续走直连模型路径。

## 范围

- 检测范围是**平台服务实际可访问的部署环境**。容器内发现结果不代表宿主机或用户浏览器电脑的
  安装情况；检测不调用真实模型、不自动安装或升级依赖。
- 本期只覆盖平台内置功能。外部客户端上的被测 Agent、Benchmark 执行端及其既有选择机制保持
  原有职责，不纳入本需求的运行时选择。
- 运行时会话语义按各自适配器实现；不跨引擎复用原生 Session ID。

## 非目标

- 不承诺不同运行时的评测结果一致。
- 不在检测阶段执行真实任务或探测模型连通性。
- 不把工作目录、独立 HOME 当作文件系统安全沙箱的替代。
- 不自动安装、升级或登录任何运行时。

## 约束

- 默认 Pi 必须开箱可用，且模型继续使用平台模型注册配置，不要求全局安装或单独登录 Pi；
  交付内置 Pi 需要新的运行时包依赖，属于需要维护者确认的依赖变更。
- 只有「存在适配器 + 版本兼容 + 满足任务所需能力」的安装才可被选择；找到可执行文件不等于
  具备平台执行能力。
- 用户更换默认值只影响新任务和新会话；历史会话与进行中任务保持原运行时绑定。
- Trace 保留真实业务归属与执行事实。

## 分期

完整需求跨数据模型、执行层与 UI，按以下阶段落地：

1. **阶段一（本设计已实现）**：运行时探测、能力/兼容性诊断、个人默认值保存与页面。
2. **阶段二**：统一执行服务与 OpenCode 适配器抽取，业务模块只提交任务与所需能力。
3. **阶段三**：内置 Pi 运行时与 Pi 适配器（含依赖交付、模型配置桥接、事件与 Trace 语义）。
4. **阶段四**：工具策略、取消/超时、worker 异常与后代回收的正反向测试，以及真实部署环境与
   浏览器验收。

阶段一只解决「看得见、选得对、存得下」，不改变任何现有执行路径；它不宣称满足全部验收标准。
