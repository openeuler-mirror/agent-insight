# IAM、002迁移与事务库适配实施计划

本批按已确认的账号/组权限设计实施，不切换现有Web应用数据库，不修改001，不将历史数据自动归组。

1. 新增002 IAM迁移：八张身份/凭据/成员/绑定表，加资源归属与显式共享两表，共十张。资源归属属于事务控制面，不随CH投影延迟失效。以Trace/资产/运行/快照/制品为授权根；Span和正文继承Trace权限，评分继承运行权限。未映射资源对普通成员拒绝访问。
2. 迁移工具校验有序版本与原始DDL校验和。SQLite显式备份、完整性检查后事务升级；已有001初始化不隐式升级。服务端迁移要求独立备份证据。所有验证使用隔离目标。
3. 实现可信IAM领域服务和统一授权门面。登录凭据与API凭据分离；身份停用、改密、退出组、撤销会话/API凭据在下一次调用重新校验。客户端不得直接传AccessScope作为凭证。组管理员可读组下全部业务资源，普通成员仅本人/共享资源，viewer只读。不提供隐式平台管理员。
4. 密码采用标准库PBKDF2-HMAC-SHA256、600000次、独立随机盐；会话和API密钥使用随机令牌，只存SHA256摘要。此批不接Web登录页面、Cookie协议、限流和账号恢复，不将基础服务称作完整上线认证。
5. 增加PG与openGauss独立驱动接入，复用领域操作合同，以事务锁维护领取/fence/回执/Outbox正确性。锁粒度与吞吐明确标为后续优化，不能据此宣称千级写吞吐。
6. 先写失败测试，再实现。验收迁移保留数据/回滚/版本漂移、跨组与普通成员隔离、Span/正文/聚合同权限、凭据撤销、真实事务数据库闭环和已有测试。同步中英指南与实施状态，独立审查；不推送、不操作运行库。

工作分工：schema_core仅负责002 DDL、IAM目录和字段字典；legacy_migration负责迁移执行器和关系库适配；主任务负责IAM与统一授权门面；design_review先提供真实openGauss隔离环境，再审查集成变更。

上述六项基础库工作已完成；192项全套专项和原生openGauss31项通过。新核心001→002有真实三库保留/回滚证据，旧Prisma库未切换，Web身份入口与完整历史转换仍在后续批次。现有应用全量有44项失败，未作为完整验收通过；详见[实施状态](implementation-status.md)。
