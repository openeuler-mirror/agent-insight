# 外部数据库配置与应用一键安装设计

## Phase 1 需求分析

用户独立部署数据库，在项目内填写带样例的配置后安装应用。项目只管理 Core/Web；唯一架构是事务后端三选一＋必需 ClickHouse。此前自动下载/安装数据库的方案被本需求替代，原数据与运行进程保留。

## Phase 2 需求设计

配置模板分别覆盖 SQLite、PostgreSQL，实际配置 storage.local.json 私有且不打包。完整字段契约见公开配置指南。--check 只读检查连接、权限、版本与结构；首次 install 对空的配套数据库使用现有 Core 迁移初始化，保存持久意图，失败可续做。已有结构过旧、混合空库、未知结构或历史库必须显式备份迁移。未改数据库表模型及 Web 布局。

两库没有分布式事务。初始化中途失败保留已经完成的表和意图；重试仅继续已确认的新环境。回滚应用前需协调恢复事务库、ClickHouse、制品及配置，不通过删表或重置补救。密钥由安装器生成，项目配置是用户唯一维护源。

## Phase 3 开发与验收

实现配置校验、样例、一键安装、只读检查、Core/Web 生命周期、凭据打包排除和中英文指南。用隔离 Compose 单独预部署数据库，通过正式安装入口验证 SQLite＋ClickHouse、PostgreSQL＋ClickHouse。覆盖初始化、重复安装、持久化读写、旧版副本、错误凭据、部分初始化及数据丢失拦截。openGauss 暂不真机验证；按用户选择不做浏览器验证。

## 本次启动验收结果

SQLite＋ClickHouse 与 PostgreSQL 16＋ClickHouse 26.8 均通过正式安装入口启动生产 Core/Web；Core 为事务 020、CH004/19表，登录页面 HTTP 200。PG 在 Docker 恢复后再次通过启动入口；应用停止后数据库仍健康。用户最终要求仅打通启动，全量测试已停止；未进行浏览器验证，不将启动成功等同所有业务功能验收。既有可选 Benchmark 数据集自动准备仍有告警，不阻止 Web 启动。
