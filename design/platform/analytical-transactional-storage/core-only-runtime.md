# 唯一存储运行架构

## Phase 1：需求与边界

应用唯一运行方式为 Storage Core：SQLite、PostgreSQL、openGauss 三选一承载事务控制，ClickHouse 承载分析事实。沿用事务迁移 020、ClickHouse 004 及核心表字典，不修改已发布 DDL。Web、采集器及后台任务不得打开旧业务数据库，关闭开关、依赖异常或缺配置不得恢复旧模式。旧数据库仅作为显式离线迁移输入。

保持原界面和接口语义，Trace 列表服务端分页，Span 每批最多 500 条，滚动追加，正文按需读取，加载提示不包含数量。

## Phase 2：设计

- 运行模式固定为 Core；旧 core 标志仅作兼容输入，其他非空值拒绝。事务连接信息只属于 Core，Web 只持有回环 Core origin 和控制器凭据。
- 控制仓库仅暴露固定 kind、受控事务及必要生命周期方法；未登记的模型、原始 SQL 和 Prisma 扩展接口拒绝，不代理旧客户端。
- Trace、评测、数据集、诊断、Infra、语义与用量使用已有 typed Core API。静态资产、设置、客户端控制使用 platform_control_records 的固定字段契约；不得以通用 JSON 存回分析事实。
- 事务库保存 ACL、路由、修订、回执、Outbox、选择及发布水位；ClickHouse 保存 Trace/Span/正文、样本、评测、统计、Infra、语义与用量事实。制品目录仍用于字典规定的资产与可靠投递，不成为查询降级库。
- 启动检查事务 schema、ClickHouse schema 与可达性；健康接口报告依赖故障。暂时故障保留已持久化的 Outbox，查询不返回假空结果。投递、删除屏障与权限检查沿用现有领域实现。
- 开发、生产、容器入口停止创建和同步旧业务 schema；构建期生成历史 DTO 类型不构成数据库连接。旧 schema 只服务离线迁移与历史格式验证。
- 离线迁移保留一致快照、owner/旧 ID 映射、制品 hash、检查点与验证报告。切换后新增写入必须先处置才能恢复旧部署，不提供在线双写或旧模式回退开关。

### 远程功能的 Core 适配

- Agent 运行时偏好保存在既有用户设置事务记录，新增路由复用 Core 请求身份与权限范围。
- 模型协议随冻结配置传递并纳入连接摘要；OpenCode 与直接评测均保留自定义鉴权和协议选择。
- 内置示例不再自动注入。启动清理通过既有私有 platform-control 命令，限定实际 owner，使用事务删除标记、数据集生命周期与 Trace 删除屏障；不改动历史迁移输入和制品。
- Span 导航复用滚动容器；网络追加前暂停自动跟随，避免触底后连续拉取全部分页。
