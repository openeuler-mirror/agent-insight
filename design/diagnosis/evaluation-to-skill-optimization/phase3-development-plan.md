# 评测 → 智能诊断 → Skill 优化：开发计划

方案已确认，按以下阶段实施；验收记录见文末。

1. **契约、迁移与快照**：先准备旧版本数据库基线、版本化增量迁移、预检/对账与恢复工具，再补充 DiagnosisRun 和计划来源引用；实现输入解析、归属校验、执行 attempt 解析、规范化哈希及幂等。现有 Trace 入口保持兼容。功能开发与迁移验证一起交付，不能把数据迁移留作上线时临时处理。
2. **评测进入诊断**：ExperimentCaseDetail 增加结果勾选和输入确认；诊断 runner 接入评测资料，新增 run 状态查询与缓存隔离。
3. **诊断进入优化**：AgentDebugCard / 新 run 页面增加发现选择、归因与 Skill 版本确认；适配到 SkillOptPlan，扩展来源枚举和溯源展示。
4. **复测闭环**：复用候选优化、来源实验复测和发布校验；展示证据链、前后配置差异和结果。
5. **验证与指南**：完成专项测试与全量 `npm run test`；同步中英文评测操作、智能诊断操作、Skill 优化操作与 API/架构文档。不因一般功能变更修改 developer-index。

## 必须验证

- 输入结果与 Trace/attempt 对应；不能误传评估器 Trace。
- 评分缺失、人工改分、重评、相互矛盾评估器结论进入正确快照。
- 相同输入复用、显式重跑、连续点击与跨用户请求隔离。
- 智能诊断和 Skills 核验部分失败、服务重启、迟到回调不污染新 run。
- 未完成报告、无证据发现、环境问题、未知 Skill 与版本漂移有明确限制。
- 优化计划来源完整、冲突需确认、候选不污染正式版本、复测不会修改基线。

## 数据迁移验收门禁

迁移专项测试必须使用独立临时数据库，禁止测试命令指向用户真实数据库。除最小测试数据外，在受控隔离环境以部署库一致性副本演练；记录实际数据规模、迁移耗时、锁定时间、所需磁盘空间和逐表对账结果，不将生产业务原文写入测试日志或仓库。

| 场景 | 验收要求 |
| --- | --- |
| 空库初始化、旧库升级、已升级库重复执行 | 表结构正确，重复执行无重复行、无旧值变化 |
| 历史实验、Case、多个执行 attempt、机器与人工评分 | 原主键、字段值、时间戳、关联完全保留，页面选择同一执行 |
| 历史诊断报告、Skills 核验、会话、优化计划与候选/正式版本 | 内容及资产哈希不变，旧入口可读，新入口识别缺失信息 |
| null 版本、空 JSON、长报告、多用户、软删除与既有异常 | 不补造信息、不跨用户合并、不恢复软删除行；异常有预检结论 |
| 迁移中断、锁冲突、磁盘不足、应用启动 schema 同步 | 安全停止或恢复，无半迁移状态对外服务，无隐式重置 |
| 升级失败后恢复备份 | 数据、schema、资产、应用版本一致，历史业务可读取 |
| 已产生新数据后回退应用 | 新旧数据均保留，新增来源可兼容，启动不删除扩展 schema |

提交验收证据包括：迁移版本、实际数据库路径确认、备份与恢复校验、迁移前后每表记录数/主键集合/全部原字段摘要、关联和资产检查、差异清单、功能冒烟结果。所有差异必须解释并符合设计；不符合预期则禁止上线。全量 `npm run test` 不能替代生产副本迁移演练。

## 浏览器验收（实施后需用户确认启动）

通过 `bash scripts/develop_start.sh` 启动，验证 golden path：选评测结果 → 确认输入 → 诊断 → 选择发现 → 生成/确认计划 → 候选 → 复测。至少验证无 Trace 和 Skill 版本冲突两个边界，记录截图、网络失败与 console。原型中的示例数据不作为真实验收证据。

## 后续扩展

实验级批量诊断先分 Case 运行，再聚合相同根因；无 Trace 结果级分析使用单独能力标识；多 Skill 发现按目标拆分优化计划。三者均不隐含在首期交付中。

## 本地验收记录（2026-11-03）

- 使用独立临时数据库，浏览器走通 Case 结果勾选、输入预览、诊断报告、Skill 基线核验、生成待确认优化计划；未记录 Skill 调用时没有生成计划入口。诊断报告使用明确标记的固定验收数据，未宣称模型在线生成通过。浏览器未记录 console 异常。
- 对本地存量库的一致性副本迁移演练：88 张历史表、625 行历史数据逐表逐原字段摘要一致；重复执行和恢复备份验证通过。未迁移远程部署库，远程升级仍必须单独备份和演练。
- 自动化专项覆盖输入变化拒绝、未知版本人工核验、已知基线漂移、无 Skill、跨用户访问、草案导入幂等、服务中断状态、异常 schema 回滚和外键异常拒绝。
- 真实模型生成候选及真实 Worker 同配置复测尚未端到端验证；生产规模、磁盘不足和迁移进程强制中断演练未完成，不作为上线验收通过项。

最终全仓测试共 4643 项：4575 通过、43 失败、2 取消、23 跳过；失败名称与未修改 HEAD 在同环境复跑结果完全一致。本功能新增快照/迁移/复测专项通过。类型检查仅剩既有测试 `access-install-presentation.test.ts` 的 Router mock 缺少 `bfcacheId`。
