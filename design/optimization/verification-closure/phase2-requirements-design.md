# 方案与自检

## 实现方案

1. 将行为非回归与目标验收分开。每个用例不允许掉分；来源评估器判 fail 的用例要求候选明确 pass，0 分且没有明确 verdict 的结果视作验收证据不足。保留评分摘要/缺失评分点供最多既定次数的定向修复，不重新运行旧版。修复耗尽后保存失败状态与证据，不能显示通过。
2. 复用现有 Experiment.configSnapshotJson 保存版本化验证证据：候选完整哈希、来源实验配置/用例摘要、覆盖范围、结果与可确认的 Issue ID；用现有 optimizationRecordId/retestExperimentId 建立双向关联。收尾核对最终候选哈希，静态修复改变内容后不能继承旧证据。只有完整、可比、通过的覆盖可标记 retest_passed；部分覆盖保留 pending_retest。复测入口验证当前候选、数据、评分配置、结果和取消状态后复用已关联结果。
3. 计划 applied 只表示修改已应用，不代表问题已解决。动态问题按已通过用例对应的原始 Issue ID 关闭，不跨未测用例按 dedupKey 批量关闭；静态问题仅在完整静态结果中同一稳定 ruleId 消失时关闭，缺少稳定对应关系时保留待确认。无计划的定向轮次也执行同一证据判断。
4. 前端明确区分定向诉求与全部问题优化；现有 chat API 增加可选范围字段，定向模式丢弃隐式全量 Issue，不改变已有显式 Issue 调用的默认含义。每次优化使用新 Agent 会话、同一候选工作区，携带既往用户约束，避免携带原始长工具历史；修复轮仅携带本轮失败证据。优化工作区内的工具钩子将过长 bash 输出保存为文件，返回有标记的头尾摘要及读取路径；提示测试输出断言、计数与少量样本。
5. 评分重试不因业务 fail 重试；保持现有异常重试策略，将每次失败的脱敏分类、耗时、重试决定写入已有 evidenceJson，并在实验结果详情展示。
6. UI 区分待验证、验证失败、部分覆盖和完整通过，展示复用证据链接。保留人工发布既有能力，不擅自增加审批或发布门禁。

## 自检

- 无 Prisma 变更、无新 API；证据从服务端持久化记录读取，不信任客户端传入通过标记。
- 旧版真实零分可复用，但目标验收不能以非负差值替代。纯回归场景不凭空要求 100 分。
- 原实验已通过的用例仍需保持不退步；对明确 fail 的来源用例要求 pass，不把正常 fail 当传输失败。
- 部分覆盖、取消、失败、无结果、配置或输入变化均不能成为可复用的完整通过证据。
- Issue 关闭仅覆盖本轮证据，不能关闭 backlog 或未执行同类用例。保留旧记录，不追溯修改历史问题状态。
- 工具全文落在优化私有工作区，明确告知截断及获取路径；不对业务被测 Agent 的输出做截断。
- 全量测试与类型检查串行，避免此前 8GB 环境并行检查引起的超时；真实模型 E2E 使用独立测试数据。

自检结论：按上述边界实施。按用户最终要求撤回 reference/ 兼容，保留标准 references/ 目录。

## 临时行为实验生命周期

优化自动创建的行为校验实验在任务结束（成功、失败或确认取消）后自动软删除，保留内部结果行用于原有证据哈希复核。清理前必须完成候选关联与问题闭环；仅处理同用户、同优化记录、同 Skill 版本且带 verificationOnly 标记的终态实验。正式复测明确标记 verificationPurpose=retest，不自动清理；未标记 purpose 的历史校验仅在创建时间位于关联优化任务创建至收尾时间之间时清理，避免误删优化结束后手动发起的历史复测。运行中及停止未确认时跳过。

同一事务写入实验 deletedAt、优化记录 verification-cleanup ID 清单及清理提示，并清空指向已删除实验的 retestExperimentId。验证查找只允许该清单中的内部软删除证据参与复用，原有候选、来源、数据、配置、结果与取消状态检查全部保留。手动删除不会获得此内部归档资格。UI 保留摘要与清理说明，不展示失效链接。此方案无需新 API、数据模型变更或额外 LLM 调用。

自检：来源实验与其他用户记录不受影响；多轮临时实验全部清理且操作幂等；清理失败不改变优化结果，事务回滚以便重试；测试覆盖清理后零调用复用、篡改失效、正式复测保留、失败与取消、运行中保护及浏览器展示。
