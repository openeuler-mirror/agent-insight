# Skill 待验证版本发布：需求分析

## 背景与目标

当前优化候选发布会立即创建正式版本并切换 `Skill.activeVersion`，诊断来源候选还要求先完成平台同配置行为复测。实际使用中，用户可能需要先取得一个稳定、带正式版本号的 Skill 包，在自己的 Agent、模型、数据和依赖环境中完成行为验证。

本需求把“创建正式版本”和“确认行为有效并激活”拆开：候选通过发布前质量门禁后，用户可在 Skill Copilot 会话结果卡片中发布为待外部验证版本；发布不切换当前激活版本。用户下载该版本 ZIP 完成验证后，在同一卡片登记通过或失败；只有通过后才能激活。

## 范围

1. 优化候选通过候选完整性、结构与脚本、适用的脚本真值和静态质量门禁后，显示“发布待验证 vN”。
2. 发布创建不可变 `SkillVersion`，记录外部验证待完成，不修改 `Skill.activeVersion`。
3. 会话卡片在发布后提供完整 ZIP 下载、验证通过、验证失败和激活入口。
4. 验证结果关联正式 Skill 版本，记录操作者、时间和可选说明；失败版本保留并可继续优化。
5. 平台行为复测继续可用，但不再是外部验证模式下创建正式版本的前置条件。

首期不上传用户本地日志或任意附件，不自动判断外部验证是否真实执行，不允许待验证或验证失败版本通过普通入口激活。

## 术语

- **发布前质量门禁**：候选完整性、结构和脚本检查、适用的脚本真值检查、静态质量评估及内容快照一致性。
- **待外部验证版本**：已经进入正式版本历史、可以下载，但尚未确认行为质量且未激活的版本。
- **激活版本**：`Skill.activeVersion` 指向、默认执行会选用的版本。

## 关键规则

- 发布不等于验证通过，也不等于激活。
- 同一候选重复发布必须幂等；基线版本或候选哈希变化时返回冲突。
- `not_applicable` 可以通过条件门禁；执行异常或未完成不能伪装成通过。
- 旧正式版本视为历史兼容版本，不因新增字段变成待验证；新外部发布版本从 `pending` 开始。
- 验证失败不删除版本，也不回退当前激活版本，因为发布时本来就没有切换激活指针。

## 验收标准

- 前置质量通过而行为验证未运行时，会话结果卡片显示发布按钮。
- 发布 v1 后，v1 可下载且 `activeVersion` 仍为 v0。
- 下载包内容与候选质量快照哈希一致。
- 待验证和验证失败版本不能通过普通激活接口激活。
- 登记通过后可以从会话卡片激活；登记失败后提供继续优化提示。
- 刷新页面后卡片能从持久化记录恢复发布、验证和激活状态。
- 跨用户、错误 Skill 名称、错误版本和过期候选均被拒绝。
