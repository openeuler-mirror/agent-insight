# Skill 待验证版本发布：开发计划

## 实施阶段

1. 扩展 `SkillVersion` 验证摘要字段并生成 Prisma Client；准备旧库无损 `db push` 验证。
2. 重构优化候选发布服务，使外部验证模式只创建版本、不激活；补充版本验证与受门禁保护的激活服务。
3. 新增按 Skill 名称的验证和激活 Route Handler，旧激活路由复用统一门禁。
4. 扩展优化记录投影，将正式版本验证状态、当前激活版本和 Skill ID 提供给会话卡片。
5. 按选定高保真方案改造 `OptimizationResultCard` 和发布确认弹窗，加入下载、登记结果和激活交互。
6. 更新中文优化操作指南、版本管理指南、API 参考和工作原理说明；英文参考同步契约变化。

## 自动化验证

- 发布：前置质量通过、诊断来源无平台复测、重复确认、版本冲突、哈希变化、跨用户和目录冲突。
- 状态：发布后版本为 `pending`、优化记录为 `published`、原 `activeVersion` 不变。
- 验证：通过、失败、结果更正、非法结果、超长说明、错误 Skill/版本和跨用户。
- 激活：`pending/failed` 被拒绝，`passed/not_required` 允许，旧 ID 路由不能绕过。
- UI：会话卡片各状态文案、发布请求参数、下载地址、验证与激活按钮条件。
- 完成后运行 `npm run test`；类型检查作为补充。浏览器 dev server 验收按仓库约定另行征询用户。
