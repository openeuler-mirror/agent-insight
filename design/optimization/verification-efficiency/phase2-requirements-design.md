# 方案与自检

## 方案

不增加数据库表或 API。建立行为用例策略、持久化校验证据和静态评估的本轮结果传递。

1. 结构检查先行。只从用途匹配、具备评分依据的用例中选择，默认上限仍为 5。关联实验用例优先；有完整来源实验时复用旧版逐用例评分，通过现有 executeSkillCaseOnClient 接口只执行候选，保留原客户端、模型和冻结的自定义评估器；校验 Skill 快照、用例输入和标准答案、完整评分及取消状态。无法匹配则明确待原实验复测，不另外执行不具可比性的本地用例。
2. 对无 rootCauses 但有标准答案的用例，将标准答案作为一个明确评分要点。无有效标准跳过；评分服务错误作为未完成处理。
3. 旧版校验结果按用户、完整 Skill 文件、输入/评分要点、运行及评审配置、环境证据做内容寻址，在数据目录持久化。有效分数直接复用；评分规则变化时只重评已有输出。无法证明输入环境稳定时不跨轮复用。保留原有用例数量，避免减少覆盖换速度。
4. 静态检查结果由检查修复步骤传给收尾，按用户、会话、版本、内容哈希和评估器版本校验。只有成功结果且内容一致可复用，修复变化或评估失败重跑。
5. 校验结果携带 skipped/incomplete 和实际测量/复用数量，前端实时与刷新恢复共享文案。不用绿色已通过表示未执行行为验证。

## 自检与权衡

- 版本号、caseId 不足以代表相同内容，禁止作为唯一缓存键；认证密钥不落缓存。
- 原实验在外部客户端上运行，且使用自定义评估器，不能复用它的数值与默认本地判官对比。缺少可比上下文时诚实提示原实验复测。
- 保留顺序执行；任意用例可能写共享目录，并发会造成污染。主要收益来自消除重复工作，不盲目提高并发。
- 未执行、基础设施失败、预算不足、无评分依据与真实 0 分分开记录。
- 缓存不存失败/取消结果；检查输入文件前后内容，执行改变输入则不缓存。
- 静态结果只在当前收尾流程内传递，不做跨配置、跨用户的全局缓存。
- 无脚本/真实输入时不进行模型断言推导；有条件才进入脚本真值门。
