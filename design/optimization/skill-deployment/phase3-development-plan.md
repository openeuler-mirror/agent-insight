# 优化后 Skill 下发：开发计划

## 阶段

1. **模型与纯契约**：新增来源、部署和事件模型；实现版本来源解析、状态机、幂等和 payload 安全校验；准备独立临时数据库迁移测试。
2. **制品与服务端 API**：实现确定性制品、短期引用、preview/create/status，接入现有用户鉴权和正式版本门禁；失败重试重新走 preview/create 并使用新幂等键。
3. **客户端公共执行器**：扩展能力和命令白名单；实现本机来源注册表、下载校验、持久备份、原子替换、版本账本、失败恢复和结果上报。
4. **框架适配**：完成 OpenCode 端到端和 Pi 来源上传；xiaoO 只在 Hook 参数确认实际 `SKILL.md` 时登记来源；JiuwenSwarm 使用用户全局目录并返回重启提示。
5. **界面与文档**：已发布优化记录增加预检、确认和进度；历史正式版本复用同一 API，下发旧版本形成 downgrade；同步中英文 optimization/platform 操作、参考和解释文档。

## 测试

- 模型/API：跨用户拒绝、未发布版本、复测门禁、幂等、离线、命令过期、来源与客户端不匹配。
- 制品：路径逃逸、符号链接、超限、哈希变化、相同版本不同内容。
- 公共执行器：首次安装、v1→v2、v3→v1、重复下发、legacy 备份、备份后失败、刷新失败、验证失败和恢复失败。
- 框架：OpenCode 原项目路径；Pi 实际 `filePath`；xiaoO 无来源阻断；JiuwenSwarm 默认和自定义数据目录、重启提示。
- 迁移：旧库升级、重复执行、原字段逐项一致、索引/外键检查和恢复演练。
- 完成后运行 `npm run test`；浏览器验收按仓库约定另行确认后使用 `bash scripts/develop_start.sh`。

## 交付顺序与完成定义

公共模型和协议完成后，以 OpenCode golden path 作为首个垂直切片。只有真实来源、备份版本、目标版本、哈希验证和失败恢复全部有自动化证据才视为框架完成；仅能写目录不算完成。JiuwenSwarm 首期以安装后内容哈希和版本账本为完成条件，并显式提示重启；Pi/xiaoO 必须从 Trace 来源解析目标，不能用配置默认路径代替。
