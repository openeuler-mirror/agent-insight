## 实际例子

原生 Skill 先生成 Trace，再用该 Trace 做无参考评测和诊断，定向优化后重跑。

## 资源

fixtures/trace_root_ssh.py；trace-only-contract.mjs 生成最小 Skill。 专用资源使用虚构或已审查的测试内容；密钥仅从外部文件注入，运行产物不写入本目录。

基线明确约定脚本非零退出时转述 stderr、停止分析，不生成推测结果；JSON 标准输出兼容 ASCII 编码，解析后的 Unicode 事实不变。这样本例的优化可以集中在追加摘要，避免静态修复额外补充基线错误处理。仍严格要求原有 SKILL.md 为候选的完整前缀，脚本和资源逐字保留，不降低候选实际复跑的事实、证据和评分要求。优化等待最多 15 分钟，并受整例截止约束。

## 操作与断言

详细可执行步骤见同目录 `scenario.mjs`；每个 `stage` 给出预期并保存实际结果。无新增数据集；原生 Skill 绑定、核心步骤覆盖、诊断锚点、候选及旧版保留。刷新重开优化记录时，确认相同快照和“前置质量通过，可发布”状态；候选业务执行和评测仍独立验证，不把该前置质量状态视为行为验证通过。

成功输入下，只有正式流程中由实际脚本结果排除的错误分支可记为不适用。检查支持“退出码为 0”的假分支，以及“退出码非 0”的真分支两种等价表达，并核对分支步骤身份；条件组也可只按退出码区分成功／失败，不要求分支说明重复“JSON 有效”；真实脚本 JSON、证据和分支步骤身份仍须有效。不适用不计为核心动作通过，核心动作的 partial／missing 仍失败。
