## 运行

先安装项目依赖，再安装此独立测试包：

```bash
npm ci --prefix tools/core-e2e
node --test tools/core-e2e/*.test.mjs
node test/e2e/run-case.mjs --case 001 --key-file /absolute/path/to/deepseek-key.txt
node test/e2e/run-case.mjs --case 002 --key-file /absolute/path/to/deepseek-key.txt
node test/e2e/run-case.mjs --case 003 --key-file /absolute/path/to/deepseek-key.txt
node test/e2e/run-case.mjs --case 004 --key-file /absolute/path/to/deepseek-key.txt
node test/e2e/run-case.mjs --case 005 --key-file /absolute/path/to/deepseek-key.txt
```

本地验收使用 Node 23.10.0（入口依赖 `node:sqlite` 与内建 TypeScript 类型剥离），复现包会记录实际运行版本。默认用本机 Chrome；CI 可先在此包目录执行 `npx playwright install chromium`，再设置 `E2E_BROWSER_CHANNEL=chromium`。普通执行使用测试缓存中固定的 `@opencode/cli@2.1.4`，不存在时自动安装；RAS 执行使用根依赖中的 `opencode-ai@1.14.39`。Python 默认 `/opt/homebrew/bin/python3`，其他机器用 `E2E_PYTHON` 显式指定。

模型固定 `https://api.deepseek.com` 的 `deepseek-flash`。密钥由进程读取：001/003/004/005 通过产品页面保存到专用应用，002/003/004/005 写入专用客户端的受限配置；不提交到仓库、不写入共享报告。测试不会从真实依赖失败后回退到 Mock。`OPENCODE_DISABLE_MODELS_FETCH=true` 只关闭额外的公共模型目录下载；DeepSeek 业务调用仍真实发生。

## 001 实际验证范围

1. 选择独立空闲端口，通过 `AGENT_INSIGHT_PORT` 传给 `scripts/develop_start.sh`，启动独立数据根和当前 schema SQLite；不会停止 3000 端口上其他工作区的应用。
2. 页面用唯一邮箱登录并刷新验证会话；真实测试并保存模型，再检查默认配置和持久化。
3. 从安装页取得当前账号命令并校验服务地址、框架和归属；从产品组件接口取得原生插件/上传器。
4. 使用正式安装模块准备常驻客户端与 FI；通过正式安装令牌/注册接口绑定，前台启动真实客户端，核对服务端及页面的 ID、在线、版本、模型、执行能力。
5. RAS 端安装真实 Python 运行时，通过 OpenCode 内嵌 Bun 调用生产 `python_bridge` 完成真实 inproc Python 初始化及 RAS `hello/bye`。两种 OpenCode 各执行一个真实 DeepSeek 短探测，检查 assistant 输出和原生 sessionId。
6. 准备后续场景的独立账号、原日志及内置 Case/Skill v0；不执行后续五个业务场景。
7. 保存结果后停止本轮客户端、应用及已跟踪子进程；不注册或停止用户的全局后台服务。

**安装边界：** 当前产品安装器即使 `--no-start` 仍会注册固定 launchd 服务，因此本测试用相同产品组件安装函数和正式注册协议进行准备，再以前台进程承载。全局 systemd/launchd 注册、重启、自启动不在本场景结论内。未修改产品安装器，也未用虚假的心跳/能力上报替代客户端。

## 报告与复现

结果位于 `exclude/core-e2e/<runId>/report.html` 和 `report.json`。首页六行，本轮选定场景展开每阶段预期、实际及失败原因；其他五例明确未执行。重复 runId 拒绝覆盖，原始失败保留。

单例复现命令就是上述 `--case 001`、`--case 002` 、`--case 003` 、`--case 004` 、`--case 005` 或 `--case 006` 命令，使用新的 runId 可保留每次尝试。报告记录产品 SHA、场景代码哈希、运行时版本、插件哈希、输入哈希和独立端口。新环境依赖没有下载成功时会失败退出，不将缺项算通过。

`model.png` / 客户端截图已遮挡输入和安装命令。`private/` 中的原始 Playwright trace、配置、安装和模型日志可能含凭证，目录为 700、文件为 600；不打入共享报告或公开工件。分享时仅提供脱敏 JSON/HTML 和截图。

`npm test` 是独立检查，失败、跳过和人为中断单独记录，不能用 E2E 通过抵扣。选定场景的阶段全部满足且清理完成才给 PASS；001/002 不证明 RAS 故障检测恢复通过，后者属于 006。

已有独立 npm 结果时，可用代码重新生成汇总和覆盖说明，过程不调用模型：

```bash
node test/e2e/report.mjs --run-dir exclude/core-e2e/<runId> --npm-result /path/to/npm-result.json
```

`npm-result.json` 记录 `observedSummary`（tests/pass/fail/skipped/cancelled）、`interrupted`、`fullSuiteComplete`、`countsAreLowerBound`。中断结果始终显示不完整，不允许按失败数为零或部分日志声称整套通过。

1. 每轮独立账号、数据库、端口、DeepSeek 配置及普通客户端；原包上传 U 保留 13 文件校验。独立生成会话 G 通过产品附件入口接收固定参考脚本，并真实生成两文件 Skill。

3. 静态评估必须真实完成并展示有效分数/意见。**生成稿**的实际发布分支依据文件就绪和生成完成，额外静态意见单列；不把模型给出的意见误当成该分支的发布接口拒绝。实际评估执行失败仍失败。优化候选继续遵守产品自身的候选质量/行为验证和发布条件；完整候选验证即使因分数相对下降被标记 retest_failed，也按预定≥80与事实/JSON真值检查，并单列产品的比较结论，不依赖不存在的复测按钮。
4. 一条私有行为 Case 贯穿基线、最终候选及发布版。Playwright 在正式四步向导选择指定 Case、客户端、模型和唯一任务完成度评估器。代码核对实际加载的 SKILL.md、全部执行文件快照、真实工具、量化事实、日志证据和新增 JSON，完成度至少 80。
5. 产品自动归档临时验证实验时，以 Node 内置 `node:sqlite` **readOnly** 核对本轮独立库的用户、候选、来源、配置、Case 和评分记录哈希，再通过正式只读 API 核对真实 Trace；不写库、不构造 Trace。验证发布版重跑、旧版逐文件保留及刷新后重开结果。
6. 整例不自动重试；新 runId 永不覆盖原报告。优化等待最多 8 分钟，实验等待最多 5 分钟。macOS 在本轮执行进程存活期间使用 `caffeinate` 防止空闲休眠，清理时释放，不修改系统持久配置。Linux/服务器不启动该工具。
7. 两轮连续验证必须使用同一测试代码和参考夹具、不同账号/数据库/原生会话。两次通过只证明已观察到的连续结果，不代表模型和网络永远无波动。
