For automated Benchmark integration, load the complete [benchmark-onboarding Skill](../../../skills/benchmark-onboarding/SKILL.md) and provide the target Agent Insight repository URL (or local path) and official Benchmark source. The package includes a versioned protocol snapshot with source commit and file digests, validation scripts, templates and tests; run records remain outside the installed Skill. Read the snapshot, compare it with the target repository using `protocol-check.cjs`, record differences and adapt templates before implementation. The target repository remains authoritative; available Agents, Git sources, collectors and deployment readiness are discovered at runtime. A matching snapshot does not prove readiness. Acceptance proceeds through endpoint contract tests, real execution/evaluation segment tests, then a fresh end-to-end run. Discover actual endpoints and identities, wait for business terminal states, correlate Case/Run/Artifact/evaluation identities and digests, and verify cleanup on success and failure. The generated driver enforces prerequisites; the generic CLI does not infer these dependencies. When a material decision remains unresolved after inspecting project and official sources, the Agent discusses the facts, options, trade-offs and recommendation with the user. Existing decisions remain valid; independent work continues while dependent steps wait. Record decisions and re-freeze affected plans; silence is not consent. Dataset acceptance must read and parse actual files or objects, verify persisted database or index records, compare their transformed contents and resource references, and test repeated imports and recovery from failed imports in an isolated dataset. Discover storage locations and contracts from the target project; record installation scope, real versus mocked evidence, and equivalent checks for other storage types. Missing access or evidence blocks acceptance. Acceptance requires frozen official scoring comparisons and required live checks, not just generated code or fixture tests. See the [Chinese onboarding guide](../../zh/how-to/evaluation/benchmarks/onboard-custom-benchmark.md#21-使用自动接入-skill) and [CLI usage](../../../skills/benchmark-onboarding/references/usage.md).

During Skill optimization, scrolling up pauses automatic output following, including progress and completion updates. Scroll back to the bottom to resume. See the [Chinese Skill optimization guide](../../zh/how-to/optimization/skills/optimize.md).

Before checking Benchmark execution targets, verify the signed-in account and its dataset/client visibility. An empty list may reflect account scope; an online client or selectable target does not prove environment readiness or deployment of new integration code.

OpenCode compatibility: updated Agent Insight resident clients support Skill snapshot isolation and read-only trigger analysis on OpenCode 1.x and 2.x (native validation: 2.1.4). Skill case generation and A/B require snapshot capability; trigger analysis additionally requires routing capability. If capabilities are missing, check the resident client version and reported capabilities; upgrading OpenCode alone is insufficient. See the [Chinese execution guide](../../zh/explanation/evaluation/skills/overview.md#opencode-执行兼容性).

Skill experiments display “Waiting for Trace ingestion” after the Agent finishes. Ingestion has a separate 60-second deadline; a timeout retains the Trace ID and does not automatically rerun the Agent. Check the collector and uploader before retrying.

Full-suite prerequisites: install the Python dependencies declared by both RAS packages, provide `pwsh` and `sqlite3` on PATH, and build the Trae collector with `npm run compile --prefix scripts/trae-collector`. Set both `AGENT_INSIGHT_RAS_PYTHON` and `RAS_PYTHON` to the prepared Python interpreter so isolated installer tests retain access to it. Use a separate SQLite database initialized with the current Prisma schema and an isolated `AGENT_INSIGHT_HOME`.
