入口：**运行观测 → Token 与任务分析**（`/task-insight`）。

页面只统计 `isSubagent=false` 的 root trace。root 行 Token 已包含子 agent，按 root 汇总可避免子 agent 行重复计数。统计周期可选 7 天、30 天、90 天或全部；时段固定按 `Asia/Shanghai` 展示。

## 页面能回答什么

- **Token 花在哪里**：按任务类型、用户和单条任务拆分 Token 与估算成本。
- **用户在用 Agent 做什么**：把 query 归为问答、文本处理、文档分析、代码任务、批处理、多步工具任务和其他。
- **哪些是长时任务**：综合耗时、Token、工具调用次数和 LLM 调用次数判定。
- **哪些可以放到晚上**：长任务默认视为可延后，出现实时要求时除外；页面给出夜间窗口、可延后任务量和可释放的日间累计耗时。

## 任务类型判定

分类优先看 query 内容，内容信号不足时才看工具调用行为。因此“修复 TypeScript 报错”即使调用很多工具，仍归为代码任务；没有明确内容类型的搜索、抓取、外部动作任务才归为多步工具任务。

| 类型 | 典型信号 |
| --- | --- |
| 问答 | 为什么、如何、是什么、介绍、解释、区别 |
| 文本处理 | 翻译、改写、润色、校对、文案 |
| 文档分析 | 文档、报告、PDF、表格、总结、提取、数据分析 |
| 代码任务 | 代码、报错、修复、调试、编译、单测、脚本、仓库 |
| 批处理 | 批量、批处理、遍历、逐个、所有文件 |
| 多步工具任务 | 搜索、检索、浏览、抓取、下载、调用接口、执行命令，或工具/LLM 调用次数较高 |
| 其他 | 未命中以上信号 |

## 长时与可延后

满足任一条件即判定为长时任务（默认值）：

| 维度 | 默认阈值 |
| --- | --- |
| 墙钟耗时 | ≥ 2 分钟 |
| 总 Token | ≥ 100,000 |
| 工具调用 | ≥ 10 次 |
| LLM 调用 | ≥ 8 次 |

可延后规则：

- 短时任务不计入可延后。
- 长时任务出现“立即、马上、今天必须、尽快、实时、ASAP”等实时要求时不建议延后。
- 长时任务出现“晚上、夜间、稍后、明天、异步、后台”等词时标记为显式可延后。
- 其余长时任务默认视为可延后。

调度建议中的“累计耗时”是可延后任务的墙钟耗时之和，用于估算迁移后能释放多少日间同步等待；**迁移时段不会减少 Token 总量本身**。要降低成本，还需要结合模型路由、缓存复用和失败重试治理。

## 数据口径与限制

- Token 优先取 `inputTokens + outputTokens`；两者都为 0 时回退 `tokens`。
- 成本按模型单价估算；未配置单价的模型按 0 计，页面会列出缺失单价的模型。
- 单次最多分析最近 10,000 条 root trace；超出时页面提示截断，请缩短时间范围查看更早数据。
- 分类是可解释的规则匹配，不是 LLM 语义判断。词表与阈值集中在 `src/lib/task-insight/classify.ts`，可按真实数据迭代。

## API 参数

需要接入自有看板时，可调用 `GET /api/observe/task-insight`：

| 参数 | 说明 |
| --- | --- |
| `range` | `7`（默认）、`30`、`90`、`all` |
| `user` | 可选；未解析出用户时回退全量 |
| `longLatencyMs` | 可选，默认 `120000` |
| `longTokens` | 可选，默认 `100000` |
| `longToolCalls` | 可选，默认 `10` |
| `longLlmCalls` | 可选，默认 `8` |

响应中的 `thresholds` 为本次实际生效阈值，`truncated` / `maxTraces` 表示是否截断及上限，`pricingMissingModels` 表示成本估算缺失单价的模型。
