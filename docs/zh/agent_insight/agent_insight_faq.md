# 常见问题

## 页面无法访问

确认 `agent-insight.service` 正在运行、访问地址和端口正确，检查服务器防火墙及服务日志。具体命令见[安装与维护](./agent_insight_installation.md)。

浏览器访问的 `localhost` 指当前用户终端；AcTrail 接入命令中的 `localhost` 指执行命令的 Agent 主机。平台部署在另一台机器时，应使用该机器的可达地址。

## 接入后没有看到新 Trace

依次检查：

1. 接入脚本是否显示配置成功，AcTrail 及 `agent-insight.otel-http` 插件实例是否正常运行。
2. Agent 主机能否访问平台地址和端口。
3. 是否真的执行过一次 Agent 任务；仅配置插件不会产生业务数据。
4. 当前登录账号是否与接入命令的 API Key 对应。
5. 链路列表的时间范围、Agent 归属、主子 Agent 范围和搜索条件是否正确。

可以使用 **重置筛选**重新查询。列表的自动刷新频率不代表采集器的上报频率。

## 任务停止后仍显示执行中或显示成功

平台依据采集数据判断生命周期。没有结束信号的记录，在服务端连续 10 分钟没有收到更新后显示超时；后续有新数据可以恢复执行中。已经被采集器标记为结束的记录不再触发这条无更新超时规则。

成功是平台根据采集信息判定的执行状态，不表示任务答案一定正确。发生异常终止时，应结合工具错误、进程退出记录和最终输出复核，不能只看 Trace 顶部状态。

## 开启仅慢节点后仍显示 Agent 行

**仅慢节点（>60s）** 筛选事件行。Agent 行保留作层级上下文，本身不按这个开关过滤；子 Agent 能否显示还取决于父任务是否命中筛选、相关层级是否展开。详细规则见[链路追踪](./agent_insight_trace.md)。

## 工具没有输出或 Tokens 为空

先确认任务已经执行到对应步骤，并等待正文加载。平台只能展示采集器已上报的字段，字段为空不能直接解释为没有产生输出或没有消耗 Tokens。检查 AcTrail 插件版本、完整请求和工具结果导出配置，再核对原始任务记录。

## 查看全部后需要复制完整内容

在节点的 Input 或 Output 旁单击 **查看全部**，待内容加载后使用弹窗中的 **Copy**。在工具时间线事件详情中，输入与输出也分别有复制按钮。复制后可粘贴到本地文本编辑器核对，不要仅依赖按钮提示。

## 模型连接失败

连接测试由平台服务端发起。检查服务端网络、Base URL、模型名、模型 API 密钥，以及网关要求的自定义请求头。模型地址应按服务方说明填写，无需填完整的 `/chat/completions` 路径。平台接入 API Key 不能替代模型 API 密钥。

## 数据集已导入但没有生成评测结果

数据集保存样本和参考数据，不会自动运行 Agent 或创建实验。先采集实际 Trace，再在实验中选择 Trace 和评估器；按需从数据集匹配参考答案。

## 评估器不可选或实验评估失败

依赖参考数据的评估器要求所有已选 Trace 都有参考答案。数据集匹配按去除首尾空白后的输入文本完全相等处理，应核对标点、换行和输入内容。

评估失败表示评分流程没有正常完成，不等于 Agent 得到 0 分。先阅读失败原因并修复模型连接或数据问题，再对失败项执行 **重评**。操作步骤见[运行评测实验](./agent_insight_experiments.md)。

## 实验均分与部分样本的情况不一致

均分只包含评估成功且有数值分数的结果；失败、待执行及已完成但没有数值分数的项目都不按 0 分计入。人工修正后，统计使用人工分。请同时检查完成、失败、待执行数量，以及每个评估器的计入数量。

## 如何反馈问题

在 [Agent Insight Issues](https://gitcode.com/openeuler/agent-insight/issues) 中提供操作系统版本、`rpm -q agent-insight` 的输出、操作步骤、预期结果和实际结果。链路问题可补充 Trace ID 和经过脱敏的相关日志。

Trace、日志和导出文件可能含任务输入、模型输出及工具内容。提交前移除 API Key、模型密钥、账号和业务敏感信息。
