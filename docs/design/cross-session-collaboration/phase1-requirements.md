# 跨 Session 协作：需求分析

以 v0.9 的上报契约及用户 2026-09-17 确认的合并展示目标为验收基准。普通自定义协作仅调用 events 接口增量上报联系，端点自动成为协作节点，不要求预登记或绑定；无 Trace 仍可查看关系。有原 Trace 时按明确会话编号关联，fromLocator 只负责步骤查找。原始正文和存储父子关系保持不变，列表和详情按协作关系合并展示。

新增协作列表、协作图和节点/连线详情。保留重复联系、循环、多父级、消息传递，显示来源和定位证据，不推断任务完成。已有明确原生调用支持只读自动图，不要求补报事件。合并 Trace 是主验收入口，协作图用于补充查看全部联系。


## 2026-09-17 验收目标修正（用户已确认）
同一协作的原始 Trace 在链路列表合并为一条，详情包含全部成员。有 fromLocator 的关系按已解析调用步骤挂载 subagent；没有定位或无法确定唯一父级的成员并列展示，按 observedAt（缺失时为接收时间）排序；该排序不证明实际调用先后。循环、回传事件保留在协作图，不作为强制父子依据。保留原始数据与 source=raw 查询；合并读取不影响其他框架上报及 Goal Plus 专用投影。测试覆盖无需绑定、步骤定位、无定位、循环、多级及分页列表只保留入口。

Goal Plus 继续保留公开 binding/event 接入、已声明 worker 的列表隐藏与逐 worker 就绪合并；主 binding 或其他 worker 晚到不阻塞已就绪成员。历史 semantic 关联状态保留，普通 reported 身份歧义不使用历史 linked 状态兜底。自动化回归与浏览器验收分别记录，不将设计目标视为已经验证的结果。
