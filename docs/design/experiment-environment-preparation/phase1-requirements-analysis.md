# 实验执行环境准备：需求分析

本文记录设计目标；实施状态统一见[需求清单](../README.md)。前端交互、后端架构与接入契约见[需求设计](phase2-requirements-design.md)，实施顺序见[开发计划](phase3-development-plan.md)。

## 1. 背景与问题

当前选择 Pi/xiaoO 安装客户端时，`scripts/install-ras-client.js` 会调用 `services/executor/src/xgovernor/setup.cjs`，准备工具链并编译 xGovernor。首次准备可能需要几分钟，但安装链路跟踪插件的用户不一定执行 SWE-bench 实验。

执行环境准备应发生在用户确定本次执行需求之后。现有第二步「Trace 来源」已经包含主机、模型、执行参数和 Case 选择，点击该步骤的「下一步」是统一检查入口。

准备需求不只来自 Benchmark。普通数据集可能需要工作目录或依赖，可靠性数据集可能需要故障注入组件和权限。同一数据集选择不同 Agent、执行方式或模型，需求也可能不同。

## 2. 目标

1. 客户端安装以链路跟踪接入及必要的基础通信为职责，不因选择 Pi/xiaoO 就编译安装 xGovernor。
2. 用户完成第二步后点击「下一步」，统一检查本次执行环境。
3. 已满足要求时直接进入第三步；可自动解决时自动准备、复查，通过后自动进入第三步。
4. 需要用户在执行机配置时，在第二步底部给出原因及处理说明；用户完成后再次点击同一个「下一步」重新检查。
5. 不增加向导步骤、准备卡片、侧栏、详情入口或独立安装按钮。
6. 以数据集对应的接入实现为入口，结合 Agent 和执行上下文决定准备内容，便于新增数据集接入。
7. 具体检查与安装在执行端完成，公共组件供多个接入实现复用。

## 3. 已确定的产品决策

| 问题 | 决策 |
| --- | --- |
| 何时检查 | 第二步配置完成并点击「下一步」时；选择主机或修改字段本身不触发远程检查和安装 |
| 判断范围 | 本次实验配置、数据集及版本/内容摘要、主机、Agent、模型、执行方式、相关运行参数与 Case 范围 |
| 提示位置 | 第二步底部操作区、上一步和下一步按钮上方 |
| 已就绪 | 直接进入第三步，不展示通过清单或常驻「已就绪」框 |
| 可自动准备 | 自动执行，无额外安装确认步骤；准备并复查通过后跳转 |
| 耗时提示 | 只有实际进入首次编译等耗时动作时显示「首次可能需要几分钟」，普通检查和快速准备不使用该文案 |
| 需人工处理 | 提示具体主机、问题和必要配置方法，恢复编辑及下一步按钮 |
| 检查/准备期间 | 锁定第二步配置及向导切换，防止重复提交和上下文变化；等待结束后再继续 |
| 技术名词 | 默认提示不展示 xGovernor、Worker 等实现名；人工处理确实需要时可展示必要的组件名或配置位置 |
| 详情入口 | 不提供；必要的处理说明直接放在底部，技术诊断保留在现有日志体系 |
| 纯已有 Trace 评测 | 无执行需求时直接进入第三步；使用已有 Trace 作为输入但仍重新执行 Agent 的场景照常检查 |

## 4. 业务与代码边界

“以数据集为单位”表示根据所选数据集找到对应的接入实现，不表示每条数据集记录都要复制一份代码，也不表示可以仅凭数据集 ID 缓存就绪结果。

- 多份同源数据集可以复用同一个接入实现。
- 接入实现组合数据集公共要求与当前 Agent/执行方式要求。
- 平台准备服务与前端只处理统一流程，不按 SWE-bench、可靠性等名称编写安装分支。
- Benchmark 的环境准备属于其接入协议，具体实现放在对应接入包的 `executor/` 下。
- 其他数据集通过对应的执行端接入实现使用相同契约，不要求伪装成 Benchmark 或引入 Evaluator。
- 本需求属于跨实验执行流程；可靠性数据集作为调用方复用，不改变 Agent RAS 环内检测恢复架构。

## 5. 范围限制

- 不在选择数据集、主机或模型时提前启动准备。
- 不增加全局环境管理中心、任意 Shell 下发或通用软件包管理平台。
- 凭据、需要交互的认证及系统管理操作由用户在执行机处理；自动准备限于已有策略允许的非交互操作。
- 主机级组件准备与每个 Case 的镜像、容器和工作区准备分开，不要求第二步下载全部 Case 镜像。
- 不将 Evaluator 环境安装混入 Agent 主机准备。
- 检查通过代表所声明的执行前条件已满足，不承诺模型余额、网络及远端服务在整个实验期间持续可用。

## 6. 验收标准

| 编号 | 场景与预期 |
| --- | --- |
| AC-01 | 安装 Pi/xiaoO 链路跟踪接入时不触发 xGovernor 下载或编译，基础客户端仍可上线 |
| AC-02 | 仅选择或修改主机、模型等字段，不触发准备；点击第二步下一步才检查 |
| AC-03 | 环境已满足时直接进入第三步，无额外成功卡片或安装按钮 |
| AC-04 | 缺少可自动准备的组件时留在第二步，底部显示进度；安装与复查成功后只跳转一次 |
| AC-05 | 普通检查、快速准备与首次耗时编译采用不同提示，已安装组件不会重复显示首次编译文案 |
| AC-06 | API Key 缺失时指出执行机及处理方式，恢复按钮；用户修复后再次点击下一步重新检查 |
| AC-07 | 下载失败、离线、权限不足等显示实际原因，不统一误报为凭据缺失；失败后允许修改或重试 |
| AC-08 | 同一数据集切换 Pi、xiaoO 或 MCTS 后使用对应检查与准备要求，已满足的公共组件复用 |
| AC-09 | 普通数据集与可靠性数据集通过相同契约接入，通用准备服务没有数据集业务安装分支 |
| AC-10 | 需要准备的主机可选；协议不兼容、未授权或不支持所选 Agent 的主机明确提示，不能伪装为可准备 |
| AC-11 | 双击、网络重试、多标签页不会对同一共享组件重复编译；旧请求结果不能推动新配置进入第三步 |
| AC-12 | 纯已有 Trace 评测跳过检查；仍需运行 Agent 的 Skill A/B 等场景不能误跳过 |
| AC-13 | 客户端断连或重启后能核对任务事实，不将状态未知显示成成功，不盲目重复安装 |
| AC-14 | 新增数据集接入主要修改自身接入模块；出现新依赖时增加可复用实现，无需修改前端流程 |
