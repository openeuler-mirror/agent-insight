# 自建评估器 Prompt + Skills：开发计划

本计划描述设计对齐后的实施顺序，不代表已实现。执行状态只在[需求清单](../README.md)维护。

## 1. 配置与快照服务

- 扩展 `src/lib/evaluators/custom-evaluator-model.ts`，定义 library/local 两种来源的联合类型、绑定输入与运行快照；本地来源不伪造库版本。
- 增加库来源名称/归属/版本解析、权限检查，以及本地文件夹上传、严格相对路径校验与用户隔离临时凭证服务；本地导入不写 `Skill/SkillVersion`。
- 两种来源共用文件 manifest 和完整快照服务；内部复用版本目录解析，不复用会静默跳过文件的分析快照加载器。
- 实现内容摘要、原子发布、容量校验和已保存绑定复用；快照读取必须由评估器或实验授权关系定位。
- 扩展 `src/app/api/user-evaluators/route.ts` 与 `src/server/user_evaluators_storage.ts` 的校验、规范化保存和缓存失效；明确省略/空数组的更新语义。
- 实现 phase2 中的三个资产只读 API、本地导入 POST 与临时文件预览 GET；补齐过期临时文件清理，保留持久快照。公开 Skill 路径使用 name，不新增以数据库 id 为 key 的接口。
- 无 Prisma schema 迁移；不修改 CI、依赖、package scripts 或部署环境变量。

## 2. 评估器配置页面

- 在 `src/components/EvaluatorsCenter.tsx` 的创建面板增加 Skills 区域、添加菜单：复用 SkillManagementPicker 卡片式库版本选择、本地系统文件夹选择、独立只读文件预览和移除；本地更新通过移除后重新添加完成。
- 在 `src/app/(main)/metrics/evaluators/[id]/page.tsx` 增加相同能力；复用 Skill 选择与只读文件查看组件。
- 展示库来源版本或本地来源摘要，明确本地导入不自动加入 Skill 库；支持混合来源保存。增加保存后快照回读，处理源资产缺失、上传损坏、导入过期、跨来源同名、越限及保存失败；保留未保存表单供修正。
- 卡片保留原有评分灰框，Skills 数量以紧凑文字单独展示；不添加启停、权重或运行时选择。

## 3. 冻结所有评测入口

- 新增统一的自建评估器冻结服务，在任务创建时保存 Prompt、评分点和 Skill 绑定。
- 接入 `src/app/api/experiments/route.ts`、`experiments/eval-traces`、对比实验、Benchmark 和 Skill 工作台创建服务，保留各自已有配置快照。
- 接入 `src/app/api/eval/trajectory/run/route.ts` 的任务创建路径。
- 修改 `run-experiment.ts`，新任务优先且必须读取冻结配置，历史无快照任务按设计兼容且不获得新绑定 Skills。
- 检查 `reuse-config.ts`、watch/追加 Case、任务重启恢复及各类 retry 路径，确保不回源取最新卡片。

## 4. OpenCode 执行与结果适配

- 增加共享 `custom-evaluator-runtime.ts`，按 Skills 空/非空选择原有路径或强制 Agent 路径。
- 准备独立目录、校验并挂载文件、构建全部主指令段和 Case 输入文件。
- 复用 `opencode-manager.ts`、`opencode-client.ts`、并发槽及取消上下文；核验当前项目携带的 OpenCode 对 directory、Skills 和权限的实际支持。
- 接入 `judge-assembly.ts` 的评分点与输出要求，有 Skills 路径不调用默认直连 Judge。
- 为全局实验与旧轨迹入口分别适配结果；保留真实工具事件和平台生成的 Skills 元数据。
- 结果详情移除 Skills/工具展示；复用已有链路页，仅在 Agent 实际会话成功落库且当前用户可访问时，在评估器标题行显示“查看评估链路”。区分页头“查看执行链路”。

## 5. 自动化验证

| 测试组 | 必须验证的行为 |
|---|---|
| 绑定与授权 | 明确版本、跨来源同名消歧、无权访问、重复名称、非 LLM 卡片拒绝绑定 |
| 本地导入 | 仅文件夹、拒绝 ZIP/单文件请求、单层包目录、缺主文件/多个 Skill 拒绝、跨用户凭证与到期处理、取消/失败不更新原绑定、全程不写库资产 |
| 完整文件 | 库来源 DB 主指令优先，本地来源字节不变，二进制保持、可执行位来源明确、清单文件缺失失败、历史目录扫描 |
| 路径与容量 | 越界、符号链接、大小写冲突、超限明确失败，无静默丢文件 |
| 保存一致性 | 快照写失败不更新卡片、返回规范化数据、省略字段保留绑定、显式空数组移除 |
| 内容固定 | 源文件更新/删除或原电脑离线仍使用冻结字节；库更换版本/本地移除后重新添加保存后才影响新实验，临时文件清理不删除持久快照 |
| 全部参与 | 多个主指令都实际进入请求，所有文件可访问；无工具的 Skill 不产生假调用 |
| Agent 路由 | 有 Skills 必须调用 OpenCode，OpenCode 失败不走 direct LLM；无 Skills 保留原路径 |
| 两入口输出 | 全局实验与轨迹入口结果适配正确，评分点 label、失败与不适用语义不丢失 |
| 冻结与复测 | 普通/对比/Benchmark/工作台/轨迹任务均冻结；修改卡片后重试、追加、监听和复用不漂移 |
| 取消与并发 | 多 Case 不串目录；排队或执行中取消可终止并清理，重试新建目录 |
| 结果证据 | 平台元数据不被模型伪造、不被归一化丢弃，截断和实际模型标记正确 |

优先用临时文件目录和可注入 OpenCode 客户端验证上述行为；不以“字符串含某函数名”代替可观察行为验证。

完成定向测试和相关类型检查后，执行 `npm run test`；记录既有基线失败与本需求新增失败，不用类型检查替代功能验收。

## 6. 真实执行与浏览器验收

设计实现后，先询问用户是否启动 dev 并验证 UI。获得确认后只使用 `bash scripts/develop_start.sh`，执行：

1. 创建 Prompt + 两个 Skill 的评估器：一个从库选择版本，一个从电脑导入；查看文件并保存，确认本地项未进入 Skill 库。
2. 用真实 OpenCode 运行一条确需脚本验证的 Case，检查工具输出、评分和两个主指令加载记录。
3. 更新库中源版本、修改本地文件后重试旧实验，验证仍用原快照；库版本更换、本地移除后重新添加保存后，仅新实验生效。覆盖多文件文件夹、仅含 SKILL.md 的文件夹，以及直接提交 ZIP/单文件被拒绝。
4. 移除一个 Skill 并保存，新实验仅加载剩余项；移除全部后新实验使用原提示词路径。
5. 验证跨来源同名拒绝，以及至少一个上传/执行边界（缺主文件、导入过期、OpenCode 失败或超限）；检查明确错误且无无声降级。
6. 检查详情刷新、并发执行、取消后的状态和浏览器 console，保留截图或快照。

未执行真实运行或浏览器验收时，报告中分别明确说明，不把自动化 mock 测试描述为真实 Agent 验证通过。
