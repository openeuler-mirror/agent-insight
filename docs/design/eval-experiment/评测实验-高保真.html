功能说明 — 评测「实验」化

把原「评测执行」升级为实验：固定一批任务、只改一个变量（LLM / Skill / Prompt / Agent 版本）、每组收一批 trace，统一评估后做组间对比。三个页面：实验列表、新建实验（四步向导）、实验对比详情。

核心解题：数据集不再是门槛。 发起评测不要求先建数据集——第 ③ 步「预期答案」整体可跳过；用户若愿意标注，可预填 trace 实际输出降低成本，标注结果可一键沉淀为数据集（数据集从前置门槛变为实验副产品，同时充当组间对比的 input 对齐键）。
1概念模型
概念含义规则
实验一次评测活动：评测 Agent + 变量 + 分组 + 评估器。变量可为「无」→ 退化为单组纯评测（覆盖原评测执行全部场景，含自动观测）。
组变量的一个取值（如 GLM-4.7 组），对应一批 trace。2~4 组；组内 trace 按元数据规则/实验标识自动关联，用户选择的是 input。
配对组间自动对齐成 case，判定三条件：① input 相同/相似 ② 双方满足本组变量取值 ③ 变量之外的关键条件一致（agent / skill / prompt 版本，按 trace metadata 自动校验）。①不满足 → 「未配对」；③不满足 → 「不可比」（input 同但条件不受控，看到的差异分不清归因）。两者均单列展示、不参与任何组间统计，可导出清单补跑/受控重跑后增量并入。
预期答案case 级参考标准（expectedOutput），可选。决定依赖型评估器的可用性与覆盖范围。
2四步向导行为
步骤行为关键规则
① 实验设计选评测 Agent、变量维度、定义分组。分组可选取值由变量维度决定（切换 LLM → 模型列表；切换 Skill 版本 → 该 Agent 的 skill 版本；Prompt 同理）；选「无变量」时隐藏分组，② 变为直接圈选 trace；stepper 任意可回跳，改动即时反映到后续步骤。
② 关联 Trace对比模式下以 input 为中心：一行一个任务输入，各组一列显示该取值下的 trace 齐备情况（有 / 缺失 / 多条·取最新可改选 / 条件不受控），勾选要纳入实验的 input——选择对象是 case，不是 trace。各组 trace 由元数据规则 / 实验标识自动关联（见表 3），无需手动圈选；缺失侧标「待补跑」，自动收集到达后自动补评；不可比行禁用勾选；单组模式退化为直接圈选 trace 列表；进行中实验可随时回本步看收集进度。
③ 预期答案（可选）为已配对 case 补 expectedOutput：预填实际输出、支持从数据集导入、可存为数据集。整步可跳过，跳过只影响 ④ 中依赖型评估器的覆盖范围，不阻断流程。
④ 评估器 → 开始按数据具备情况门控评估器，展示实验概要后启动。依赖预期答案的评估器：覆盖为 0 → 禁用+说明+回跳链接；部分覆盖 → 可选，仅对具备的子集评测并在结果页标注覆盖率（如 12/50）。
3各组 Trace 的三种收集方式
来源机制本期范围
存量自动匹配实验创建时按各组变量取值的元数据规则自动关联历史 trace——用户不逐条圈选 trace，选择对象是 input；同 input 多条默认取最新（可改选）。单组模式仍为手动圈选 trace。本期
自动收集新 trace用户切好变量配置后照常运行 agent，新 trace 自动归组，页面实时显示「已收 18/50 · 有效配对 16」。归组依据自动判定：变量取值可从 trace 元数据读出时（如切换 LLM → 模型字段）按元数据规则归组、零代码改动；元数据读不到（Prompt / 编排版本，Skill 版本视框架而定）或需隔离线上灰度流量时，注入实验标识（环境变量或 SDK 打标）作为归组依据。本期
平台触发执行平台代跑（内置基准 / 已注册可调用 agent）。规划中，入口置灰
4对比详情页
模块内容
结论横幅一句话结论：综合得分差 + 代价差（如「A 组高 6.3 分，B 组成本低 26%」），由汇总数据直接算出，不调用大模型。
组汇总卡每组：综合分、成功率、成本、时长、步数——后四项来自 trace 天然指标，无评估器也能对比；优势项带 ▲ 标绿。
评估器分解逐评估器双色条形对比；部分覆盖的评估器标注「覆盖 12/50」。
逐 case 配对表同一 input 下 A/B 输出摘要 + 得分 + 胜负徽章；按 全部/A 胜/B 胜/平/未配对 筛选；得分列可切换评估维度（综合 / 结果类·任务完成度 / 轨迹类·轨迹质量），承接原"结果评测 vs 轨迹评测"二分，胜负徽章固定按综合分；行点击打开case 评测详情抽屉。
case 评测详情抽屉原「结果评测 / 轨迹评测」详情的完整保留：A/B 两侧并排，各含 ① 输出摘要 ② 结果评测——任务完成度得分 + Judge 理由 ③ 轨迹评测——轨迹质量得分 + 四子维度（完整性/工具选择/冗余度/归因）+ Judge 理由 ④「查看完整 trace 评测详情」深链到 /eval/trajectory/[id]——该页同步重构（见表 5），链路观测步骤树页不动。单组实验详情页即原「评测执行」批次页形态（汇总卡 + trace 评测列表 + 点行进详情），完全沿用。
可比性规则组间一切对比（结论横幅 / 组汇总卡 / 评估器分解 / 胜负统计）仅基于"可比配对"交集计算——可比 = input 相同 + 变量之外条件受控。单边跑过的 case 没有对照，若计入组均分会把"任务集差异"错当"能力差异"（选择偏差）；input 相同但条件不受控的标「不可比」，计入会把"混杂变量的贡献"错当"变量差异"（归因污染）。两者单列展示自身得分仅供参考；可导出清单补跑（未配对）或以受控条件重跑（不可比），新 trace 配对成功后增量补评并自动并入统计；可比率过低（建议阈值 70%）时结论横幅降级提示"对比可信度有限"。

底部整宽紫色大按钮跳转链路观测常规 btn-outline 移至页头右侧（「前往链路观测 · 执行步骤树 →」）。
信息零删减：任务输入 / Ground Truth / 实际输出、关键观点覆盖判定、问题定位（失败阶段+步骤+Skill 归因）、judge 执行路径分析原文、三维度得分与 findings、评测中/失败/未开启等状态文案、链路观测跳转——全部保留，仅换呈现方式。分数颜色分档（绿≥80 / 黄≥50 / 红<50）保留在分数徽章上。
⚠ 兼容与迁移：现有「评测执行」批次自动迁移为「无变量·单组」实验；「自动观测」保留为 ② 步中「自动收集」的一个开关（持续接收新 trace）。评估器需新增 requires 声明（如 expectedOutput）以支撑 ④ 步门控——这是唯一的模型层改动。
