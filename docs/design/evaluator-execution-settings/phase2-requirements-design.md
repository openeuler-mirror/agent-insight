## 2. 选择评估器

- 搜索名称和描述，去掉首尾空格，英文不区分大小写。
- 来源为“全部来源 / 内置 / 自定义”；当前实验存在 Benchmark 官方评估器时增加“Benchmark”。来源依据实际元数据，不依赖显示名称。
- 每页建议 12 个；先在现有适用范围内搜索与筛选，再分页。前端已加载的卡片数据足够时使用本地分页，不为本需求单独新增列表 API。
- 搜索/筛选变化时回到第一页；数量不足一页隐藏分页；空结果展示“未找到匹配的评估器”。数量变化时页码校正到有效范围。
- 勾选集合独立于过滤结果和页码；已选计数包含所有页。隐藏在其他页或被筛选隐藏不等于取消选择。
- 原有前置条件门控、自动绑定 Benchmark 不可取消等规则保持不变。不能因为分页而绕过门控或删除已选项。

## 3. 评估运行设置

### 3.1 实验级策略

默认选择“使用系统默认”，不展示统一配置输入框；切换为“统一配置”才展开两个字段。“评估器单独配置（可选）”不受此显隐控制：两种模式下均可展开并编辑。切回系统默认后可保留未提交的统一设置草稿，生效策略以当前模式为准。

| 字段 | 页面单位 | 语义 |
| --- | --- | --- |
| 评估超时 | 秒 | 每条 Case、每个评估器的一次完整评估尝试的时间预算 |
| 重试次数 | 次 | 首次失败后最多额外尝试的次数，0 表示不重试 |

提示文案：

- 评估超时：“每条 Case、每个评估器的单次尝试上限；每次重试重新计时。”
- 重试次数：“失败后最多重试的次数，不包含首次执行；0 表示不重试。”

600 秒/2 次表示最多三次尝试，每次独立获得 600 秒；不是整个实验或所有重试合计 600 秒。页面不展示计算出的累计耗时。

显式配置为超时 30～3600 秒、重试 0～3 次，均为整数；首次展开统一配置为 600 秒、2 次，不据此裁剪旧系统策略。空值、非整数或越界内联报错并阻止开始实验；服务端重复校验。

### 3.2 评估器单独配置（可选）

- 区域默认折叠，标题固定为“评估器单独配置（可选）”；有覆盖时可附“已单独配置 N 个”。无须先启用统一配置即可展开和编辑。
- 只显示已选且声明支持超时/重试配置的 LLM 评估器；不受上方搜索、来源筛选或分页影响。
- 输入框直接展示当前生效的具体数值：系统模式下，未覆盖项填入各评估器自己的系统默认超时和重试次数；统一模式下，未覆盖项填入统一配置；有单项覆盖时始终展示覆盖值。
- 系统默认数值由服务端提供，并与执行策略保持一致；不能填空、用“系统策略”代替数值、填统一示例值，或仅因选择系统模式而禁用输入框。默认值尚未梳理为准确尝试语义的评估器，必须先完成预算适配再声明支持，不能将内部请求超时冒充整次尝试预算。
- 修改一行任一字段，将该行当前超时和重试作为完整的一组显式覆盖；不支持一个字段继承、另一个覆盖。
- 是否继承由覆盖项是否存在决定，不以数值是否等于统一配置推断。单独输入了与统一配置相同的数值，仍是单独配置。
- 修改立即更新实验表单，无额外确认修改步骤；最终随“开始实验”提交。
- 每行最后一列只有恢复操作。统一模式显示“恢复统一配置”，系统模式显示“恢复系统默认”。
- 系统模式下点击恢复，将该行两字段填回该评估器自己的系统默认数值；不要求先切换至统一配置，也不影响其他行。
- **每行恢复按钮始终可点击，不因未修改、值相同或已经恢复而置灰。** 点击幂等地删除该行整组覆盖，恢复超时与重试，并重新继承上层策略。
- 恢复不修改上方配置，不触发真实执行、不发送独立保存请求，也不弹确认窗口。
- 更新上层策略仅影响继承项；切换系统/统一模式不清除单独配置。
- 取消勾选某评估器时，其覆盖不提交；建议同时清除该覆盖，再次勾选时继承上层。搜索/翻页隐藏不能触发该清理。
- 无支持项时显示简短空态，不渲染无法使用的统一输入和空表。

### 3.3 适用范围

自定义 LLM 评估器为首要覆盖对象。内置评估器必须有明确的运行适配和能力声明后才支持统一与单独配置，不能仅凭 `evaluatorType === 'LLM'` 判断。

代码评估器保留已有规则配置入口，不增加 LLM 超时字段。Benchmark 官方评测继续使用服务策略，不进入单独配置表；其额外选中的自定义 LLM 评估器按普通规则处理。Agent 执行配置维持原位置与语义。

## 4. 执行与失败语义

### 4.1 预算与取消

显式配置的超时从实际获得运行资源、开始一次评估尝试时计时，不包含排队。尝试内的评分调用、解析和必要传输步骤共用该次剩余预算；不能让每个内部模型调用都重新获得完整时间。

尝试截止时间向结果行、模型客户端和流式客户端传递。旧的 180 秒请求、300 秒结果行、空闲超时等限制不能静默截断用户设定的更长预算。连接建立、队列与清理可有独立保护，但需以独立原因报告。

到期应触发取消信号，终止本地工作并清理会话/进程；仅 `Promise.race` 返回不足以完成取消。确认旧尝试结束后再重试；无法确认清理时不重叠启动新尝试，并报告清理失败。不能承诺远端 Provider 一定停止计费。

### 4.2 重试

- 统一由尝试调度层拥有重试预算，`maxAttempts = maxRetries + 1`。
- 新显式策略关闭 SDK 隐藏重试；传输回退若重新发起完整评分，应消耗一次额外尝试，不能成为不计数的隐藏重试。
- 可恢复失败包括超时、临时网络错误、可恢复服务错误；退避等待独立于尝试预算，并遵守取消信号。
- 评分低、评判不通过属于正常结果，不重试。
- 配置错误、鉴权失败、不可恢复配额错误、用户取消不重试。
- 解析失败是否重试应统一为明确规则；建议保留现有可重试解析错误，但同样消耗用户配置的次数，不额外赠送修复调用。
- 任一尝试成功后结束，不继续调用。失败保留错误类型、已尝试次数、耗时和实际配置；失败不能伪装为有效零分。
- 手动重新评估使用实验保存的配置，形成新的运行周期；自动重试次数与历史累计尝试次数应区分。

### 4.3 内置特殊路径

轨迹质量的评分和附加建议不直接套一个通用默认秒数。适配时明确预算覆盖阶段，保留评分成功后建议失败不推翻有效评分的行为；阶段适配不完整前不声明支持新的统一覆盖。

多调用评估器的所有必要子调用受同一次尝试预算控制。不能把整次任务允许重试两次，误实现为每个子调用各自自动重试两次。

Benchmark 的任务限制、派发摘要、独立服务定时器和平台回收保持现有契约，本需求不修改它们。

## 5. 数据与接口修改方案

以下契约沿用现有实验创建、详情与重试接口，不新增 API 路由。复用 `Experiment.evaluatorConfigsJson`，不新增 Prisma 字段。

保留原 `evaluatorConfigs` 文本规则映射，增加独立请求字段，避免将运行策略混入 Exact Match/F1 的字段白名单：

```json
{
  "evaluatorExecutionConfig": {
    "mode": "uniform",
    "uniform": { "attemptTimeoutSeconds": 600, "maxRetries": 2 },
    "overrides": {
      "custom-example": { "attemptTimeoutSeconds": 900, "maxRetries": 1 }
    }
  }
}
```

- `mode` 为 `system` 或 `uniform`；`system` 模式允许仍有单项覆盖，但不提交不生效的统一草稿。
- 每个覆盖必须同时含两个字段，并且属于当前已选、当前用户有权使用、声明支持配置的评估器。
- 服务端验证未知字段、类型、范围、支持能力及模式一致性；无效配置返回 `400`，不得静默忽略。
- 服务端按“单项覆盖 → 统一配置 → 系统策略”解析。服务端生成实际配置快照，不能信任客户端提供的 resolved 值。
- 面向向导的能力数据必须包含每个支持项的系统默认 `attemptTimeoutSeconds` 和 `maxRetries`；页面据此初始化系统模式行内输入及恢复操作，不从统一配置草稿或固定常量推断默认值。
- 存储包装扩展为 `schemaVersion: 2`，保留 `configs` 保存原匹配规则，新增 `execution` 保存用户策略与服务端解析快照。读写封装统一升级，避免旧序列化器丢掉新字段。
- 快照包含 `policyVersion: 1`、各评估器配置来源和实际运行参数。未适配项不写入 `resolved`，继续走 legacy 路径，不把旧 180 秒请求限额直接改称完整尝试预算。
- `{}`、旧无包装对象和 `schemaVersion: 1` 继续兼容；缺少运行配置的旧实验保留原行为，不隐式迁移重试语义。
- 详情返回用户选择与服务端生效配置；向导复用恢复模式和覆盖关系，新建时重新验证评估器有效性及默认值；冻结配置克隆则保留原执行快照。
- 自动与手动重评从持久化配置读取，不能依赖页面内存。运行中不通过本表单修改既有实验策略。

## 6. 本次实现决策

1. 支持仅使用 Prompt 的自定义 LLM Judge，以及内容、创造力表达、文本、流畅性、安全、深度、严谨性、工具利用/选择/成功率、无参考任务完成度与四个结果指标。准确 ID 清单集中在 `evaluator-execution-config.server.ts`。带 Skills 的自定义评估器、轨迹质量、依赖参考的任务完成度、执行过程质量、步骤效率、外部检索幻觉和 RAS 保留原策略。
2. 新策略默认预算：通用 Judge 为 180 秒/2 次，四个结果指标为 300 秒/2 次；现有超时环境变量在 30～3600 秒有效范围内可覆盖这两个默认值。新策略取消 SDK 嵌套重试、把超时统一为整次尝试预算；历史实验保持原有多个定时器的语义。能力数据通过现有用户评估器 GET 接口的 `view=execution-config` 返回。
3. 允许范围为 30～3600 秒、0～3 次；统一配置初始值为 600 秒/2 次。重试退避为 2/8/20 秒，结构化解析失败归为可重试；清理等待上限 5 秒，未确认停止时终止重试并保留清理标记。
4. 通用 Judge 在新策略下只直连模型，关闭 OpenCode 强制传输和失败后隐藏回退，保证没有不计数的完整评分。旧实验及未适配特殊评估器的传输保持原状。后续支持进程型传输须另行适配排队预算、取消及子进程重试契约。
5. 详情 API 增加 `evaluatorExecutionConfig`、`evaluatorExecutionResolved`；成功/失败结果 evidence 记录实际配置及本轮尝试数，沿用结果行历史累计 `attempts`。没有新增数据库迁移、API 路由或详情页布局。
