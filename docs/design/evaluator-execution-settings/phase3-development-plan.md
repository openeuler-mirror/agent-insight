# 实验评估器超时与重试配置：开发计划

目标交互和运行契约见[需求设计](phase2-requirements-design.md)，需求范围见[需求分析](phase1-requirements-analysis.md)。本文件描述实施顺序；是否实现统一记录在[需求清单](../README.md)。

## 1. 清点评估路径与支持能力

- 从 `run-experiment.ts` 的真实分发路径整理自定义及内置评估器的模型请求、子阶段、SDK 重试、传输回退、资源排队与结果行超时。
- 优先接入自定义 `callJudgeLlm` 路径；明确它与 `custom-llm-evaluator.ts` 的另一个评测入口不同。
- 建立前后端共用的配置能力描述，提供支持状态、各评估器系统默认超时与重试的具体数值、默认策略版本和允许范围；页面显示值与实际执行语义一致，不能只在前端按 ID 临时判断。
- 定下需求设计第 6 节的工程参数。只有预算和取消完整适配的内置评估器才加入支持清单。

## 2. 共享配置与持久化

主要修改位置：

- [evaluator-run-config.ts](../../../src/lib/evaluators/evaluator-run-config.ts)：扩展存储版本与统一解析，保留现有文本规则语义；运行策略逻辑可拆为相邻模块，避免扩大文本规则类型的职责。
- [实验创建接口](../../../src/app/api/experiments/route.ts)：接收运行策略、验证已选项/权限/能力，生成实际快照并持久化。
- [实验详情接口](../../../src/app/api/experiments/[id]/route.ts)：返回运行策略及生效值，支持复制实验回显。
- 检查 Skill 实验、Benchmark 混合普通评估器及所有创建/复制入口，保证旧调用方不传新字段仍可用。

优先复用现有 JSON 列，不增加数据库迁移或新路由。若实现中证明必须修改 Prisma schema 或新增 API，应先补充设计并对齐，不直接扩大范围。

## 3. 运行引擎

主要修改位置：

- [run-experiment.ts](../../../src/lib/engine/experiment/run-experiment.ts)：读取实际策略；按评估器选择尝试次数、超时与退避；记录失败原因和配置，不再让固定 300 秒限制覆盖显式策略。
- [judge-llm.ts](../../../src/lib/engine/experiment/judge-llm.ts)：贯通剩余预算与信号；新策略消除 SDK 隐藏重试和未计数完整回退。
- [cancellation-context.ts](../../../src/lib/engine/experiment/cancellation-context.ts)：组合实验取消和尝试超时，保证清理与尝试生命周期闭合。
- 已声明支持的内置适配器及其模型客户端：传递同一尝试预算，处理多调用和可选分析阶段。
- 带 Skills 的自定义 LLM 评估器已确认采用简化方案：在 `custom-evaluator-runtime.ts` 与 `judge-llm.ts` 中，将固定 180 秒限制替换为配置的单次 OpenCode 执行超时，覆盖执行中的模型和工具调用；排队、环境准备、Skill 文件部署和服务启动沿用系统策略。将配置的计时与重试边界放到实际执行周围，不能直接在整个运行入口套用超时。可重试技术失败后重新调用 OpenCode，复用同一输入和冻结配置；保留原始错误信息，复用现有取消与清理机制，确认旧执行结束后才重试，不叠加整次执行重试循环。完成后登记能力、显示真实系统默认值，复用现有前端配置并补充“超时和重试作用于 OpenCode 评估执行。”。此适配已实现。
- Agent 任务完成度与轨迹质量已确认超时和重试均只作用于评分阶段：在评分阶段内部适配预算与重试循环，评分重试复用成功的前置分析结果；前置分析、Skill 分析和附加建议沿用系统策略。对应行显示“仅配置评分阶段，Skill 分析和附加建议沿用系统策略。”；收拢评分内部重试和完整评分回退，避免 SDK 与外层次数相乘，并调整旧结果行保护以免提前截断配置的评分预算。此适配已实现。
- Agent RAS 可靠性故障检测恢复评估器已确认支持评分阶段超时与重试：适配 `ras-reliability-evaluator.ts`，前置读取证据后复用 Trace 与事件，在模型判定、输出校验和计分周围接入预算及重试，再登记配置能力。区分可重试技术失败、模型配置错误及正常故障未发生，移除新策略下按宽泛消息匹配返回 `warn` 而吞掉技术错误的行为；技术失败耗尽后记录评估失败。前端复用原配置交互；保留旧实验与隐藏兼容 ID 的契约。此适配已实现。
- [结果重试接口](../../../src/app/api/experiments/[id]/results/[resultId]/retry/route.ts)、[Case 重试接口](../../../src/app/api/experiments/[id]/cases/[caseId]/retry/route.ts)：保留原有 Agent 重跑语义，评估阶段使用保存的配置；区分新运行周期与自动重试。

旧实验缺少新配置时保持 legacy 路径。新配置不得通过修改全局环境变量实现，避免多个实验相互污染。

## 4. 前端最小修改

主要入口：[ExperimentWizard.tsx](../../../src/components/eval/ExperimentWizard.tsx)。

1. 在现有卡片列表上方添加搜索、来源筛选和全局已选计数，下方添加分页。
2. 保留全部候选卡片与勾选集合；过滤/分页仅影响展示，不改变门控和选择状态。
3. 在分页下方增加“评估运行设置”：系统默认/统一配置及两个输入框。
4. 增加默认折叠的“评估器单独配置（可选）”，只列全部已选的支持项，使用行内输入及逐行恢复。系统默认模式也可展开编辑，未覆盖项输入框填入服务端提供的各自系统默认超时和重试数值，不能留空或展示“系统策略”占位。
5. 恢复按钮始终可点击；无确认弹窗、无该区域底部按钮、无配置方式列。
6. 分开管理上层策略、单项覆盖、输入草稿与生效值。空字符串不能被 `Number('')` 错误转换为合法零值；隐藏在折叠区的非法覆盖仍须提示并阻止启动。
7. 取消勾选清理覆盖，搜索/筛选隐藏不清理。支持复制实验恢复与无支持项空态。
8. 沿用原“开始实验”的创建/启动/失败补偿流程，提交时新增运行策略字段。
9. 复用共享令牌和 UI 组件，不改变实验摘要、卡片布局、Agent 执行设置的位置及已有文本规则弹窗。
10. 按已确认方案，为选中的 SWE-bench、Zsoft L1 显示独立服务不支持实验配置的提示，不显示其超时／重试输入或恢复按钮；与普通评估器混选时仍保留提示，不修改服务运行策略。此提示已实现。
11. 为选中的 4 个代码评估器显示不调用模型、不支持超时和重试配置的提示，不显示相关输入或恢复按钮；保留原匹配规则配置及平台运行策略，不增加 Worker 改造。此提示已实现。

## 5. 自动化验证

| 层级 | 关键用例 |
| --- | --- |
| 配置 | 模式/单项优先级；整组覆盖；系统模式保留覆盖；恢复幂等；合法整数与边界；未知字段/无权限/未选中/不支持项拒绝 |

| 执行 | 600 秒配置突破旧 180/300 秒限制；重试 0/1/2 的完整尝试计数；成功即停止；无隐藏 SDK 重试/回退；取消时不重试 |
| 资源 | 排队不消耗尝试预算；尝试到期中断；清理未确认时不重叠启动；退避可取消；定时器和监听器清理 |
| 内置/Benchmark | 多调用共享单次预算；已完成评分不被附加建议失败推翻；官方 Benchmark 配置不受影响 |
| 任务完成度/轨迹质量 | 配置仅约束评分超时与评分重试；评分重试复用前置分析；0 次重试不影响 Skill 分析和附加建议的系统策略；建议失败不重跑评分；旧外层保护不提前截断配置的评分预算 |
| RAS 检测恢复 | 评分超时及 0/1/2 次重试生效；解析失败和临时故障重试、耗尽记录失败；未确认故障发生时无分且不重试；低分不重试；缺少模型与取消不重试；评分重试复用相同证据、不重跑 Agent 或注入故障；旧实验兼容 |
| 带 Skills 自定义评估器 | 配置的超时传入 OpenCode 执行且不被固定 180 秒截断；模型和工具调用共享本次执行时间；排队、准备与服务启动不占预算；0/1/2 次重试最多执行 1/2/3 次；复用冻结输入配置；旧执行结束后才重试；正常低分与取消不重试；系统默认回显和历史行为兼容 |
| UI 状态 | 跨页/筛选保留勾选；页码复位/夹取；单项表跨页完整；系统默认模式可编辑且展示各自默认数值；每行恢复始终可点并恢复正确来源的两字段；行内修改即时生效；非法输入阻止启动 |

优先使用可控时钟、延迟模型替身与可取消工作验证，不依靠真实等待 600 秒。测试应验证外部行为与资源生命周期，而不是仅断言常量或实现结构。

实现完成后先执行相关专项，再按仓库要求运行 `npm run test`；类型检查与 lint 作为补充，不替代功能测试。纯设计文档变更检查链接、线框和差异即可，不以测试通过声称功能已实现。
