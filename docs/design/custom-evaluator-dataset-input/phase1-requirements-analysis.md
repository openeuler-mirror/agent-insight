# 自定义评估器数据集输入变量：需求分析

## 背景

自定义评估器当前支持 `{{input}}`、`{{output}}`、`{{reference_output}}` 和
`{{trajectory}}`。其中 `{{input}}` 是本次执行的完整任务输入；实际业务任务经常在数据集
核心输入之外附带客户背景、格式要求等信息，评测方希望能单独取得匹配数据项的输入，避免
Judge 把冗余上下文当作待评价目标。

创建页同时存在“参考输出”和“预期输出”两种展示文案，而运行时
`{{reference_output}}` 实际对应数据集 `expectedOutput` 或实验 case 的预期输出快照。

## 目标

- 新增 `{{dataset_input}}`，表示匹配到的数据集 case 的 `input`。
- 保持 `{{input}}` 表示实际任务输入，保证存量自定义评估器兼容。
- 引用 `{{dataset_input}}` 的评估器只有在实际输入匹配数据集输入时才可用。
- `{{dataset_input}}` 与 `{{reference_output}}` 同时使用时必须来自同一个数据集 case。
- 面向用户的 `reference_output` 展示名称统一为“预期输出”。
- 实验保存匹配时的数据集输入快照，保证后续数据集变化不改变历史实验语义。

## 非目标

- 不重命名技术变量 `{{reference_output}}`。
- 不改变 `{{input}}` 的含义。
- 不用 LLM 语义相似度决定评估器可用性。
- 不改变不引用 `{{dataset_input}}` 的评估器行为。

## 验收口径

1. 实际输入规范化后包含数据集输入时视为命中；多项命中选择最长的数据集输入。
2. 反向包含不命中；没有确定性命中时评估器不可用或运行时记为不适用。
3. 创建、编辑与服务端保存校验都接受 `{{dataset_input}}`。
4. 实验与 Trace 评测均能把匹配 case 的原始输入注入 Judge。
5. 历史评估器与历史实验无需迁移即可继续读取和运行。
