# 客观答案匹配评估器

评估器 ID `preset-similarity-answer-match`，执行入口 `runAnswerMatch`，源码 `similarity-answer-match-evaluator.ts`。

## 目标与输入

判断客观问答中 Agent 回答是否覆盖标准答案的核心内容，适用于有唯/标准参考答案的结果验收。输入为 `actualOutput`（模型回答）与 `referenceOutput`（标准答案），`caseInput`（用户问题）作为信息点提取与语义判同的语境参考。未标注标准答案时直接返回不计分结果、不调用模型——只展示原因，不进综合分与类目均分，不产生 0 分。

## 判定流程

四个阶段，能确定命中的先由代码判定，不能确定的才交给 Judge。

### 1 关键信息点提取（LLM）

从标准答案提取回答该问题时必须覆盖的信息点，类型限定四类：

| type | 含义 | 示例 |
|---|---|---|
| `number` | 关键数值 | `42`、`3.14`、`2024 年` |
| `term` | 专有名词 | `Transformer`、`H2O` |
| `conclusion` | 核心结论 | 「X 大于 Y」 |
| `condition` | 必要条件 | 「温度不能超过 100℃」 |

提取的输入是「用户问题 + 标准答案」两部分：标准答案常含背景介绍、补充说明、与当前问题无关的细节，只有把问题一起交给模型，才能筛掉这些内容、保留依赖问题语境才能判断重要性的要点。`number` 信息点要求连同单位一起提取（`100℃`、`1234.5 亿元`），否则代码层无法核对单位。

并列要点拆成多个信息点（回答可能只命中其中部分），无关修饰不提取。`points` 非数组或类型越界抛 `SimilarityJudgeParseError`。提取不到任何信息点时返回不计分结果，且不再进行后续判同。

### 2 代码层精确匹配

无模型参与，命中即定档；不确定一律留给判同，不在这里下结论：

- `number`：同时提取阿拉伯数字（支持千分位逗号与小数）与中文数字（`四十二`、`一百亿`、`两`），把紧跟阿拉伯数字的中文量级词并入数值（`3.5亿` → 3.5e8、`1万` → 1e4），再解析数值后面紧跟的单位（`℃`/`°C`/`摄氏度` → `c`，`℉`/`°F`/`华氏度` → `f`，`%`、`亿元`、`km` 等；表外文本视为无单位）。单位命中优先于量级拆分：`3.5亿元` 仍是 3.5 亿元，不会被拆成 3.5 万元；`千米`/`千克` 这类以量级字开头的单位也不会再吐出一个多余的 `1000`。要求信息点中的**每个**数值都被回答命中，避免数值范围（`100-200℃`）只核对到第一个数值；范围连接符 `-` 不作为负号。全文只出现一种单位时（`100-200℃`）视为各数值共用该单位。
  - 完全覆盖（**仅当信息点里每个数值都带单位**）：全部数值都能在回答中找到等值数值，且单位相容——信息点写了单位时回答必须给出同一单位（`100℃` vs `100℉`、`100` 均不算命中，交判同）。**未带单位的裸数值即使命中也不算终判**：回答里出现 `3` 可能只是分点序号或章节编号，凭数值本身无法断定它回答了问题，因此与未命中的信息点一起交判同复核语境。
  - 部分覆盖：全部数值命中但存在**小数位**精度截断（`3.14` vs `3.14159`）。整数前缀（`2` vs `25`、`1` vs `100`）是另一个数量级的错值，按未命中处理。
  - 其余情况（有数值缺失、单位不符、单位缺失、裸数值命中）→ 交 LLM 判定，不在此直接判覆盖或未覆盖。
- `term`：去掉空白、`-`、`_` 后小写，`Self-Attention` 与 `self attention` 等价。英文术语按词边界命中（`C` 不命中 `CPU`，`art` 不命中 `start`），中文术语按子串命中。单个汉字没有词边界可依（`水` 会命中 `水果`），直接交判同而非判为覆盖。

`conclusion` 与 `condition` 不参与代码匹配，直接进入判同。

### 3 LLM 层语义判同

代码层无法定档的信息点（数值未命中、单位不符、以及裸数值命中）交 Judge 逐点判定，返回按序号严格对齐的 `judgments`（`matched` / `not_matched` / `uncertain`）。序号越界、判定值非法或漏返某个信息点一律抛 `SimilarityJudgeParseError`（可重试），不把「漏返」静默当成未覆盖而扣分。同义转述、主被动变换、信息合并或拆分按覆盖处理；信息点含数值时要求同时核对数值与单位，数值相同但单位不同且不等价（`100℃` vs `100℉`）判 `not_matched`；`matched` → 100/covered，`not_matched` 与 `uncertain` → 0/missing（证据分别写明「判定不匹配」「判定不确定」，与代码层未命中区分）。部分覆盖只可能由代码层数值截断产生。

### 4 综合评分

见下节。

## 计分

```text
base      = round( Σ 信息点得分 / 信息点数 )        # covered 100 / partial 50 / missing 0
deduction = 缺失 conclusion 数 × 10 + 缺失 number 数 × 20
score     = clamp(round(base - deduction), 0, 100)
若 base > 50 且存在缺失的 conclusion：score = min(score, 60)
verdict   = score >= 80 ? pass : score >= 60 ? warn : fail
```

逐点均值给出覆盖基准，再对两类高价值缺失额外扣分：关键数值是客观题的硬答案，缺失扣分重于核心结论，且都比重算均值更直接地压低总分。`base > 50` 时的 60 分上限针对「多数信息点命中但核心结论丢失」——结论缺失的回答不构成对问题的有效回答，不应因其余信息点大量命中而拿到高分。

## 输出

卡片输出 `verdict`、`summary`、`score`、`points`、`evidence`。`points` 每个信息点一条，按标准答案的信息点顺序展开（不因走代码层或 LLM 层而重排），label 为 `类型：信息点文本`（文本截断 80 字），score 与 status 取匹配结果，逐点证据写明该点走代码层还是 LLM 层及原因；卡级 `evidence` 汇总综合评分（含覆盖基准 `base` 与扣分调整）与逐信息点判定。`summary` 分别给出完全覆盖 / 部分覆盖 / 遗漏的信息点数与遗漏项（最多列两项）；只要存在部分覆盖（50 分）就不会自称「与标准答案一致」，避免与 `verdict` 口径打架。

## 边界与测试

空标准答案、标准答案提取不出信息点两种边界都不记分且不显示 0 分，后者只调用提取、不调用判同。回答正确但附带无关信息不扣分，语序完全不同而语义相同的结论按覆盖处理。专项测试在 judge 边界依次注入提取与判同两次返回，覆盖需求自带的十条用例、数值等价与截断、结论缺失扣分与 60 分上限、漏返 / 越界 / 非法枚举三类解析错误，以及数值与单位提取（单位归一化、范围共用单位、范围连接符不当负号）、单位不符与范围缺项时交判同、短术语词边界与单个汉字术语交判同、提取阶段传入用户问题、数量级词（`3.5亿` 与 `350000000` 等值、`3.5亿元` 不被拆成 3.5 万元、`3千米` 不重复计数）、裸数值命中交判同复核语境、整数前缀不算精度截断、报告按信息点顺序展开、部分覆盖时 summary 不自称「与标准答案一致」。
