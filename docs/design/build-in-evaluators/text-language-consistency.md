# 文本语种一致性评估器

## 目标与输入

结合 `caseInput` 与 `actualOutput` 判断回复主语言是否匹配用户问题，并识别没有合理理由的语言混杂。非空用户问题是必要输入；缺失时在调用 Judge 前 fail-fast，使该评测行进入失败状态。

## 判定与输出

Judge 返回主语言一致性、非必要语言混杂、代码切换合理性和双语场景处理四个维度的离散等级、引用、理由、建议和不超过 80 字的具体总结。输出包含 `score`、`summary` 和四个 `points`，不输出卡级 `evidence`；建议使用 `EvalPoint.suggestion`。

模型调用固定使用 `temperature=0`，减少同一文本重复判档时的采样漂移；最终分仍完全由代码按离散等级确定。

## 关键维度、普通维度与确定性计分

`primary_language_match`（主语言一致性）是关键维度；完全使用错误主语言会使回答无法直接服务用户，因此其影响高于局部语言混杂。

`unnecessary_mixing`（非必要语言混杂）、`code_switch_rationale`（语言切换合理性）和 `bilingual_handling`（双语场景处理）是普通维度。

四个维度统一使用 `safe/minor/moderate/severe = 100/80/20/0` 评分点映射。关键维度按 100 权重生成扣分，普通维度按 90 权重生成扣分：

`d_i = weight_i × (100-s_i)/100`

卡片总分沿用安全评估器的“最大扣分完整计入、其余扣分均摊追加”公式：`M=max(d_i)`，`D=M+(Σd_i-M)/N`，其中 `N=4`，最终 `score=clamp(round(100-D),0,100)`。

因此主语言完全错误且判为 `severe` 时综合分为 0，满足需求中的“不高于 10 分”；普通维度单项 `severe` 时综合分为 10。所有扣分均随严重度单调增加。

## 边界与测试

标准技术术语和缩写、产品或人名、通用寒暄、代码关键字、翻译对照及带解释的外文引用属于强制豁免；外语内容全部属于这些类别时，混杂与切换理由维度必须判 `safe`。一个或少量通用外语寒暄与主语言寒暄并用时，不要求另行翻译或证明功能性必要。外文资料、定义、法规或作品的逐字原句只要在相邻位置已有主语言概念名称、简要释义、概括或转述，就按原文引用豁免，不要求逐句直译，也不因引文较长或已有成熟译文而改判为正文混杂。知识性问答中，原文被明确作为定义、定律、法规或作品的引述，并由相邻主语言名称或概括标明指代对象，即已具备引用理由；不得仅因原文较长或存在成熟译文而扣分。用户以两种语言提出彼此独立的问题或信息片段，而回复只使用其中一种语言时，双语处理至少判 `moderate`。

技术主题本身不自动构成豁免。在单一主语言正文中出现三个及以上具有成熟本地译名的普通外语词或词组作为句子成分时，`unnecessary_mixing` 必须判 `severe`；只有正式缩写、协议或 API 的固定名称、代码标识符、品牌名及没有通行本地译名的术语继续豁免。普通外语词不能只因常见于技术讨论就视为标准技术标识。Prompt 使用通用类别描述，不枚举验收题中的具体答案词。

专项测试保留需求自带 14 组用户问题与回复，并覆盖空 `caseInput` 不调用 Judge、关键/普通维度配置、评分点映射和单调扣分等契约。
