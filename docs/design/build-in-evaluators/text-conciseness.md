# 文本简洁性评估器

## 目标与输入

评估 Agent 回答是否用足够少的文字完成主需求，同时保留必要步骤、条件和限制。`actualOutput` 是评分对象，`caseInput` 用于判断主需求和必要信息；仅评价冗余与完整性，不重新评价事实正确性。

## 判定与输出

Judge 对表达效率、套话精简度、主需求聚焦度、信息完整性返回 `safe/minor/moderate/severe`、问题原文、中文理由、精简建议和不超过 80 字的具体总结。输出包含 `score`、`summary` 和四个 `points`，不输出卡级 `evidence`；建议写入 `EvalPoint.suggestion`。

模型调用固定使用 `temperature=0`，减少同一文本重复判档时的采样漂移；最终分仍完全由代码按离散等级确定。

## 加权与兜底

离散等级映射为评分点 `100/70/40/0`，四维权重分别为 `0.3/0.2/0.3/0.2`：

`B = 0.3×表达效率 + 0.2×套话精简 + 0.3×主需求聚焦 + 0.2×信息完整`

在基础加权分上应用确定性上限：表达效率 `severe` 不高于 30；套话或主需求聚焦 `severe` 不高于 40；信息完整性 `moderate/severe` 分别不高于 60/50；表达效率 `moderate` 不高于 70。最终分为所有适用上限与 `B` 的最小值并四舍五入。

上限体现需求中的兜底原则：回答过短而缺失必要信息时，不能因其它维度简洁而获得高分。各维度从轻到重升档时，综合分不会上升。

判档使用不可降档的通用锚点：简单事实问题已在一个短句中完整作答、其余内容只重复修饰或主观评价时，表达效率判 `severe`；没有用户问题时，若一个简单命题被多组同义强化词或评价性修饰包裹，且大部分文字可删除而不损失命题信息，也判 `severe`。完整操作过程可在不丢失步骤的前提下由一串叙述句整体压缩为操作路径时判 `moderate`，局部措辞拖沓才判 `minor`；大部分从句仅逐字展开导航/点击动作时，不因步骤正确完整而判 `safe`。简单问题的答案未在开头明确给出，且成因、历史、邻近话题或未请求扩展占据主要篇幅时，主需求聚焦判 `severe`；该判断按信息占比和答案是否前置，不机械依赖句数。二元判断或单一事实问题应以独立短句或主句直接给出核心结论，把结论嵌在冗长来源、成因或限定从句之后不算前置；若还同时加入两类及以上可删除的成因、附加指标、相邻时段、相关话题或额外提醒，主需求聚焦判 `severe`。Judge 的理由或总结若已经明确指出答案被多句背景延后、位于回复末尾或未请求内容占主要篇幅，必须同步将主需求聚焦判为 `severe`。操作型回答只有泛化动作，并在必要来源或版本、前置条件、关键选项、结果验证中缺少两类及以上信息时，信息完整性判 `severe`；依赖具体软件、文件、平台或制品的任务若只给出任何产品都适用的通用界面动作，也属于无法执行的泛化步骤。缺少可选替代方案或额外确认提示不构成信息缺失。Judge 输出前需复核理由与档位一致，已经明确指出上述硬锚点时不得保留较轻等级。

对于二元或单一事实问题，若核心结论没有作为开头的独立短句或主句，而是埋在来源、成因或背景从句之后并伴随额外扩展，即使这些背景真实有用，主需求聚焦仍判 `severe`；核心答案被延后不能因“最终回答了问题”而降档。若第一句不是独立直接结论，且后文同时包含成因/来源/背景与至少一类未请求扩展，必须使用 `severe`，不得降为 `moderate`。简单比较或单一事实问题在直接结论首次出现前已有一段或多句背景，且背景占回复一半或以上时，即使背景有事实价值也必须使用 `severe`。
若回复没有实质性回答或可执行内容，主体全是对话元话语、空泛评价、致谢或收束，主需求聚焦必须为 `severe`，不能因语法完整而降档。

## 边界与测试

概念解释、客服投诉和安全提醒所需的必要长度不算冗余；简单事实问答可以只用一句话，核心答案应优先于可选背景。

专项测试保留需求自带 12 条样例，并验证加权公式、兜底上限、0 分保留及建议字段。
