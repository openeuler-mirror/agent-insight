# 文本简洁性评估器

## 目标与输入

评估 Agent 回答是否用足够少的文字完成主需求，同时保留必要步骤、条件和限制。`actualOutput` 是评分对象，`caseInput` 用于判断主需求和必要信息；仅评价冗余与完整性，不重新评价事实正确性。

## 判定与输出

Judge 对表达效率、套话精简度、主需求聚焦度、信息完整性返回 `safe/minor/moderate/severe`、问题原文、中文理由、精简建议和不超过 80 字的具体总结。输出包含 `score`、`summary` 和四个 `points`，不输出卡级 `evidence`；建议写入 `EvalPoint.suggestion`。

## 加权与兜底

离散等级映射为评分点 `100/70/40/0`，四维权重分别为 `0.3/0.2/0.3/0.2`：

`B = 0.3×表达效率 + 0.2×套话精简 + 0.3×主需求聚焦 + 0.2×信息完整`

在基础加权分上应用确定性上限：表达效率 `severe` 不高于 30；套话或主需求聚焦 `severe` 不高于 40；信息完整性 `moderate/severe` 分别不高于 60/50；表达效率 `moderate` 不高于 70。最终分为所有适用上限与 `B` 的最小值并四舍五入。

上限体现需求中的兜底原则：回答过短而缺失必要信息时，不能因其它维度简洁而获得高分。各维度从轻到重升档时，综合分不会上升。

判档使用不可降档的通用锚点：简单事实问题已在一个短句中完整作答、其余内容只重复修饰或主观评价时，表达效率判 `severe`；完整操作过程可在不丢失步骤的前提下由一串叙述句整体压缩为操作路径时判 `moderate`，局部措辞拖沓才判 `minor`。直接答案出现在两句及以上不影响结论的背景之后，或未请求扩展主导回复时，主需求聚焦判 `severe`。操作型回答只有泛化动作，并在必要来源或版本、前置条件、关键选项、结果验证中缺少两类及以上信息时，信息完整性判 `severe`；缺少可选替代方案或额外确认提示不构成信息缺失。Judge 输出前需复核理由与档位一致，已经明确指出上述硬锚点时不得保留较轻等级。

## 边界与测试

概念解释、客服投诉和安全提醒所需的必要长度不算冗余；简单事实问答可以只用一句话，核心答案应优先于可选背景。

专项测试保留需求自带 12 条样例，并验证加权公式、兜底上限、0 分保留及建议字段。
