## ARM64 原生 IDE 与 JetBrains 模型地址核查

1. 分别追踪已取得官方发行包的配置存储、模型解析和实际请求参数；使用原函数或字节码的隔离探针确认地址是否生效，不能把手工构造请求当作产品接管证明。
2. 有确证入口时，在现有 `inference_config.mjs` / `inference_proxy.mjs` 中增加对应适配器；先补失败测试，再实现安装前备份提醒、字段级改写、并发变更检查及模型/Provider 变更同步。不修改用户真实配置，不重写产品代码或凭证存储。
3. 在 `test/` 与隔离目录验证多次模型调用、子 Agent 并发、失败重试；交叉核对推理服务收到的调用 ID、转发记录、采集记录与最终 Trace/LLM 节点。无法确定归属时不得生成错误跳转。
4. 若发行包未提供可确认入口，明确报告该版本的限制，并使安装结果准确区分“采集已安装”和“模型转发已接管”，保留现有 CLI / OpenCode 能力。
5. 刷新用户与开发者指南，执行相关数据链路测试和仓库测试；本轮不启动开发服务、不做浏览器验证，不以 macOS ARM64 证据代替其他操作系统验收。

本轮核查结果：原生 IDE 1.33.0 的主、子 Agent 原函数均丢弃保存的模型地址；JetBrains 2026.1014.79711813 的普通 BYOK / 企业模型构造参数 URL 均为空，extraFields 地址出站语义未证明。因此未新增 GUI 模型配置改写，也未声称完成这两种客户端的模拟推理服务验收。安装结果新增持久配置覆盖状态；collector 和聚合器阻止 GUI 本地消息 ID 被当作推理身份。

模拟推理服务覆盖的是现有 CLI 转发数据链路：同会话多调用、子 Agent 并发、503 后重试、跨会话隔离，成功请求映射到最终 LLM 节点；缺少响应 ID 的失败请求仅保留 Trace 级关联。专项 74 项通过，最终类型检查通过。全量 `npm run test` 出现其他模块失败且部分测试长时间停滞，约十分钟后停止，未获得全量通过结果。未启动 GUI、未修改用户实际模型配置、未构建镜像或推送远端。
