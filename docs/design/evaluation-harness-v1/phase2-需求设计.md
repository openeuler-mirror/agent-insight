# 需求设计

## 模块与存储

复用 Experiment、ExperimentCase、ExperimentEvalResult、Session、Execution；新能力集中于 `src/lib/evaluation-harness/`，避免在路由内混合规则和执行业务。新增不可变 EvaluationAssetVersion（用户、类型、对象标识、版本号、内容与 SHA256），EvaluationCredential（AES-256-GCM 密文和引用）以及 EvaluationAnalysis（静态报告和运行汇总）。实验 configSnapshotJson 保存完整 manifest，Case 的 caseValuesJson 保存逐轮定义，结果 evidenceJson 保存逐条判定和 Trace 引用。

版本唯一键为用户、类型、对象标识和版本号。内容与历史快照不可修改；归档仅改变目录可见性，Case 回写创建新数据集版本。数据集统一提供删除入口，仅保护内置可靠性评测集；版本化数据集删除复用全版本归档，退出目录和新实验选项，保留历史实验快照。Agent 的登记版本只用于记录外部运行配置，平台不自动切换部署。凭证不进入快照；加密主密钥由部署环境提供，缺少时拒绝持久化凭证。

## 接口与执行

`/api/evaluation-harness` 提供受用户身份约束的目录、版本创建、生成、静态分析、实验创建、结果、回写和趋势查询。业务分层实现，可供脚本和 UI 使用；普通实验接口保持兼容。实验和版本分析页面通过专用组件接入，不新增独立侧栏中心。

执行适配器接受目标版本描述与 Case 消息，返回会话标识、逐轮输入/输出、调用和路由事实；预期答案不发给被测目标。Demo 在独立进程执行，HTTP 适配器使用显式 endpoint。已有 Trace 评估必须保留来源身份。输出在送往 Judge、UI 或持久化前清理常见凭证字段。每条尝试独立记录，取消后不会恢复为完成；重试仅处理连接错误、429/5xx 与超时。

规则执行器读取结构化逐轮期望，产生 pass/fail/unknown。未知证据与评估服务错误不伪装成业务失败，也不产生通过分。关键规则失败可跳过语义 Judge；其他规则先运行，再运行 LLM。评估结果落现有表，以正常 Trace 深链定位。

## 页面

实验新建四步沿用实验设计、Trace 来源、预期答案、评估器与执行。Agent/版本和数据集/版本分别同一行；Agent 可新增登记版本，数据集只选已有版本。逐轮配置不另设公共规则重复输入。实验详情集中展示失败与优化入口。评估器使用预置目录。版本组合可展开运行历史，趋势只在模型、评估器和测试条件一致时判断变化。

## 2026-09-07 统一实验流程

新建实验仅保留四步：实验设计、Trace 来源、Case 与预期、评估器与执行。统一选择已登记目标、已有观测/客户端 Agent、版本化评测集和原有数据集。名称与版本仍分开；接入目标及新增版本功能保留。执行能力由已选对象决定，不以“多轮/普通”页签区分实验。原有客户端生成、历史 Trace、监听、模型对比及 Skill 嵌入式向导继续复用原执行路径。

版本化评测支持新执行和已有 Trace 回放。回放明确绑定 Case 与原 Execution ID，服务端验证当前用户、目标名称和会话归属；冻结逐轮实际证据与内容散列，复用原 Trace ID，禁止重新调用 Agent 或新造 Trace。仅采集到的工具、路由、状态参与判断；缺失证据保持 unknown，不从 Case 预期推导实际行为。回放和新执行在趋势条件中分组，防止混合解释。

普通数据集继续使用完整原有字段与评估器；版本化 Case 继续保留多轮输入、工具规则、分类/难度/标签、评估器版本、静态检查、关键失败门槛、Badcase 分析及修订回归。接口扩展复用已有 `/api/evaluation-harness`，不改 Prisma schema。外部接入目录、真实模型、预约及分布式等原未验收范围不因页面合并被宣称完成。

## 2026-09-07 版本分析主入口完善

侧栏版本分析默认打开实验版本视图，旧 Trace 标签分析作为辅助页签保留；旧 `/version-analysis/experiments` 地址兼容同一页面。首屏自动选有运行记录的 Agent 和评测集。每个版本组合一行，显示最近实验、状态、通过率及可展开的完整历史。趋势固定其中一方版本，按评估器、模型、执行参数和 Case 范围分组，默认采用可比较版本最多的条件，每版本取最近一次已完成且有评分的实验；缺失评分不合成为零分。版本组合表不随趋势条件隐藏记录。

实现复用现有目录 API，无新增 API / Prisma 变更。验证覆盖默认条件选择、两种比较方向、失败/缺失评分、历史保留和对象隔离，并在现有演示账号浏览器核对实际记录、实验跳转及 Trace 标签入口。目录 API 当前只返回最近 100 次运行，页面明确展示此范围。

2026-09-07 调整：根据用户反馈，移除难以理解的“从已有 Trace 提取目标定义”辅助功能（界面和服务操作）。目标定义、版本快照、静态分析与生成评测集的需求保留，通过手动接入或目标目录获取定义。已有 Trace 回放评估保留。

2026-09-07 界面收敛：新建实验复用原有步骤条和“实验类型”的“无变量 · 单组 / LLM 对比”标签式选择、A/B 模型配置及自动补全，取消新增的“实验目的”下拉。版本化 Case 的模型对比仍按原生数据集/Trace 适配范围门控。移出实验设计中的“执行 Skill 静态分析”按钮；Skill 工作台已有静态质量评估（结构、描述、流程、安全及工程健壮性）。外部目标描述的简化静态检查与工作台完整 Skill 检查不等价，现有 static 服务保留，但不在实验设计中作为第二套同名入口展示。


### 2026-09-07 统一 A/B 对比扩展

现有实验 create 配置增加可选 comparison：dimension 为 agent/skill/llm/evaluator。Agent/Skill 指定 targetBId；Skill 限制同一 Skill 的两个版本。LLM 指定 modelA/modelB，执行端必须回报匹配 model，拒绝只记录标签却未切换模型的执行。Evaluator 指定 evaluatorBIds，A 为主 evaluatorIds，两组对完全相同的 Trace 独立评分，关键停止不跨组传播。其他资产和 Case 范围固定。第一版 Agent/Skill/LLM 的版本化执行使用 generate；已有 Trace 对比复用原生配对流程，评估器可直接回放冻结证据。

Agent/Skill/LLM 两侧 Case 使用原有分组关系；评估器仅保留一份 Case/Trace，结果按各组评估器集合投影。报告保存分组配置、通过率、有效配对数、逐 Case 判定差异及实际输出；未知/运行失败不伪造分数，不用整体平均掩盖组间差异。对比实验不混入单组版本趋势。

### 2026-09-08 评测集对比与共享条件收敛

在已有 A/B 能力上新增 `comparison.dimension = dataset`。第一步把实验类型放在实验名称下，先确定对比模块，再展示对应布局。只有选定模块存在 A/B 两份配置，其他模块只维护一份共享条件：Agent 对比共享 Skill 和模型配置；Skill 对比共享执行接入与模型；LLM 对比共享目标版本；评估器对比共享同一份 Trace；评测集对比共享目标版本、模型和评估器。除评测集对比外，两组还共用相同 Case 子集和预期答案。并发、超时、重试及通过率门槛统一配置。后续步骤只读沿用所选对象、版本，需要更改时返回实验设计；开始实验时冻结配置。

评测集对比沿用现有 `/api/evaluation-harness`，不新增 API 或 Prisma 模型。A 组使用主配置的 `datasetId` 和可选 `caseIds`，B 组使用 `comparison.datasetBId` 和可选 `caseBIds`。两组必须选择不同的已发布版本，可以来自同一个评测集，也可以来自不同评测集；分别校验用户归属、归档状态和 Case 范围。第一版不直接比较普通未版本化评测集或未发布草稿。Case 子集可以不同且数量不必相同，每组至少选择一个 Case。执行使用 `generate`，同一目标分别执行两组样本，生成各自 Trace。

第二步分别选择 A/B Case，运行参数共用；第三步分别展示两组首次输入、最终预期输出和只读逐轮规则；第四步选择一套公共评估器及门槛。Case 修改仍在数据集详情逐条保存草稿、统一发布新版本，实验向导只选择已发布内容。manifest 中每组保存目标、评测集快照、Case 范围和评估器 ID，执行器按 Case 所属组读取相应评测集，公共执行条件不另建副本。`comparison` 严格校验所选维度允许的字段，拒绝夹带其他模块的 B 组配置；Agent/Skill 目标内包含的非对比模型配置须一致，Agent 对比还核对 Skill 配置，Skill 对比核对执行接入。

详情按组计算总 Case 数、通过率和未评完整数量。对同一评测集的不同版本按 Case ID 对应；不同评测集按逐轮输入对应。对应后继续比较各轮输入、预期输出和规则，定义变化标为 `changed`，单组独有标为 `a-only` / `b-only`；双侧列可以缺一侧，仍展示存在侧的结果与详情入口。只有定义一致且双侧有完整判定的 Case 参与有效配对数和 B−A 判定差值；缺侧、规则变化及 unknown 不进入差值。页面明确各组通过率反映各自测试范围，避免把新增难例或更改验收标准误判为 Agent 改善或退化。A/B 实验继续从单组版本趋势中排除。

按原条件创建回归恢复 A/B 评测集版本及各自 Case 子集；用户改选评测集或版本后，改选侧重新按该版本选择 Case。普通 Trace 对比返回第二步时保留同一配置下的共享标注，变更 Agent、实验类型、组值或数据集内容时清除旧标注，避免把旧预期答案套到新实验条件。

### 2026-09-08 Agent / Skill 交互纠偏

产品界面中 Agent 始终是执行主体，Skill 是该 Agent 使用的配置；不暴露后端将两者复用为 target 资产的分类。各对比统一 A/B 卡片及单一共享条件区。新 Skill 对比采用共同 Agent + 同 Skill 的两个版本，通过加载确认协议实际执行；旧直接 Skill 模式保留历史兼容。该修改是实现界面和执行语义的修正，没有新增 Prisma 字段或 API 路由。
