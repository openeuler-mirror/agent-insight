# Agent 测评闭环第一版

2026-09-06。基于 master `358c0313`；参考 open-fin/agentgate 的 review/refactor-1-architecture 分支 architecture.md 和 product-requirements-zh.md。产品入口遵循已确认的 Agent Insight 高保真，不复制 AgentGate 的独立产品导航。

## 交付范围

- 实验内选择 Agent/Skill、已有版本或用户声明的新 Agent 版本；外部版本和用户登记版本明确区分，不声称自动部署或检测变更。
- 测评集独立版本；实验只能选已有版本；编辑用例另存版本，历史不变。支持多轮输入、输出预期、工具规则、路由、状态、类别、难度和标签。
- 真实 Demo Agent/Skill 和通用 HTTP 执行适配；同一 Case 连续多轮会话，收集工具参数、输出和路由。在统一实验向导中保留现有客户端下发和 Trace 页面。
- 优先执行确定性规则，支持关键失败中止后续 LLM；复用已有模型配置并通过 OpenAI 兼容协议调用，新增加密凭证引用以满足公共/私有凭证选择。
- 固定目标、数据集、评估器和执行配置快照；并发、超时、取消、基础设施重试；业务失败不重试。
- 结果按 Case、评估器、类别、难度汇总；证据缺失不计作通过；规则门槛和关键失败形成验收结果。
- 实验级 Badcase 聚类、观测路由混淆矩阵、证据与建议；修改 Case 另存数据集版本并创建回归。
- 静态分析检查描述完整性、技能重叠和提示词一致性，独立标记静态风险。自动生成测评集使用实际描述/提示词和 LLM，生成后人工审阅。
- 版本分析按 Agent 与数据集筛选，版本组合一行、重复运行保留历史，固定其中一方比较另一方。

## 延后

复合评估器权重语义、预约和公共队列、多模态、完整血缘图、自动发布/CI/CD、自动修改外部 Agent；这些与参考文档延后范围一致。第一版建议由人审阅、外部修改并登记版本。

## 验收

单元测试覆盖逐轮规则、未知状态、版本不可变、重试语义、凭证保护和汇总；集成测试使用隔离数据库与真实 HTTP Demo 服务；浏览器验证新建、运行、Trace、Badcase 回写、回归和版本趋势；LLM 使用真实可用连接验证生成与评分，没有连接时明确未验证并请求配置，不用 fake judge 冒充真实验收。

## 第一版实现边界

当前新增能力以原实验/数据集/评估器/版本分析页面的版本化入口提供，使用既有 Experiment、Case、结果表和原生 Trace；客户端下发与历史 Trace 评估复用原能力，并归入统一四步向导。新版多轮执行目前接入独立 Demo 和通用 HTTP 目标，真实业务客户端需提供该 HTTP 适配接口。Demo 从独立服务的 `/targets` 读取目标及版本定义，平台保存快照；不在平台管理外部部署。

静态分析采用描述完整性、文字重叠、Prompt 对齐和兜底说明启发式；动态 Badcase 按失败检查类型分组，提供对应排查方向及真实路由矩阵，尚未实现语义聚类和自动根因定论。LLM 自动生成及逐轮 Judge 已实现 OpenAI 兼容调用和契约检查，2026-09-09 已使用真实 DeepSeek 模型验收自动生成、人工保存和公共/私有连接评分。第一版限定单服务进程和 SQLite。

## 2026-09-07 流程统一后的需求保留清单

本次仅合并实验流程及补充已有 Trace 回放，不删除交付范围，也不把尚未验收的功能改写为已验收。接入目标和用户登记版本保持原样。

| 要求 | 统一后位置与边界 |
|---|---|
| Agent / Skill 与评测集版本 | 第一步，本体和版本分别选择；未登记对象明确标识 |
| 单轮、多轮与每轮输入、输出、工具规则 | Case 与评测集内容决定轮数；第三步查看、编辑并另存版本 |
| HTTP / Demo 执行、客户端下发、历史 Trace | 第二步按所选对象和评测集的已有能力提供；原生客户端需在线，HTTP 逐轮执行使用版本化 Case |
| 路由、审批红线、工具参数顺序、结束状态 | 第四步规则评估；已有 Trace 也进入逐轮规则链 |
| 原生评估器、参考答案、Tool / Skill 目录门控 | 原有评测集的第三、四步；不把多轮规则降为最终输出比较 |
| 静态分析、自动生成、数据集版本及导入导出 | 原位置保留；真实模型生成、人工审阅保存及执行已验收 |
| 结果证据、Badcase、回写、回归、版本趋势 | 详情和版本分析保留，回放与新执行按不同条件比较 |
| 监听、模型对比、Skill 内嵌实验、可靠性下发 | 复用原生向导与执行链；不因移除分类页签删除 |

目前仍有适配边界：只有观测记录的 Agent 不能直接执行版本化多轮 Case；需要登记现有 HTTP 接入目标。原有客户端与原有数据集保留原版本语义，不能宣称已经具备新资产目录的完整版本追溯。此限制不能通过隐藏文档需求处理，后续适配继续保留在需求范围。


## 2026-09-08 演示版逐项核对（当前结论）

本节覆盖上文历史方案中的界面范围。依据为 AgentGate `review/refactor-1-architecture` 分支的 [产品需求](https://github.com/open-fin/agentgate/blob/review/refactor-1-architecture/docs/product-requirements-zh.md) 与 [架构设计](https://github.com/open-fin/agentgate/blob/review/refactor-1-architecture/docs/architecture.md)，以及用户本次九项补充。目标分支为 `upstream/refactor-for-nh`。

“真实执行”指平台通过 HTTP 请求独立 Demo Agent，持久化实际输出和 Trace，再执行评估器；Demo Agent 的业务决策采用确定性规则，因此不能证明真实大模型的业务效果。2026-09-09 已补充浏览器实际创建数据集/评估器版本、实验执行、Case 证据、回写、回归及趋势验收；真实 LLM 生成、审阅保存及公共/私有评分也已补验；以下矩阵为当前状态。

| 需求 | 当前入口与实现 | 覆盖程度 / 验证边界 |
|---|---|---|
| 外部 Agent/Skill 与版本 | Agent 与 Skill；读取目录，保存外部 ID、外部版本、规范化内容散列和快照 | 已有 HTTP 目录与独立 Demo；未连接真实客户平台。外部撤回的内容不可再选，旧快照保留 |
| 总览 | 数量、今日/运行中/执行失败任务、最近通过率和失败类型、最近任务 | 已实现；任务数量按账号全量统计，趋势与失败分布限最近 100 次实验 |
| 自动生成测评集 | 读取实际 Prompt、Skill 描述/Prompt、工具、可选输入输出 schema；调用真实模型生成分类、多轮、难度、标签和期望 | 真实模型生成 8 条 Case，浏览器审阅保存 v1，并选单轮/多轮各一条实际执行；生成预期可能偏离真实业务，必须人工审核 |
| 数据集管理 | 卡片、对象版本、JSON/Excel 导入导出、创建、复制、删除/恢复、逐条编辑/撤销、发布版本 | 已实现；草稿在当前浏览器，发布后保存到服务器；历史实验固定旧版本 |
| 单轮/多轮与 Case 元数据 | 首次输入、最终预期；逐轮输入输出、路由、工具名称/参数/顺序、禁止调用、字段/结构、分类/难度/标签/备注 | 已实现；单轮和多轮共用流程 |
| 规则评估器 | 规则子集、版本、关键失败跳过后续 LLM，评分点/分数/证据/建议 | 实际 HTTP 执行及规则评分通过；业务失败与未知区分 |
| LLM 评估器与公共/私有连接 | 评分 Prompt、逐轮判定/原因、确定性汇总分、公共连接和加密私有连接 | 真实公共/私有模型对同一 Trace 分别评分成功；逐轮分数、原因与证据已在浏览器核验。私有密钥加密保存、不回显、不进实验快照 |
| 复合评估器 | 同一实验选择多个规则/LLM，规则优先，全部通过才通过 | 基础多评估器组合可用；独立权重/表达式未实现，PRD 5.4.3 明确允许第一阶段先保留定义 |
| 任务执行与状态 | 四资产/版本、共享 IP/模型、并发/超时/重试、立即执行、取消、执行状态、尝试记录 | HTTP 实跑通过；预约和持久队列未实现，属于第二阶段 |
| 四类版本 A/B | 第一步只展开对比项，另外三项共享；详情 A/B 总览和 Case 结果 | Agent/Skill/评估器/评测集实际请求和分组结果通过；评估器组共用 Trace；数据集变更 Case 不算 Agent 改善 |
| 总体指标 | 通过率、按评估器/分类/难度、路由、所选 Skill 触发、工具规则、延迟、执行失败、Badcase | 已实现基础指标；总分采用通过率，不是独立加权综合分。Skill 触发是“该 Skill 应/不应触发”的二元判断，与多分类路由区分 |
| Case 详情与 Trace | 原实验 Case 列表、结果/轨迹两类评估结果，真实逐轮输入输出、工具参数与返回 | API 与浏览器逐轮证据验证通过；规则及真实 LLM 结果均已验收 |
| Case 回写与回归 | 修改分类/难度/备注/规则后发布新数据集版本，实验级回归和单 Case 重跑 | 真实回写、旧快照保留、单 Case 执行通过 |
| 调优中心 | 实验详情“分析问题并优化”，按失败检查类型归类、分布、代表 Case、证据/建议、路由混淆矩阵 | 基础规则归类可用；不声称完成语义聚类或可靠的自动因果根因定位；不自动修改外部 Agent |
| Skill 静态分析 | 独立页面，检查描述重叠、职责/兜底说明、Prompt 对齐风险 | 已实现确定性启发式，独立运行无需执行 Case；结果仅为风险提示，未实现语义冲突模型 |
| 版本与回归关系 | 四行对象选择，勾选版本变化维度、实验组合记录与趋势；完整版本/参数/连接类型快照 | 四维真实记录和趋势通过；完整血缘图/接受优化建议闭环属于第二阶段 |
| 架构中 CLI/API 与标准化轨迹 | 既有 CLI、HTTP 适配、统一逐轮证据、原生 Trace 存储 | 保留契约；新建实验界面按用户要求只选 Case，不呈现已有 Trace 回放分支 |
| 后续增强 | 预约队列、独立复合权重、多模态、完整血缘、CI/CD 门禁 | 尚未开发；按 PRD 阶段划分保留在清单中，未用无效 UI 声称覆盖 |

本版隐藏 RAS/故障注入、通用运行监控、Skill Copilot/工作台优化、无关评估器、模型费用、Trace 标签管理、历史 Trace 选取与监听，以及独立 LLM 对比的页面入口。保留底层代码和历史数据，避免演示裁剪破坏存量实现。输入/输出 schema 是可选的外部事实，未提供时不自动补造。

第一阶段演示核心流程已于 2026-09-09 完成 HTTP、浏览器及真实 LLM 验收；实际客户 Agent 接入和第二阶段增强不在本次验收结论中。最新截图见报告。详见 [本次测试报告](test-report/report.md)。
