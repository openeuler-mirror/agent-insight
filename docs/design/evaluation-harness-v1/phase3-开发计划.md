### 复现方式

测试脚本要求数据库路径包含 `harness-e2e`，应使用单独的数据目录。先创建空 SQLite 文件，并通过 `DATABASE_URL=file:/绝对路径/harness-e2e/data/witty_insight.db npx prisma db push` 初始化当前 schema，再运行以下流程；`AGENT_INSIGHT_DATA_DIR` 指向该隔离根目录。

1. 启动 `node examples/evaluation-harness/server.mjs`，服务端设置 `EVALUATION_DEMO_URL=http://127.0.0.1:4319`。
2. 运行 `node --import tsx scripts/evaluation-harness-e2e.ts` 和 `node --import tsx scripts/evaluation-harness-resilience-e2e.ts`。
3. 使用 `AGENT_INSIGHT_DEV_PORT=3019 bash scripts/develop_start.sh` 启动隔离开发服务，或构建并运行 standalone 产物；API 脚本默认访问 3019，也可设置 `AGENT_INSIGHT_URL`。
4. 运行 `node --import tsx scripts/evaluation-harness-api-e2e.ts`，再在浏览器实际操作新建、Case 编辑、Trace 和版本回归。

最终接口验收曾发现 Trace 写入误用不存在的 sessionId 字段；已改用原模型的 agentSessionId 并添加 Prisma 输入类型约束，重新通过真实 HTTP 执行与 Trace 入库验证。

新增门槛边界断言：非关键规则失败和模型异常同时出现时，即使阈值为 0 也不能放行；未完成的必需评估使得分为空，按关键规则配置跳过的 LLM 单独标记为 skipped。
