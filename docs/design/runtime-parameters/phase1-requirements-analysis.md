# Runtime 参数配置需求

将参数默认值、预设、校验和交付方式声明在 Runtime YAML，执行客户端上报生效定义，平台提供通用编辑器。平台必须遵循执行端原有参数名称、类型、层级和输入入口，不能自行分组、拆分或重命名业务配置。参数属于执行 Runtime，可跨 Benchmark 使用。

不修改 Prisma、不新增 API 路由。已有实验快照、客户端能力 JSON 和执行目标接口承载新字段。

## 通用参数能力

用户已确认采用树形编辑与 JSON 编辑双视图，以及 JSON 粘贴/文件导入、差异预览、导出和参数模板。两种视图维护同一份配置；无效草稿保留但阻止创建实验。参数结构由执行端声明：平铺应用仅编辑根级标量，只有原生支持嵌套配置的应用才启用对象、数组和 null，保留原格式与层级。后续类似 OpenCode 的 YAML 配置接入必须遵循其实际文件格式和入口，不能因平台具有 JSON 编辑能力就自行改为 JSON、发明配置层级或宣称已有 YAML 交付。

MCTS 使用平铺 CLI 原名，JSON key 仅省略 `--` 前缀：`max-iters`、`branching`、`max-turns-init`、`max-turns-step`、`max-turns-author`、`max-turns-author-step`、`token-fuse-limit`。新增执行端已支持的业务参数时，在平台增加同名 key/value 即直接透传，无需逐字段维护映射或修改平台代码。模式、Runtime、Case、数据集和输出位置等调度参数由平台生成，禁止用户覆盖。MCTS 不允许对象、数组和 null，不增加 `search`、`solver`、`author` 等自造层级。

配置按完整对象保存，导入整体替换。创建实验冻结最终值，复用和重跑不重新补入最新默认值。模板按用户和 Runtime 隔离，保存不可变修订，通过已有用户设置接口和 JSON 存储承载。已有实验快照原样保留；复用旧 MCTS camelCase 参数时，仅按既有兼容规则提供名称转换预览，用户确认后生成新草稿，不能静默改写历史。

执行端保留稳定 JSON 文件/参数通道及已有声明式 CLI 映射模式，分别用于实际支持这些接口的应用。MCTS 使用原名 CLI 直传。平台和客户端首次启用新能力时需同步升级；OpenCode 当前仍保留空参数定义，不增加未经其执行端确认的配置交付方式。
