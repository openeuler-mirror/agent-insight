## 0. 一句话现状

P0 能力（FR-001~010）的**功能形态全部到位、端到端可用**；但其中若干 P0 指标目前是**确定性降级版**，且因**采样回填未接真 judge**，**评测覆盖率长期为 0%、分数多由确定性推断**。P1/P2 多为文档明确的第二阶段，按计划未做或以 N/A 占位。

**下一阶段目标不是加功能，是把现有每个数字做"可信"**：让分数尽量是"评出来的"、可追溯到样本与口径、并显式带不确定性。

### 已落地的"文档假设修正"（实现期发现，见代码注释）

1. `buildFaultPathSteps` 不产 `status==='error'` → 错误步改由内容信号判定，且 **LLM 步只看结构化元信息**（"谈论失败"≠"步骤失败"，防分析类 agent 误报）。
2. `Execution.isAnswerCorrect @default(false)` → 未评测 trace 不得判失败；确定性口径=具体失败信号优先→answerScore→显式 true→打底成功。
3. 动态 dedupKey 近乎逐条唯一 → `/report` 问题项封顶 100，全量计数走 `problemCounts`。
4. 错误维卡片改显分数（无错 trace 占比），消除"次数+达标徽章"口径混搭。

## 2. 下一步：以"数据可信度"为纲（不增呈现）

产品判断：**页面呈现已足够，下一阶段只做"让数据可信"，不加新视图/新维度。** 按对可信度的贡献重排（而非按 FR 编号）：

### 第一梯队 — 让分数"是评出来的"（解锁评测覆盖）
- **NFR-001 把回填 `defaultEvaluator` 接成真 judge（单模型级联）。** 解锁面最大：评测覆盖↑、FR-002 完成度 judge 加成、过程维 P1（FR-011/013）拿到轨迹分、归因 LLM 化都连带活起来。
  - 级联结构：规则层(L0) → 按簇判一次复用(L1) → 单模型便宜档 1-pass+步骤摘要(L2) → 自一致性 k-vote 升级(L3)；预算按 影响度×(1−覆盖) 排序。
  - 触发与执行解耦：QM 只出"该评谁"的优先级信号，执行穿评测层写回 `Execution.answerScore`（规范字段，单一 SoR）；读路径保持零模型调用。

### 第二梯队 — 让每个数"可追溯、带不确定性"
- **NFR-006 逐项溯源 hover**：判读/维分/问题项可 hover 看 n、计算口径、关联 trace。
- **FR-018 置信带 / 占比置信区间**：judge 抽样指标画带，占比按 n 叠 CI；样本越少带越宽。
- **归因可信化**：接 `attribution-prompt` LLM 归因（对齐四分类）+ 置信度，归因标签 hover 显来源（规则兜底 / 诊断投票 / LLM）与置信度。

### 第三梯队 — 让确定性信号更准（降低对模型的依赖）
- **FR-003 安全**：正则启发式换检测件（Presidio/PII、注入检测）。
- **FR-004 工具正确性**：补参数语义/不相关工具调用判定（可 AST 化的走规则）。

### 明确缓做（只增表面、不增可信度）
FR-017 挫败信号、FR-015 语义聚类新视图、FR-014 成本单位切换/自定义日期、状态全页过滤、QualitySnapshot 跨窗口基线——除非可信度梯队完成后有余力，否则不排期。

## 3. 贯穿原则（可信度护栏）

- **读路径零模型调用**（D-001）：所有模型判定走后台回填，不在 `/report` 同步跑。
- **单一 SoR**：QM 触发的分析穿归属模块、写 trace 规范字段（answerScore / TrajectoryEvalResult / AgentDebugReport），靠 executionId + interactionsHash 去重，永不建并行存储。
- **决策归位**：怎么评（规则/模型）由评测器在评测时按 trace 决定；QM 只读结果 + 出"先评谁"的优先级。
- **不确定即标注**：覆盖率低/样本不足/确定性打底，一律置灰或显式标注，绝不让推断分冒充确定结论（NFR-002，已落地，继续坚持）。
