# 持续优化 · Skill

Skills 是 Agent Insight 中最有代表性的能力之一。你可以把它理解为一类可被 Agent 调用、可版本化、可分析、可优化的能力资产。

> **Note**
> 在 Agent Insight 里，Skill 不只是 Prompt 片段，而是围绕
> `SKILL.md`、脚本、参考资料、评测结果和版本发布构成的完整工程对象。

## Skills 适合解决什么问题

- 把零散经验沉淀成可复用能力
- 让 Agent 在合适时机自动调用特定能力
- 用结构化方式管理 Skill 的版本、分析结果和优化迭代
- 对“这个 Skill 到底有没有效果”给出更可验证的结论

## 一个 Skill 包含什么

一个完整 Skill 通常由以下部分组成：

- **SKILL.md**：主文档，定义用途、触发条件、输入约束和执行方式
- **scripts/**：可执行脚本，供运行时调用
- **references/**：参考资料或上下文文档，供模型理解使用
- **版本信息**：每次发布都会形成一个可追踪版本
- **分析结果**：包括静态合规、触发分析、A/B 测试、用例分析等

## Skills 的典型生命周期

在平台中，Skill 通常会经历 4 个连续环节：

1. **管理**
   先把 Skill 作为资产纳入平台，查看列表、版本与状态。
2. **生成**
   根据需求描述自动生成 Skill 初稿。
3. **分析**
   判断 Skill 是否触发正确、结构是否规范、效果是否真的提升。
4. **优化**
   基于问题和结果反馈，迭代出新的 Skill 版本。

> **Tip**
> 如果你想把持续优化中的 Skill 能力快速用起来，最推荐的顺序是：
> 先看总览页，再按“管理 → 生成 → 分析 → 优化”逐步使用。

## 工作台怎么使用

从侧边栏进入 **持续优化 → Skill** 后，左侧是 Skill Copilot，右侧是当前 Skill 的固定工作区。新会话从以下任一方式开始：

- **生成一个 Skill**：通过对话澄清目标、输入输出、适用边界与安全约束；生成完成时自动应用静态质量规则。
- **上传已有 Skill**：上传目录先形成未发布快照，不会静默修改或直接写入正式版本。
- **从 Skill 管理中心选择**：同时选择 Skill 与精确版本，作为当前会话的工作版本。

Skill 准备好后，左侧提供 **Skill 评估、Skill 实验、Skill 优化** 三个确定性操作。右侧四个页签分别承担：

| 页签 | 用途 |
| --- | --- |
| Skill 详情 | 查看文件树、内容、工作版本与未发布状态 |
| Skill 评估 | 检查结构、描述、流程和安全约束，不运行真实任务 |
| Skill 实验 | 以触发分析、用例分析或 Skill A/B 预设运行真实实验 |
| 优化记录 | 查看证据、候选快照、复测状态与最终发布结果 |

历史会话会恢复对话、工作 Skill、版本、最后页签与已有任务状态，不会因为重新打开而自动重跑。生成、评估、实验、优化与候选复测一旦由服务端接受，就会继续在后台执行；切换 Skill 页签、离开 `/skills` 或关闭当前页面只会停止该页面的实时刷新，返回后会从持久化状态继续展示。

长期资产管理已移动到 **配置 → Skill 管理中心**；旧 SkillHub、生成、评测和优化深链接在兼容期继续可用。

## Skill 实验的四步流程

**触发分析、用例分析和 A/B 测试**共用同一个四步实验向导，只是默认数据、对比方式和评估器不同：

1. **实验设计**：确认名称、Agent 和可选数据集。触发分析可由 AI 生成应触发/不应触发用例，并支持分组编辑、转换、新增和删除；A/B 只提供 Skill 版本对比。
2. **Trace 来源**：可选择已有 Trace，也可按数据集 Case 生成 Trace。触发分析和 A/B 默认生成，用例分析默认选择已有 Trace。
3. **预期答案**：生成 Trace 时检查本次实验的数据集快照，不回写原数据集；选择已有 Trace 时可导入匹配标注、手工标注或存为新数据集。
4. **评估器与执行**：检查冻结摘要和数据前置条件，再使用当前预设的评估器启动实验。触发分析只使用预置评估器 **`skill-trigger-analyzer`**，逐条比较“应触发”标注与真实路由结果，每条 Case 只生成一个“触发准确率”评分点。误选与漏选是同一评估结果的分类统计，不会调用任务完成度、结果准确性或轨迹质量评估器。

选择已有 Trace 时，实验评估已发生的真实轨迹；选择平台生成时，触发分析会在隔离环境中固定当前版本并让 Agent 自主决定是否调用 Skill，用例分析会加载当前版本执行任务；这两类都只有一个实验组，A/B 测试才对同一批 Case 运行两侧版本。

启动后仍留在 Skill 实验页签内，可查看执行进度、四个运行阶段、已冻结配置和 Case/评估明细。点击 Case“详情”时只替换 Skill 工作台右侧内容，左侧 Skill Copilot、当前 Skill 和顶部页签保持不变；返回时回到当前 Skill 实验详情，不会进入全局实验页。用户点击开始后，创建到执行接收之间的内部 `draft` 在 Skill 工作台统一呈现为“运行中”；执行请求被服务端接受时会立即把持久化状态推进为 `running`，异步启动失败则转为失败，尚未被接受的启动失败会自动回滚。Skill 实验记录只出现在当前 Skill 的实验列表；全局“评估与实验”保持独立，不展示触发分析、用例分析、Skill A/B 或候选复测记录。

## 发布门禁

- 生成或上传得到的是工作快照。平台会按当前全部文件的内容 hash 匹配静态评估，只有评估执行完成且不存在 `high` 问题时，发布按钮才可用。
- “评估执行成功”不等于“质量门禁通过”：评估中、评估失败、文件已变化、存在高风险问题和门禁通过会分别展示。文件发生变化后必须重新评估；评估进行期间不能发布。
- 门禁未通过时，可在 Skill 详情或 Skill 评估中点击 **AI 修复问题**。优化 Agent 会读取本次问题清单、修改未发布工作快照并自动复验；修复结果仍需用户检查，平台不会自动发布。正式版本发起同一操作时则生成独立优化候选，继续执行复测与发布流程。
- 优化得到的是候选版本，不覆盖当前正式版本。
- 优化候选必须使用关联实验的冻结配置完成复测；复测通过后才出现发布操作。
- 发布始终要求二次确认。复测失败、优化失败和放弃记录都会保留。

## Skills 和 Agent 的关系

这两个概念经常被一起提到，但职责不同：

- **Agent** 是执行主体
- **Skill** 是 Agent 可调用的能力单元

一个 Agent 可以加载多个 Skill；一个 Skill 也可能被多个 Agent 复用。

因此，Skills 模块本质上是在做“能力资产治理”，而不仅仅是做一次性的 Prompt 编辑。

## 什么时候该创建 Skill

以下情况通常适合把能力沉淀成 Skill：

- 某个任务会被反复执行
- 调用条件可以被相对清晰地描述
- 你希望多个 Agent 复用同一套能力
- 你希望对这项能力做独立分析和优化

不太适合沉淀成 Skill 的情况：

- 只是一次性临时实验
- 能力边界非常模糊
- 还没有稳定场景，不知道何时该触发

## 建议的使用顺序

### 第一次接触 Skills

建议按这个顺序体验：

1. 进入 Skill 工作台，从管理中心选择一个已有资产
2. 用一个真实需求试一次 Skill 生成
3. 在工作区打开 Skill 评估或 Skill 实验查看结果
4. 再进入 Skill 优化理解候选、复测和发布流程

### 已经有现成 Skill

如果你已经有 Skill 资产，可以这样用：

1. 先在 **配置 → Skill 管理中心** 确认列表与版本
2. 回到 Skill 工作台选择该精确版本并运行评估或实验
3. 对问题集中的版本发起优化，复测通过后再确认发布
