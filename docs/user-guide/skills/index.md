# 持续优化 · Skill

Skills 是 Agent Insight 中最有代表性的能力之一。你可以把它理解为一类可被 Agent 调用、可版本化、可分析、可优化的能力资产。

> **Note**
> 在 Agent Insight 里，Skill 不只是 Prompt 片段，而是围绕
> `SKILL.md`、脚本、参考资料、评测结果和版本发布构成的完整工程对象。

## Skills 适合解决什么问题

- 把零散经验沉淀成可复用能力
- 让 Agent 在合适时机自动调用特定能力
- 用结构化方式管理 Skill 的版本、分析结果和优化迭代
- 对“这个 Skill 到底有没有效果”给出更可验证的结论

## 一个 Skill 包含什么

一个完整 Skill 通常由以下部分组成：

- **SKILL.md**：主文档，定义用途、触发条件、输入约束和执行方式
- **scripts/**：可执行脚本，供运行时调用
- **references/**：参考资料或上下文文档，供模型理解使用
- **版本信息**：每次发布都会形成一个可追踪版本
- **分析结果**：包括静态合规、触发分析、A/B 测试、用例分析等

## Skills 的典型生命周期

在平台中，Skill 通常会经历 4 个连续环节：

1. **管理**
   先把 Skill 作为资产纳入平台，查看列表、版本与状态。
2. **生成**
   根据需求描述自动生成 Skill 初稿。
3. **分析**
   判断 Skill 是否触发正确、结构是否规范、效果是否真的提升。
4. **优化**
   基于问题和结果反馈，迭代出新的 Skill 版本。

> **Tip**
> 如果你想把持续优化中的 Skill 能力快速用起来，最推荐的顺序是：
> 先看总览页，再按“管理 → 生成 → 分析 → 优化”逐步使用。

## Skill 工作区有哪些页签

从侧边栏进入 **持续优化 → Skill** 后，顶部通过四个页签切换既有能力。切换页签不会改变各页面原有功能和数据，只是把原来分散的入口收敛到同一个工作区。

### SkillHub

这是 Skill 资产总入口，主要用于：

- 查看当前 Workspace 下的 Skill 列表
- 搜索 Skill 名称和描述
- 查看当前激活版本
- 从这里进入上传、AI 生成或企业同步等创建方式

对应文档： [Skills 管理](./manage)

### 生成

当你只有一个需求描述，还没有整理出 Skill 文件结构时，可以从这里开始：

- 用自然语言描述想让 Agent 学会什么能力
- 由 AI 起草 Skill 内容
- 生成后继续保存、发布或进入后续分析

对应文档： [Skills 生成](./generate)

### 评测

分析页负责回答“这个 Skill 到底好不好、问题在哪”。它关注的不是单一分数，而是多个维度：

- **用例分析**
- **静态合规**
- **触发分析**
- **A/B 测试**

这些维度共同决定当前 Skill 的健康状态和下一步动作。

对应文档： [Skills 评测总览](./evaluation/overview)

### 优化

优化页面向已经存在的 Skill 版本，帮助你：

- 选择具体 Skill 和版本
- 查看当前版本文件内容
- 进入优化工作流
- 形成新的版本候选

对应文档： [Skills 优化](./optimize)

## Skills 和 Agent 的关系

这两个概念经常被一起提到，但职责不同：

- **Agent** 是执行主体
- **Skill** 是 Agent 可调用的能力单元

一个 Agent 可以加载多个 Skill；一个 Skill 也可能被多个 Agent 复用。

因此，Skills 模块本质上是在做“能力资产治理”，而不仅仅是做一次性的 Prompt 编辑。

## 什么时候该创建 Skill

以下情况通常适合把能力沉淀成 Skill：

- 某个任务会被反复执行
- 调用条件可以被相对清晰地描述
- 你希望多个 Agent 复用同一套能力
- 你希望对这项能力做独立分析和优化

不太适合沉淀成 Skill 的情况：

- 只是一次性临时实验
- 能力边界非常模糊
- 还没有稳定场景，不知道何时该触发

## 建议的使用顺序

### 第一次接触 Skills

建议按这个顺序体验：

1. 进入 Skills Hub，看当前已有资产
2. 用一个真实需求试一次 Skills 生成
3. 选择某个 Skill 进入分析页看结果
4. 再进入优化页理解版本迭代方式

### 已经有现成 Skill

如果你已经有 Skill 资产，可以这样用：

1. 先在 Skills Hub 中确认列表与版本
2. 用分析页判断当前版本健康度
3. 对问题集中的版本进入优化页处理
