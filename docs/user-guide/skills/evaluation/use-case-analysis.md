# 用例分析

用例分析验证某个 Skill 版本在真实任务中的表现，重点回答：

- 最终结果是否完成用户目标。
- 执行轨迹是否稳定、合理并正确使用 Skill。
- 低分问题集中在哪些 Case。

## 创建用例实验

1. 在工作台顶部选择目标正式版本。
2. 打开 **Skill 实验**。
3. 点击 **新建用例实验**。
4. 选择待执行 Agent，并按需选择评测数据集。
5. 在第 2 步选择 Trace 来源。
6. 确认预期答案和评估上下文。
7. 选择评估器并开始实验。

## 两种 Trace 来源

### 选择已有 Trace

适用于复盘真实调用：

- 按 Agent、时间、标签或关键字筛选 Trace。
- 至少选择一条 Trace；也可启用监听模式，自动接收该 Agent 后续上报的 Trace。
- 第 3 步可手工标注参考答案，或从数据集按任务输入匹配参考答案和 Tool/Skill 目录。

选择已有 Trace 不会重新运行 Agent，评估的是已经发生的执行。

### 生成新 Trace

适用于标准数据集回归：

- 第 1 步必须选择包含 Case 的数据集。
- 第 2 步选择在线运行主机、模型和需要执行的 Case。
- 系统在当前 Skill 版本上下文中重新运行 Agent。
- 第 3 步检查本次实验冻结的数据集预期答案快照。

生成 Trace 的结果更适合版本回归，因为输入和运行配置更容易固定。

## 默认评估器

用例分析会优先带入：

- **Agent 任务完成度**：评价最终输出是否完成目标。
- **Agent 轨迹质量**：评价规划、调用和中间过程。

还可以按数据条件选择其他预置或自建评估器。依赖参考答案或 Tool/Skill 目录的评估器，只有全部 Case 满足前置条件时才可用。

页面主要区域包括：

### 核心指标

- **执行进度**：有效数据完成数。
- **任务结果分**：来自结果类评估器。
- **轨迹质量**：来自轨迹类评估器。
- **当前结论**：实验数据完成后给出的可用性提示。

截图示例中 6/6 个评估结果已齐，任务结果分为 97.5，轨迹质量为 89.0，当前结论为“可使用”。

### 实验进度

依次展示冻结配置、运行第一批用例、运行剩余用例和生成实验结论。运行中页面会持续更新，最终指标在全部预期结果收敛后确认。

### 已冻结配置

记录 Skill、Agent、数据集、Trace 来源、评估器和运行配置。该信息用于复现和比较实验。

### Case 与评估明细

点击 **查看 Case 与评估明细**可以展开标准实验详情：

- 实验状态、Case 数、评估器数和完成/失败数量。
- 综合均分与评估器分解。
- 每条 Case 的输入、参考输出、实际输出和结果/轨迹得分。
- **详情**用于查看单条证据与评分点。
- **新增 Case**用于继续补充样本。

失败评估器可在单条详情或实验操作中重试；已经完成的得分不会因为重试失败项而消失。

## 结果解读

| 结果分 | 轨迹分 | 常见判断 |
| --- | --- | --- |
| 高 | 高 | 结果与执行过程都稳定，可继续扩大回归集 |
| 高 | 低 | 答案暂时正确，但过程不稳定或工具使用不合理 |
| 低 | 高 | 流程基本正确，但任务口径、知识或最终表达不足 |
| 低 | 低 | 先查看低分 Case 和 Trace，再判断是 Skill、数据还是运行环境问题 |

不要只看综合均分。结果类和轨迹类评估器失败时应分别定位。
