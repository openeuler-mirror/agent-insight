# 实验

本页适用于 `refactor-for-nh` 的评测演示模式。演示在 Agent Insight 原有界面上精简入口，展示 AgentGate 需求中的测评闭环；不另设一套侧栏或整页样式。监听 Trace、可靠性注入、独立 LLM 对比等入口在演示中隐藏，原功能代码和历史数据保留。

默认构建使用完整模式。部署演示时，需在构建阶段设置 `NEXT_PUBLIC_EVALUATION_DEMO=true`；仅修改已构建服务的启动环境不会切换界面。

## 左侧导航

左侧沿用原有名称、图标和可折叠层级，只隐藏演示不需要的入口：

- **仪表盘**：查看评测概况。
- **运行观测**：保留 **Agent 概览、版本分析**。
- **评估与实验**：保留 **实验、评测数据集、评估器**。
- **配置**：保留 **模型注册**。

分组仍可展开或收起。“链路追踪”不单独占据演示侧栏入口，从实验 Case 进入即可。

在 **Agent 概览** 中查看 Agent 或 Skill 卡片，选择版本后点击“检查 Skill 定义”，可在详情中查看描述重叠、职责等静态风险，无需运行实验。检查结果绑定所选对象和版本，不会混用其他版本的报告。该能力对应需求中的独立静态分析，不单独占据左侧入口。

## 开始前

在 **Agent 概览** 中同步外部目录并查看可执行版本。Agent/Skill 由外部平台维护，测评系统读取定义并保存快照。登记版本 `vN` 是平台快照编号，详情中同时保留外部版本标识。若外部服务不再提供某个历史定义，该快照不能用于新实验，历史实验仍可查看。

在 **评测数据集** 中维护用例并发布版本。列表沿用原数据集卡片、搜索和操作布局，版本数据集在同一个页面展示。

**评估器** 沿用原来的预置/自建页签、卡片、搜索和详情；每个评估器可以选择版本，编辑后发布新版本。使用 AI 生成用例或 LLM 评分前，需要在 **模型注册** 中配置并启用公共连接，或通过评估器页面的 **模型连接** 保存私有连接。私有连接加密保存。管理员需为服务配置固定的 `EVALUATION_CREDENTIAL_KEY`；重启时继续使用同一主密钥，不能每次重新生成。

## 新建实验四步

向导沿用原有步骤条、内容卡片和上一步/下一步操作布局，在其中增加版本选择、单变量对比和 Case 配置。

### 1. 实验设计

先填写名称，选择单组或 Agent、Skill、评估器、评测集中的一个对比类型。

四类对象均通过两个下拉框分别选择对象和版本。对比项显示 A/B 两组；其余三类只配置一次，两组共享。Skill 对比要求同一个 Skill 的不同版本，Agent 负责实际执行该 Skill。也可以在其他实验中不额外加载 Skill，沿用 Agent 内置定义。

评估器可以选择多个，规则先执行，再执行 LLM；全部通过才算通过。评估器 A/B 对同一份实际执行记录分别评分，Agent 不重复执行。

**执行地址 / IP** 指平台把 Case 发往的 Agent HTTP 服务；**Agent 执行模型** 随请求发给该服务。评估器的评分模型独立配置。带接入凭证的 Agent 只能使用其绑定地址，若需更换接入需先在外部目录登记。`demo-basic` 和 `demo-reasoning` 是独立 Demo 服务的规则模拟模式，不是真实大模型。

### 2. 选择 Case

从已选版本中多选 Case，支持搜索、全选和取消。评测集对比为 A/B 分别选择 Case；其他对比共用同一批 Case。开始实验后平台自动执行 Agent、收集输出和 Trace，不再选择“生成 Trace / 选择 Trace”。

### 3. 预期答案

每个 Case 一行：首次输入、最终预期输出，以及可展开的逐轮规则。多轮 Case 不拆成多行。本步只读；要修改用例，进入评测集逐条编辑并发布新版本，然后重新选择版本。

### 4. 确认并执行

核对四类对象版本、执行地址、模型与 Case 数。设置通过率门槛，按需展开并发、超时、重试。点击 **开始实验** 后进入详情。

## 查看结果和优化

实验详情的右上角提供 **分析问题并优化、按原条件创建回归、导出报告**。摘要显示四类版本、地址、模型及通过情况。

Case 列表使用原有详情形式，进入 Case 后分 **结果评测** 和 **轨迹评测** 展示评估器结果。规则评估器包含路由、审批红线、工具参数、字段/结构等评分点；每个评分点有判定、分数、实际证据与规则生成的排查建议。实际执行异常或缺失证据为“未评完整”，不能当作通过或 0 分。

从 Case 打开 **执行 Trace**，沿用原有 Trace 详情和执行树，查看真实用户输入、Agent 输出、采集到的 Prompt、Skill、工具参数和返回结果。未采集到工具证据与确实没有调用工具会分别提示。Trace 的 Skills 页展示执行端确认加载的外部版本及定义指纹；“已加载定义”不等于调用 Skill 工具，所以可能有已加载 Skill，而 Skill 调用次数仍为 0。演示不展示无关的导入、标签、诊断和评论操作，完整模式继续保留这些能力。

**分析问题并优化** 按失败检查类型分组，提供代表 Case、证据、排查建议和预期/实际 Skill 混淆矩阵。这是基于规则的基础归类，不是语义聚类或已证实的根因。Agent/Skill 的修改在外部平台完成；平台内可修改 Case、发布新数据集版本，再回归。

## 回归与版本趋势

**按原条件创建回归** 预填原实验四类版本、执行地址、模型、Case 范围和参数。用户可选择外部更新后的 Agent/Skill 版本或新发布的数据集/评估器版本。新实验保留来源实验关联，历史结果不覆盖。Case 详情也可以单独重跑一个 Case。

**版本分析** 顶部只有 Agent、Skill、评估器、评测集四行。勾选某项则比较该对象的所有版本，未勾选的项固定为所选版本。下方显示真实实验记录和通过率趋势；A/B 使用各组自身评分，同一个版本组合取相同执行条件下最近一次有效评分。模型、运行参数或人为挑选的 Case 范围不一致时自动分开。完整数据集版本变化可展示总体趋势，但不把修改过的用例差异解释成 Agent 改善。

每张趋势图上方显示该组实验保存的执行模型、地址、Case 范围、并发、超时、重试、通过门槛和执行方式。选取部分 Case 时，可展开查看具体名称；因附加评估器或评分模型连接不同而分图时，也显示对应配置。历史未记录的参数显示“未记录”，不会套用当前设置。勾选评估器版本比较时，评分模型可能随版本变化，需要查看具体实验确认。

图按“图 1、图 2……”编号，下方实验记录的“对应趋势图”可直接跳到该图。重复实验保留在表中，但图中每个版本组合仍只取最近一次有效评分。默认运行全部 Case 与手动全选属于相同范围，不会因此分成两张图。

当前目录展示最近 100 次实验。多项同时变化只展示版本组合趋势，不作单变量因果判断。

## 当前演示边界

本版提供规则、多轮执行、模型生成及公共/私有 LLM 评分入口。生成的 Case 是草稿：先检查输入、预期答案、状态与工具要求，再保存新版本；格式正确不代表业务预期正确。预约队列、独立复合评估器权重/条件、多模态和 CI/CD 门禁属于需求后续阶段，尚未实现。完整要求与验证状态见 [需求覆盖清单](../../design/evaluation-harness-v1/phase1-需求分析.md)。

界面隐藏只服务于本次演示，不代表移除原产品能力。后续迁入 `master` 时，可保留版本、对比和评测能力扩展，不必启用演示入口筛选。

2026-09-09：问题分析中的代表 Case 只链接该检查实际失败的执行记录，同名 A/B Case 不会混入另一组已通过的结果。演示 Case 详情不展示评论入口。版本分析的 Agent 选项不混入历史直接以 Skill 为目标的实验。
