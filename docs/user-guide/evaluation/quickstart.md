# 跑通第一次评测

本指南提供两条最短路径：

- 普通评测：选择一条已有 Trace，使用一个评估器完成评分；
- Benchmark 评测：选择 Benchmark 数据集和 Case，由 Agent 执行并运行官方评测。

## 前置条件

- 已在 **配置 → 模型注册** 中配置可用模型；
- 已安装 Agent 客户端，且目标 Agent 至少上报过一条 Trace；
- 当前账号可以访问目标 Agent 和 Trace。

### SWE-bench 等容器 Benchmark 的评测服务

容器 Benchmark 还需要管理员提前部署 Evaluator，并安装对应 Benchmark 数据集。部署、端口和镜像管理命令见 [Benchmark 服务安装指南](../../developer-guide/benchmark/service-deployment-guide.md)。

用户只需在新建实验时确认：

- Benchmark 数据集可以选择；
- 目标 Agent 执行客户端在线；
- 官方 Benchmark 评估器已自动选中。

### SWE-bench Case 仓库源码来源

源码来源由 Agent 执行机管理员配置，普通实验用户无需设置。需要使用本地缓存或指定 Git 服务时，参见 [配置 SWE-bench Case 源码来源](../../developer-guide/benchmark/service-deployment-guide.md#71-配置-swe-bench-case-源码来源可选)。

### 首次运行 Benchmark 的额外前置条件

首次运行 Benchmark 时：

1. 进入 **评估与实验 → 实验**，点击 **新建实验**；
2. 选择 Benchmark 数据集和要运行的 Case；
3. Trace 来源选择 **生成 Trace**；
4. 选择在线且支持该 Benchmark 的 Agent 执行端；
5. 确认官方评估器已自动绑定，然后开始实验。

首次建议只选择一个 Case。SWE-bench 的 ARM64 环境适合验证流程，正式成绩以 Linux x86_64 官方镜像为准。

## 步骤一：新建普通实验

1. 进入 **评估与实验 → 实验**；
2. 点击右上角 **新建实验**；
3. 输入实验名称；
4. 选择待评测 Agent；
5. 数据集保持 **不选择数据集**；
6. 实验类型选择 **无变量 · 单组**；
7. 点击 **下一步：Trace 来源**。

## 步骤二：选择已有 Trace

1. 选择 **选择 Trace**；
2. 使用搜索、时间范围或用户标签缩小范围；
3. 勾选一条输入和输出都便于核对的 Trace；
4. 点击 **下一步：预期答案**。

首次运行不建议使用监听模式。监听模式适合持续评测后续产生的新 Trace。

## 步骤三：处理预期输出

- 评估器不需要预期输出时，可以直接进入下一步；
- 评估器需要参考答案时，填写预期输出；
- 已有匹配数据集时，可以使用 **从数据集导入匹配**。

## 步骤四：选择评估器并开始

1. 选择至少一个可用评估器；
2. 首次实验建议只选择一个评估器；
3. 点击 **开始实验**。

系统接受任务后会自动进入实验详情页。

## 步骤五：阅读实验详情

实验运行期间页面会自动刷新。重点查看：

- 实验状态是否进入已完成或失败；
- Case 数量和评估器数量是否正确；
- 综合均分是否产生；
- 评估器的计入数量和失败数量是否合理。

在 Case 明细中点击 **详情** 查看单条结果。

## 步骤六：核对评分依据

在详情页依次检查：

1. 任务输入、预期输出和实际输出是否属于同一个 Case；
2. 评估器结论是否与得分一致；
3. 未达标项是否给出了可定位的证据；
4. 改进建议是否指向具体输出或执行步骤。

如果机器评分明显不合理，可以填写理由并保存人工修正。评论只用于协作记录，不改变分数。

Benchmark 评测失败时，先打开 Case 详情查看失败阶段和错误信息；需要处理服务或镜像问题时联系管理员。
