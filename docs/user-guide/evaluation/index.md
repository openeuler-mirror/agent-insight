# 评测中心

评测中心用于将运行中的问题样本、目标定义与评分标准组织为可重复执行的离线评测流程，支持版本对比、质量回归与优化决策。

> **Note**
> 运行观测负责发现问题，评测中心负责将问题沉淀为可复用的评测资产，并持续验证版本变化是否带来真实改进。

## 评测中心解决什么问题

- 将真实问题沉淀为可重复执行的结构化样本
- 明确通过、失败与优先级判断标准
- 比较不同 Agent、Skill、提示词或版本的实际表现
- 将一次性排障经验转化为长期回归能力

## 核心模块

### 评测数据集

评测数据集用于定义样本范围、输入结构、预期输出与补充元数据，是评测执行与结果对比的基础资产。

主要承担以下职责：

- 明确本次评测覆盖的任务范围
- 固化输入样本与参考结果
- 保证关键场景与边界场景可重复复现

对应文档： [评测数据集](./datasets)

### 评估器

评估器用于定义评分口径，将输入、输出、预期输出或执行轨迹转换为可比较的结构化结果。

主要承担以下职责：

- 定义结果或过程的判定标准
- 输出可聚合的分数与原因
- 统一不同批次之间的评判口径

对应文档： [评估器](./evaluators)

### 评测执行

评测执行用于将数据集、评估器与评测对象组合为一次完整实验，并跟踪批次状态、失败样本与阶段性结果。

主要关注以下信息：

- 批次运行状态
- 已完成、运行中与失败数量
- 样本级评分结果
- 平均分与整体趋势

对应文档： [评测执行](./run-evaluation)

### 结果分析

结果分析用于将分数与原因进一步转化为优化判断，支持识别失败模式、比较不同批次并确认是否发生回归。

对应文档： [结果分析](./analyze-results)

## 最小闭环

无论评测对象是 Agent 还是 Skill，完整闭环通常包括以下五步：

1. 准备一组结构稳定的数据集样本
2. 配置一个或多个评估器
3. 发起评测任务
4. 阅读批次结果与失败样本
5. 用结果指导修复、优化或版本决策

## 与运行观测的衔接

运行观测与评测中心的职责边界可概括如下：

- **运行观测**：发现真实链路中的异常样本与高价值问题
- **评测中心**：将问题样本沉淀为离线验证机制并持续复测

典型流程如下：

1. 在链路追踪中识别高价值异常样本
2. 将样本整理为评测数据集
3. 配置评估器并发起评测
4. 在版本变更后重复执行同一组评测

## 适用场景

以下情况通常适合优先建立评测机制：

- 同类问题反复出现
- 修复验证依赖高成本人工复核
- 版本数量增加后难以横向比较
- 团队对“是否变好”缺少统一标准

## 建议起步方式

首次建立闭环时，建议先控制规模，再逐步扩充覆盖范围：

- 优先选择 5 到 20 条代表性样本
- 优先配置最关键的评估器
- 优先跑通一次完整闭环
- 稳定后再补充更多场景与维度
