# 评估与实验

评估与实验用于把真实运行中的问题转化为可重复、可比较的质量验证。你可以直接圈选已有 Trace，也可以让平台按数据集 Case 生成新 Trace，再使用一个或多个评估器产出实验级和 Case 级结论。

> **Note**
> 运行观测负责发现问题；评估与实验负责固定样本与判定口径，并持续验证 Agent、模型或配置变化是否带来真实改进。

## 页面入口

侧边栏 **评估与实验** 下包含三个页面：

| 页面 | 用途 |
| --- | --- |
| **实验** | 创建实验、选择 Trace 来源、运行评估并查看结果 |
| **评测数据集** | 管理输入、参考答案、轨迹和评估上下文 |
| **评估器** | 查看预置评估器，创建和维护自建 LLM 评估器 |

## 实验

实验是一次完整评测的归档单位。一个实验由待评测 Agent、若干 Case 和一组评估器组成，创建后立即开始执行。

实验支持两种 Trace 来源：

- **选择 Trace**：复用目标 Agent 已经产生的真实 Trace，适合线上问题复盘和历史样本抽查。
- **生成 Trace**：选择在线运行主机与模型，按数据集 Case 重新执行 Agent，适合离线回归和固定题库验证。

数据集在实验设计阶段是可选项。选择已有 Trace 时可以不选数据集，也可以用数据集为 Trace 补充参考答案和 Tool/Skill 目录；生成 Trace 时必须选择包含 Case 的数据集。

实验结果按两层组织：

- **实验详情**：查看状态、综合均分、评估器分解、Case 明细与实验级评论。
- **Trace 评测详情**：查看单条 Case 的输入、参考答案、实际输出、评分点、证据、人工修正和评论。

对应文档：[实验](./experiments)

## 评测数据集

评测数据集用于沉淀可复用的输入样本和评估上下文。数据项可以来自人工录入、JSON/CSV 批量导入，也可以从 Trace 详情回流。

常见字段包括：

- `input`：任务输入。
- `reference_output` / `expected_output`：参考答案。
- `trajectory`：结构化执行轨迹。
- `available_tools` / `available_skills`：工具类评估器需要的完整能力目录。

对应文档：[评测数据集](./datasets)

## 评估器

评估器定义“怎么判”。实验可以同时选择多个可执行的预置评估器和自建评估器；依赖参考答案、Tool/Skill 目录或特定数据集类型的评估器，会在实验第 4 步检查前置条件。

评估结果不会只给出总分。支持结构化评分点的评估器还会返回结论、证据、未达标项和改进建议，便于下钻定位问题。

对应文档：[评估器](./evaluators)

## 最短闭环

首次使用时，不要求先准备完整数据集。推荐先用一条已有 Trace 跑通流程：

1. 进入 **评估与实验 → 实验**。
2. 新建实验并选择待评测 Agent。
3. 在 **Trace 来源** 中选择一条已有 Trace。
4. 按需补充参考答案。
5. 选择至少一个满足前置条件的评估器并开始实验。
6. 在实验详情查看综合结果，再打开 Case 详情检查证据。
7. 将有代表性的输入与参考答案沉淀为数据集，用于后续回归。

详细步骤：[跑通第一次评测](./quickstart)

## 与 Skill 工作台的边界

全局 **评估与实验** 面向 Agent 级通用实验。Skill 的静态质量检查、触发分析、用例分析和 Skill 版本 A/B 测试统一在 **持续优化 → Skill** 工作台中完成。

两者共用实验执行与结果能力，但入口和归档范围不同：

- 全局实验按实验和 Agent 组织。
- Skill 实验按当前 Skill 与精确版本隔离，只显示该版本的实验记录。
