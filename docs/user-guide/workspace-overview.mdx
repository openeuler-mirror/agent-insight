# 概览面板

概览面板是你进入 Agent Workspace 后看到的第一屏。它把分散在各模块的关键信号汇聚到一处，让你在几秒内回答三个问题：**当前 Workspace 是否健康、有没有需要立即关注的 Agent、接下来应该从哪里下钻。**

<Note>
  概览面板不是一张“只看数字”的大盘，而是一张面向日常运维与排障的**工作台入口页**。
  它的目标是帮你快速判断状态、缩小范围，而不是在这一页完成全部分析。
  如果你刚接入平台，建议先通过本页确认 Agent、Trace 与各模块入口是否已经可用。
</Note>

## 这页能帮你做什么

- 一眼掌握当前 Workspace 的整体健康状态
- 快速了解 Agent 规模、运行状态与近期活跃度
- 通过核心指标（成功率、P95 时延）发现需要优先关注的对象
- 借助快捷入口直达常用模块，把概览页当作整个 Workspace 的“启动台”
- 通过近期活动迅速回到最近处理过的 Trace、评测或 Skill

## 数据口径：以平台为默认维度

进入排版细节前，先明确一个贯穿全页的口径：**概览面板默认以「平台」为过滤维度**。

也就是说，你看到的 Agent 数量、成功率、P95 时延和近期活动，通常都建立在当前所选平台（如 `opencode`、`openclaw`、`hermes`）的筛选条件之上。一旦切换平台，整页数据会随之联动刷新。

<Tip>
  如果指标看起来与预期不符，先确认顶部选中的平台是否正确——多数“数据对不上”的疑问，都源于停留在了非预期的平台维度上。
</Tip>

## 页面构成

概览面板由四类信息区块组成，从“整体状态”逐层收敛到“可执行动作”：

| 区块 | 回答的问题 | 典型用途 |
| --- | --- | --- |
| Workspace 当前状态 | 现在整体是否正常？ | 判断接入是否完成、数据是否在更新 |
| Agent 核心列表 | 哪些 Agent 最值得关注？ | 识别异常、对比成功率与时延 |
| 快捷入口 | 接下来去哪里操作？ | 直达 Agent、Skills、评测、链路 |
| 近期活动 | 最近发生了什么？ | 回到刚处理过的对象，减少来回查找 |

### 1. Workspace 当前状态

这一区块回答“现在整体是否正常”，关注的是面向接入与可用性的基础信号：

- 当前是否已存在已注册 Agent
- 是否出现异常或长期空闲的 Agent
- 当前筛选条件下的整体健康状态
- 看板是否在持续刷新、数据是否在更新

如果这里长期显示“尚未注册 Agent”或数据迟迟不刷新，应优先回到接入流程排查，而不是怀疑指标本身。

### 2. Agent 核心列表

核心列表展示一组重点 Agent，帮助你快速识别当前最值得关注的对象。常见字段如下：

| 字段 | 含义 |
| --- | --- |
| **Agent 名称** | 目标 Agent 的展示名称 |
| **平台** | 所属客户端平台，如 `opencode`、`openclaw`、`hermes` |
| **状态** | 运行中、空闲、异常等当前运行态 |
| **调用量** | 近期请求总数，反映活跃程度 |
| **成功率** | 成功调用占比，用于看整体健康趋势 |
| **P95 时延** | 第 95 百分位耗时，比平均值更能反映长尾体验 |

<Tip>
  当调用量较小时，成功率和 P95 的统计意义有限，仅适合用于趋势判断；
  真正的根因定位仍建议进入 [链路追踪](./observability/view-traces) 查看具体 Trace。
</Tip>

### 3. 快捷入口

快捷入口把最高频的动作前置到首屏，让你从“看板”一步跳到“操作页”。常见入口包括：

- **新建 Agent** → [Agent 管理](./agent-management)
- **Skills 生成** → [Skills 生成](./skills/generate)
- **运行评测** → [评测执行](./evaluation/run-evaluation)
- **链路分析** → [链路追踪](./observability/view-traces)

对高频用户而言，这一区块的价值最高，可以把概览面板当作 Workspace 的统一启动台。

### 4. 近期活动

近期活动帮助你迅速回到刚发生过的重要操作或结果，例如：

- 新产生的链路数据
- 最近一次评测任务
- 最近处理过的 Skill
- 刚刚执行过的分析或优化动作

如果你经常在多个模块之间切换，这一区块能显著减少来回查找的成本。

## 如何解读关键指标

概览面板上的指标各有适用边界，理解口径才能避免误判。

### Agent 数量

Agent 数量反映当前 Workspace 已纳管的智能体资产规模：

- **为 0**：通常说明尚未登记 Agent，或仍停留在演示数据阶段
- **逐步增加**：平台开始承载真实业务 Agent，接入在推进
- **数量多但活跃少**：需结合近期调用量判断是否存在闲置资产

### 成功率

成功率适合观察整体健康趋势，但**不适合单独用于定位根因**：

- 成功率下降时，优先进入链路追踪查看失败样本
- 成功率正常但用户仍反馈差，往往是效果偏差类问题，需进一步看过程
- 对 Agent 而言，“没报错”不等于“结果正确”

### P95 时延

P95 时延用于观察慢请求与长尾体验：

- P95 升高但平均耗时不高，通常意味着少量请求异常慢
- 常见原因包括模型抖动、工具超时、子 Agent 递归过深
- 需结合具体 Trace 的 Span 树，判断慢点究竟落在哪一层

### 自动刷新

概览面板会周期性刷新，以便持续查看最新状态，适合：

- 正在接入新 Agent，等待第一条数据出现
- 正在观察某个异常是否恢复
- 刚执行完评测或分析，等待活动列表更新

<Tip>
  如果你在分析历史数据，可临时关闭自动刷新，避免页面频繁变化打断阅读。
</Tip>

## 常见使用方式

### 刚接入平台时

重点确认这 3 件事，三者都正常即说明 Workspace 已基本可用：

1. 是否已经出现已注册 Agent
2. 是否能看到最近活动
3. 快捷入口能否正确带你跳到对应模块

### 日常巡检时

把概览面板当成每日入口，自上而下扫一遍：

1. 查看 Agent 状态是否存在异常
2. 观察成功率与 P95 是否出现明显波动
3. 如发现异常，进入链路追踪或评测中心继续深挖

### 排障时

概览面板不负责最终定位，但能帮你快速缩小范围：

1. 先识别出哪个 Agent 异常
2. 通过快捷入口进入 [链路追踪](./observability/view-traces) 看具体执行
3. 如需结构化回归，再进入 [评测中心](./evaluation/index)

## 概览面板不负责什么

为避免误用，下面这些工作不建议停留在概览面板完成：

| 你想做的事 | 应该去 |
| --- | --- |
| 逐条排查失败执行 | [运行观测](./observability/index) |
| 建立评测集与评测任务 | [评测中心](./evaluation/index) |
| 创建或优化 Skill | [Skills 能力](./skills/index) |
| 登记或整理 Agent 资产 | [Agent 管理](./agent-management) |

概览面板的定位是“发现与分流”，真正的“分析与处置”交给对应专业模块。
