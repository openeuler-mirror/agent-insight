# 核心概念

理解这些概念后，你会更容易读懂 Agent Insight 的页面结构、指标口径和工作流。本页按核心模块重构，重点把 `user-guide` 里的高频专有名词集中整理成术语表，方便你在阅读其它页面前先建立统一语义。

> **Note**
> Agent Insight 同时覆盖接入配置、真实运行观测、离线评测和 Skills 生命周期管理。
> 同一个对象会在多个模块里出现，但含义侧重点不同。本页优先解释“它是什么”，具体操作仍以对应模块页面为准。

## 一句话理解平台

可以把平台理解成这样一条主线：

1. 在 **Workspace** 中接入并管理 **Agent**
2. Agent 每次真实运行都会产生一条 **Trace**
3. 你可以通过 **链路追踪** 和 **智能诊断** 理解问题发生在哪里
4. 你也可以把线上问题沉淀成 **评测数据集** 做离线回归
5. 通过 **评估器** 和 **评测批次** 量化结果差异
6. 最后把稳定经验沉淀为 **Skill**，继续进入生成、评测和优化闭环

> **Tip**
> 如果你只记一句话，可以记成：
> **Agent 产生 Trace，Trace 暴露问题，评测量化问题，Skill 沉淀解法。**

## 核心模块术语表

下面按产品导航中的模块顺序整理术语。阅读本页后，再进入对应页面，会更容易理解各模块的职责边界与概念关系。

### Agent Workspace

**Agent Workspace** 不是单个页面，而是承载业务 Agent 全生命周期操作的一级工作区。其下包含概览、Agent 管理、运行观测、评测中心和 Skills 能力等子模块。

| 模块 | 术语 | 说明 |
| --- | --- | --- |
| Agent Workspace | **Agent Workspace** | 面向业务 Agent 的主工作区，用来承载运行观测、离线评测、Skills 管理和基础操作入口。 |
| Agent Workspace | **Workspace** | 当前 Agent 所属的逻辑工作空间，Agent、Trace、评测资产和 Skill 资产都会按 Workspace 组织。 |
| Agent Workspace | **概览** | Agent Workspace 的首页，用来快速判断当前工作区状态、看关键指标并进入后续模块。 |
| Agent Workspace | **Agent 管理** | 用于登记、查看和维护 Agent 资产的页面，是接入后识别 Agent 身份和状态的入口。 |
| Agent Workspace | **Agent** | 被平台接入和管理的智能体实例，通常对应一个真实运行中的服务、CLI 工具或执行进程。 |
| Agent Workspace | **主 Agent** | 直接接收用户请求、承担主任务目标的入口 Agent。 |
| Agent Workspace | **子 Agent** | 由主 Agent 在执行过程中派生出来、负责局部子任务的 Agent。 |
| Agent Workspace | **已注册 Agent** | 已在平台完成登记、可被统一展示和管理运行数据的 Agent。 |
| Agent Workspace | **未注册 Agent** | 尚未完成平台登记的 Agent，可能已经运行，但不会以标准资产方式被管理。 |

### 运行观测

**运行观测** 是面向真实执行分析的二级模块，下设 **链路追踪**、**智能诊断** 和 **质量监控** 三个页面。

| 模块 | 术语 | 说明 |
| --- | --- | --- |
| 运行观测 | **运行观测** | 负责查看真实线上执行的模块，帮助你理解 Agent 实际做了什么、哪里慢、哪里错。 |
| 运行观测 | **链路追踪** | 查看 Trace 列表和详情的页面，用于定位某次执行经过了哪些步骤、卡在了哪里。 |
| 运行观测 | **智能诊断** | 基于失败或异常 Trace 自动做问题归因的页面，输出结论、证据和建议。 |
| 运行观测 | **质量监控** | 从成功率、时延、错误率等维度长期观察 Agent 质量趋势的页面。 |
| 运行观测 | **Trace** | 一次完整任务执行从开始到结束的全链路记录，是观察真实执行的最小完整单位。 |
| 运行观测 | **Span** | Trace 里的单个执行片段，表示一次更细粒度的步骤，例如 LLM 请求、工具调用或子 Agent 执行。 |
| 运行观测 | **Token** | 模型推理过程中消耗的输入、输出或缓存相关 Token，用于衡量资源成本。 |
| 运行观测 | **耗时** | 单个 Span 或整条 Trace 的执行时长，用于定位慢点和瓶颈。 |
| 运行观测 | **工具调用** | Agent 调用外部工具、脚本、接口或系统能力的行为。 |
| 运行观测 | **工具错误率** | 工具调用失败次数占总调用次数的比例，用于判断外部依赖是否稳定。 |
| 运行观测 | **效果偏差类故障** | 系统没有显式报错，但输出结果偏离预期的问题，如答非所问、遗漏关键步骤。 |

### 评测中心

**评测中心** 是面向离线质量验证的二级模块，核心页面包括 **评测数据集**、**评估器** 和 **评测执行**。

| 模块 | 术语 | 说明 |
| --- | --- | --- |
| 评测中心 | **评测中心** | 负责把线上问题沉淀为离线测试资产，并对 Agent 或 Skill 做可重复、可比较的质量验证。 |
| 评测中心 | **评测数据集** | 一组结构化样本，用于离线验证 Agent 或 Skill 的质量，把线上问题沉淀为可重复回放的测试资产。 |
| 评测中心 | **评估器** | 给一次执行结果或轨迹打分的规则集合，用来定义“什么叫好，什么叫不好”。 |
| 评测中心 | **评测执行** | 运行一次完整离线评测任务的页面，用于选择数据集、评估器和对象并查看结果。 |
| 评测中心 | **理想输出评测集** | 适用于有标准答案的场景，重点比较最终输出是否与参考结果一致。 |
| 评测中心 | **轨迹评测集** | 适用于需要检查执行过程的场景，除了输入和预期输出外，还会记录轨迹信息。 |
| 评测中心 | **reference_output** | 评测样本中的标准答案或参考输出字段，是结果比对的重要基线。 |
| 评测中心 | **trajectory** | 评测数据中的轨迹字段，用于记录 Agent 的过程信息；它是评测字段，不等同于线上完整 Trace。 |
| 评测中心 | **LLM Judge** | 由模型按评价标准打分的评估方式，适合难以用纯规则覆盖的复杂质量判断。 |
| 评测中心 | **评测批次** | 一次完整离线评测任务的执行实例，包含数据集、评测对象、评估器和结果。 |
| 评测中心 | **结果评测** | 关注最终输出是否正确、完整、符合预期的评测方式。 |
| 评测中心 | **轨迹评测** | 关注中间过程是否合理的评测方式，例如有没有按预期调用工具、是否走了正确步骤。 |

### Skills 能力

**Skills 能力** 是面向 Skill 生命周期管理的二级模块，包含 **Skills Hub**、**Skills 生成**、**Skills 评测** 和 **Skills 优化** 等页面。

| 模块 | 术语 | 说明 |
| --- | --- | --- |
| Skills 能力 | **Skills 能力** | 围绕 Skill 资产的管理、生成、评测和优化建立的能力模块。 |
| Skills 能力 | **Skills Hub** | 查看 Skill 列表、版本、状态和入口的统一页面，可理解为 Skill 资产总览。 |
| Skills 能力 | **Skills 生成** | 根据需求描述自动生成 Skill 初稿的页面。 |
| Skills 能力 | **Skills 评测** | 从静态合规、触发分析、用例分析和 A/B 测试等角度评估 Skill 效果的模块。 |
| Skills 能力 | **Skills 优化** | 基于分析结果修订已有 Skill 版本并发布新版本的页面。 |
| Skills 能力 | **Skill** | 可被 Agent 加载并按需调用的能力包，是版本化、可复用、可评测的能力单元，而不只是一个提示词。 |
| Skills 能力 | **SKILL.md** | Skill 的主文档，用于定义用途、触发条件、输入约束和执行方式。 |
| Skills 能力 | **scripts/** | Skill 中的可执行脚本目录，用于放置命令、自动化逻辑或工具调用实现。 |
| Skills 能力 | **references/** | Skill 中的参考资料目录，用于补充上下文、规则、背景知识或示例。 |
| Skills 能力 | **静态合规** | 检查 Skill 内容、结构和脚本是否符合规范的分析方式。 |
| Skills 能力 | **触发分析** | 判断 Skill 在该触发的时候有没有触发、不该触发的时候有没有误触发。 |
| Skills 能力 | **用例分析** | 从具体 case、执行轨迹和结果质量角度定位 Skill 在真实任务中的问题。 |
| Skills 能力 | **A/B 测试** | 通过对照组和实验组比较，验证某个 Skill 是否真的带来收益。 |

### 配置

**配置** 是独立于 Agent Workspace 的平台设置分组，负责模型依赖、外部搜索能力和接入配置等基础能力管理。

| 模块 | 术语 | 说明 |
| --- | --- | --- |
| 配置 | **配置** | 平台级设置分组，用于管理模型依赖、外部搜索能力和 Agent 接入说明。 |
| 配置 | **模型注册** | 为当前 Workspace 配置模型供应商、Endpoint 和 API Key 的过程，是诊断、评测、Skill 生成等能力的前置条件。 |
| 配置 | **联网搜索** | 为部分生成、分析或推理流程配置外部搜索能力的页面。 |
| 配置 | **安装指导** | 平台为某个 Agent 生成的接入说明页，用于复制安装命令、API Key 和上报配置。 |

## 常见混淆

### Agent 和 Skill 的区别

| 对比项 | Agent | Skill |
| --- | --- | --- |
| 本质 | 运行中的执行主体 | 被 Agent 选择和调用的能力资产 |
| 关注点 | 谁在执行任务 | 用什么能力完成任务 |
| 常见页面 | Agent 管理、链路追踪 | Skills Hub、Skills 评测、Skills 优化 |

### Trace 和 trajectory 的区别

| 对比项 | Trace | trajectory |
| --- | --- | --- |
| 所属语境 | 运行观测 | 评测数据 |
| 含义 | 一次真实执行的完整链路记录 | 评测样本中的过程字段 |
| 用途 | 看真实世界发生了什么 | 让离线评测也能检查过程是否合理 |

### 智能诊断和评估器的区别

| 对比项 | 智能诊断 | 评估器 |
| --- | --- | --- |
| 主要作用 | 解释为什么不好 | 量化到底差了多少 |
| 输入对象 | 异常或失败 Trace | 评测结果或评测轨迹 |
| 产出形式 | 归因结论、证据、建议 | 分数、规则结果或判定理由 |
