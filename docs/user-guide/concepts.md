# 核心概念

理解这些概念后，你会更容易读懂 Agent Insight 的页面结构、指标口径和工作流。本页按核心模块重构，重点把 `user-guide` 里的高频专有名词集中整理成术语表，方便你在阅读其它页面前先建立统一语义。

> **Note**
> Agent Insight 同时覆盖接入配置、真实运行观测、离线评测和 Skills 生命周期管理。
> 同一个对象会在多个模块里出现，但含义侧重点不同。本页优先解释“它是什么”，具体操作仍以对应模块页面为准。

## 一句话理解平台

可以把平台理解成这样一条主线：

1. 在 **Workspace** 中接入并管理 **Agent**
2. Agent 每次真实运行都会产生一条 **Trace**
3. 你可以通过 **链路追踪** 和 **智能诊断** 理解问题发生在哪里
4. 你也可以把线上问题沉淀成 **评测数据集** 做离线回归
5. 通过 **评估器** 和 **评测批次** 量化结果差异
6. 最后把稳定经验沉淀为 **Skill**，继续进入生成、评测和优化闭环

> **Tip**
> 如果你只记一句话，可以记成：
> **Agent 产生 Trace，Trace 暴露问题，评测量化问题，Skill 沉淀解法。**

## 核心模块术语表

下面按产品导航中的模块顺序整理术语。阅读本页后，再进入对应页面，会更容易理解各模块的职责边界与概念关系。

### 仪表盘

**仪表盘** 是平台首页，用来快速判断当前运行状态、查看关键指标并进入后续模块。

### 运行观测

**运行观测** 面向真实执行分析，下设 **Agent 概览**、**链路追踪** 和 **推理基础设施**。

| 模块 | 术语 | 说明 |
| --- | --- | --- |
| 运行观测 | **运行观测** | 负责查看真实线上执行的模块，帮助你理解 Agent 实际做了什么、哪里慢、哪里错。 |
| 运行观测 | **Agent 概览** | 沿用原 Agent 管理能力，用于查看、登记和维护 Agent 资产。 |
| 运行观测 | **链路追踪** | 查看 Trace 列表和详情的页面，用于定位某次执行经过了哪些步骤、卡在了哪里。 |
| 运行观测 | **推理基础设施** | 登记推理服务指标源，并把 session 时间窗与 vLLM / OTLP 指标关联，用于判断排队、KV cache 或 decode 延迟等基础设施瓶颈。 |
| 运行观测 | **Trace** | 一次完整任务执行从开始到结束的全链路记录，是观察真实执行的最小完整单位。 |
| 运行观测 | **Span** | Trace 里的单个执行片段，表示一次更细粒度的步骤，例如 LLM 请求、工具调用或子 Agent 执行。 |
| 运行观测 | **Token** | 模型推理过程中消耗的输入、输出或缓存相关 Token，用于衡量资源成本。 |
| 运行观测 | **耗时** | 单个 Span 或整条 Trace 的执行时长，用于定位慢点和瓶颈。 |
| 运行观测 | **工具调用** | Agent 调用外部工具、脚本、接口或系统能力的行为。 |
| 运行观测 | **工具错误率** | 工具调用失败次数占总调用次数的比例，用于判断外部依赖是否稳定。 |
| 运行观测 | **效果偏差类故障** | 系统没有显式报错，但输出结果偏离预期的问题，如答非所问、遗漏关键步骤。 |

### 评估与实验

**评估与实验** 面向离线质量验证，核心页面包括 **实验**、**评测数据集** 和 **评估器**。

| 模块 | 术语 | 说明 |
| --- | --- | --- |
| 评估与实验 | **评估与实验** | 负责把线上问题沉淀为离线测试资产，并对 Agent 或 Skill 做可重复、可比较的质量验证。 |
| 评估与实验 | **实验** | 选择 Agent、数据集、评估器和 Trace，运行并查看结果。 |
| 评估与实验 | **评测数据集** | 一组结构化样本，用于离线验证 Agent 或 Skill 的质量。 |
| 评估与实验 | **评估器** | 给一次执行结果或轨迹打分的规则集合，用来定义“什么叫好，什么叫不好”。 |
| 评估与实验 | **reference_output** | 评测样本中的标准答案或参考输出字段，是结果比对的重要基线。 |
| 评估与实验 | **LLM Judge** | 由模型按评价标准打分的评估方式，适合难以用纯规则覆盖的复杂质量判断。 |

### 诊断分析

**诊断分析** 复用既有智能诊断页面，基于失败或异常 Trace 输出归因结论、证据和建议。

### 持续优化 · Skill

**持续优化** 下只保留 **Skill** 入口，进入后通过 **SkillHub**、**生成**、**评测** 和 **优化** 四个页签完成 Skill 生命周期管理。

| 模块 | 术语 | 说明 |
| --- | --- | --- |
| 持续优化 | **SkillHub** | 查看 Skill 列表、版本、状态和入口的资产总览页签。 |
| 持续优化 | **生成** | 根据需求描述自动生成 Skill 初稿的页签。 |
| 持续优化 | **评测** | 从静态合规、触发分析、用例分析和 A/B 测试等角度评估 Skill 效果。 |
| 持续优化 | **优化** | 基于分析结果修订已有 Skill 版本并发布新版本。 |
| 持续优化 | **Skill** | 可被 Agent 加载并按需调用的能力包，是版本化、可复用、可评测的能力单元。 |
| 持续优化 | **SKILL.md** | Skill 的主文档，用于定义用途、触发条件、输入约束和执行方式。 |

### 配置

**配置** 负责模型依赖、外部搜索能力和客户端安装等基础能力管理。

| 模块 | 术语 | 说明 |
| --- | --- | --- |
| 配置 | **配置** | 平台级设置分组，用于管理模型依赖、外部搜索能力和 Agent 接入说明。 |
| 配置 | **模型注册** | 为当前 Workspace 配置模型供应商、Endpoint 和 API Key 的过程，是诊断、评测、Skill 生成等能力的前置条件。 |
| 配置 | **联网搜索** | 为部分生成、分析或推理流程配置外部搜索能力的页面。 |
| 配置 | **客户端安装** | 平台为某个 Agent 生成接入说明，用于复制安装命令、API Key 和上报配置。 |
| 配置 | **OpenClaw** | 默认通过同名命令包装函数注入 OTel 配置，按 OTLP/HTTP 上报 Trace 和 Log；OpenClaw 仍直连模型供应商。旧 watcher 是互斥的兼容接入方式。 |

## 常见混淆

### Agent 和 Skill 的区别

| 对比项 | Agent | Skill |
| --- | --- | --- |
| 本质 | 运行中的执行主体 | 被 Agent 选择和调用的能力资产 |
| 关注点 | 谁在执行任务 | 用什么能力完成任务 |
| 常见页面 | Agent 管理、链路追踪 | Skills Hub、Skills 评测、Skills 优化 |

### Trace 和 trajectory 的区别

| 对比项 | Trace | trajectory |
| --- | --- | --- |
| 所属语境 | 运行观测 | 评测数据 |
| 含义 | 一次真实执行的完整链路记录 | 评测样本中的过程字段 |
| 用途 | 看真实世界发生了什么 | 让离线评测也能检查过程是否合理 |

### 智能诊断和评估器的区别

| 对比项 | 智能诊断 | 评估器 |
| --- | --- | --- |
| 主要作用 | 解释为什么不好 | 量化到底差了多少 |
| 输入对象 | 异常或失败 Trace | 评测结果或评测轨迹 |
| 产出形式 | 归因结论、证据、建议 | 分数、规则结果或判定理由 |
