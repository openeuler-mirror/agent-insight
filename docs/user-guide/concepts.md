# 核心概念

理解这些概念后，你会更容易读懂 Agent Insight 的页面结构、指标口径和工作流。

> **Note**
> Agent Insight 同时覆盖线上观测、离线评测和 Skills 管理，因此同一个对象会在多个模块中出现。
> 本页的目标是帮你先建立统一语义，再去看具体页面。

## 一张图理解关系

可以把平台理解为下面这条链路：

1. **Agent** 接收请求并运行
2. 每次运行产生一条 **Trace**
3. Trace 由多个 **Span** 组成，记录 LLM、工具、子 Agent 等执行片段
4. 线上 Trace 可以进入 **智能诊断** 做问题归因
5. Trace 也可以沉淀为 **评测数据集**，进入离线评测
6. 评测时由 **评估器** 对结果或轨迹打分
7. 稳定经验可以沉淀为 **Skill**，再被 Agent 在后续执行中调用

> **Tip**
> 如果你只记一句话，可以记成：
> **Agent 产生 Trace，Trace 暴露问题，评测量化问题，Skill 沉淀解法。**

## Agent 与 Workspace

### Agent

在 Agent Insight 里，**Agent** 指被平台接入和管理的智能体实例，通常对应一个真实运行中的服务、CLI 工具或执行进程。

常见理解方式：

- 一个对外提供能力的智能体服务，可以登记为一个 Agent
- 同一业务在不同环境中，通常拆成多个 Agent 管理
- 一个复杂系统中，既可能有主 Agent，也可能派生出子 Agent

### Workspace

**Workspace** 是承载 Agent、运行数据、评测资产和配置的逻辑工作区。你可以把它理解为团队或项目级边界：

- Agent 属于某个 Workspace
- Trace、评测数据集、Skill 资产也按 Workspace 组织
- 模型注册、安装指导等能力通常围绕当前 Workspace 生效

## 运行观测相关概念

### Trace

**Trace** 表示一次完整任务执行从开始到结束的全链路记录。

一个 Trace 通常包含：

- 请求何时发起、由哪个 Agent 执行
- 执行是否成功，耗时多久，消耗了多少 Token
- 中间调用了哪些模型、工具、Skill 或子 Agent
- 最终输出是什么，失败时卡在什么节点

如果你把一次用户请求看成一部电影，那么 Trace 就是整部电影，而不是某一帧截图。

### Span

**Span** 是 Trace 里的单个执行片段，表示一个更细粒度的步骤，例如：

- 一次 LLM 请求
- 一次工具调用
- 一次数据库查询
- 一个子 Agent 的派生执行
- 一段自定义业务逻辑

Span 之间通常形成树状结构，因此你可以看到某一步是谁触发的、耗时占比多少、问题是向上游还是下游扩散。

### 主 Agent 与子 Agent

- **主 Agent**：直接接收用户请求的入口 Agent
- **子 Agent**：由主 Agent 在执行过程中派生出来、负责子任务的 Agent

这一区分在多 Agent 编排场景尤其重要。看 Trace 时，主 Agent 决定整体任务目标，子 Agent 体现任务拆分与协作路径。

### Token、耗时与工具调用

这些是平台里最常见的观测指标：

- **Tokens**：模型推理消耗的输入、输出或缓存命中 Token
- **耗时**：单个 Span 或整条 Trace 的执行时长
- **工具调用**：Agent 调用外部工具、脚本或接口的行为
- **工具错误率**：工具调用失败次数占总调用次数的比例

它们帮助你回答三个最常见的问题：

- 这次为什么慢？
- 这次为什么贵？
- 这次为什么失败？

## 诊断相关概念

### 智能诊断

**智能诊断** 会读取失败或异常 Trace 的上下文，自动给出归因结论、证据和建议。

它解决的不是“有没有报错”，而是“问题更像发生在哪一类环节”，例如：

- 模型调用失败
- 工具超时或权限不足
- 输出内容偏离预期
- Skill 没有命中或命中后效果不稳定

### 原始错误与效果偏差

平台里常把问题分成两类：

- **原始错误类故障**：系统真的报错了，如超时、5xx、权限拒绝
- **效果偏差类故障**：系统没报错，但结果不符合预期，如答非所问、遗漏关键步骤

很多 Agent 质量问题都属于第二类，因此只看日志是否报错通常不够。

## 评测相关概念

### 评测数据集

**评测数据集** 是一组结构化样本，用来离线验证 Agent 或 Skill 的质量。每条样本一般包含：

- `input`：输入问题或任务描述
- `reference_output`：标准答案或参考输出
- 其他用于评测的元数据

数据集的意义是把线上偶发问题，变成可重复回放的测试资产。

### 评估器

**评估器** 用于给一次执行结果打分，它决定“什么叫好，什么叫不好”。

常见类型包括：

- **规则型评估器**：按明确规则比对
- **脚本型评估器**：运行自定义逻辑评分
- **LLM Judge**：由模型按照评价标准打分

没有评估器，评测只能停留在“看起来还行”；有了评估器，结果才可量化、可排序、可回归。

### 评测批次

**评测批次** 是一次完整离线评测任务的执行实例。它通常包含：

- 选中的数据集
- 被测试的 Agent 或 Skill 版本
- 使用的评估器集合
- 每条样本的分数、结论和失败详情

当你比较两个版本、建立发布门禁或回归检查时，看的通常就是不同评测批次之间的差异。

### 结果评测与轨迹评测

- **结果评测**：关注最终输出是否正确
- **轨迹评测**：关注中间过程是否合理，例如是否按预期调用工具、是否走了正确步骤

对 Agent 来说，最终答案对了不代表过程合理；过程合理也不代表最终答案一定好。这两类评测互相补充。

## Skill 相关概念

### Skill

**Skill** 是可被 Agent 加载并按需调用的能力包。它不只是一个提示词，而是一个版本化、可复用、可评测的能力单元。

一个 Skill 通常包括：

- `SKILL.md`：主文档，定义用途、触发条件、输入约束和执行方式
- `scripts/`：可执行脚本
- `references/`：参考资料或上下文文档

### Skill 生命周期

在平台里，Skill 通常经历三个阶段：

1. **生成**：根据需求起草 Skill
2. **分析**：检查触发准确性、静态合规和真实效果
3. **优化**：基于问题反馈迭代内容并发布新版本

这也是 Agent Insight 区别于“只管 Prompt 仓库”的关键点之一。

### A/B 测试

**A/B 测试** 主要用于判断某个 Skill 是否真的带来收益。

典型对比方式：

- A：不挂载该 Skill 的对照版本
- B：挂载该 Skill 的实验版本

然后在同一批输入上比较通过率、评分和轨迹差异。

### 触发分析

**触发分析** 关注的不是 Skill 执行得好不好，而是它该不该被调用、有没有被正确调用。

它通常回答两类问题：

- 应该触发的时候，是否真的触发了？
- 不应该触发的时候，是否误触发了？

## 常见混淆

### Agent 和 Skill 的区别

- **Agent** 是运行中的执行主体
- **Skill** 是被 Agent 选择和调用的能力资产

Agent 更像“执行者”，Skill 更像“可装配能力”。

### Trace 和评测批次的区别

- **Trace** 来自一次真实执行
- **评测批次** 来自一组离线测试执行

前者用于观察真实世界发生了什么，后者用于验证版本变化带来的影响。

### 智能诊断和评估器的区别

- **智能诊断** 偏向失败归因和问题解释
- **评估器** 偏向结构化评分和量化判断

一个回答“为什么不好”，另一个回答“到底差了多少”。
