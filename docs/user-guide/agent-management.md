# Agent 概览

Agent 概览页位于 **运行观测** 下，沿用原 Agent 管理页面的能力，负责查看并管理平台已识别的真实运行 Agent。

> **Note**
> 只有先把 Agent 纳入管理，后续的链路追踪、评测和 Skills 分析才有稳定的归属对象。
> 如果你已经看到未注册 Trace，也建议尽快回到这里完成正式登记。

## 这页用来做什么

- 注册新的 Agent
- 查看 Agent 来自哪个平台
- 区分主 Agent 与子 Agent
- 识别哪些 Agent 已纳管，哪些仍是未注册状态
- 为接入流程提供统一入口，并衔接到客户端安装

## 什么是“已注册 Agent”

在平台里，**已注册 Agent** 指你已经明确登记并纳入管理的智能体实例。

一个已注册 Agent 通常具备这些特征：

- 有清晰的名称
- 知道它运行在哪个平台上
- 能和后续 Trace 记录稳定对应
- 可以作为评测和分析的目标对象

如果数据已经上报到了平台，但这个 Agent 还没有在管理页登记，它通常会以“未注册 Agent”的形式出现。

## 注册一个新的 Agent

在 Agent 概览页，你通常会通过“注册 Agent”弹窗完成登记。常见输入项包括：

- **平台名称**：例如 `opencode`、`openclaw`、`hermes`、`qoder`
- **Agent 名称**：建议使用稳定、可区分的名称
- **Agent 描述**：可选，用来补充用途说明

> **Tip**
> 名称最好能体现业务语义和环境，例如 `support-bot-prod`、
> `code-review-agent-dev`。后续排查和评测时会更容易区分。

## 命名建议

一个好的 Agent 名称应满足这几条：

- **稳定**：不要频繁改名，避免影响理解和追踪
- **可读**：能看出这是做什么的
- **可区分**：不同环境、不同业务不要共用同名
- **面向业务**：优先用业务语义，而不是临时实验名称

推荐示例：

- `customer-service-prod`
- `research-assistant-dev`
- `workflow-router-staging`

不推荐示例：

- `test`
- `agent-1`
- `new-bot-final-v2`

## 平台字段是什么意思

对于 Hermes trace，平台仍然是 `hermes`，主 Agent 名称会从 Hermes 当前 active profile 自动识别：profile 为 `default` 时显示为 `hermes`，其他 profile 显示其 profile 名；子 Agent 名称来自 Hermes 上报的子 Agent role/name。

平台字段用于标识 Agent 所依赖的运行时或执行框架。当前常见平台包括：

- `opencode`
- `openclaw`
- `hermes`

这个字段的意义不只是展示，还会影响你如何理解接入方式、运行上下文和部分分析结果。

当同一个业务在不同平台上有多套实现时，建议分别登记成不同 Agent。

## 主 Agent 与子 Agent

在多 Agent 系统里，平台会区分：

- **主 Agent**：直接接收用户请求的入口 Agent
- **子 Agent**：由主 Agent 派生、专门处理子任务的 Agent

Agent 概览页的价值之一，就是让你从资产视角看清当前系统到底是：

- 单 Agent 模式
- 一个主 Agent 加少量子 Agent
- 多层协同的复杂编排模式

如果你在链路里看到很多派生执行，回到这里看主子关系通常会更容易理解整体结构。

## 未注册 Agent 是什么

未注册 Agent 指的是：**平台已经收到了它的 Trace，但它还没有被正式登记为资产**。

这通常发生在以下场景：

- 先完成了接入，再补 Agent 概览中的登记信息
- 客户端使用了新的名称上报数据
- 系统中临时派生了一个尚未纳管的运行实体

未注册状态本身不一定是错误，但它意味着：

- 资产治理还不完整
- 页面筛选和归类可能不够稳定
- 团队成员不一定知道这个 Agent 的真实用途

因此，看到未注册 Agent 后，通常建议尽快转为正式登记。

## Agent 概览与客户端安装的关系

很多用户会把“注册 Agent”和“接入 Agent”混在一起，但它们其实是两步：

1. **注册 Agent**：在平台里登记这个对象
2. **客户端安装**：让真实运行环境按平台要求完成接入

建议顺序通常是：

1. 先在 Agent 概览页创建 Agent
2. 再进入 **配置 → 客户端安装**
3. 复制命令或配置项到真实环境执行
4. 回到链路追踪确认第一条 Trace

## API Key 应该怎么看

在实际接入过程中，平台会使用 API Key 将客户端上报的数据与当前账号或 Workspace 绑定。

使用时建议注意：

- 复制 Key 前确认当前登录账号正确
- 如果切换过账号，先刷新或重新登录再复制
- 不要把不同环境混用同一套接入配置
- 如果上报到了错误账号，通常需要先检查是否用了过期或错误的 Key

> **Warning**
> 如果客户端使用了错误的 API Key，上报数据可能会落到其他账号或错误的归属下。
> 看到“为什么 Trace 没出现在当前 Workspace”时，优先检查这里。

## 常见工作流

### 新项目第一次接入

1. 注册 Agent
2. 填写平台和描述
3. 进入客户端安装复制命令
4. 在运行环境执行接入
5. 到链路追踪确认数据

### 把未注册 Agent 转为正式资产

1. 在管理页确认未注册对象的实际用途
2. 统一名称和平台信息
3. 完成正式登记
4. 再观察后续 Trace 是否稳定归属到该 Agent

### 为多个环境分别管理 Agent

1. 为开发、预发、生产分别创建 Agent
2. 使用清晰命名区分环境
3. 分别完成接入配置
4. 后续按 Agent 维度看成功率、Trace 和评测结果

## 常见问题

### 为什么已经有 Trace 了，但看起来没有 Agent？

可能原因包括：

- 当前 Trace 来自未注册 Agent
- 你不在正确的 Workspace
- 过滤条件排除了对应 Agent

### 为什么同一个业务看起来出现了多个 Agent？

常见原因：

- 不同环境使用了不同名称
- 客户端配置不一致
- 主 Agent 和子 Agent 被分别展示

### Agent 概览页和链路追踪页谁更重要？

两者关注点不同：

- **Agent 概览**：看资产和归属
- **链路追踪**：看具体执行过程

一般是先在 Agent 概览里找到对象，再去链路追踪里看细节。
