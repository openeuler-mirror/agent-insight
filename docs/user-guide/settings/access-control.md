# 安装指导

安装指导页用于把真实运行中的客户端接入 Agent Insight，是“平台配置”里最直接影响是否有数据进来的页面。

> **Note**
> 如果你已经创建了 Agent、也配置了模型，但链路追踪里仍然没有数据，优先回到这里检查接入命令和 API Key。

## 这页能做什么

- 生成对应操作系统的一键接入命令
- 查看当前账号的 API Key
- 确认平台地址和上报路径
- 帮助你把客户端快速接入当前平台

## 页面通常包含什么

### 1. 安装命令

页面会按操作系统提供对应的一行命令，例如：

- Linux / macOS
- Windows PowerShell

你只需要复制对应命令，到目标运行环境执行即可。

### 2. 当前账号 API Key

右侧面板通常会展示当前账号对应的 API Key，用于：

- 脚本执行时输入
- 绑定上报身份
- 确保后续 Trace 归属到正确账号

### 3. 接入信息

你通常还能看到：

- 当前账号
- 平台地址
- API Key 状态
- 上报路径

这部分适合在接入失败时做快速交叉检查。

## 推荐使用顺序

最常见的接入路径如下：

1. 先确认你已经登录正确账号
2. 打开安装指导页
3. 复制与你目标环境匹配的一行命令
4. 在 Agent 所在机器执行
5. 按提示粘贴当前 API Key
6. 触发一次最小执行
7. 到 [链路追踪](../observability/view-traces) 确认是否已有数据

## 为什么这里的 API Key 很关键

API Key 决定了客户端上报的数据归属到谁。

如果你使用了错误 Key，常见后果包括：

- 数据跑到别的账号
- 当前 Workspace 看不到 Trace
- 明明客户端有执行，但页面像“没有接入成功”

> **Warning**
> 如果你最近切换过账号，复制命令和 API Key 前最好先确认页面已刷新到当前登录态。

## 什么时候应该重新回来看这页

以下情况建议重新检查安装指导页：

- 刚换了账号或环境
- 重新部署了客户端
- Trace 突然不再上报
- 怀疑接入命令或 Key 过期、混用或复制错误

## 常见工作流

### 第一次接入 Agent

1. 在 [Agent 管理](../agent-management) 中完成登记
2. 打开安装指导
3. 复制命令并执行
4. 粘贴 API Key
5. 在运行观测中确认第一条 Trace

### 修复“没数据”的问题

1. 回到安装指导页确认当前账号和 API Key
2. 确认命令是在正确机器执行的
3. 确认 Agent 真的有执行
4. 再去链路追踪看是否已经出现数据

### 多环境接入

更推荐：

- 开发环境先单独验证
- 每个环境使用清晰命名的 Agent
- 不要混用不同环境的接入配置

## 常见问题

### 为什么页面显示的 API Key 看起来不对？

常见原因：

- 你切换过账号但页面未刷新
- 当前登录态和你预期不一致
- 本地缓存了旧身份信息

### 为什么命令执行成功，但还是看不到 Trace？

优先检查：

- 执行环境是否正确
- API Key 是否正确
- 服务端地址是否可达
- Agent 是否真的跑过一次请求
