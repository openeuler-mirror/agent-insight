# 模型注册

模型注册页用于统一管理平台所依赖的外部 LLM 配置，是评测、分析、优化等能力的基础前提。

> **Note**
> 如果没有可用模型，很多核心能力虽然页面能打开，但无法真正运行。
> 因此模型注册通常是你完成登录后最先需要配置的设置之一。

## 这页能做什么

- 注册新的模型供应商配置
- 管理不同模型的 API Key、Base URL 和参数
- 指定默认模型
- 检查当前模型配置是否健康可用
- 为评测、优化和分析提供统一的模型依赖

## 适合什么时候先来这里

以下场景建议优先检查模型注册：

- 第一次进入平台
- 想跑评测，但任务无法启动
- 想用 Skills 生成或优化，但模型调用失败
- 想切换默认模型或供应商

## 常见配置对象

模型注册支持接入外部 LLM 供应商。当前文档语义上可理解为支持：

- 主流闭源供应商
- 国内厂商
- 自定义兼容接口
- 本地或自托管推理服务

你可以把这里理解为“平台级模型目录”，而不是某个单页面的临时输入框。

## 一个模型配置通常包含什么

常见字段包括：

- **名称**：便于团队识别的配置名
- **供应商**：如 OpenAI、Anthropic、DeepSeek 或自定义兼容服务
- **模型名**：实际要调用的模型
- **Base URL / Endpoint**：供应商地址
- **API Key**：鉴权凭证
- **默认状态**：是否作为当前默认模型使用

## 为什么默认模型很重要

默认模型通常用于：

- 评测与分析流程的兜底调用
- 新任务未显式指定模型时的默认选择
- 平台某些自动化能力的基础配置

> **Warning**
> 删除当前默认模型前，最好先切换到另一个可用模型。
> 否则后续评测、诊断或优化流程可能失去可用的兜底模型。

## 注册模型时的建议

### 使用能长期复用的命名

建议让名称能体现用途或供应商，例如：

- `openai-default`
- `deepseek-eval`
- `local-vllm-lab`

### 区分实验模型与正式模型

如果你同时有生产可用模型和试验模型，建议分开命名和管理，避免误切默认配置。

### 配完后先做健康检查

注册成功不代表真正可用。更稳妥的做法是：

1. 保存配置
2. 确认健康状态
3. 再去评测、分析或生成页面使用

## 常见工作流

### 第一次配置平台

1. 新增一个模型
2. 填好 API Key 和 Endpoint
3. 设为默认模型
4. 检查健康状态
5. 再去运行评测或 Skills 相关功能

### 新增一个专用评测模型

1. 保留当前默认模型不动
2. 新建第二个模型配置
3. 用清晰名称标识其用途
4. 在后续相关任务中按需切换或指定

### 更换默认模型

1. 确认新模型可用
2. 将其切换为默认
3. 再考虑删除旧默认模型

## 常见问题

### 为什么模型已经保存，但某些功能还是跑不起来？

常见原因：

- API Key 错误
- Base URL 不可达
- 模型名不匹配
- 新模型不是默认模型，而当前任务依赖默认配置

### 为什么建议至少保留一个默认模型？

因为很多平台能力需要一个稳定兜底配置。如果默认模型为空，部分分析和评测流程就会失去可执行基础。
