# 用量统计

用量统计面向**平台管理员**，用于查看所有用户对平台各功能的真实使用情况，判断功能采用度与产品投入方向。

> **Note**
> 本页数据用于产品分析，**不用于**业务计费、权限审计或用户绩效考核。统计链路是最终一致的：极端情况下（进程崩溃）可能丢失少量尚未落库的尾部事件。

## 开启条件

用量统计默认关闭，需要同时满足两个条件才会出现入口：

| 条件 | 配置 |
|-|-|
| 功能开启 | 环境变量 `AGENT_INSIGHT_USAGE_ENABLED=1` |
| 当前用户是管理员 | `AGENT_INSIGHT_ADMIN_USERS` 显式配置且包含当前用户名 |

⚠️ 与平台其他管理员功能不同，用量统计对 `AGENT_INSIGHT_ADMIN_USERS` 是 **fail-closed** 的：**未配置时任何用户都不是管理员**，不会回退到默认账号 `admin`。这是为了避免"忘了配置就等于对某个账号全开"。

普通用户既看不到菜单入口，直接访问 `/usage` 或调用管理 API 也会得到 403。

## 什么算一次"有效使用"

只有**用户主动触发**且**到达成功边界**的行为才计 1 次。

**计数**的例子：

- 打开某条 Trace 的详情
- 下载 Skill 版本、上传 / 发布 Skill
- 运行实验、创建数据集、保存模型配置
- 复制安装命令（剪贴板写入成功）

**不计数**的情况：

- 页面进入、菜单点击、地址栏打开、浏览器刷新、重渲染
- 筛选、排序、分页、展开普通 UI 区块
- 后台自动任务、列表轮询、预加载
- 服务端自动重试（属于同一次用户意图）
- 失败与用户取消

此外还有几条去重规则：

- 一次点击打开详情记 1 次，不按详情内部的多个请求计数。
- 流式任务在任务创建成功时计 1 次，不在每个 chunk 或流结束时重复计数。
- 批量任务按一次用户提交计 1 次，不按内部 case、Trace 或文件数量计数。

## 页面结构

1. **时间范围**：7 天 / 30 天 / 90 天 / 全部。日期按 `Asia/Shanghai` 自然日切分。
2. **两个指标**：使用用户（去重用户数）、有效使用次数。
3. **每日有效使用趋势**：按自然日逐日展示；"全部"范围点数过多时只在绘制层抽样，统计口径仍是逐日数据。
4. **功能使用排行**：16 个可统计功能。支持按有效使用次数升 / 降序、使用用户数降序、功能名称升序排序，默认按有效使用次数降序。排序只重排展示，不改变合计。
5. **功能详情**：点击整行或"查看详情"打开抽屉，展示该功能的两个指标、每日趋势与使用行为构成。

> 功能排行按“是否定义了有效使用行为”统计，不与当前侧边栏叶子项一一对应。版本分析、版本管理等保留页面即使不再提供侧边栏入口，历史与直接访问产生的有效使用仍可进入排行；仪表盘只有页面浏览、没有有效业务动作，因此不计数。

## 数据保留

| 数据 | 保留策略 |
|-|-|
| 原始事件 | 默认 365 天（`AGENT_INSIGHT_USAGE_RAW_RETENTION_DAYS`） |
| 日聚合 | 永久保留 |

"全部"范围只读日聚合表，因此原始事件被清理后，历史统计结果不会变化。

## 隐私边界

用量统计只保存"谁在什么时候用了哪个功能"，具体包括用户名、功能 key、事件 key、时间与规范化后的路径（pathname，不含 query）。

**不会保存**：请求正文、Trace 内容、诊断内容、Skill 文件、模型密钥、API Key、IP 与 User-Agent。页面也不提供用户使用明细或用户下钻。

## 关闭与回滚

将 `AGENT_INSIGHT_USAGE_ENABLED=0` 并重启服务即可：入口隐藏、采集 API 不再入队、后台 flush 不再启动。统计表会保留，不会被删除，也不影响任何现有功能。
