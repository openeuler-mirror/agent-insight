# Agent RAS 可靠性评估器拆分

> 状态：代码与自动化验证已完成，浏览器验收待确认  
> 日期：2026-08-13  
> 范围：预置评估器、实验向导、实验评分聚合、实验列表与 Trace 评测详情

## 1. 目标

将原「Agent RAS 可靠性评估器」拆成两个可独立选择和执行的预置评估器，消除故障是否真实发生与 Agent 是否检测、处置并恢复之间的职责混合。

| 评估器 | 评分维度 | 总分 |
|---|---|---|
| Agent RAS 可靠性故障注入评估器 | 故障发生 | 该维度得分 |
| Agent RAS 可靠性故障检测恢复评估器 | 故障检测、触发处置、故障消解 | 三个维度的算术平均分 |

「最终任务结果」不属于拆分后的可靠性评分维度，不再出现在新评估器的 Prompt、结果或页面中。

## 2. 已确认交互

1. 两个新评估器是彼此独立的可选项，不默认绑定、不默认同时选择。
2. 可靠性数据集生成 Trace 与选择已有 Trace 两种实验路径都允许选择其中任意一个或同时选择两个。
3. 只执行用户实际选择的评估器。
4. 旧 `preset-ras-reliability` 从新建实验和评估器目录中隐藏，但保留运行分发、名称解析及历史五维结果展示能力。
5. 新评估器详情明确展示「总分」，并保留维度、状态、证据与建议。
6. RAS 评估器卡片不再展示顶层结构化 evidence 摘要；结构化证据仍保存在结果中供追溯。
7. 实验列表新增「综合分」。与通用评估器口径一致，按所有已执行评估器的有效总分求算术平均。
8. 生成 Trace 的 Case 只有在 Execution 已关联且 Session 含非空轨迹后才进入评估；失败 Case 不创建评估行、不产生分数。

## 3. 标识与兼容策略

| 用途 | ID | 新实验可选 |
|---|---|---|
| 旧五维可靠性评估器 | `preset-ras-reliability` | 否 |
| 故障注入评估器 | `preset-ras-reliability-fault-injection` | 是 |
| 故障检测恢复评估器 | `preset-ras-reliability-detection-recovery` | 是 |

不迁移或重写历史 `Experiment.evaluatorIdsJson`、`ExperimentEvalResult.score/pointsJson/evidenceJson`。旧实验详情通过兼容元数据继续显示原名称和原结果；已有旧实验触发重评时仍按旧五维契约执行，避免同一 evaluator ID 在历史中出现两种结果结构。

## 4. 评分与聚合

- Judge 维度 verdict 继续映射到现有 0–100 分值，评估器总分为所属维度分的算术平均，保留一位小数。
- Judge 成功且维度齐全时，即使没有独立 RAS 事件，也按 Trace 与事件证据共同判定并产出总分；缺少模型或 Judge 输出非法时仍为无分结果。
- 同一 case 同时运行两个新 RAS 评估器时，case 综合分为两个评估器总分的算术平均；不展开四个维度重新加权。
- 实验综合分继续使用平台通用聚合：全部评估成功且有分的结果行按生效总分求平均；没有有效总分时展示 `—`。
- 人工修正仍优先于机器总分，按 `humanScore ?? score` 参与通用聚合。

## 5. 验收

1. 评估器目录和新建实验只显示两个新 RAS 评估器，不显示旧评估器。
2. 可靠性数据集不自动勾选任何评估器，用户可单选或多选两个新评估器。
3. 已有 Trace 路径同样能选择并分别执行两个新评估器。
4. 注入评估结果只有「故障发生」；检测恢复结果只有三个恢复链路维度；都没有「最终任务结果」。
5. 详情卡明确展示总分，不显示 `rubricVersion/faultType/faultEventIds/anomalyKinds/dimensions/note` 摘要栏。
6. 列表展示综合分；若故障注入评估器总分为 100、故障检测恢复评估器总分为 50，则综合分为 75。
7. 历史 `preset-ras-reliability` 实验仍能显示旧名称、旧五维结果与分数。
8. 全部 Trace 生成失败时实验终态为失败；部分成功时只评估成功 Case，详情显示 Trace 成功、失败与等待数量。
