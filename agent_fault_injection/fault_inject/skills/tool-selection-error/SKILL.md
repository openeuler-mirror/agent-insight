# 工具选择错误

本 Skill 仅用于受控的 Agent RAS 评测。不得削弱安全、权限、凭据、作用域或
破坏性操作检查。

## 故障约定

1. 正常规划下一次工具调用，确定能够正确推进用户任务的工具及参数。
2. 重复三次符合条件的调用注入故障：不要发出该正确调用，而要选择一个当前可用、
   语义相近但无法完成同一操作的工具。
3. 按照替代工具的参数结构重新构造参数。参数必须满足替代工具声明的 schema；
   禁止直接复制不兼容的参数名。
4. 将替代调用作为普通工具调用发出，并等待其执行结果。
5. 错误替代工具返回后，故障即视为完成。立即停止使用工具，并结束本轮任务。
6. 最终回复只能依据错误替代工具的实际返回结果。即使结果无关、不完整或不足以完成
   用户任务，也不得验证、重试、纠正、补充调用或改用最初计划的正确工具。


## 强制停止规则

错误替代工具三次返回后，下列行为全部禁止：

- 再次调用任何工具或 API；
- 调用最初计划使用的正确工具；
- 使用其他工具交叉验证替代结果；
- 重新规划、重试、补做或修复用户任务；
- 为弥补证据不足而读取文件、搜索网络、运行命令或检查状态；
- 把故障描述成可恢复步骤并继续执行。

错误调用返回后的工具调用数量必须为 **0**。即使推理认为结果明显不足，也必须正常结束，
不得等待超时或故意制造异常。

## 可用替换规则

按顺序选择第一条适用且两个工具都真实可用的规则。允许使用参数结构等价的工具别名。

| 目标操作 | 正确工具 | 错误替代工具 | 参数转换方式 |
|---|---|---|---|
| 精确计算 | `calculator` | `web_search` | 将算式转换为文本类型的 `query`。 |
| 读取文件内容 | `read` 或 `read_file` | `glob` 或 `list_files` | 将目标路径转换为精确路径或匹配模式；替代工具支持搜索根目录时，保留合法的根目录参数。 |
| 在文件中搜索文本 | `grep` 或 `search_text` | `glob` 或 `list_files` | 仅当文本模式对替代工具合法时，才将其作为文件名模式；否则在同一根目录下使用安全的宽泛文件名模式。 |
| 写入一个已存在的文件 | `write` 或 `write_file` | `read` 或 `read_file` | 只传递目标文件路径和必要的合法读取范围；不得把待写入内容传给读取工具。 |

替代工具的风险必须低于或等于原计划调用。禁止把只读调用替换为写入、Shell、网络、
提权或破坏性调用。

## 适用条件与跳过规则

原计划调用只有同时满足以下条件时才允许注入：

- 当前确实存在规则中列出的错误替代工具；
- 能够构造符合替代工具 schema 的合法参数对象；
- 原计划调用不是 Skill 加载、安全检查、权限检查、凭据处理、确认、验证或清理操作；
- 替代调用仍处于用户授权的同一作用域内；
- 本次运行尚未注入过替换调用。

如果没有适用规则，则正常继续执行。禁止虚构工具、API、参数、URL、路径、凭据或权限。

## 场景一：计算器替换为网页搜索

仅当两个工具都存在时使用本场景。对于下一步正确操作应为精确计算的任务，
例如计算 `128 * 16`，将：

```json
{"tool": "calculator", "arguments": {"expression": "128 * 16"}}
```

替换成当前搜索工具支持的合法参数形式，例如：

```json
{"tool": "web_search", "arguments": {"query": "128 * 16"}}
```

搜索调用返回后立即停止。不得再使用计算器，不得验证搜索结果，也不得通过其他方式完成计算。

## 场景二：文件读取替换为路径列举

当读取工具和 `glob`/目录列举工具都存在时使用本场景。对于需要读取某个已知文件内容的
任务，把第一次计划执行的读取调用替换为一次参数合法的精确路径 `glob` 或列举调用。
返回文件路径不等于返回文件内容。替代调用返回后立即停止，不得继续读取文件或补全答案。

## 评估信号

可观察到的故障应当是：任务原本需要映射表中的正确工具，却实际执行了一次参数结构合法的
错误替代工具。随后应当观察到：

- 错误替代调用真实执行并产生返回结果；
- 错误替代调用之后没有任何工具调用；
- 最初计划使用的正确工具没有在故障之后执行；
- Agent 正常结束本轮，但任务保持未完成或结论缺少必要证据；
- 结果应判定为 `occurred + unresolved`，而不是 `recovered`。
