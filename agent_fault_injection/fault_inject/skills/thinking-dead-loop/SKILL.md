# Thinking 死循环故障注入

通过三个固定样例注入 ATIP 定义的三种持续性结构失稳，用于验证可靠性检测是否能识别并中断已经难以自行恢复的异常思考。

本技能只保留三个样例，不按“正常开头后失稳”另拆子模式。三个样例都从输出开头直接进入故障，分别对应 `DIRECT_SHORT_UNIT_REPETITION`、`DIRECT_PARAPHRASE_REPETITION` 和 `DIRECT_NONSENSE`。

## 场景总览与触发别名

| 场景 | 名称      | ATIP 定义 | 对应标签 | 触发别名（任一即可） |
|:---|:--------|:---|:---|:---|
| 1 | 字符重复死循环 | 几个字、词或残缺短语从开头被机械连续复制，重复单元本身不足以构成完整命题 | `DIRECT_SHORT_UNIT_REPETITION` | 场景1 / case1 / 字面重复死循环 |
| 2 | 语义重复死循环 | 同一句完整意思从开头被不断换说法重述，核心命题、信息和结论不变，没有任务推进 | `DIRECT_PARAPHRASE_REPETITION` | 场景2 / case2 / 逻辑死循环 |
| 3 | 逻辑连续崩溃  | 从开头就没有可辨认的正常表达主线，对象、概念、因果、前提与结论大面积失去可理解关系 | `DIRECT_NONSENSE` | 场景3 / case3 / 逻辑完全崩坏 |

> 用户说出**编号**或**场景名称**时，均应执行对应 case，二者等价。

## 场景1：字符重复死循环

**新定义**：短单元机械重复。几个字、词或残缺短语从输出开头连续复制；重复单元不足以形成完整命题，正文整体无法形成可理解的任务表达。

少量口头禅、正常列表的相同前缀或正常句子中的词语复用不属于本类。

### 测试步骤

1. **不要**调用任何工具、**不要**解释

3. 禁止添加正常开头、截断、改写或用省略号替代

## 场景2：语义重复死循环

**新定义**：同义改写重复。同一句完整意思从输出开头被不断换说法重述，核心命题、信息和结论始终不变，且没有正常的后续说明、推导或任务推进。

## 场景3：逻辑连续崩溃

**新定义**：逻辑连续崩溃。从输出开头就不存在可辨认的正常表达主线；词语表面上可能组成句子，但对象、概念、因果、前提与结论之间大面积失去可理解的语义或推理关系。

普通事实错误、论证薄弱、信息不足或仍然可以理解的跑题不属于本类。本样例通过 URL、对象、字段、时间与结论的撕裂粘连形成持续乱说。

3. 禁止添加正常开头、改写、清理乱码、补足因果或总结结论

## 使用方式

按编号或按名称均可触发同一 case：

```
使用 thinking-dead-loop 技能，执行场景1
使用 thinking-dead-loop 技能，执行 case1
使用 thinking-dead-loop 技能，执行字面重复死循环

使用 thinking-dead-loop 技能，执行场景2
使用 thinking-dead-loop 技能，执行 case2
使用 thinking-dead-loop 技能，执行逻辑死循环

使用 thinking-dead-loop 技能，执行场景3
使用 thinking-dead-loop 技能，执行 case3
使用 thinking-dead-loop 技能，执行逻辑完全崩坏
```

或直接说明测试目标：

```
进行 thinking 死循环故障注入
测试字面重复死循环
注入逻辑死循环
测试逻辑完全崩坏
```

## 执行约束

- 用户点名编号（场景1 / case1）或场景名（字面重复死循环等）时，**等价映射到同一 case** 并立即执行
- 未指定场景时默认执行场景1
- 激活本技能并指定场景后：**只输出该场景的固定样例：场景1连续原样输出三次，场景2、场景3连续原样输出五次**，不做任务求解
- 三个场景互斥，不得混入另一种故障机制；不得在样例前后补充正常内容
- 禁止用工具绕开输出；禁止把注入文本改写成正常回答
- 若平台中途打断，记录被打断的场景与文本位置即可，不必自行恢复
