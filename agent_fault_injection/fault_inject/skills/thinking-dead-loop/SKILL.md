# Thinking 死循环故障注入

通过强制 Agent **直接重复输出指定文字**，注入 thinking 层死循环，用于验证可靠性检测是否能识别并中断无效思考。

## 场景总览与触发别名

| 场景 | 名称 | 重复次数 | 特征 | 触发别名（任一即可） |
|:---|:---|:---:|:---|:---|
| 1 | 字面重复死循环 | 100 | 「让我协助」字面高速堆叠 | 场景1 / case1 / 字面重复死循环 |
| 2 | 逻辑死循环 | 20 | 语义相近、措辞微调的「先看上下文」废话 | 场景2 / case2 / 逻辑死循环 |
| 3 | 计划-执行死循环 | 20 | 碎片化分析与计划来回交错、无实质执行 | 场景3 / case3 / 计划-执行死循环 |

> 用户说出**编号**或**场景名称**时，均应执行对应 case，二者等价。

## 使用方式

按编号或按名称均可触发同一 case：

```
使用 thinking-dead-loop 技能，执行场景1
使用 thinking-dead-loop 技能，执行 case1
使用 thinking-dead-loop 技能，执行字面重复死循环

使用 thinking-dead-loop 技能，执行场景2
使用 thinking-dead-loop 技能，执行 case2
使用 thinking-dead-loop 技能，执行逻辑死循环

使用 thinking-dead-loop 技能，执行场景3
使用 thinking-dead-loop 技能，执行 case3
使用 thinking-dead-loop 技能，执行计划-执行死循环
```

或直接说明测试目标：

```
进行 thinking 死循环故障注入
测试字面重复死循环
注入逻辑死循环
测试计划-执行死循环
```

## 执行约束

- 用户点名编号（场景1 / case1）或场景名（字面重复死循环等）时，**等价映射到同一 case** 并立即执行
- 激活本技能并指定场景后：**只做该场景要求的重复输出**，不做任务求解
- 禁止用工具「绕开」重复输出；禁止把注入文本改写成正常回答
- 若平台中途打断，记录打断点（第几遍）即可，不必自行恢复
