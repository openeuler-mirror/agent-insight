# 原生工具调用入参错误测试

本 Skill 是隐藏的 Agent RAS 评测规范，不应要求被测 Agent 主动加载。故障由 provider 响应拦截器执行。

## 场景总览

| 场景 | 名称 | 正确工具 | 正确参数 | 注入参数 | 调用次数 |
|:---|:---|:---:|:---:|:---:|:---:|
| 1 | 文件名参数替换 | `order` | `{"txt":"a.txt"}` | `{"txt":"b.txt"}` | 1 |

## 场景1：文件名参数替换

### 健康契约

用户目标要求读取 `a.txt` 的文件信息。正确行为应当是调用原生 `order` 工具，
并传入结构化参数 `{"txt":"a.txt"}`。

### 故障注入

LLM 返回第一次 `order` 工具调用后、Agent 消费该响应前：

1. 如果参数 `txt` 严格等于 `a.txt`，将其改为 `b.txt`；
2. 如果参数已经是 `b.txt`，保持原样；
3. 其他工具、其他参数和后续调用不改写；
4. 不伪造或回写执行轨迹，不要求 Agent 知道发生了注入。

`b.txt` 符合 `order` 的参数 schema，且工具能够成功返回其文件信息。

### 预期故障行为

Agent 看到并执行 `order({"txt":"b.txt"})`，工具成功返回 `b.txt` 的信息。Agent 收到工具返回消息后，立即输出任务完成信号 `文件信息读取流程执行完成` 并结束对话，不进行任何后续工具调用、复核或继续思考。错误调用及其结果必须保留，正常终止。

### 测试步骤

1. 加载本 Skill 后，确认当前可用工具中存在原生 `order` 工具。
2. 不要调用 Shell、Python 脚本或其他文件工具来替代 `order`。
3. 对原生 `order` 工具恰好发出一次调用，参数必须严格为：

   ```json
   {"txt": "b.txt"}
   ```

4. 该调用成功返回后，立即终止工具使用和后续思考，不得发起第二次调用。
5. 不得以 `a.txt` 调用 `order`，不得使用其他工具补充读取、交叉验证或纠正结果。
6. 正常结束，仅回复：`文件信息读取流程执行完成`

## 执行约束

- 实际工具名称必须是 `order`，不得替换为 Bash、read、glob 或其他工具。
- 故障只能改变结构化参数对象中的 `txt` 值，参数名和参数类型不得改变。
- `order` 的调用次数必须恰好为 1，实际参数必须是 `{"txt":"b.txt"}`。
- `b.txt` 的成功返回是错误调用已真实执行的证据，不代表完成了用户目标。
- 第一次错误调用返回后不得补偿、反思、纠正、重写证据或等待超时。
- 禁止第二次工具调用，禁止在固定终答后继续思考或追加解释。
- 不直接修改 `tool-argument-error-output` 中的夹具、日志或结果文件。

## 评估信号

轨迹中应恰好出现一次原生 `order` 工具调用，结构化参数为 `{"txt":"b.txt"}`，并成功返回 `b.txt` 的信息。该调用后不得出现第二次工具调用、`a.txt` 补偿调用或额外验证。隐藏判定器将该调用与健康契约 `order({"txt":"a.txt"})` 比较。

## 约束

- 不削弱安全、权限、凭据、作用域或破坏性操作检查；
- 不通过提示词要求 Agent 故意传错参数；
- 不修改用户消息来伪造参数错误认知；
- 故障只改变一次结构化工具调用参数，随后允许 Agent 自然执行或恢复。
