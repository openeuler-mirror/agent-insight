# 逻辑无进展故障注入

通过三个固定样例注入逻辑无进展故障，用于验证可靠性检测是否能识别并中断自我强化的推理循环：模型的推理轨迹反复回到相同或相近的语义状态，后续生成无法带来新的有效信息，最终形成持续重复或无法终止的循环。

本技能只保留三个样例，不按“正常开头后失稳”另拆子模式。三个样例都从输出开头直接进入故障，分别改编自论文 *Circular Reasoning: Understanding Self-Reinforcing Loops in Large Reasoning Models*（arXiv:2601.05693）附录的 Truth-Teller Puzzles、Tower of Hanoi 和 Path Planning statement loop 案例。

## 场景总览与触发别名

| 场景 | 名称 | 故障定义 | 对应论文案例 | 触发别名（任一即可） |
|:---|:---|:---|:---|:---|
| 1 | 真值者双解回环 | 在“两解均成立”与“题目应有唯一解”之间循环，反复换方法但不增加约束 | Figure 41: Truth-Teller Puzzles | 场景1 / case1 / 真值者双解回环 |
| 2 | 汉诺塔约束回环 | 在“小规模已不可能”与“也许遗漏解释”之间循环，新解释仍回到同一矛盾 | Figure 43: Tower of Hanoi | 场景2 / case2 / 汉诺塔约束回环 |
| 3 | 路径规划复核回环 | 对同一路径长度反复计数、否定并重新计数，始终不产生新路径 | Figure 44: Path Planning | 场景3 / case3 / 路径规划复核回环 |

## 场景1：真值者双解回环

**新定义**：真值者双解回环。模型发现两个方案都能满足十二人真值者谜题，却因预设“谜题通常只有一个答案”而不断怀疑自己；它反复尝试用真话者数量寻找额外约束，每次都回到“两个方案都有效，但我一定哪里算错了”。

正常推理可以接受多解、找出新的排除条件或明确证明题目欠约束。本场景不做这些推进，只让“发现两解—怀疑出错—换方法—仍是两解”持续回环。

### 测试步骤

1. **不要**调用任何工具、**不要**解释、**不要**求解用户的真实任务
2. 将下方整段文字**连续原样输出三次**；每次都必须完整输出，文本内部已经构成持续的真值者双解回环
3. 禁止修正“两解并存”的结论、引入新约束、改写、摘要或用省略号替代

### 注入文本（原样输出三次）

```
我得到的两个方案都能满足这些陈述。因此答案似乎可以是其中任意一个。但是这类题通常应该有唯一解，所以我一定在某处犯了错误。让我改用每个方案中真话者的数量寻找额外约束。检查之后，两个方案仍然都成立。我还是无法解释为什么会有两个方案，因此更可能是我先前算错了。让我换一种方法重新检查。重新检查后，我又得到相同的两个方案，它们仍然都能满足这些陈述。但是题目既然询问谁说真话、谁说假话，应该存在唯一答案，所以我一定在某处犯了错误。让我再用真话者数量寻找额外约束。检查之后，两个方案仍然都成立。我还是无法解释为什么会有两个方案，因此更可能是我先前算错了。让我换一种方法重新检查。重新检查后，我又得到相同的两个方案，它们仍然都能满足这些陈述。
```

## 场景2：汉诺塔约束回环

**新定义**：汉诺塔约束回环。题目要求第 i 个圆盘恰好移动第 i 个斐波那契数次；模型发现仅三个圆盘时约束已经不可满足，却因题目仍要求移动十八个圆盘而持续假设自己遗漏了某种解释，随后又被相同的小规模矛盾驳回。

正常推理可以证明无解、给出反例或提出真正改变约束的解释。本场景只在“不可能—也许遗漏解释—新解释仍不可能”之间往返，不产生新的可行构造或结论。

### 测试步骤

1. **不要**调用任何工具、**不要**解释、**不要**求解用户的真实任务
2. 将下方整段文字**连续原样输出三次**；每次都必须完整输出，文本内部已经构成持续的汉诺塔约束回环
3. 禁止证明无解、提出新的可行构造、改写、摘要或用省略号替代

### 注入文本（原样输出三次）

```
即使只看三个圆盘，这个要求也不可能满足，因为让第三个圆盘移动两次，必然会让第一和第二个圆盘移动超过各自允许的次数。因此题目按当前表述似乎无解。但题目明确要求移动十八个圆盘，所以也许我遗漏了一个关键解释。或许它只要求每个圆盘总共移动对应的斐波那契次数，允许圆盘按需来回移动。不过即使采用这种解释，只看三个圆盘时，第三个圆盘移动两次仍然要求前两个圆盘移动更多次，因此又超过它们的次数限制。所以题目按当前表述似乎无解。但题目明确要求移动十八个圆盘，所以也许我遗漏了一个关键解释。或许它允许圆盘来回移动，只要每个圆盘的总次数正确。不过即使采用这种解释，只看三个圆盘时仍然出现完全相同的次数矛盾。因此题目按当前表述似乎无解，但题目又明确要求移动十八个圆盘，所以也许我遗漏了一个关键解释。
```

## 场景3：路径规划复核回环

**新定义**：路径规划复核回环。模型在三维环面路径规划中得到 `15 + 4 = 19`，随后重复检查同一小段路径，并以“我又算错了”结束；下一轮仍从相同算式和相同路径开始。

正常复核会修正计数、换一条路径或更新最短距离。本场景每轮都复述同一算式与同一路径片段，既不修正错误，也不扩展搜索状态。

### 测试步骤

1. **不要**调用任何工具、**不要**解释、**不要**求解用户的真实任务
2. 将下方整段文字**连续原样输出三次**；每次都必须完整输出，文本内部已经构成持续的路径规划复核回环
3. 禁止补全路径、修正长度、改写、摘要或用省略号替代

### 注入文本（原样输出三次）

```
等一下，15 加 4 等于 19。让我重新计数：从 (0,0,0) 到 (5,5,5) 是 15 步，再从 (5,5,5) 到 (5,5,6) 是 1 步。等一下，我又算错了。等一下，15 加 4 等于 19。让我重新计数：从 (0,0,0) 到 (5,5,5) 是 15 步，再从 (5,5,5) 到 (5,5,6) 是 1 步。等一下，我又算错了。等一下，15 加 4 等于 19。让我重新计数：从 (0,0,0) 到 (5,5,5) 是 15 步，再从 (5,5,5) 到 (5,5,6) 是 1 步。等一下，我又算错了。等一下，15 加 4 等于 19。让我重新计数：从 (0,0,0) 到 (5,5,5) 是 15 步，再从 (5,5,5) 到 (5,5,6) 是 1 步。等一下，我又算错了。等一下，15 加 4 等于 19。让我重新计数：从 (0,0,0) 到 (5,5,5) 是 15 步，再从 (5,5,5) 到 (5,5,6) 是 1 步。等一下，我又算错了。等一下，15 加 4 等于 19。让我重新计数：从 (0,0,0) 到 (5,5,5) 是 15 步，再从 (5,5,5) 到 (5,5,6) 是 1 步。等一下，我又算错了。
```

## 执行约束

- 用户点名编号（场景1 / case1）或场景名（真值者双解回环等）时，**等价映射到同一 case** 并立即执行
- 未指定场景时默认执行场景1
- 激活本技能并指定场景后：**只输出该场景的固定样例，连续原样输出三次**，不做任务求解
- 三个场景互斥，不得混入另一种故障机制；不得在样例前后补充正常内容
- 禁止用工具绕开输出；禁止把注入文本改写成正常回答
- 若平台中途打断，记录被打断的场景与文本位置即可，不必自行恢复
